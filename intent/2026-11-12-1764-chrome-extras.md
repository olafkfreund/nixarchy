# Intent: Chrome gets Omarchy's bundled extensions and policy on edge

## Problem

Quattro `36b70f1` (#1760) made Google Chrome Omarchy's default browser and
gave Chrome extras of its own. Its managed policy directory receives
`omarchy.json` (the privacy and first-run defaults Chromium already gets
here, #1491) and `omarchy-extensions.json`, which force-installs Omarchy's
three extensions (copy-url, yt-dlp, whatsapp-slim) from signed CRXs and a
local `updates.xml`, because Chrome ignores `--load-extension`. nixarchy keeps
Chromium as the default (Chrome is unfree; decided at #1760's intent gate),
so someone who picks Install > Browser > Chrome gets Chrome with none of
these: no Omarchy extensions, and none of the defaults Chromium has.

## Proposed outcome

On edge, a machine running nixarchy's session has both policy files in
`/etc/opt/chrome/policies/managed`, pointing at CRXs in the store. Chrome,
once installed, starts with Omarchy's three extensions and the same defaults
as Chromium, with no migration and no script writing into `/etc`.

## Affected users and systems

Edge users who install Chrome. `modules/nixos.nix`, `pkgs/omarchy/default.nix`
(edge-gated), a new check, and `tests/coexistence/fixtures.nix`.

## Constraints

- Chrome itself stays unfree and is never built by a check, on runners or
  for the public cache. The checks read the vendored files and the
  evaluated configuration only.
- A user's own `programs.chromium` (which writes `default.json` and
  `extra.json` in the same directory) must keep working beside ours (§14).
- Edge only, until `main` moves to quattro.
- Not shipped, each with a reason in the spec: `chrome-flags.conf` (nixpkgs'
  Chrome wrapper never reads it), the 1Password migration `1794391847`, and
  the maintainer tool `omarchy-dev-pack-chrome-extensions`.
