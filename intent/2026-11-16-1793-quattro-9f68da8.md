# Intent: edge adopts quattro 9f68da8 (Omaview, icon sets, Files as file chooser)

## Problem

Edge is held on quattro `74de104` (#1793). The edge run on 2026-11-15
(run 43768125851) tried `9f68da8`, which is 43 upstream commits later. It
stopped at two failures, and 159 checks did not run because they depend on
them:

- `omarchy-edge-20261115-9f68da8`: the `bin/omarchy-agent-account-add` hunk
  of `pkgs/omarchy/1625-no-mise.patch` no longer applies. Upstream replaced
  the `mise use -g` block the hunk removes with a `cli_missing` function and
  an `install_cli` wrapper that streams mise's download progress to the
  agents panel. The new code still installs agent CLIs through mise, which
  nixarchy has removed (#1625).
- `nixarchy-user-migrations-ledger`: one new command and four migrations
  that touch user files have no row:
  - `omarchy-install-browser-extensions` (run by `1794741886`) re-seeds
    Chromium-family browsers' bundled extensions, and writes Chrome's
    managed policy as root;
  - `1794644424` moves `~/.config/omarchy/themed/icons/*.svg.tpl` to
    `~/.config/omarchy/icons/papercraft/` and redraws icons;
  - `1794763180` installs launchers for signed-in agents into
    `~/.local/share/applications`;
  - `1794774234` runs `omarchy-pkg-add omaview`, deletes stock `imv` and
    `mpv` launchers by checksum, and drops `imv` and `mpv-mpris`;
  - `1794775358` adds `FileChooser=folio;gtk` to the user's
    `hyprland-portals.conf` and restarts the portal.

More checks may fail once the package builds, because the cascade hid
them. The spec lists them after a build, not before.

Behind those failures, the batch changes what a user gets:

- **Omaview replaces imv and mpv.** Upstream's
  `default/applications/mimeapps.list` opens images, video and audio (MP3,
  FLAC, WAV, Opus and others; 45 entries) with `omaview.desktop`. Three
  scripts call `omaview` directly: the screen-recording and download
  notifications, and the Plymouth preview. The Hyprland window rules move
  from imv/mpv to Omaview, and `launcher.hides` hides mpv. The
  screen-recording webcam overlay now runs `ffplay` instead of `mpv`. On
  edge, nixarchy's own MIME defaults send six video types to `mpv.desktop`
  (`modules/nixos.nix:2421-2426`), which must be reconciled. Omaview (omacom/omaview v0.1.0, MIT, released
  2026-11-15) is not in nixpkgs. The Omarchy build requires every desktop ID
  a shipped `mimeapps.list` names to exist (`pkgs/omarchy/default.nix`).
  `mpv` stays as the video-wallpaper engine. The build's desktop-ID guard
  (`pkgs/omarchy/default.nix:1307`) reads only `config/*mimeapps.list`. It
  does not cover this file, so a missing Omaview would not fail the build.
  Links would simply open nothing.
- **App icons become an icon set.** There are new `omarchy-icons-*`
  commands (set, list, preview, install, remove, update, switcher) and two
  sets (arcade, papercraft), picked apart from the theme. User templates
  move out of `themed/icons`.
- **Files becomes the file chooser.** The migration adds
  `FileChooser=folio;gtk` to the Omarchy portal config, but only where that
  config exists and no chooser has been picked yet. Edge packages Folio at
  v0.2.0 (`pkgs/apps/folio.nix`), which has no portal backend. Folio's
  `share/folio.portal` and its D-Bus service first ship in v0.5.0
  (2026-11-15). Edge registers only `xdg-desktop-portal-gtk`
  (`modules/nixos.nix:2440`).
- **Browser extensions are repaired on browser choice.**
  `omarchy-default-browser` (line 48) now runs
  `omarchy-install-browser-extensions --check` for an installed
  Chromium-family browser, and aborts the selection if the repair fails
  (line 55). The command needs root for Chrome's managed policy, and it
  requires the policy directories and their parents to be root-owned and
  not writable by others (line 45). nixarchy makes those directories owned
  by `browserThemeUser` when that option is set.
- **Agent launchers.** Each signed-in agent gets its own launcher. A
  first sign-in from the agents panel also sends a "ready to code"
  notification. There is a new `omarchy-agent-logo`.
- **Smaller items:**
  - Snapdragon/N1x/Surface/IdeaPad hardware migrations (Arch-only boot and
    firmware);
  - ChromeOS EC lid bindings;
  - holding Alt in the system menu to reboot to firmware;
  - `--help` and missing-argument handling across scripts;
  - safer quoting in `hsl`, `tsl` and `tdlm`, and `eff` no longer opening
    an editor when its picker is cancelled;
  - Grok's zero-quota usage fallback;
  - ChatGPT removal quits the running app first;
  - translations.

## Proposed outcome

- Edge runs quattro `9f68da8` with every check green, and `edge` publishes.
- **Agent CLIs:** they are still installed by Nix, never mise. The
  account-add path still refuses with nixarchy's message when the CLI is
  missing. The new launcher and notification work.
- **Omaview:** it is packaged as `pkgs/apps/omaview.nix`, in the same way as
  Folio, and installed where upstream installs it. Images, video and audio
  open in it, including nixarchy's own video defaults. imv is dropped where
  upstream drops it, and the webcam overlay's `ffplay` resolves.
- **Icon sets:** the commands work against the read-only Omarchy tree, and
  a user's moved templates land where upstream puts them.
- **File chooser:** Folio's chooser is registered with the portal, and its
  `.portal` file names FileChooser with a working D-Bus activation. If that
  cannot be made to work, the GTK chooser stays and nothing advertises a
  backend that does not exist.
- **Browser choice:** picking a Chromium-family browser still works, both
  with `browserThemeUser` set and without it, and both check and repair
  modes behave as upstream's do.
- **Ledgers:** every new migration and command has a row in the ledgers'
  own vocabulary (`ported`, `partial`, `declined`, `not-needed`, plus
  `run`), with the reason.
- No host changes until edge publishes. The hosts then follow edge as
  usual.

## Affected users and systems

- Edge users (the owner's p620 and razer follow `edge`). `main` is
  unaffected until a later edge→main merge.
- **Files:** `flake.nix`/`flake.lock` (pin), `pkgs/omarchy/default.nix`
  and `1625-no-mise.patch`, new `pkgs/apps/omaview.nix`,
  `pkgs/apps/folio.nix` (to v0.5.0),
  `data/user-migrations.nix`, `data/user-migration-commands.nix`,
  `data/omarchy-packages.nix`, `data/bin-ledger.nix`, and possibly
  `modules/nixos.nix` (the portal, Omaview, and the MIME defaults).
- Folio, `data/user-migration-commands.nix` and the agent changes exist
  only on `edge` so far. The carry builds on `edge`, not `main`.

## Constraints

- The carry goes to `edge-candidate` with the pin in all three places
  (`flake.nix` url, `omarchyVersion`, `flake.lock`), per CLAUDE.md §8.
- Omaview must build from source in the sandbox. It is MIT, so it may go
  in the public cache.
- No mise anywhere (#1625).
- Mode A: Omaview and the portal change apply only where nixarchy already
  installs the Omarchy desktop.
- Every new or retargeted check proves it fails (§1).

## Open questions

1. **Omaview.** Proposal: package v0.1.0 now, as Folio was. The alternative
   is to rewrite the shipped `mimeapps.list` and the three scripts back to
   imv/mpv until Omaview is in nixpkgs. That keeps edge further from
   upstream and means carrying three script patches.
2. **The Folio file chooser.** Folio 0.2.0 has no backend; 0.5.0 does.
   Proposal: bump Folio to 0.5.0 in this carry and register its portal.
   The spec verifies the `.portal` file names FileChooser and that D-Bus
   activation works. If that fails, keep GTK.
3. **`omarchy-install-browser-extensions`.** Proposal: adapt it as
   `omarchy-theme-set-browser-policy` was, with no root, relaxing its
   ownership check to nixarchy's tmpfiles-owned directories. Skipping it is
   not an option: `omarchy-default-browser` calls it and aborts on failure.
