# Intent: edge adopts quattro 36b70f1 (Chrome by default, Agent at the root menu)

## Problem

Edge is held on quattro `ceb30ed` (#1760). The edge run on 2026-11-12
(run 43165761596) tried `36b70f1`, 124 upstream commits and 300 files
later, and stopped at three failures; 149 more checks did not run because
they depend on the first:

- `omarchy-edge-20261112-36b70f1`: the `--replace-fail` in
  `pkgs/omarchy/default.nix:578` that adds `chromium*` to the browser
  `case` in `bin/omarchy-launch-webapp` no longer matches. Upstream now
  lists `chromium*` itself, so that half is fixed upstream. Its fallback is
  still `google-chrome.desktop`, then `chromium.desktop`, and NixOS names
  Chromium's entry `chromium-browser.desktop` (`pkgs/AGENTS.md`, "every web
  app failed"). nixarchy renames that ID in three other scripts
  (`pkgs/omarchy/default.nix:1247`) but not in this one, so a fallback
  still finds no Chromium.
- `nixarchy-default-agent-routes`: it reads `setup.default.agent.*` rows
  from the menu and finds none; the 24 rows are now `agent.harness.*`
  (the "got 1" is its count of an empty match). Upstream moved agent setup out of
  Setup > Default to a root **Agent** menu (Agent > Harness, Agent >
  Instructions), so the check reads the old layout. This is the check
  measuring the arrangement, not a lost route (CLAUDE.md §1, read backwards).
- `nixarchy-user-migrations-ledger`: three new migrations touch user files
  and have no row in `data/user-migrations.nix`:
  - `1794344676`: links the shared `AGENTS.md` into added Grok accounts;
  - `1794387387`: rewrites the legacy Super + Ctrl + X dictation bind in
    `~/.config/hypr/bindings.lua` to `o.rebind`, because that key now opens
    the agents panel. nixarchy already runs upstream's `1793477875`
    (`data/user-migrations.nix:194`, `ported`, `run = "upstream"`), which
    appended exactly that legacy line for existing dictation users, so
    real homes here can hold it;
  - `1794397144`: removes `yaru-icon-theme` with pacman and the arrow links
    Setup made inside it, because Files draws its own icons.

The checks that cascaded have not run against `36b70f1`, so more ledgers
(bin, package, menu rows, patched files) may fail once the package builds.
The spec lists them after a build, not before.

Behind those failures, the batch changes what a user gets:

- **Google Chrome is the default browser for new installs.** Upstream's
  `mimeapps.list` names `google-chrome.desktop` for `http`/`https`, Chrome
  replaces Chromium in the base package set (`install/omarchy-base.packages`
  now lists `google-chrome` and no `chromium`), and gets the bundled extensions from signed
  CRXs, the 1Password extension, seeded flags and the browser policy.
  Web apps fall back to Chromium where Chrome is not installed. Chrome is
  unfree in nixpkgs, and the build requires every desktop ID a shipped
  `mimeapps.list` names to exist in the Omarchy output
  (`pkgs/omarchy/default.nix:1224`).
- **Agent is a root menu entry.** Setup > Agent moves to the root beside
  "Make something", with Harness and Instructions. Super + Ctrl + X opens
  the agents panel.
- **One shared set of agent instructions.** The new
  `omarchy-agent-instructions` links each harness's global instructions
  file to `~/.agents/AGENTS.md`, moving existing content there or backing
  up a differing file and replacing it with a link. Picking a default agent
  calls it. That changes which rules each agent reads, in the user's home.
  nixarchy's own default-agent setter does not call it today.
- **Yaru leaves, and themes set Adwaita icons.** Files draws its own
  icons, the migration changes GTK and Qt settings that name Yaru, and
  `omarchy-theme-set-gnome` now runs `gsettings set
  org.gnome.desktop.interface icon-theme "Adwaita"` on every theme change.
  nixarchy ships `yaru-theme` for the icon theme (`modules/nixos.nix:1461`,
  ledger row in `data/omarchy-packages.nix:306`).
- **The editor writes MIME defaults.** `omarchy-cmd-editor-mimetypes`
  points every text type at the chosen editor in `~/.config/mimeapps.list`.
  Its `--unless-chosen` mode keeps a type the user picked an app for; an
  explicit editor choice replaces matching associations.
- Smaller items: the agents panel shows and controls tailnet-shared models
  (Tailscale), the screen-recording indicator shows the microphone level,
  Surface Laptop 8 setup on
  existing installs, and translations.

## Proposed outcome

- Edge builds and passes its checks on quattro `36b70f1`, and #1760 closes.
- Web apps open in Chromium in both cases: when Chromium is the default
  browser, and when another, unsupported browser is the default and only
  Chromium can run web apps. A check proves both; replacing the old
  `case` patch alone does not.
- `default-agent-routes` reads the rows the pinned menu has (Agent > Harness
  on quattro, Setup > Default > Agent on v4.5.0, so `main-pin` stays green) and still
  proves every row has an install route nixarchy supports, or an explicit
  refusal that keeps the previous default.
- Shared agent instructions are decided (open question 4): a user's
  distinct per-agent rules and a link they made themselves survive.
- An existing per-type editor choice in `mimeapps.list` survives the
  upgrade; only an explicit new editor choice replaces associations.
- Each new migration behaves as decided in the spec, and its row in
  `data/user-migrations.nix` records that (`ported`, `partial` or
  `not-needed`). The Super + Ctrl + X rewrite runs on a user's own file,
  so it is either ported with the same exact-line guard or recorded as not
  needed, never applied more broadly.
- The default browser is decided explicitly (open question 1), and a
  machine whose user chose a browser keeps it.
- `main` (tag v4.5.0) does not change behaviour. Lines that depend on the
  pin hold under both pins, as the #1752 gate now checks.

## Affected users and systems

- Edge users, and p620 and razer, which deploy edge.
- `pkgs/omarchy/default.nix` (the web-app patch, the desktop-ID check,
  runtime inputs), `modules/nixos.nix` (the browser default, MIME
  defaults, the Yaru icon theme), the ledgers in `data/`, and the checks
  that read them (`default-agent-routes`, `user-migrations-ledger`,
  `patched-files`, the menu-row mapping, `session`, `coexistence`).
- `main` only through code that has to hold under both pins.

## Constraints

- Nothing unfree by default: a machine with `allowUnfree = false` must
  still evaluate and build (`checks.options` covers this).
- One copy of each line works under both pins (§8), proven by edge's
  `main-pin` job. A row only quattro needs carries `edge = "only"`.
- The carry goes on `edge-candidate` and pins quattro in both copies in
  `flake.nix` plus `flake.lock` (§8). The artifacts merge to `main` by
  their own PR.
- A user's own browser, `text/html`/`http` handler, text-type handlers and
  icon theme survive (§14), with a coexistence fixture for each default
  that changes. Upstream's theme setter forcing Adwaita has to be squared
  with that promise.
- Upstream scripts that write a user's `mimeapps.list` or an agent's
  instructions file must not replace a Home Manager symlink there (#1304).
- New commands the batch calls (the microphone level, the tailnet model
  panel, Surface setup) are in `runtimeInputs` or deliberately skipped,
  and the panel degrades when Tailscale is off (§2).
- Docs that name the moved menu and the new key (`docs/manual`, the
  keybinding list, `tests/demo/`) follow the change (§4).
- Every check I add or retarget is proven to fail first (§1).

## Open questions

1. **Default browser: confirm Chromium stays the default.** The
   no-unfree constraint already rules out Google Chrome as a default; what
   this decides is carrying Chromium against upstream's base set. My
   recommendation is to keep Chromium as the default, give it upstream's
   extensions, flags and policy where those moved to Chrome, and
   keep Chrome under Install > Browser, where it already is
   (`data/apps.nix:36`). Chrome is unfree, so following
   upstream would make the default depend on `allowUnfree`, and the shipped
   `mimeapps.list` would name a desktop ID that is missing whenever it is
   off. The spec would carry upstream's Chrome policy, flags and extension
   work for users who pick Chrome.
2. **Yaru and icons: follow upstream to Adwaita on edge?** My
   recommendation is yes on edge only (`edge = "only"`), with a session
   screenshot of Files and of a GTK and a Qt app after a theme change,
   and leaving an icon theme the user set themselves alone. `main` keeps
   Yaru, because v4.5.0's theme setter sets `Yaru-<colour>` icons.
3. **Super + Ctrl + X for existing dictation users:** keep their dictation
   toggle, or give the key to the agents panel? My recommendation is to
   run upstream's `1794387387` as is (`ported`, `run = "upstream"`): it
   changes only the exact line `1793477875` wrote, so the panel keeps the
   key for everyone else and hand-written binds are left alone.
4. **Shared agent instructions: adopt `~/.agents/AGENTS.md`?** My
   recommendation is to adopt it on edge, including from nixarchy's
   default-agent setter, with upstream's move-or-back-up behaviour, and
   to leave a symlink the user made (Home Manager included) as it is.
