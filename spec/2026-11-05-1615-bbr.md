# Spec: BBR and fq reach nixarchy, a user's `mkDefault` survives, and upstream's sysctl values can't drift silently

Part of #1610. The intent's decisions stand: adopt BBR and fq, a user's own
`mkDefault` survives, fix all 15 keys, value-check the three `sysctl.d` files,
assert `/proc/sys` in a booted VM, Kyber stays declined, and the release note says
how to restore `cubic`.

Everything marked "measured" was run on 2026-11-05 in a throwaway worktree of this
branch, evaluating `nixosConfigurations.reference` with `extendModules`. The
prototype took 4 s and 630 MB per run.

## Design

### 1. The priority: `mkOverride 1250`

`modules/nixos.nix:2222` becomes:

```nix
kernel.sysctl = lib.mapAttrs (_: lib.mkOverride 1250) {
  "net.ipv4.tcp_mtu_probing" = 1;
  "net.core.default_qdisc" = "fq";
  "net.ipv4.tcp_congestion_control" = "bbr";
  # ...the other 12 keys, unchanged
};
```

**This departs from the rule.** `modules/services/default.nix:19` and §7 say
`mkDefault` on scalars, and `modules/AGENTS.md:454` says it for this block.

**Why the rule fails here.** `boot.kernel.sysctl` merges through `mergeOneOption`
(nixpkgs `nixos/modules/config/sysctl.nix:17`), so two definitions at one priority
are an error, even with equal values. A user's `mkDefault` is at 1000, the same as
ours. Only a priority weaker than 1000 lets it through. `mkDefault`'s promise that
"their plain definition wins" is still kept; this also keeps it for their
`mkDefault`.

**Why 1250.** The tree already uses it for the same collision and documents it
(`modules/nixos.nix:2291`, `modules/AGENTS.md:816`). `mkOptionDefault` (1500) would
tie with a user's `mkOptionDefault` and refuse to evaluate. At 1250 that user
silently loses, which is rare and doesn't break the machine. No nixpkgs module sets
any of the 15 keys (grep of `nixos/modules`), so nothing else's default is displaced.
Another module's `mkDefault` beats ours too, as any opinion should.

Measured, as `[qdisc, congestion control, swappiness]`:

| The user's definition | Today | Keys added at `mkDefault` | Keys added at 1250 |
|---|---|---|---|
| none | `[null, null, 150]` | `[fq, bbr, 150]` | `[fq, bbr, 150]` |
| `razer`'s shape: `mkDefault "fq"`, `mkDefault "bbr"` | `[fq, bbr, 150]` | **eval error** | `[fq, bbr, 150]` |
| `mkDefault "fq_codel"`, `"cubic"`, `10` | **eval error** | **eval error** | `[fq_codel, cubic, 10]` |
| plain `"cake"`, `"cubic"`, `10` | `[cake, cubic, 10]` | same | same |
| `mkForce` of the same | `[cake, cubic, 10]` | same | same |
| plain `null` on congestion control | `[null, null, 150]` | `[fq, null, 150]` | `[fq, null, 150]` |

The first eval error in the "today" column is the collision on `vm.swappiness` that
the intent measured, and it is why the other 13 keys change too.

**`razer`'s shape** is `lib.mkDefault` on both keys, read from
`modules/common/networking.nix:54-55` in a worktree of the owner's config
(`nixos-bump-174`), with no plain value under `hosts/razer`. That repo is not
touched. The fixture below copies the shape.

**Not in scope:** `fs.inotify.max_user_watches` is nixpkgs' own `mkDefault`
(`sysctl.nix:122-123`), so a user's `mkDefault` on it ties with nixpkgs and not
with us. It stays `covered`, and we don't set it.

Text that must change with this: the comment at `modules/nixos.nix:2219-2221`,
`data/etc-overlay.nix:220,230` (which also names the new keys),
`modules/AGENTS.md:451-454`, and a sentence in AGENTS.md §7 naming this exception.

### 2. What the intent left unverified

**`systemd-sysctl` with the module absent: a quiet `cubic`, not a failed unit.**
Measured with systemd 262's real binary inside `unshare -Urn`, where writing an
unknown algorithm returns the same `ENOENT` the kernel returns for a missing one:

```
Couldn't write 'nosuchcc' to 'net/ipv4/tcp_congestion_control', ignoring: No such file or directory
sysctl-exit=0
```

The next key in the file was still applied. So a kernel without `tcp_bbr` boots
fine, `nixos-rebuild switch` doesn't fail, and the machine runs `cubic` with one
journal line. **That is why evaluation can't see it and the VM assertion must read
`/proc/sys`.** Limits: `default_qdisc` isn't visible in a network namespace
(measured), so the `fq` half relies on the same `ENOENT` path and wasn't run.

We add no `boot.kernelModules`. It isn't needed on nixpkgs' kernel (the intent's
`p620` measurement), and it turns a quiet fallback into a failing
`systemd-modules-load` on a kernel without the module.

**`security.lockKernelModules`: no boot-time conflict, by reading; not booted.**
`disable-kernel-module-loading` runs after `config.systemd.defaultUnit`
(`nixos/modules/security/lock-kernel-modules.nix:24-30`), and `systemd-sysctl` runs
long before it, so the module loads first. A later `switch` on a locked machine
that hasn't loaded them yet reaches the measured `ENOENT` branch: exit 0, `cubic`
until reboot. nixarchy never sets this option (grep of `modules`, `installer`,
`tests`). Unrun: the VM gate was closed (`gh run list` printed 3).

**Microvm guests: one template gains the keys; not booted.** Measured:

| Template | Congestion control, qdisc | Kernel |
|---|---|---|
| `nixarchy-desktop` | `bbr`, `fq` | 7.3.1, the reference's `linux-config` drv, so `=m` |
| `shell` | `null`, `null` | 6.18.60 |

`modules/microvm/guest.nix` doesn't import nixarchy; only `nixarchy-desktop` does
(`modules/microvm/templates/nixarchy-desktop.nix:20`). Whether the guest loads the
module wasn't run. If it can't, it gets the quiet `cubic` above, which harms
nothing. No assertion is added for it.

**Existing interfaces.** `/proc/sys` changes on `switch`, but an interface keeps its
qdisc until it next comes up, and open TCP connections keep their algorithm. The
outcome says "after a reboot" for this reason. By reading, not measured.

### 3. The value check: `checks.etc-sysctl`

A new file, `tests/etc-sysctl.nix`, taking `pkgs`, `reference` and `inputs.omarchy`.
It computes everything at evaluation and fails in a `runCommand`, not a `throw`,
because an eval error kills a whole batch and reports the siblings as never run (§13).

1. **Which files:** rows of `data/etc-overlay.nix` whose name starts `sysctl.d/`.
   So a new upstream file goes red in `etc-overlay` until it has a row, and is then
   covered here with no second list. A row whose file is gone is reported.
2. **Parse** each file: drop blank lines and `#` comments, split on the first `=`.
   Any other line shape is reported, not skipped. Comments and order can't trip it.
3. **Compare** with `reference.config.environment.etc."sysctl.d/60-nixos.conf".text`,
   parsed the same way. That text is what the machine reads, so no coercion is
   reimplemented. A `vm.swappiness` of `150` and a `"150"` can't disagree.
4. **Record a decision:** a row may carry
   `differs."<key>" = { upstream = "<value>"; reason = "..."; };`. A key is accepted
   if upstream still holds that value. A row is red if upstream moved again, or if
   the key no longer differs, so a decision can't go stale. The `etc-overlay` check
   reads only `class` and `reason` (`tests/etc-overlay.nix:43`), so it is unaffected.
5. **Sweep for the user's `mkDefault`:** extend `reference` once with
   `mkDefault "sentinel"` on every key from a `native` row, and report any key that
   isn't the sentinel or doesn't evaluate. This is derived from upstream's files, so
   a future key can't be forgotten (§4). `covered` rows are excluded: see above.
6. **Floor:** fewer than 10 keys found is a failure, since an empty list passes
   everything (the same reason as `tests/etc-overlay.nix:81`).

**Wiring.** A `checks.etc-sysctl` entry in `flake.nix` beside `etc-overlay` (`:2711`),
and nothing in a workflow (§4): `generated-checks.sh` picks it up on pull requests,
and `edge-build.sh:29,47` builds the same list.

**Edge.** Add `etc-sysctl` to `LISTED` in `.github/scripts/edge-report.sh:11`.
Otherwise a quattro commit that changes a value reads as "investigate", not as
"needs a classification row". The decision is a `differs` entry or a changed value,
carried on `edge-candidate` under §8's existing rule.

**The hole, named in `tests/AGENTS.md`:** the other `native` rows, including the
`key=value` drop-ins for systemd, logind, oomd, NetworkManager, sudo and Docker
logs, map to differently shaped options and are still classified by name only. An
edit to one of those upstream files stays silent. `modules/AGENTS.md:451-453` gets
the same correction: sysctl edits now fail, the others don't.

### 4. The VM assertion

Add to `tests/session.nix`, beside the existing `/proc/sys` read (`:324`). `session`
is the existing check with nixarchy on and nixarchy's own kernel: it sets no
`kernelPackages`. `integration` doesn't boot.

The assertion reads `/proc/sys/net/ipv4/tcp_congestion_control` and
`/proc/sys/net/core/default_qdisc` and compares them with the values in
`nodes.machine.boot.kernel.sysctl`, not literals, so a recorded `differs` needs one
edit. The value check says the configuration matches upstream; this says the kernel
runs the configuration.

### 5. The other test rows

- `tests/options.nix:1200`: add `etcNativeCongestionControl` and `etcNativeQdisc`, for
  the off state (Mode A gains nothing). The value check only sees the on state.
- `data/etc-overlay.nix:330`: "Tracked in #1386" becomes declined, citing the owner's
  2026-10-20 decision. No code changes for Kyber.

### 6. The release note

**`release-notes.sh` would say the opposite of the truth.** Its section 2 scans for
`name = lib.mk(Default|Force)` (`.github/scripts/release-notes.sh:255`). Measured on
the diff of this change, it matches nothing: sysctl keys are quoted and their
`mkDefault` is in the `mapAttrs`. So a release would print "No NixOS default this
port sets moved." That has been true of every sysctl since #642.

Widen the awk pattern, not the `present` guard, to also match
`"(net|vm|fs|kernel)[.]...." =` lines. When any such line moved, print once:

> To keep another value, set it in `boot.kernel.sysctl`; a plain value or your own
> `mkDefault` wins, and `null` leaves the key to the kernel.

The commit subject, which section 4 of the notes lists, and the Discussions post
(§14) carry the specific step. Draft for both:

> nixarchy now runs BBR and fq, as Omarchy does. New TCP connections on a machine
> with no opinion move from `cubic` to `bbr` on the next rebuild, and interfaces move
> to `fq` at the next reboot. To go back:
>
> ```nix
> boot.kernel.sysctl."net.ipv4.tcp_congestion_control" = "cubic";
> boot.kernel.sysctl."net.core.default_qdisc" = "fq_codel";
> ```

`pkgs/omarchy/skills/nixos-performance/SKILL.md:248-253` needs no change: its plain
`cake` and `bbr` still win.

## Coexistence

Added to `tests/coexistence/fixtures.nix`, asserted in `tests/coexistence/default.nix`
under `tryEval`, so a tie names the fixture rather than aborting the whole check.

| Fixture | Shape | Must hold | Can fail on |
|---|---|---|---|
| `sysctl-razer` | the five keys of `networking.nix:54-58`: `mkDefault` on four, plain `tcp_mtu_probing` | evaluates, `fq`, `bbr` | ours at `mkDefault`: measured eval error |
| `sysctl-own-mkdefault` | `mkDefault "fq_codel"`, `"cubic"`, `10` on swappiness | their three values | ours at `mkDefault`: eval error. Ours at 900: measured `[fq, bbr, 150]` |
| `sysctl-own-plain` | plain `"cake"`, `"cubic"`, the skill's advice | their values | ours at `mkForce`: not run; it follows from the table |

**Both of the first two are needed.** Measured at priority 900, `sysctl-razer` stays
green, because its values equal ours and so it can't tell who won. Only the differing
fixture sees that. `sysctl-razer` is kept because it's the real machine this exists for.

Nothing added here needs a warning or assertion: a user's value wins silently, which
is the correct outcome.

## Alternatives rejected

- **Keep `mkDefault`, the issue's suggestion.** Breaks `razer` at evaluation.
- **`mkOptionDefault`.** Ties with a user's `mkOptionDefault`. 1250 is already documented.
- **Weaken only the two new keys.** The other 13 have the same collision, in one
  `mapAttrs`, and splitting is more code (intent, question 3).
- **Install upstream's file through `environment.etc`.** A `99-` file overrides a
  machine's `60-nixos` (`modules/AGENTS.md:449`).
- **`boot.kernelModules = [ "tcp_bbr" "sch_fq" ]`.** Not needed, and worse on a kernel
  without them. See section 2.
- **Put the values in `tests/etc-overlay.nix`.** It takes only `pkgs` and needs the
  `omarchy` package built. Adding `reference` couples a cheap inventory check to an
  evaluation, and the sibling needs no package at all.
- **Read `boot.kernel.sysctl` in the value check.** It needs a reimplementation of
  `sysctl.nix`'s value rendering.
- **Read upstream from the shipped tree.** That is import-from-derivation. `etc-overlay`
  already proves the tree ships, and `pkgs/omarchy/default.nix` patches nothing here.
- **Leave `release-notes.sh` alone.** The notes would state a falsehood about this change.

## Risks

- **Every machine with no opinion changes TCP behaviour** on its next rebuild. This
  is what was approved. BBR on lossy Wi-Fi wasn't measured here; `p620` and the
  owner's config are the only evidence. The note gives the way back.
- **A user at `mkOptionDefault` silently loses** to ours. Rare, and not a failure.
- **A silent `cubic` on a kernel without the module.** Only the `session` assertion
  would notice, and only for nixarchy's kernel.
- **A real collision the sweep can't see:** a user's `mkOverride 1250` on one of
  these keys ties. That is an odd thing to write; not handled.
- **`modules/nixos.nix` is shared with #1611-#1614.** The diff stays inside the block
  at `:2219-2237`.
- **`nix fmt` and the local `nixpkgs-fmt` hook** can reindent the file (§5). Check
  `git diff --stat`. Don't use a heredoc inside a `''` string in the new test (§5).
