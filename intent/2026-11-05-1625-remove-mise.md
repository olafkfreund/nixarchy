# Intent: mise installs and controls nothing on a nixarchy machine

## Problem

The owner's decision, 2026-11-05: "strip mise from the code, I do not want mise
to install or control anything on our machines."

Today mise ships on every machine and acts on it in 12 ways. This map is measured
against `main` at Omarchy v4.5.0. Upstream paths are in the v4.5.0 tree; "read"
means read in the code, "ran" means executed here.

| # | What it does | Where | Reach on NixOS |
|---|---|---|---|
| 1 | On every machine's PATH | `pkgs/omarchy/default.nix:85,272`, `data/omarchy-packages.nix:174`, asserted by `build.yml:1137` | every machine |
| 2 | Activates in every interactive shell and takes over PATH | upstream `default/bash/init:1-2`, `pkgs/omarchy/zsh-rc:44`, `pkgs/omarchy/fish-rc:107` | ran: on p620, zsh puts `command-wrappers/bin`, `installs/node/latest/bin` and `shims` on PATH |
| 3 | Reads two config files nixarchy installs into `/etc/mise/conf.d` | `data/etc-overlay.nix:108,118` | `ls /etc/mise/conf.d` on p620 shows both |
| 4 | Rebuilds links on every Home Manager activation | `modules/home.nix:1556-1560` (#1386) | every machine |
| 5 | Rebuilds links at first login | upstream `install/user/mise.sh`, from `all.sh:18` | every new user, and `omarchy finalize user --force`. `install/user/mise-work.sh` only runs `mkdir`, and nix-bin's `omarchy-refresh-applications` no longer runs `mise.sh` |
| 6 | Decides which account a typed `claude`, `codex` or `grok` runs as | `omarchy-agent-accounts.toml` `[wrappers]`, `tests/agent-account-routing.nix` | every activated shell |
| 7 | Puts its shims and wrappers on PATH for launched agents | `pkgs/omarchy/default.nix:1149`, `omarchy-default-agent` (end of file), upstream `omarchy-agent-account-exec:50-53` | menu agents, and every account-exec run |

Files that mention mise and do not run it here: `omarchy-install-gaming-lutris`,
`omarchy-install-openclaw-cli` (`type -aP` only), `omarchy-theme-set-hermes`,
`omarchy-update-aur-pkgs` (comments). `omarchy-upgrade-to-quattro` runs it and is
unreachable (`data/bin-ledger.nix`). `omarchy-update`, `omarchy-migrate`,
`omarchy-install-preinstalls`, `omarchy-remove-preinstalls` and
`omarchy-default-agent` are nix-bin replacements, so upstream's calls in them
never ship. `omarchy-mise-unshadow` deletes launchers and never runs mise.

### Claims this map corrects

- **The lazy stubs do not exist here.** The issue and
  `docs/manual/development-tools.md:386-389` say the first `gh` downloads through
  mise. On v4.5.0 those stubs come from `etc/mise/conf.d/omarchy-tools.toml`, and
  `data/etc-overlay.nix:113` deliberately does not install that file. p620 has 3
  shims, all `node`, `npm` and `npx`, and none for any listed tool. So the page is
  stale, and `gh`, `ghui`, `hey`, `basecamp` and `cf` lose nothing, because they
  have no route today.
- **`omarchy-mise-install` has no caller left**, only comments. Nothing writes
  launchers any more, so `tests/mise-launchers.nix` guards dead code. Launchers
  from older versions can still be sitting in `~/.local/bin`.
- **`env-bootstrap` does not run here.** `default/bash/envs:17` guards it on
  `/usr/share/omarchy`, which does not exist. A clean `bash -l` on p620 has no
  mise directory on PATH. Shims reach PATH only through rows 2 and 7. For the same
  reason `default/uwsm/env.d/10-omarchy` is not read: it installs under
  `/usr/share/uwsm`, which does not exist here.
- **Most `mise` grep hits in tests are "promise" and "optimise".**
  `tests/options.nix` has 5 real mentions, not 28; `tests/install.nix` has 0, not
  4. Of upstream's `bin/`, 20 files name it and 15 call it.

### Who loses a route

Ten things, and only one of them works today with nothing to replace it.

| Tool | Route today | nixpkgs at our pin |
|---|---|---|
| `pi` | row 8 | `pi-coding-agent`, `mainProgram = "pi"` |
| `omp` | row 8 | `omp`, `mainProgram = "omp"` |
| `ori` | row 8, works | none |
| `kimi`, `mcode`, `freebuff`, `commandcode` | row 8, **already broken** without a `node` on PATH: `exec: node: not found` (#1622) | none |
| Rails, Laravel, Phoenix | row 10 | runtimes yes (`ruby`, `php`, Elixir via `data/apps.nix`); no framework installer |

Those are the routes nixarchy offers. Beyond them, a person may have run `mise use`
for anything, globally or in a project's `mise.toml`, and each of those stops too.

The 31 tools in `omarchy-tools.toml` were never on this route. For the record, 23
have a nixpkgs package and 8 do not: `basecamp`, `hey-cli`, `cf`, `kimi`, `mcode`,
`commandcode`, `freebuff`, `ori`. None of the 23 is in `pkgs/omarchy/default.nix`'s
runtime list, so none is on a machine unless selected; `uv` is a `data/apps.nix`
entry. `omarchy-setup-git:90` already checks for a missing `gh`.

### What breaks if mise is simply dropped

- **First login aborts. Ran:** `bash -eE -c 'source install/user/mise.sh'` with no
  mise exits 127. `omarchy-provision-user` sources `all.sh` under `set -euo
  pipefail`, so it stops before `omarchy-refresh-applications`, the default browser
  and the finalize marker. This failure is silent and hits new users.
- **Agent account routing, partly.** Typed `claude`, `codex` and `grok` go back to
  the default account, and their subprocesses with them. The launchers are fine:
  they resolve the account themselves (case 5 of `checks.agent-account-routing`).
  `omarchy-agent-account-exec` relies on mise stripping its dispatch directory
  from PATH to avoid recursing (`:22`), so any replacement has to do that itself.
- **The add-account flow** fails on a machine with no agent CLI: the panel reports
  an install failure and hides the cause, and the command prints
  `mise: command not found`.
- **`ga`** prints `mise: command not found` every time, then carries on.
- **Tools a person installed through mise** leave PATH at the next shell. A default
  agent recorded in `~/.config/omarchy/defaults/agent` stays recorded, so the menu
  then reports it missing until they choose again.
- **Old launchers block their own fix.** A launcher in `~/.local/bin` with no Nix
  twin fails with `mise: command not found`. It also satisfies `command -v` at
  `omarchy-default-agent`, so choosing that agent runs the dead launcher and never
  reaches `nixarchy-pkg-add`.
- **A person's own mise changes behaviour** once `/etc/mise/conf.d` goes: it loses
  `upgrade.auto_prune = false`, the `cursor-agent` alias and the account wrappers.
  Stale `command-wrappers/bin` links stay on disk pointing at an old store path.
  Whether their own activation puts those back on PATH is not measured; the spec
  has to answer that.
- **Checks that encode it, by design:** `mise-launchers`, `agent-account-routing`,
  `remove-preinstalls`, `provision-launchers`, `options` (`etcMise`,
  `etcMiseAccounts`, the wrappers case), the bin, package and etc-overlay ledgers,
  and `build.yml:1137`.

## Proposed outcome

On a freshly built nixarchy machine with default options:

1. `mise` is not on PATH, not in the closure, and `/etc/mise` does not exist.
2. No shipped code path runs mise or adds its directories to PATH: no shell rc, no
   activation, no first-login step, no menu row, no panel, no launcher. The only
   exception is row 12, the read-only probes, and only while a person's own `mise`
   is on PATH.
3. First login completes.
4. `omarchy agent account use` still reaches a typed `claude`, `codex` or `grok`,
   and an agent's subprocesses (decision 3).
5. A menu row, panel action or command that used mise either has a Nix route or
   says plainly why it has none. None ends in a command-not-found, and a missing
   agent CLI points at `omarchy default agent <agent>`, as the exec does since #1386.
6. On an existing machine nothing a person owns is deleted. After the rebuild they
   are told what stopped working and how to move or remove it.
7. A future Omarchy bump that adds a mise call turns a check red, naming the file.
   That holds for edge carries too (#1608).
8. The docs say all this, including that `gh` comes from Nix.

`programs.nix-ld` stays. It has its own users: `docs/manual/boxes.md:29`,
`docs/manual/troubleshooting.md:102`, the `nixos-binaries` skill and
`modules/nixos.nix:1218`. Only its stated reason changes, because
`modules/AGENTS.md:248-267` credits it to mise.

## Affected users and systems

- Every machine with `programs.nixarchy.enable`, including p620 (`claude` and `node`
  installed through mise, 3 shims).
- Users of any of the 10 tools above, and anyone who typed `mise use`.
- `#1622` owns what the seven agents become. This task removes the mechanism: the
  `mise_pkg_for` function and its arm in `omarchy-default-agent`. For #1622: `pi`
  and `omp` now have nixpkgs packages, as do `cursor-cli` and `muse-code`, which the
  script still calls "not in nixpkgs"; and `attr_for kilo` uses the `kilocode-cli`
  alias, which warns and points at `kilo`. Order matters: if #1625 merges first,
  `pi` and `omp` would regress with a Nix route available, so #1622 merges first,
  or #1625 carries those two `attr_for` lines. The other five fail with a message
  naming the reason until #1622 says what they become.
- Edge: `omarchy-agent-accounts.toml` and its check came from an edge carry (#1386),
  and #1608's carries will meet the new guard.

## Constraints

- **Never delete a user's files silently.** `~/.local/share/mise`, `~/.config/mise`,
  shims and launchers a person wrote stay. The one exception is decision 4:
  upstream's exact generated launcher, removed and reported, as
  `omarchy-mise-unshadow` already does when a Nix command replaces it (#707).
- **§14:** this is a changed default, so it needs a Coexistence section in the spec,
  a fixture in `tests/coexistence/fixtures.nix`, and the release notes plus
  Discussions post with the migration step.
- **Mode A:** a configuration that imports the module without enabling anything is
  unchanged, and `checks.options` keeps asserting both states. A user's own
  `pkgs.mise` must still build and run beside nixarchy.
- **§2:** the guard must read what shipped scripts call rather than rely on memory.
  `.github/scripts/check-bin-ledger.py` already has a behaviour scan (`PATTERNS`,
  `:85`) that survives bumps; `default/` and `install/` are outside it today.
- **§1:** every new or retargeted check gets a recorded failing run.
- **§11:** `build.yml:1137` is a workflow edit, so the PR proposes it and a human
  merges.
- Patches over upstream stay small, because each one is re-applied at every bump.
  A person can type any shipped command, so one that would run mise is removed or
  made to refuse, even with no menu row. Only comments, the row 12 probes and
  `omarchy-upgrade-to-quattro`, whose call to `omarchy-update-mise` is skipped once
  that command is gone, may stay vendored, each recorded by the guard.
- Any plan names only `codex` or `agy` as coders.

## Open questions

The owner approved every recommendation below on 2026-11-05.

Four for the owner, each with a recommendation.

1. **What does a person's own mise get?** This intent assumes your rule is about
   nixarchy and not about the user, so please confirm it. A person can install mise
   and it runs normally. nixarchy never activates it, so they add
   `eval "$(mise activate zsh)"` to their own rc, and we document that line.
   **Recommended:** confirm that, and let the two row 12 probes stay, because they
   only read, and only when that person's mise is on PATH. The alternative is
   stripping them too, which adds two patches at every bump.
2. **Rails, Laravel and Phoenix menu rows.** **Recommended:** keep them visible and
   disabled, with a description pointing at `devenv.nix` and `languages.*`, as other
   "Not available on NixOS" rows do. `omarchy install dev-env` refuses for all 18
   and names the Nix route. No `nixarchy dev init` template exists for these three.
   The alternative is writing templates for them, which is new scope.
3. **Account routing for typed agents.** **Recommended:** keep the feature, with a
   small Nix-built dispatch directory ahead of PATH doing what the mise wrappers do.
   The alternative is dropping it, so only launcher starts follow `omarchy agent
   account use`, which removes code and quietly changes what the command means.
4. **Existing machines.** **Recommended:** the release note and Discussions post
   §14 requires, plus one line at activation when `~/.local/share/mise/installs` is
   not empty, naming the tools found and the optional cleanup. That directory and
   not its parent, because `mise reshim` created the parent on every machine. Also,
   activation removes every launcher of upstream's exact generated shape and lists
   each one, even with no Nix twin, because mise is gone and it can only fail and
   block its own replacement. Nothing else is deleted. The alternatives are the
   release note alone, which most people will not read before their `node`
   disappears, and leaving dead launchers in place, which keeps the block above.
