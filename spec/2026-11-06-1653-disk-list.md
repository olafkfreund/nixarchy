# Spec: The installer's disk list opens on an internal disk

## Design

Move the row-building out of `ask_device` (`installer/install.sh`) into one function, `disk_rows`, that prints the rows internal disks first. `gum choose` opens on the first row, so nothing else changes.

- A disk sorts last when `lsblk -dnro RM,TRAN <dev>` reports `RM=1` or `TRAN=usb`. `mmc` isn't a signal, because a built-in SD reader and soldered eMMC report the same thing.
- If `lsblk` can't answer, the disk counts as internal, so a failed probe leaves `lsblk`'s order rather than guessing.
- Each group keeps `lsblk`'s order. That leaves a machine with one disk, or with only removable disks, seeing what it sees today.
- The row format, the filters (zram, floppy, minimum size) and the boot-medium exclusion don't change. They move into `disk_rows` with the loop, and the comments on them move too.
- `ask_device` keeps its empty-list refusal, the `gum choose`, and `remember_disk`.

The decisions on the intent's questions, as approved: sort on `RM` or `TRAN=usb`, and leave out 4096-byte LUKS sectors and the old RAID/volume-group test. The last one stays untried and is recorded on #1610.

**#1649 reuses `disk_rows`** to ask for a replacement disk, so the two land as one pull request, one commit per issue, with a merge commit. This commit comes first.

## Coexistence

None. This only runs on the installer's live system, before any configuration exists.

## Alternatives rejected

- **Sort in the awk filter or with `sort`.** Rows hold free text from `MODEL`, and `sort` needs a stable key prepended and removed. Two variables are simpler.
- **Preselect with `gum choose --selected`.** It still leaves a USB stick listed above the disk it opens on, and it depends on matching the full row text.
- **Hide removable disks.** The approved intent keeps them, since installing onto one is legitimate.
- **Sort on size.** A big external drive would then come first.

## Risks

- **An enclosure that reports `RM=0` over a transport other than USB** (Thunderbolt NVMe, eSATA) still sorts as internal. That is today's behaviour for it, and the summary still asks before anything is erased.
- **Real hardware is unmeasured.** No guest here has a USB disk, so the check stubs `lsblk`. `tests/install-matrix.py` names that in a row.

## Verification

- **New `checks.installer-disk-list`:** extracts `disk_rows` with `sed` like `tests/installer-from-repo.nix`, with `lsblk` stubbed by device, and reads the rows offered. Cases: USB stick listed first with NVMe second, so NVMe comes first; a USB enclosure reporting `RM=0`; an SD card in a USB reader (`RM=1`); eMMC beside USB (eMMC first); built-in SD reader beside NVMe (`lsblk` order kept); two internal disks (order kept); only removable disks (order kept); one disk; `lsblk` failing for the flags (order kept); the boot medium and a floppy still dropped.
- **§1:** remove the sort, watch the first case fail, restore it. A second break drops `TRAN=usb` and must fail the enclosure case.
- **Unchanged:** `installer-ui`, `installer-wizard`, and `install` reach `ask_device` as before.
