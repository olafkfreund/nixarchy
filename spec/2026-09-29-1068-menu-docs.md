# Spec: README and site describe the menu and defaults that ship

## One change to the approved defaults

The intent's Q1 default was (a): run `docs/capture-screenshots.sh` inside
`nix run .#vm` with a GL window on your desktop. **This spec uses the headless
demo scene instead:**

- `nix build .#demo-scene-menus` boots a VM, presses Super+Space for real,
  summons `install` by route, and captures through qemu's screendump.
- That is how `19-trigger.jpg`, `20-ask.jpg` and `21-setup-agent.jpg` were
  made (`docs/screenshots/README.md`).
- The pictures are the same, **nothing appears on your screen**, and the
  frames come from a reproducible build rather than a hand session.

Overrule this at approval if you want (a) regardless.

The Q2 wording is as approved.

## Design

### 1. Getting started (`docs/manual/getting-started.md:150-160`)

The paragraph and its two captions become:

```markdown
**`Super + Space`** opens the menu: [nixarchy-menu](plugins#menu), a palette.
Type what you want (an app, a command, a sum, a file) and it finds the row.
The whole Omarchy menu is still inside it, under **Omarchy Menu**, and every
`omarchy menu` route still lands where it did. If you would rather walk the
tree, `programs.nixarchy.defaultPlugins.menu = false;` brings the stock menu
back.

![Super+Space: nixarchy-menu's palette](../img/desktop/menu.jpg)
```

The Install caption becomes "Install, scoped: the same rows, searchable",
over the new `install.jpg`.

**The next paragraph stays true and is untouched.** "This is where nixarchy
differs … Upstream's Install rows run `pacman -S`. Here they write a line
into `~/.config/nixarchy/apps.nix`." That is still what the rows do.

### 2. README

- **The screenshot row** (`README.md:57-59`): the header "the menu" becomes
  "the menu (Super+Space)". Both images are replaced in place, at the same
  paths, so no link changes.
- **The "What works" table** gains four rows in the table's own register,
  directly after the **Install ▸ Apply changes** row:

  ```markdown
  | **Super+Space** | a palette over the whole menu ([nixarchy-menu](https://github.com/olafkfreund/nixarchy-menu)): apps, Omarchy's rows, sums, conversions, files, hotkeys, a hand-off to your agent. **On by default**; `defaultPlugins.menu = false` brings the stock menu back |

  | **Setup ▸ Plugins ▸ Add Plugin** | the plugin marketplace, audited in a sandbox before anything installs ([nixarchy-plugin-browser](https://github.com/olafkfreund/nixarchy-plugin-browser)). **On by default**, Super+Alt+U |

  ```

  Every claim in these rows is already made, with its evidence, in

### 3. The front page (`docs/index.md` feature bullets)

Three bullets join the list, in its verb-first register:


The count sentence ("Fifteen ship by default: twelve are always on, three

checks it.

### 4. The pictures

`nix build .#demo-scene-menus`, built by drvPath and only with CI idle (§6):

- the `menu-root` frame → `docs/screenshots/01-menu-root.jpg` (1600×875, as
  today) and `docs/img/desktop/menu.jpg` (760×475, as today);
- the `menu-install` frame → `docs/screenshots/02-install.jpg` and
  `docs/img/desktop/install.jpg`, at the same sizes.

Each frame is scaled and cropped to the size of the file it replaces, so the
page layout does not move, and written as JPEG at quality 85, which matches
today's ~92 KB. `docs/AGENTS.md` sets the house style: a whole desktop,
nothing staged. A frame is only used after it has been **looked at**, to
confirm the palette is what is on screen and not the stock menu or an empty
desktop.

- If the scene's `menu-root` shot catches the palette mid-animation, the plan
  takes the scene's later frame of the same hold.
- If the scene cannot produce a usable frame, the text changes land alone and
  the pictures become a follow-up. They are not faked.

`docs/screenshots/03`–`14` (the stock submenus) are linked from nowhere in
`README.md` or `docs/` (checked), so they are left alone. Deleting unlinked
pictures is a separate tidy-up.

### 5. `docs/capture-screenshots.sh`

It still works against `omarchy.menu`, because the alias resolves to
nixarchy-menu. Two things in it are now wrong:

- **It closes an open menu with a second `toggle`.** On nixarchy-menu that
  starts dictation (`docs/AGENTS.md`, "Driving the menu in a recording").
  `close()` becomes `wtype -k Escape` (wtype is on the session PATH through
  the menu entry's packages), followed by a wait for the layer to go.
- **`menu_open` pipes `hyprctl layers` into `grep -q` under `set -euo
  pipefail`,** the #1058 trap. It becomes
  `[[ $(hyprctl layers 2>/dev/null) == *'namespace: omarchy-menu'* ]]`.

The header comment says it captures nixarchy-menu. `docs/` is outside the
#1060 guard's scan. Widening the guard is not in scope here, and this PR says
so.

## Alternatives rejected

- **Option (a), a VM window on your desktop:** covered above.
- **Leaving the stock-menu pictures with a caption saying so:** that shows a
  newcomer a menu they will not get.
- **Deleting the 03–14 submenu pictures now:** unrelated to what the pages
  say. A tidy-up for another day.

## Risks

- **The demo scene's frames may look different from the old stills**, since
  they come from the demo VM, not a hand-captured one. The house style is
  "whole desktop", which the demo frames are, and the pictures are reviewed
  before commit.
- **The README table grows by four rows.** The other defaults (pkg, GitLab,
  GitHub, herdr, rebuild, ai-mirror) already have rows, so this finishes a
  pattern rather than starting one.
