# Spec: Verify only running Distrobox containers

## Design

- In `pkgs/verify.sh:1057-1063`, replace the unrestricted `podman ps -a` selection with a Podman listing filtered by `label=manager=distrobox` and running state. Use the same label on an all-state listing to count skipped boxes; report that count in one concise line. The pinned Distrobox 1.8.2.5 creator adds `manager=distrobox` (`distrobox-create:723` in the pinned package), while `podman ps` without `-a` selects running containers. If either listing fails, record a Boxes failure and do not enter any box, rather than treating the failure as an empty result. An empty running list is a note that no running boxes were checked, not a claim that no boxes exist.
- Preserve the existing first-start, exported-app, and entrypoint-mount checks for selected boxes in `pkgs/verify.sh:1064-1130`. Their `distrobox enter` call at line 1094 must receive running Distrobox names only. This matters because pinned `distrobox-enter:708` starts a stopped container before entering it.
- Add a cheap `tests/verify-boxes.nix` check, wired into `flake.nix`'s uniform checks, that executes the Boxes section from the same `pkgs/verify.sh` source against stubbed Podman and Distrobox commands. Model one running Distrobox, one stopped Distrobox, and one ordinary Podman container. Assert that only the running Distrobox is entered and inspected, the stopped count is one, and the ordinary container is neither entered nor reported as a box. A separate failing-listing case must assert a nonzero failure count and zero enters. The check must fail if extraction finds no Boxes section, so a moved section cannot silently pass.
- `pkgs/verify.sh` is also touched by #1085. Rebase this branch onto main after #1085 merges before implementation, and keep the edit in the Boxes section. `tests/options.nix` and the other in-flight criticals files are outside this issue.

## Alternatives rejected

- Keep `podman ps -a` and inspect each name before entering: still risks starting stopped containers and adds a per-container command where Podman's built-in filters suffice.
- List all labeled boxes but try to enter stopped ones to check first-start health: verification would keep changing user state; the owner chose running boxes only.
- Treat a failed `podman ps` as an empty list: that turns a discovery failure into an apparently healthy result.

## Risks

- A box created by a tool that omits Distrobox's `manager=distrobox` label will not be checked. This matches the selected identity rule; verify the pinned creator and document the absence if encountered on real hardware.
- A container can stop between Podman's running-state listing and `distrobox enter`. The selection removes the current unconditional startup of stopped boxes, but a concurrent state change remains possible; verification should not add a separate start command.
- #1085 can change nearby lines in `pkgs/verify.sh`; rebase after it merges and rerun the check on the combined tree.
