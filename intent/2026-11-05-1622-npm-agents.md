# Intent: Seven agents get a route that does not go through mise

## Problem

The owner has ruled that mise must not install or control anything on these
machines (#1625). `omarchy-default-agent` sends seven agents through it
(`mise_pkg_for`, :69-80, and `mise use -g` at :284): **kimi, mcode, freebuff,
commandcode, pi, omp and ori.** Once mise is gone they have no route, and their
rows in Setup > Defaults > Agent would fail or lie.

Four of them are already broken. kimi, mcode, freebuff and commandcode install
through mise's npm backend and then cannot start on a machine with no `node`:

```
.../node_modules/.bin/kimi: line 18: exec: node: not found    (rc 127)
```

That is what #1622 was filed for. It went unnoticed because the variable (§3) is
whether the machine already has `node`, and the maintainer's does. Measured
earlier, in a throwaway `HOME` with mise 2026.10.17; nothing here is run again:

- Each launcher is `#!/bin/sh` ending in `exec node`, so anything packaging these
  has to provide node to the launcher, which a Nix wrapper does.
- mcode needs a `better-sqlite3` native binding. Installed without one,
  `--version` passes and the binding is missing. A binding for one Node ABI is
  refused by another (`NODE_MODULE_VERSION 147 ... requires 137`), so a package
  has to build it against the Node it runs on. What mcode loses without it was
  not measured.
- freebuff's npm package is a downloader: first run fetched 49.6 MB. It is not
  the program.

Giving these agents a node from mise is not an option, and neither is keeping
any `mise` call in this script.

## What each agent can become

Read from nixpkgs at this flake's pin (root input `nixpkgs_2`, `0bb2eedc`), from
each project's npm or GitHub metadata, and from `numtide/llm-agents.nix`'s package
files. Nothing was installed or built. The two nixpkgs attributes were evaluated
with `allowUnfree = false`; both resolve a `drvPath`. nixpkgs' `pi-coding-agent`
builds `earendil-works/pi`, the same project mise's `pi` resolved to.

### Which agents have no route left

**pi and omp have one in nixpkgs**, through the `attr_for` path 15 agents already
use. The comments at :67-68 and `modules/nixos.nix:672-674`, which say nixpkgs has
no package for them, are out of date.

**kimi, mcode, freebuff, commandcode and ori have none inside nixarchy** unless we
package them. All five are named by `numtide/llm-agents.nix`, which is the third
route this script already has: `elsewhere_attr_for` (:235-242) records the choice,
says the agent is not installed, and names the package. cursor-agent, hermes and
muse go that way, and the script prints why that flake is not an input
(`lib.inputSources` would carry its nixpkgs onto the ISO and every host, about
486 MB).

## Proposed outcome

- No path in `omarchy-default-agent` calls mise, and its help text no longer
  offers it as an install route.
- Choosing pi or omp adds the nixpkgs package to the user's configuration and
  builds it, like claude or codex.
- Each of the other five does one of two things, as the owner decides below: it
  installs from our own Nix build with no download at runtime, or it records the
  choice and says plainly that nixarchy does not install it and where it is
  packaged. Nothing claims an agent is installed when it is not.
- The menu row stays, because `check-menu.py` compares rows to accepted ids and
  the row's truthful answer is the one above. Upstream carries the row either way.
- A user who already has one of these agents working by their own means keeps it,
  through `command -v` at :172-176. A leftover mise shim does not count as that:
  today, in a shell with the shims on `PATH`, the check finds
  `~/.local/share/mise/shims/<agent>`, records it and launches it, skipping every
  route above.
- An agent id with no route still gets "No way to install" and exit 1 (:272-275),
  so a future menu row cannot silently do nothing.
- Comments at :7-38, :67-68 and :84, and the `defaultAgent` description at
  `modules/nixos.nix:671-674`, say what is true. That description is already wrong
  about `antigravity`. The option's enum (:643) is seven ids and leaves out most of
  `attr_for`, so it is not widened here.

## Affected users and systems

Anyone who picks one of these seven. Machines where someone already installed one
through mise lose it when #1625 lands, and the recorded default then names an
absent command. `omarchy-agent` already answers that truthfully (upstream's :52):
"kimi is not installed. Choose an installed agent with: omarchy default agent
<name>".

Expected files: `pkgs/omarchy/nix-bin/omarchy-default-agent`,
`modules/nixos.nix`'s option description, `tests/agent-attrs.nix` (which already
checks `attr_for` names exist), and possibly `pkgs/` if we package anything.

## Dependency on #1625

#1625's agent owns removing the mechanism: the runtime dependency, shell
activation, shims, lazy stubs, `mise reshim`, upstream's 20 commands and the other
four replacements, including the shim line at `pkgs/omarchy/default.nix:1149`.
This issue owns what these seven agents become, and every `mise` line in this
script: `mise_pkg_for`, the install and shim code at :276-299, and the shim case in
the `command -v` check at :173. #1625 has nothing left to do in this file.

**#1625 cannot finish until this lands**, because this script is one of its
callers. This issue needs nothing from #1625 and can merge first. **Merging it
alone does not meet the owner's ruling:** mise stays on the machine, in the shell
rc and at `default.nix:1149` until #1625 lands.

Whether a user's existing `~/.local/share/mise` and `~/.config/mise` are cleaned up
is #1625's question. This issue touches neither.

## Constraints

- **No mise, and no download at runtime.** A package is a Nix build. That excludes
  packaging freebuff's npm downloader as it stands.
- **Mode A:** nothing changes for someone who never picks one of these.
- **Unfree stays opt-in and off the cache** (§6). commandcode, and ori if its
  licence is what llm-agents says, cannot go on a public cache, and
  `allowUnfree = false` machines must get a truthful answer rather than an
  evaluation error.
- **No new flake input.** `llm-agents.nix` is named, not carried, for the reason
  the script already prints.
- **Anything we package we maintain:** a hash per release, for agents that release
  often (kimi moved from 2.4.1 to 2.5.1 today). `pkgs/AGENTS.md`'s rules apply.
- **§1 and §3:** a check over the seven rows, proved to fail with a `mise` call
  put back, and any package's check run with no `node` on `PATH`.

## Open questions

1. **pi and omp through nixpkgs?** Recommendation: yes. Both evaluate without
   unfree. nixpkgs' pi is one release behind upstream's latest (1.4.0 against
   1.5.0), which is the normal cost. Whether either is on cache.nixos.org was not
   checked, so a choice might compile.

2. **The five with no nixpkgs package: package, or name and decline?**
   Recommendation: decline all five through the existing `elsewhere_attr_for`
   route, naming their llm-agents.nix attributes. It adds no maintained package,
   and three of them have no source we could build or a licence that does not
   agree with itself.

   **kimi is the one real candidate if the owner wants any carried:** public
   source, MIT, built from source by llm-agents. It would cost a package and a hash
   per release. Package it only if the owner wants Kimi to work without a second
   flake, and I would do that as its own issue. Nobody has asked for it beyond
   upstream's menu row.

3. **Should the decline say the licence?** Recommendation: the unfree note, as
   cursor-agent has at :261-265, for commandcode only, whose npm licence is
   `UNLICENSED`. ori's sources disagree, so the script should not call it unfree.

4. **Should a decline replace a working default?** `elsewhere_attr_for` records the
   choice before advising (:249), deliberately, for cursor-agent, hermes and muse.
   Moving five more rows there widens it: someone on a working claude who clicks
   kimi is left with a default that will not launch. Recommendation: decline without
   recording while the command is absent, for all eight rows, and let them choose
   again once it is installed. This reverses a choice the script's comment defends,
   so it is the owner's call.
