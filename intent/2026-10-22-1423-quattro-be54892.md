# Intent: edge adopts Omarchy quattro be54892

## Problem

Edge's 2026-10-22 run could not build on upstream's newest quattro,
be54892, and fell back to the last good pin, 087f73d (#1383). That is
why #1423 was filed. The fallback published `main`'s fixes, so nothing is
broken for users. But edge has stopped following upstream, and it stays
behind until somebody re-anchors.

The cause is one line. Upstream #15966 ("Switch the default kernel from
Update > Kernel") adds `|| root.activeMenu === "update.kernel"` to the
`cardWidth` line in `shell/plugins/menu/Menu.qml`. Our #1339
`--replace-fail` rewrites that exact line (edge's copy is the #1400 carry,
dd8393e5). The pattern no longer matches, so `.#omarchy` fails and every
check built on it reports "1 dependency failed".

## Proposed outcome

- Edge publishes on quattro be54892.
- The menu card still fits its widest label (#1339).
- Upstream's new kernel menu gets the 520 width upstream gave it.
- #1423 closes when that run is green.

## Affected users and systems

- Edge-channel machines, p620 among them.
- `main` is untouched: it is on 4.5.0-rc1, which does not have this line.
  The carry reaches `main` when the rc2 bump PR merges `edge`, as #1400's
  carries do.

## Constraints

- Edge only fast-forwards. The work goes onto `edge-candidate` and is
  published by a `from_candidate` run, never by pushing `edge`.
- The re-anchor must keep upstream's new menu id. Matching the old line
  some other way would silently drop the kernel menu's width.

## Open questions

- Whether be54892 needs anything beyond the re-anchor. Today's build
  stopped at the first failure. Building on the new pin answers it.
