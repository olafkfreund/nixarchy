# Spec: a nixpkgs bump's system jobs finish well inside their limits

## Design

### A. Bump branches push the allowlist closures, minus what only this commit uses

`cachix-push.sh` (closure mode) keeps pushing from `main` exactly as now. It
gains one more allowed context: a `pull_request` event whose head branch
(`GITHUB_HEAD_REF`) matches `update/nixpkgs-*`, and whose head repository
(`.pull_request.head.repo.full_name` in `$GITHUB_EVENT_PATH`) is
`$GITHUB_REPOSITORY`.

In that context it pushes each entry's closure **minus two sets**: every
store path that references the flake source, and every path that references
the Omarchy tree. Both come from `nix-store --query --referrers-closure`:

- the flake source path is `nix flake metadata --json . | jq -r .path`;
- the Omarchy tree is `nix path-info .#omarchy`, which embeds the commit hash
  (#212), and which the toplevels reference.

What is left is what the squash-merged `main` will ask for:

- the compiled packages, such as `quickshell` (21 minutes on the runner) and
  `gliff` (17);
- their dependencies.

The script prints how many paths it pushed and how many it left out as
commit-specific. Every other ref still exits 0 with its current message.

### B. The session VM test runs as its own job

"Drive a session and the app-selection loop" (10 minutes) moves out of
`system-build` into a new job, `system-session`. It has the same `needs: gate`,
the same `!cancelled()` and gate-failed handling, and the same failure-digest
output.

The `system` aggregator gains it in both of its hand-kept lists, `needs:` and
the result loop, so a failure there fails `system` (#1341, #1134).

It builds the VM toplevel it boots. On a cold bump that compile runs in
parallel with `system-build`'s, instead of after it. On a warm run it
downloads.

### C. `cache-budget.sh` builds the allowlist in one evaluation

Today it runs one `nix build` per entry (~30). It becomes one
`nix build --no-link --json` over every entry, read for the output paths.
The per-entry size accounting then uses those paths, not the attributes. A
failing build still names the entry: on batch failure it falls back to the
current per-entry loop.

## Alternatives rejected

- **Push the whole closure from bump branches:** that adds the Omarchy tree
  (124 MB) and each commit's toplevel every night, which #697 is about.
- **Move the allowlisted-tools step to its own job:** its outputs must be
  pushed by the job that builds them, so the push would have to move with it.
  That is a second step for later; this change takes the larger, simpler
  split first.
- **Self-hosted runners on p620 for these jobs:** they would share one warm
  store, the biggest win. But the host is a desktop with two install slots
  (§6). That is a measured follow-up, not part of this change.

## Risks

- **A path that depends on the commit without referencing the source or the
  tree** would be pushed as junk. It is never downloaded, so the free tier
  evicts it first, and the budget step does not count it.
- **The new job adds a runner per PR run.** These are hosted runners, and no
  install slot is involved.

## Verification

- **`tests/cache-budget.nix`** (stubbed `nix`, `nix-store` and `cachix`):
  - a bump PR from this repository pushes the closure minus both sets;
  - a bump-named PR from a fork pushes nothing;
  - another PR pushes nothing;
  - `main` pushes the full closure.

  Each is shown red with its guard removed.
- **actionlint** on `build.yml`.
- **The aggregator** fails with `system-session` failing: shown by reading
  the loop, and on the first PR run.
- **`cache-budget.sh`** produces the same report before and after, on the same
  tree.
- **After merge,** the next bump's log shows "pushed N, left out M as
  commit-specific", and `main`'s following `system-build` downloads
  `quickshell` instead of compiling it.
