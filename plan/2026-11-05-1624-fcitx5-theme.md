# Plan: The system profile carries fcitx5's themes, and nothing else of fcitx5's

Worktree `/mnt/data/vmtest/wt-1624`, branch `fix/1624-fcitx5-theme`, on `main` at `066beb7b` or later (#1634 is in).

## Decisions carried from the approved spec

1. `environment.pathsToLink` gains `/share/fcitx5/themes` when `usingFcitx5`. Not all of `/share/fcitx5`: that would show
   every addon's `.conf` on `XDG_DATA_DIRS` to any fcitx5, including a stale addon-less daemon.
2. The patch at `pkgs/omarchy/default.nix` (`omarchy-theme-set-fcitx5`) stays. A store path would dangle after garbage collection.
3. Existing machines are not repaired on upgrade. The glyphs arrive at the next theme change, and the release note gives the command.
4. It lands after #1634, which is already on `main`.
5. Nothing checks the rendered window. That hole stays, and the PR names it.
6. A user's own `pathsToLink` entry merges, and a user's own theme named `default` wins by `system.path`'s silent priority. Both are accepted, with no fixture: nothing fails, and it is what they installed.
