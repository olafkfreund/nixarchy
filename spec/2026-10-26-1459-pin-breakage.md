# Spec: a nixpkgs bump that breaks a commit-pinned input is caught, said out loud, and its fix proposed

## Design

Five parts. Parts A and B make the problem visible; C proposes the fix;
D and E keep it visible later.

```
flake-update.yml, 07:00
  move nixpkgs
  eval-gate.sh ──passes──► dated PR, auto-merge
       │                   (or: promote an open bot draft, see B)
     fails
       ▼
  pin-fix.sh: for each allowlisted input whose probe failed,
              try its upstream default-branch HEAD, re-run eval-gate.sh
       │
       ├─ now passes ──► draft PR on update/nixpkgs-blocked:
       │                 nixpkgs + the input move(s), upstream commits listed,
       │                 never auto-merged
       └─ still fails ─► draft PR on update/nixpkgs-blocked:
                         nixpkgs only, the failing targets and their errors
```

### A. One evaluation gate, shared by the nightly bump and the canary

**What it is.** A new script, `.github/scripts/eval-gate.sh`. It evaluates
the derivation of every target in the set below, with no build. It exits 0
when all of them evaluate. It exits 1 when any fails, and prints one line
per failing target, `<target><TAB><first error line>`. That output is what
B and C consume.

**The set**, derived rather than hand-kept (§4):

- everything `cache-allowlist.sh` prints (the `omarchy`, `system`,
  `runners` and `apps` groups);
- every probe target of the auto-fix table (C), which today adds
  `.#zen-browser` and `.#checks.x86_64-linux.hypr-rdp-builds`.
  zen-browser is not in the allowlist because it is `prebuilt`.
  `hypr-rdp-builds` is the only target that forces sops-nix's
  `sops-install-secrets`, the #1030 break.

**Left out on purpose:**

- `checks.microvm-template`: 6.8 GB of RSS on its own. The 18 runners
  already force the microvm module.
- `checks.options`: 11.5 GB.
- every check: 16+ minutes, AGENTS.md §6.

**How it evaluates.** A single `nix path-info --derivation <targets…>`
first, so nixpkgs is evaluated once. An eval error aborts the whole batch
and names nothing about the rest (§13), so after a failure the script
re-evaluates each target in its own process to name every failing one. That
second pass runs only on failure.

**Measured on p620** with `--no-eval-cache` (a warm cache answered in
0.07 s and measured nothing):

| set | time | peak RSS |
|---|---|---|
| today's gate (two toplevels) | 55 s | 2.9 GB |
| **this set (33 targets)** | **118 s** | **5.9 GB** |
| the same set plus `microvm-template` | 119 s | 11.3 GB |

On the broken commit `700ee61c` (nixpkgs 3ec6363, microvm fdfc182), today's
gate passes and this set fails in 62 s with
"`boot.initrd.systemd.enable` … no longer has any effect". On the fixed
commit `1d56f54d` it passes. That is the §1 red and green, measured.

**Callers:**

- `flake-update.yml`'s "Both toplevels still evaluate" step is replaced by
  this script.
- `nightly.yml`'s canary ("Their machine still evaluates") calls the same
  script. The canary stays non-gating and keeps filing through the report
  job, as it does today.

### B. A failed bump opens a draft PR, and a later clean night promotes it

This copies `omarchy.yml`'s #1383 shape (lines 442-489, and `gh pr ready`
at its arm step), adapted to `flake-update.yml`'s dated branches.

**Branches:**

- A night whose gate fails, after C has tried, writes to one constant
  branch, `update/nixpkgs-blocked`, as a **draft**. The body:
  - says which targets failed, with their first error lines from A's
    output;
  - names any input C moved, with the upstream commit list;
  - says it will not merge itself.

  The title is
  `nixpkgs: blocked, <n> target(s) do not evaluate` or
  `nixpkgs: blocked on <input>, fix proposed`.
- A night whose gate passes:
  - **Open draft on `update/nixpkgs-blocked` whose head commit was made by
    this workflow:** the job rewrites that branch with tonight's clean,
    nixpkgs-only bump, retitles and re-bodies it as a normal bump, runs
    `gh pr ready`, and arms auto-merge. This is the owner's decision 3.
  - **Otherwise:** the dated branch and PR, exactly as today.
- **A human's commit on the draft is never overwritten.** If the head
  commit's message lacks the workflow's trailer
  (`Generated by .github/workflows/flake-update.yml`), the job leaves the
  draft alone, opens the dated PR as today, and comments on the draft once
  saying a clean bump exists.

**Auto-merge rule.** It is armed only when `flake.nix` is unchanged and the
only lock node that moved is `nixpkgs`. The job checks this with `git diff`
before arming, and a refusal names what moved. This holds even on the
promote path, so a promotion can never auto-merge an input move.

**"Never silent" also covers the job dying.** `pkgs/review.sh` gains
`ci flake-update.yml 30`, beside the other scheduled workflows at line 548.
It also gains one row:

- it is a finding when an open PR on `update/nixpkgs-blocked` is older than
  3 days, saying "nixpkgs has not moved since <date>";
- the nightly review issue carries that row, so a draft nobody opens still
  reaches a person.

### C. The fix is proposed: `pin-fix.sh`, for an allowlist of four

**What it is.** A new script, `.github/scripts/pin-fix.sh`. It runs only
after A fails. It holds one table, mapping each allowlisted input to the
target that probes it:

| input | probe target | why that target |
|---|---|---|
| `microvm` | `.#microvm-agent` | imports `microvm.nixosModules.microvm` (`flake.nix` `mkMicrovm`) |
| `sops-nix` | `.#checks.x86_64-linux.hypr-rdp-builds` | forces `sops-install-secrets` (#1030) |
| `zen-browser` | `.#zen-browser` | the package itself |
| `mcp-servers-nix` | `.#checks.x86_64-linux.vm-toplevel` | `modules/home.nix:105` calls its `lib.mkConfig`, but only where ai-mirror's MCP config is generated. **Not yet verified to be forced by `vm-toplevel`.** The plan's first step proves it with a §1 break (point the input at a commit whose `lib.mkConfig` throws). If the toplevel does not force it, the plan names the target that does, or drops the input from the table and says so. |

**Candidates.** An input is a candidate when its probe target is among A's
failures. Parsing the error text for the culprit is rejected below. A
toplevel failure makes `mcp-servers-nix` a candidate, the only allowlisted
input the toplevels reach.

**For each candidate, in table order:**

1. **Resolve the target commit.** Read the pin from the input's `url` in
   `flake.nix`, as a full or short commit. Read upstream's default-branch
   HEAD from `gh api repos/<owner>/<repo>/commits/HEAD`.
2. **Refuse unless all of these hold:**
   - `compare/<pin>...<head>` has `status == "ahead"`, so it is a
     fast-forward: never `behind`, `diverged` or `identical`;
   - `ahead_by <= 100` (#1457 needed 42);
   - the new sha matches `^[0-9a-f]{40}$`;
   - the owner is not `olafkfreund` (decision 1; enforced by the table, and
     asserted again).

   Each refusal is a line in the draft body, giving the reason.
3. **Move the pin and re-lock.** Replace the pin in that input's `url` line
   only. Assert the line count with `grep -c`: exactly one line changed
   (§1's trap: a `sed` that matches nothing exits 0). Run
   `nix flake lock`. Refuse if the lock now has more than one node with
   `"repo": "nixpkgs"`, comparing the count before and after.
4. **Re-run the gate.** If A now passes, stop; the moves so far are the
   proposal. If not, keep this move and try the next candidate. One
   nixpkgs change can break two inputs.

**When nothing passes.** If no combination passes, every move is reverted
(`git checkout HEAD -- flake.nix flake.lock` (§5)), and the draft carries
nixpkgs alone plus the errors.

**What lands in the draft for each move:**

- the input name;
- old and new commit;
- `ahead_by`;
- the compare URL;
- each upstream commit's short sha, author and subject, from
  `compare/<old>...<new>`, capped at 100 lines.

**A testable core.** `pin-fix.sh` has a `--decide` mode. It reads the
compare JSON and the table inputs from files and prints `move <sha>` or
`refuse <reason>`, with no network. `checks.pin-fix` runs it against
fixtures. The cases:

- fast-forward 42: move;
- fast-forward 101: refuse;
- `diverged`: refuse;
- `behind`: refuse;
- `identical`: refuse;
- a malformed sha: refuse;
- an `olafkfreund` owner: refuse.

The check also covers the `url`-line replacement against a copy of
`flake.nix`:

- exactly one line changes, and the other 18 pinned urls are untouched;
- a pin that is not in the file is a loud failure, not a silent no-op.

### D. The review tells the truth about commit pins

**`pkgs/flake-pins.py`:**

- An `original.ref` that is all hex, 7 to 40 characters, is a **rev**. Its
  `at` becomes `locked.rev`, the full sha. This fixes zen-browser
  `ec2c94c95846` and nix-skills `0ef9aeb`.
- An `original.ref` shaped `YYYY-MM-DD…` is a **tag**. This fixes
  nix-index-database `2026-09-06-071918`. `latest_tag`'s
  `^v?[0-9]` filter already admits dated tags.

**`pkgs/review.sh`'s `rev` arm** (lines 433-486) gains one question. Today
the arm says ok in two cases: there are no version tags, or the pin is
`ahead` of the newest tag. In both, the review now also asks
`compare/<pin>...HEAD`.

- **`identical`:** ok, "at HEAD".
- **`ahead` by N, the commits HEAD has past the pin:**
  - third-party owner and the pin is older than 7 days: **finding**,
    "N commits behind <default branch>" (decision 2);
  - otherwise ok, "N behind HEAD". The owner's repos get a note, never a
    finding, and a third-party pin under 7 days old is not one yet.
- **`diverged` or `behind`:** a finding, "pin is not on the default
  branch". Upstream force-pushed, or we pin a fork's commit.
- **API error or 404:** the current "not comparable" ok, unchanged.

The decision becomes a pure function behind a new `--rev-row` mode. It
takes the name, owner, age, newest-tag status and HEAD compare as
arguments, the shape of the existing `--cirow` and `--main-install-verdict`
modes. So `tests/review-pins.nix` can assert it with no network. The
fixtures:

- microvm's real 2026-10-26 state (newest v0.5.0, `ahead` of it, HEAD 42
  past the pin, 49 days old): **finding**;
- the same for an `olafkfreund` repo: ok;
- 42 behind but 3 days old: ok;
- `identical`: ok;
- `diverged`: finding.

`tests/review-pins.nix`'s shape assertions gain `zen-browser rev`,
`nix-skills rev` and `nix-index-database tag`.

### E. The lesson is written down

- **`AGENTS.md` §4** gains one bullet: an automated bump whose gate
  evaluates a subset of what ships cannot see a break in a pin outside that
  subset. And an auto-bump that refuses silently stalls for good when the
  break is in a pin it does not move. The rule: gate on the cache
  allowlist, refuse loudly, as a draft PR.
- **`docs/internals/workflows.md`'s `flake-update.yml` section** describes
  the new steps, the blocked branch and the promote rule.
- **`flake-update.yml`'s header** ("NIXPKGS ONLY, deliberately") is
  amended: nixpkgs alone is still what it moves and auto-merges. It may now
  *propose* the four allowlisted inputs, behind a human.

## Alternatives rejected

- **Find the culprit from the error text.** Every flake input is named
  `…-source` in the store, and #1457's assertion is raised inside nixpkgs'
  own module, not microvm's file. Mapping a path back to an input needs
  `nix flake archive --json` and `--show-trace`, and still misattributes
  lazily-forced errors (agy). The probe-target table is exact for the four
  inputs it covers, and costs nothing.
- **Try every input that follows nixpkgs.** That would sweep in the owner's
  13 `olafkfreund/*` inputs, whose bumps have a manual checklist
  (`docs/internals/flake.md:476`). It also pulls unreviewed code from repos
  nobody chose to trust automatically. The owner chose four (decision 1).
- **Auto-merge a fix that passes.** A fix that evaluates proves neither
  that it builds nor that it behaves. Upstream code moving into `main` with
  no human is a supply-chain path. Both reviewers and the intent rule it
  out.
- **Evaluate every check, or include `checks.microvm-template` /
  `checks.options`.** The measurements above: 11.3 GB with the template
  check, and 16+ minutes for all checks. The cache allowlist is what ships
  and what main pushes, so it is the right surface.
- **A hand-written list of targets in the workflow.** A second list fails
  open (§4). The allowlist exists, is enforced by `cache-budget.sh`, and
  gains a runner the day a template is added.
- **Keep dated branches for failed nights.** Promote (decision 3) needs a
  branch a later night can find. One constant blocked branch also stops
  failed drafts piling up, one per night.
- **Report every tagless pin that is behind as a finding.** The review
  must not manufacture work (`review.sh:456`). The owner's own repos are
  bumped deliberately, so behind is their normal state.

## Risks

- **The gate's cost on a cold hosted runner.** 118 s and 5.9 GB were
  measured on p620 with a warm store. A cold `ubuntu-26.04` runner also
  fetches every input's source. The job keeps its 30-minute timeout; the
  first runs' step timings are checked in the PR. If memory is a problem,
  splitting the batch by group bounds the peak at the 2.9 GB toplevel cost.
- **A wrong probe target.** If a target stops reaching its input, for
  example hypr-rdp-builds stops forcing sops-nix, C never proposes that
  input and the failure falls through to a plain draft. That is loud, not
  silent. `checks.pin-fix` asserts each probe target exists in the flake's
  outputs, so a rename is caught. It cannot assert the target still
  reaches the input; the table's "why" column says what to re-check.
- **The promote path overwrites a draft.** It does so only when the
  draft's head carries the workflow trailer, so a human's commit stops it.
- **A transient GitHub API failure** in C or D. C treats it as a refusal,
  so the draft is still opened with the errors. D keeps today's "not
  comparable" ok. Neither ends the run (`review.sh`'s `|| cmp=""` errexit
  pattern, #1006).
- **The canary gets slower:** about one more minute, nightly, non-gating.
- **Nothing reaches a user's machine.** CI and review only.

## Coexistence (§14)

Not applicable: no module option, package or default changes.

## Verification

- **A, §1 red and green.** Run `eval-gate.sh` on `700ee61c`: exit 1, naming
  every microvm runner with the assertion line. On `1d56f54d`: exit 0. Both
  outputs go in the PR.
- **C, unit level.** `checks.pin-fix` covers each refusal and the move, and
  is shown failing by breaking `--decide`: drop the `ahead` requirement and
  the `diverged` case must go red. The same goes for the url-line
  replacement guard.
- **C, end to end, locally.** On a scratch worktree at `700ee61c`, run
  `pin-fix.sh` with A's failures. It must propose microvm `4876e2a`, ahead
  by 42, and A must then pass. Run it again with microvm removed from the
  table: no proposal, and every move reverted.
- **D.** The new `tests/review-pins.nix` fixtures, each shown failing:
  revert the `rev` arm change and the microvm fixture must stop being a
  finding; revert the classifier and `zen-browser rev` must fail.
- **B and the workflows.** `actionlint` clean, then one
  `workflow_dispatch` of `flake-update.yml` on the branch after merge
  approval. The workflow edits merge only with the owner's approval (§11).
  The draft and promote paths cannot be run without a broken nixpkgs, so
  their decision logic lives in scripts covered above. What stays only in
  YAML is the `peter-evans/create-pull-request` wiring, which is
  `omarchy.yml`'s proven shape.
- **E.** `nix run .#review` locally shows microvm against today's main as
  a finding, until #1457 merges; afterwards it shows "at HEAD".
