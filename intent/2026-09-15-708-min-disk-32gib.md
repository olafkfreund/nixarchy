# Intent: 32 GiB is the minimum disk, and everything agrees on it

## Problem

The owner has decided that 32 GiB is the smallest disk nixarchy promises to work
on. Nothing in the repository agrees on a number today:

| where | today |
|---|---|
| installer, whole-disk install | refuses under **8 GiB** (`installer/install.sh:791`) |
| installer, beside another OS | requires **32 GiB** (`FREE_MIN_GIB=32`, `install.sh:822`) |
| `tests/install.nix`, `tests/install-encrypted.nix` target | **20 GiB** |
| `tests/install-iso.nix`, `installer/vm.nix` target | **24 GiB** |
| `tests/free-space.nix` | 36 GiB disk, 32 GiB free region |
| installed machine GC (`installer/host.nix:170-171`) | `min-free` **5 GiB**, `max-free` **20 GiB** |

Three consequences, all seen on 2026-09-15:

- **CI tests machines smaller than the promise.** 20 GiB and 24 GiB targets are
  below the new minimum, so a change can fail CI for a disk nixarchy no longer
  supports, and pass nothing that says it fits the one it does.
- **GC can never finish on small disks.** On a disk near `max-free`, "collect
  until 20 GiB is free" cannot be satisfied, so every dip below 5 GiB starts an
  automatic collection. Nix 2.34.8 segfaults when one runs during
  `nixos-rebuild switch`, which is why #702 was reverted in #706.
- **Running out of room fails an hour late, in the wrong place.** Nothing
  measures free space after an install. The symptom is a crashed switch, a hung
  driver and a 90-minute timeout.

## Proposed outcome

- **The installer refuses under 32 GiB in both modes,** and the manual and the
  installer's own text say 32 GiB.
- **Every install-class test targets 32 GiB,** the size nixarchy promises, so CI
  fails when a change no longer fits it.
- **GC thresholds suit a 32 GiB machine.** A freshly installed 32 GiB machine is
  not below `min-free`, and a collection has a reachable target.
- **A free-space check.** An installed 32 GiB target with too little headroom
  fails an install check with the free space printed, at the point it happens.
- **Blocked work gets a budget.** #701's redesign and the reverted nixpkgs bump
  can be measured against this.

## Affected users and systems

- **Users:**
  - installing onto 8–31 GiB disks, who will now be refused before anything is
    touched;
  - every installed machine, whose GC thresholds change on its next rebuild.
- **Code:** `installer/install.sh`, `installer/host.nix`, `installer/vm.nix`,
  `installer/try.sh` (which mirrors `vm.nix`'s disk size).
- **Tests:** `tests/install.nix`, `tests/install-encrypted.nix`,
  `tests/install-iso.nix`, `tests/installer-wizard.nix` (asserts the 8 GiB
  floor).
- **Docs:** `docs/manual/getting-started.md`, `docs/manual/the-iso.md`,
  `docs/manual/dual-boot-install.md`.
- **CI:** p620, where install-class VM disk images get bigger. Its disk-free
  guard (40 GiB floor, #663) must still hold with two installs running at once.

## Constraints

- **Refuse before touching anything.** The installer must refuse undersized disks
  before it partitions (#300's principle), never partway through.
- **Machines already installed on smaller disks keep working.** They are not
  broken by a threshold change; they simply fall outside the promise.
- **Mode A is untouched.** `min-free`/`max-free` live in `installer/host.nix`,
  which Mode A never imports.
- **Every changed check is seen red first** (AGENTS.md §1): an undersized disk
  refused, and the free-space check failing when headroom is gone.
- **p620 still fits two install jobs.** Measured, not assumed (AGENTS.md §6).
- **No hiding the segfault.** Sizing so collections do not run during a switch is
  the fix here. The Nix bug itself is reported upstream separately.

## Open questions

1. **Thresholds.** Which `min-free`/`max-free` for a 32 GiB machine? A fixed pair
   (for example 2 GiB / 6 GiB), or values scaled to the disk at activation?
2. **Free-space headroom.** How much must an installed 32 GiB target have free
   after install for the check to pass? It needs a number the spec measures.
3. **`installer-vm` / `try.sh`.** Do they move to 32 GiB too? They are for trying
   nixarchy, not a CI gate, but they are what a user runs first.
