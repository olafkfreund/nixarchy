# Intent: build the six omacom apps with CMake

## Problem

The nightly review (#1758, 2026-11-13) lists new releases of six apps nixarchy
builds itself: hype 0.7.1, monologue 0.4.0, omacalc 0.4.2, omacut 0.8.3,
omawrite 0.7.5 and signed 0.3.2. `update.yml` (run 43369722753) tried each bump
and reverted all six, because every one failed to build. Upstream replaced its
qmake project (`<app>.pro`) with a `CMakeLists.txt` in each release, and our
packages still use `qt6.qmake`, which now finds no project and prints its usage.
Until this is fixed, these apps stay on their old versions and the nightly
review stays red.

## Proposed outcome

All six packages build at upstream's newest release with CMake, install the same
files as today, and `nix run .#update` can bump them again.

## Affected users and systems

Everyone with `omarchyApps.enable` (all six are Omarchy default apps).
`pkgs/apps/{hype,monologue,omacalc,omacut,omawrite,signed}.nix`.

## Constraints

- Same installed layout: binary, `.desktop`, icon, licence where shipped today.
- The apps keep their runtime wrapping (`qtWrapperArgs`, runtime PATH).
- Hype's About/version text must show the real version, not `dev`: its
  CMakeLists reads the version from the unpack directory name or `git describe`.
- Upstream's test suites are not run here (they need Qt Pdf, Python and an
  offscreen platform); today's qmake builds do not run them either.
