# Intent: Make the remaining robustness paths predictable

Refs #1098 (Robustness only).

## Problem

The current code confirms these findings, although the issue's line numbers have moved:

- `modules/services/syncthing.nix:76-77` constructs both Syncthing directories under `/home/<user>`, even when `config.users.users.<user>.home` differs.
- `modules/services/open-webui.nix:51` places a literal IPv6 host in a URL without brackets. The wildcard `::` case is already converted to loopback; a specific IPv6 bind is not.
- `modules/flatpaks.nix:54` assigns `services.flatpak.enable = true` at normal priority, so a user setting it to `false` gets a definition conflict instead of retaining control.
- `modules/home.nix:216,246,256,1702,1741` has direct file writes outside Home Manager's `run` wrapper. These can modify user files during a dry run; the adjacent `run mkdir` and `run mv` calls do not protect the direct writes.
- `pkgs/omarchy/nix-bin/nixarchy-channel:202` inserts the Home Manager URL after every matching `inputs.nixpkgs.follows` line, not only the intended root input.
- `pkgs/omarchy/default.nix:675` puts `nixos-version` before `cut` without pipeline failure propagation. If `nixos-version` fails, `cut` can succeed on empty input and the promised exit-1 fallback is missed.
- `pkgs/skills-relink.nix:63` uses `ln -sfn` for an owned skill. With an existing real directory of the same name, GNU `ln` descends into it and creates a nested link. The existing check tests a real directory only on the guarded-input path, not this owned path.
- `modules/apps.nix:3520-26` passes `XDG_CONFIG_HOME` into the detached rebuild but drops a custom `XDG_STATE_HOME`; the resumed process then reads its applied-file state from a different directory.
- `pkgs/rebuild-panel/RebuildState.qml:127,134,140` reads the rebuild unit's journal without an invocation filter. The panel's live view is bounded to the last 500 entries, so “whole history” overstates that view; copying or opening the full log can still include previous runs. `nixarchy-apply --log` already scopes to an invocation, with a 200-line fallback.
- `modules/apps.nix:3422-23` evaluates text produced from `systemctl show` as shell code. The fields are normally systemd-controlled, so this is not evidence of a user-input exploit, but the parser should not execute its input.
- `modules/apps.nix:3459,3909` does not ensure the JSON `exit` field is numeric. `jq --argjson` checks JSON syntax, not its type, so a malformed property that is itself valid JSON (for example, `true`) can violate the promised numeric contract. The later status helper interpolates the code into JSON directly.

No other Robustness claim was dropped as false. The `exit` case is limited to malformed or stubbed `systemctl` output: real systemd exposes `ExecMainStatus` as a typed integer.

The VM lock item (`pkgs/microvm.nix` and `pkgs/verify.sh`) is excluded, pending the criticals PR and #1085. Stale scripts, stale docs, installer validation, and CI hygiene are separate work.

## Proposed outcome

Each confirmed path respects the user's selected home, module priority, and dry-run state; URL and channel output remain valid for supported inputs; skill linking does not alter a real directory; detached rebuilds retain the caller's state location; and rebuild status and logs are parsed and scoped without surprising output from another run. Checks added for these changes must fail when the defect is reintroduced.

## Affected users and systems

Existing-flake adopters with nonstandard home directories or Flatpak settings; Open WebUI, Syncthing, Home Manager activation, the channel switcher, agent skills, and detached rebuild users. No install or VM path is in this slice.

## Constraints

- Keep both opt-in module states working and preserve user-owned configuration; Home Manager activation remains safe on dry run.
- Do not touch the criticals PR's installer, MicroVM, or options-test files. Do not build or open a PR at this gate.
- This is a partial issue: use `Refs #1098`, never a closing keyword. Keep each new check cheap and prove its red and green behavior before a later PR.
