# Intent: the site, the manual and the README match what ships

## Problem

Three weeks of changes reached `main` and `edge` faster than the pages
that describe them. A read-only audit on 2026-10-22 found nine places
where a reader is told something untrue, or not told something that is
now true. Some of them cost a reader real time:

- The install example pins `v4.0.3-2`, a release that predates
  `defaultPlugins`, so a new user copies a broken starting point.
- The front page says Super+Space opens a palette, but it opens Omarchy's
  menu.
- The channels page says edge freezes when upstream breaks. Since
  #1383/#1394 it keeps taking `main`'s fixes, as it did for #1423.
- The new Nixarchy menu folder, the edge-only Appearance rename, edge's
  `omarchy agent account use`, and `nixarchy-verify` appear nowhere a user
  would look.

Three screenshots also show menus that have since moved.

## Proposed outcome

- Every item in #1424's list is true on the published site
  (olafkfreund.github.io/nixarchy), in the manual and in the README.
- The install example works when copied.
- The three page lists still agree, and `build.yml`'s docs guards stay
  green.
- The screenshots are re-captured, or the unreferenced one is removed.

## Affected users and systems

- Readers of the site and the README.
- New users following the install example.
- Edge-channel users reading the channels page.
- No code and no shipped behaviour changes.

## Constraints

- Docs only: `README.md`, `docs/index.md`, `docs/manual/*.md`, and
  `docs/screenshots/` for the images.
- Describe `main`/stable behaviour, and edge only in the edge section, as
  the pages do now.
- `docs/AGENTS.md`'s house style applies to any picture: a whole desktop
  at 16:10, shown big.
- Re-capturing screenshots drives the owner's live session
  (`tests/demo/screencast/`), so it happens only when the owner says so.

## Open questions

1. **Install pin:** `v4.0.6-1`, the newest tag, or `/release`, the
   branch that follows the newest tag? A tag stays reproducible but goes
   stale again; the branch never goes stale but moves under the reader.
   Recommendation: `/release`, with a sentence saying a tag can be
   substituted.
2. **Screenshots:** in this PR, which then waits for a capture session, or
   a follow-up so the text fixes ship today? Recommendation: a follow-up.

## Decisions (owner, 2026-10-22)

1. The install example pins `/release`, with one sentence saying a tag can be substituted.
2. Screenshots are a follow-up; this PR fixes the text.
