# Spec: A commit pin the review flags is moved and checked by the daily bump

Approved by the owner's standing pre-approval (2026-11-26). The design is Codex's (read-only design pass on #1945's team, 2026-11-26), taken as written except where noted.

No change to the design.

## Design

Extend `flake-update.yml` with a separate job that proposes **one stale input pin per run**. Use the existing 07:00 UTC schedule and `workflow_dispatch`. Open a pin-only PR for human merge after the evaluation gate passes.

1. **Trigger and base.** Give the job a clean checkout of `main` and run it independently of the nixpkgs bump’s result, including when nixpkgs is already current. The existing 07:00 slot follows the 06:00 review. `update.yml` handles package version and hash updates. Use a dedicated branch per input, leave an existing proposal branch alone, and try the oldest eligible pin first. [.github/workflows/flake-update.yml:46](/mnt/data/vmtest/wt-1945/.github/workflows/flake-update.yml:46) · [.github/workflows/flake-update.yml:89](/mnt/data/vmtest/wt-1945/.github/workflows/flake-update.yml:89) · [.github/workflows/update.yml:44](/mnt/data/vmtest/wt-1945/.github/workflows/update.yml:44)

2. **Eligibility.** Intersect `data/pin-fix.nix` with root inputs whose `flake.nix` URL contains a commit SHA or SHA prefix matching the locked revision, and whose GitHub owner is someone other than `olafkfreund`, case-insensitively. That covers `microvm`, `sops-nix`, `mcp-servers-nix`, and `zen-browser` in this checkout. Share the review’s comparison and age logic. The default-branch head must be `ahead`, and the oldest missing commit must be **at least eight whole days old** because the review truncates to whole days before testing `> 7`. Preserve the review’s release-first rule, so a missing release stays a release finding. Keep `pin-fix.sh`’s 1–100 commit bound. Larger jumps, diverged pins, and unreadable comparisons go in the run summary for human follow-up. [data/pin-fix.nix:6](/mnt/data/vmtest/wt-1945/data/pin-fix.nix:6) · [pkgs/flake-pins.py:24](/mnt/data/vmtest/wt-1945/pkgs/flake-pins.py:24) · [pkgs/review.sh:232](/mnt/data/vmtest/wt-1945/pkgs/review.sh:232) · [pkgs/review.sh:573](/mnt/data/vmtest/wt-1945/pkgs/review.sh:573) · [.github/scripts/pin-fix.sh:38](/mnt/data/vmtest/wt-1945/.github/scripts/pin-fix.sh:38)

3. **Rewrite and check.** Resolve the default branch to a full SHA and compare against that exact SHA. Reuse `pin-fix.sh --replace`, then run `nix flake lock`. Require exactly one URL edit, the expected locked SHA, `--moved` reporting only the selected root input, and `--intact` passing its follows and nixpkgs checks. Run `eval-gate.sh` against the resulting tree. It already evaluates the selected probe, every other pin probe, and every cached output. If any check fails, restore both flake files and record the failure before trying the next candidate. Include the old and new SHA, upstream compare link, and probe result in the PR body. 4. **Merge protection.** Keep auto-merge disabled for these PRs. `--owner` determines whether the workflow may overwrite its blocked draft. `--only-nixpkgs` is the auto-merge content guard, and a pin proposal changes both `flake.nix` and `flake.lock`. Open with `BUMP_TOKEN` so independent build and install CI runs. Require the existing branch-protection checks on the proposed head before human merge. Keep upstream commit text out of generated commit messages and use the existing sanitizer for any upstream text included in the PR body. 5. **Fixture.** Extend `checks.pin-fix` with a fixed clock and compare JSON fed through the selector the job actually calls. Assert a move at eight days and a refusal at seven days, 23 hours. Also refuse an old pin with only recent missing commits, an unlisted input, a branch or tag, an own-repo pin, a missing release, and identical, diverged, or malformed comparison data. For the break proof, change the threshold to `>= 7`, capture the boundary fixture failing, then restore it and rerun. The existing generated-check step already runs `checks.pin-fix` on PRs. [tests/pin-fix.nix:50](/mnt/data/vmtest/wt-1945/tests/pin-fix.nix:50) · [tests/review-pins.nix:293](/mnt/data/vmtest/wt-1945/tests/review-pins.nix:293) · [.github/workflows/build.yml:618](/mnt/data/vmtest/wt-1945/.github/workflows/build.yml:618) · [CLAUDE.md:241](/mnt/data/vmtest/wt-1945/CLAUDE.md:241)

6. **API budget.** Budget **at most 20 upstream REST requests per scan** for the four current candidates. Each costs up to three for release eligibility and three for default-branch metadata, head SHA, and compare, but release eligibility costs three only when a tag comparison is needed. To keep the cap at 20, fold the review’s separate tags reachability check into the tags fallback and retain its success status. Use `github.token` for discovery, `git ls-remote` to check proposal branches, and `BUMP_TOKEN` only for the single PR creation. Nix fetches and PR-action calls are outside the discovery count. Let PR events start CI without polling the owner’s account, whose 5,000-request hourly limit was exhausted during CI watches in #1948.
