# Spec: quattro's new /usr references stop the edge channel publishing

## What the three commands do (read at quattro 81fd2d2)

- **`omarchy-install-t3code-app`**:
  - It runs `"$download" --appimage-extract 'usr/share/icons/hicolor/*/apps/t3code.png'`
    in `$work`, then loops over `"$work"/squashfs-root/usr/share/icons/...`.
    Both `usr/` paths are inside the AppImage it just unpacked into a temp
    directory.
  - `[[ $link_target == "/usr/bin/t3" || … "/usr/bin/t3-nightly" ]]` decides
    whether to replace a `~/.local/bin/t3` link that an Arch package once
    pointed there. On NixOS no such link exists, so the test is false and the
    first branch (no link yet) is the one taken.
  - Nothing reads or writes the host's `/usr`.
- **`omarchy-remove-ai-t3-code`**: `case $(readlink ~/.local/bin/t3) in … /usr/bin/t3 | /usr/bin/t3-nightly) rm -f …`.
  These are pattern strings, and the `$HOME/.t3/bin/t3` pattern beside them
  is the one that matches on NixOS. Nothing touches `/usr`.
- **`omarchy-hw-fingerprint`**: `platform_readers=/usr/share/omarchy-platform/fingerprint-readers`,
  read only `if [[ -r $platform_readers ]]`. Upstream's `docs/file-layout.md`:
  a platform package (omarchy-mac, Apple Silicon) names non-USB readers there,
  "Omarchy ships none", and "a platform file never hides a USB reader". On
  x86_64 NixOS the file cannot exist, so the command does exactly what it does
  on every non-Mac Omarchy machine: the USB scan.

All three are harmless on NixOS, so none is patched (the intent's first open
question: exception, not a NixOS path).

## Design

`tests/session.nix`, the `/usr` guard's `allowed` list (it opens at line 1842
and ends with `"omarchy-install-hermes-cli", "omarchy-install-openclaw-cli"]`).
Before the closing `]`, append, in the list's style of a comment above each
group:

```python
               # New in quattro. Every /usr is inside the AppImage it just
               # extracted (squashfs-root/usr/...), or a string compared with
               # the target of a ~/.local/bin/t3 link an Arch package made.
               "omarchy-install-t3code-app", "omarchy-remove-ai-t3-code",
               # Quattro. Reads /usr/share/omarchy-platform/fingerprint-readers
               # behind -r: a file only a platform package (omarchy-mac, Apple
               # Silicon) writes. Absent here, so detection is the USB scan, as
               # on every non-Mac Omarchy.
               "omarchy-hw-fingerprint",
```

Nothing else changes. The guard computes `set(offenders) - set(allowed)`, so
names that stable 4.0.5 does not ship are inert on `main`, and they take
effect on edge at its next merge of `main`.

## Alternatives rejected

- **Patch `omarchy-hw-fingerprint` to a nixarchy path.** Nothing would write
  that file, and the patch would be carried at every bump to excuse a
  reference that already does no harm.
- **Carry the exceptions on the `edge` branch only.** Edge merges `main`
  daily, and an edge-only change to `tests/session.nix` is a conflict
  waiting in that merge (#1350 was exactly that). On `main` they are inert.
- **Widen the guard to skip `squashfs-root/usr` or quoted `/usr/bin/…`.**
  That weakens a check by pattern in order to excuse two commands. Named
  exceptions keep each decision reviewable.

## Out of scope (the intent's second question)

Whether `omarchy-install-t3code-app` works on NixOS (an AppImage needs FUSE or
extraction plus a dynamic loader) is about the menu row, not the guard. I will
check it once this lands. If it fails, I will file it separately with the
#1320 treatment: dim the row with a reason.

## Risks

- **An exception outliving its reason:** a later quattro could change one of
  these commands to really write to `/usr`, and the exception would hide it.
  The same is true of every entry in this list. The comment says what was
  checked, so the next reader can re-check it.
- **Another failure behind this one:** edge's `verify` stopped at the first
  failing assertion in `session`, so assertions after line 1931 never ran on
  quattro. The edge re-run is what finds out. A new failure there is a new
  issue.

## Verification

- **Cheap, before the VM (§6 tier 1/2).** A bash script runs the guard's own
  shell scan against the bin directory of the edge Omarchy package (quattro
  81fd2d2, built from `edge-candidate` plus this commit) and the guard's set
  difference against the `allowed` list parsed from `tests/session.nix`:
  - with the new entries: no offenders;
  - with `"omarchy-hw-fingerprint",` deleted: exactly `omarchy-hw-fingerprint`
    reported (§1), and the same for one t3 entry.
- **On `main`:** `checks.session` is unchanged in behaviour, and this PR's CI
  runs it.
- **The real proof:** after merge, `main` is merged into `edge-candidate`, and
  `omarchy-edge.yml` runs with `from_candidate=true`. `verify` passes the
  `/usr` guard, and #1350 closes if the rest passes too.
