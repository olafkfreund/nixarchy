# Intent: The installer's disk list opens on an internal disk

## Problem

`installer/install.sh:740-763` lists disks in `lsblk` order, and `gum choose` opens on the first row. The boot medium is already left out (`install.sh:732`), but a second USB stick or an external drive that sorts first is the highlighted row, and two presses of Return carry on with it. The summary still asks before anything is erased, so this is a wrong default, not silent data loss.

## Proposed outcome

With an internal and a removable disk attached, the list shows the internal disk first and opens on it. Removable disks stay in the list, so installing onto one still works. A machine with one disk, or only removable disks, sees what it sees today.

The exception is an SD card in a built-in reader. The kernel reports it as `RM=0`, `TRAN=mmc`, the same as a laptop's soldered eMMC, so it can't be told apart safely and stays in `lsblk` order. Sorting `mmc` last would push an eMMC laptop's only internal disk below a USB stick.

## Affected users and systems

Anyone running the installer with more than one disk attached. Installed systems and Mode A are untouched. `--from`/`--host` installs use the saved disk, not this list.

## Constraints

- Removable disks aren't hidden or refused.
- The rows keep their format: `<device> <size> <model>`, because the first field is what's read back.
- This changes only the order, not the erase confirmation.
- The existing filters (boot medium, zram, floppy, minimum size) still apply.
- A check reads the rows actually offered, with two eligible disks. Today's stubs offer one disk, or return a preset device without reading the menu, so they can't see the order.

## Open questions

1. **What counts as removable?** `lsblk`'s `RM` flag is the simple answer, but many USB enclosures report `RM=0`, so an external drive can still pass as internal. `TRAN=usb` catches those. The recommendation is to sort last on either signal, and not on `mmc`.
2. **4096-byte LUKS sectors (`omacom/omarchy#336`): include or leave out?** Recommendation: leave out. It's a performance change to every new encrypted install, unrelated to this list, and nothing here has measured it. Cryptsetup's own default for the disk stays in force.
3. **Old RAID or volume group on the disk (`omacom/omarchy#327`): include or leave out?** Recommendation: leave out, and test it separately. No install has been tried on such a disk, so it isn't known whether it fails here.
