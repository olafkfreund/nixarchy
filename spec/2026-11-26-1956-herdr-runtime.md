# Spec: login does not fail on a missing herdr

Approved by the owner's standing pre-approval (2026-11-26).

## Design

`herdr` joins `passthru.runtimeDeps` in `pkgs/omarchy/default.nix` (installed system-wide at lowPrio by `modules/nixos.nix`), as `herdr ? null` so nixpkgs-stable, which lacks it, still evaluates and keeps the plugin route. The package ledger row moves from `skip` to `nix = "herdr"`. `checks.autostart-runtime` reads the shipped `autostart.lua` and fails when it starts `herdr server` and the package does not ship herdr.

## Alternatives rejected

Patching autostart to skip a missing herdr: its text differs between v4.5.0 and quattro, so one substitution cannot match both, and it would hide a missing tool instead of installing it.

## Risks

herdr in both the system profile and the plugin's home profile: separate buildEnvs, no collision.

## Verification

`checks.autostart-runtime` red with herdr removed, green with it; every generated check.
