# Spec: the pkexec probe either passes or says why it failed

## The intent's open questions, answered

1. **How strict is "the current shell's agent": by PID, in the journal.**
   - IPC is not available. `shell/plugins/polkit/PolkitAgent.qml` (392 lines)
     declares no `IpcHandler`; it only logs `omarchy polkit agent registered`
     (`:186`) or `… is not registered; another agent may be running`
     (`:187`).
   - The journal line carries the logging shell's own PID:
     `omarchy-shell[2139748]` was the shell restarted on p620 at 08:22 on
     2026-10-02.
   - The shell can be relaunched within a session (p620's was, at 09:27,
     10:14 and 10:18 the same day).
   - So "registered at any point since boot", today's probe, can be a dead
     shell's line. Filtering by the running Quickshell's PID cannot.
2. **The second probe** (`systemd-run --user` pkexec, #765 PR 3): it gets the
   same hardening, in the same change, through a shared helper.

## Design

### D1. A helper, `pkexec_probe(launch_cmd, label)`, in `tests/session.nix`

It is used by both probes and runs these steps.

1. **Agent ready, for the shell that is running now.**
   - Find the shell's PID:
     `pgrep -o -f 'quickshell.*omarchy'` (match whatever the file already
     uses to find the shell; `pgrep -a quickshell` is printed at `:~475`).
   - Poll up to 120 s for
     `journalctl -b -t omarchy-shell _PID=<pid> -o cat`, captured into a
     variable (never a pipe into `grep -q`, see `tests/AGENTS.md`), to contain
     `omarchy polkit agent registered`.
   - If the PID changes while polling, the shell restarted: re-read it and
     keep waiting.
   - If the line `is not registered; another agent may be running` appears
     for that PID, fail at once with that line. That is a real fault, not a
     timeout.
2. **Launch, checked.**
   - The first probe's `hyprctl dispatch 'hl.dsp.exec_cmd(…)'` has its reply
     captured; anything but `ok` fails at once, quoting the reply and the
     `HYPRLAND_INSTANCE_SIGNATURE` used.
   - The pkexec command line is wrapped so its output goes to
     `/tmp/pkexec-<label>.log` and its exit status to
     `/tmp/pkexec-<label>.rc`. For example:
     `sh -c '/run/wrappers/bin/pkexec … >/tmp/pkexec-x.log 2>&1; echo $? >/tmp/pkexec-x.rc'`.
   - The second probe's `systemd-run --user` launch gets the same wrapping.
3. **The dialog.** The probe waits for a `polkit-agent-helper@*` unit, as
   today (90 s).
   - On timeout, before failing, it prints:
     - the dispatch reply;
     - `/tmp/pkexec-<label>.log` and `.rc`, if present: "no file" itself
       means pkexec never ran;
     - `journalctl -b -u polkit --no-pager | tail -40`;
     - `journalctl -b -t omarchy-shell --no-pager | tail -40`.
   - Then it fails with a one-line summary naming which stage stopped.
4. **The rest is unchanged:** `send_chars("omarchy\n")`, then the
   `/tmp/pkexec-ok` (or `touch`) owner check, as today.

### D2. What stays exactly as it is

- **What is proven is unchanged:** the Omarchy dialog answers a pkexec started
  inside the session, and one started from a `systemd-run --user` unit.
- **The timeouts are the same.**
- **No retry.** A failure ends the test, now with a diagnosis.

### D3. §1, the staged red, since the flake cannot be summoned

A throwaway probe branch through CI (`workflow_dispatch`, as #1156's breaks
were run), with the shell's polkit agent kept from registering. The plan picks
the least invasive way. Candidates:
- disable the `omarchy.polkit` plugin in the fixture's `shell.json` seed;
- or start a competing polkit agent first, which produces line `:187`.

Expected: the probe fails **at stage 1**, with the "not registered" line or
the agent timeout, and prints its diagnostics. It does not fail as the
generic 90 s `polkit-agent-helper` timeout of the #1161 run. A second staged
break, a deliberately wrong `HYPRLAND_INSTANCE_SIGNATURE`, must fail at
stage 2 quoting `hyprctl`'s reply.

## Alternatives rejected

- **Add an IpcHandler to the polkit plugin.** That patches upstream's shell
  for a test's convenience. The journal already carries the fact.
- **Retry the dispatch.** It hides the race (AGENTS.md §10).
- **Longer timeouts.** Neither suspected cause is slowness.

## Risks

- **A broken PID match makes the probe wait the full 120 s and fail:** for
  example, a launcher change that puts the shell under a wrapper PID. That is
  a loud failure, and it names the stage, so acceptable.
- **The helper adds about 40 lines to `tests/session.nix`.** That is offset by
  folding both probes onto it.
