# Plan: edge adopts quattro ceb30ed (Files for Nautilus, Plain as the editor)

Self-contained: it carries every approved spec decision. Builds, local
checks, commits, pushes and the dispatch are the session's (Claude's), never
an agent's. Codex and the coder edit files only. They do not stage, commit,
push or build (managed rule, and `handoff`'s guard). agy is a reviewer only:
`agent-run agy` cannot reach `/mnt/data` worktrees, so step 6 goes to the
coder instead.

## Decisions (from the approved spec)

1. **Where it lands.** One carry on `edge-candidate` (now `b654130d`, the
   same as `edge`) carries the code, the pin and the pin-derived rows. The
   artifacts go to `main` on `fix/1750-quattro-ceb30ed`. The pin is quattro's
   newest commit at carry time (`ceb30ed` today), in both `flake.nix` copies
   (the input `url` and `omarchyVersion`) plus `flake.lock`. The carry is
   then dispatched with `from_candidate=true` (§8).
2. **The pin-derived flags** come from `pkgs/omarchy/default.nix`, without
   IFD:
   - `basePackages`, the split `install/omarchy-base.packages` with blank
     lines and comments dropped;
   - `hasPapers = elem "papers" basePackages`, rewritten to use it;
   - `hasFiles = elem "folio" …` and `hasPlain = elem "plain" …`;
   - `preinstallsMoonlight = hasInfix "moonlight-qt"` of
     `bin/omarchy-install-preinstalls`.

   `passthru` gains `hasFiles`, `hasPlain`, `basePackages`, `preinstallsMoonlight`,
   `fileManagerDesktop` (`"folio.desktop"` or `null`) and `editorDesktop`
   (`"plain.desktop"` or `"nvim.desktop"`).
3. **Two packages**, `pkgs/apps/folio.nix` and `pkgs/apps/plain.nix`. They
   are modelled on `owe.nix`:
   - `fetchFromGitHub omacom/<name>` at tag `v0.2.0`, with `nix-update` as
     the `updateScript`;
   - `qt6.qmake` and `wrapQtAppsHook`;
   - they install the binary, `pkgbuild/<name>.desktop`, the SVG icon and
     the MIT licence;
   - inputs: Files takes Qt base, declarative, imageformats, multimedia and
     wayland, plus `glib`, `zlib` and `libarchive`; Plain takes Qt base,
     declarative and wayland;
   - no optional dependencies (no WebEngine);
   - exported as `nixarchy-apps.folio` and `nixarchy-apps.plain`, and listed
     in `packages` beside `owe` (`origin/edge:flake.nix:1603`), so
     `.#folio` and `.#plain` build;
   - passed to `pkgs/omarchy/default.nix` explicitly, in the
     `inherit (final.nixarchy-apps) …` beside `ttfx`
     (`origin/edge:flake.nix:1372`), with `folio` and `plain` added to that
     file's arguments. `callPackage` does not search `nixarchy-apps`, so a
     bare `folio` would resolve to nixpkgs' unrelated notes app.
4. **The package.** `(if hasFiles then folio else nautilus)`, and `plain`
   when `hasPlain`. `xdg-user-dirs` is already unconditional
   (`origin/edge:pkgs/omarchy/default.nix:327`), so
   it is not added. The editor `--replace-fail` reads
   `default-editor-install-plain.upstream.sh` when `hasPlain`, and the old
   file otherwise. Both are exact text. The desktop-ID check (line 1236)
   reads only `config/*mimeapps.list`, so it is not extended.
5. **The module** (`modules/nixos.nix`):
   - `text/plain = editorDesktop`, which means Plain on edge (decision A);
   - `inode/directory = fileManagerDesktop`, only when it is non-null;
   - both stay inside the `mkDefault` map;
   - preinstalls: `moonlight-qt` when `preinstallsMoonlight`, and `sushi`
     when `basePackages` names it;
   - a name the pin no longer installs moves from `current` to `retired` in
     the `preinstallsExclude` assertion, so old exclusions still evaluate.

   In `modules/apps.nix`, `editor:plain` joins `editor:nvim` in the
   "already ships" arm.
6. **The migrations.**
   - `1794341736`: `ported` and `edited`. Upstream's state half runs
     unchanged. The `mimeapps.list` half runs only when the file is regular
     and writable, or absent. A symlink is left alone, with a note.
   - `1794330979`: `partial` and `edited`, shaped exactly like `1794165002`.
     The `pkg-add` and `pkg-drop` lines go, the `mimeapps.list` rewrite gets
     the same symlink guard, and the `shell.json` dock block is removed. A
     user's Nautilus dock pin stays, and the ledger reason says so.
   - A fresh home (no `shell.json` before the seed) marks both done through
     the existing loop, so it gets Plain.
7. **Ledgers.** On the carry:
   - `data/omarchy-packages.nix`:
     - `folio = { nix = "nixarchy-apps.folio"; }`,
       `plain = { nix = "nixarchy-apps.plain"; }`,
       `xdg-user-dirs = { nix = "xdg-user-dirs"; }`;
     - the rows the check calls stale (`nautilus`, `sushi`,
       `moonlight-qt`) removed;
     - each new hardware package it names gets
       `skip = "One <vendor> laptop; not targeted.";`, the wording of the
       existing `asus-proart-p14-speaker-firmware` row;
   - `data/user-migrations.nix`:
     - `"1794341736"`: `decision = "ported"`, `run = "edited"`, reason
       "keeps Neovim for an existing home without a saved editor; a
       symlinked mimeapps.list is left alone (#1750)";
     - `"1794330979"`: `decision = "partial"`, `run = "edited"`, reason
       "points a Nautilus handler at Files and leaves a symlinked
       mimeapps.list alone; the dock pin is not moved, because shell.json is
       written only through the shell (#847, #1750)";
   - `data/apps.nix`: `moonlight = { menuId = "install.gaming.moonlight";
     label = "Moonlight"; category = "Gaming"; attr = "moonlight-qt";
     arch = "moonlight-qt"; }`, shaped like `lutris`;
   - `data/menu-actions.nix`:
     - `"remove.gaming.moonlight"` = "owned: pkg-drop is inert here
       (decision 10)", as `remove.gaming.battlenet`;
     - `"setup.default.editor.plain"` = the same "owned: its one rm clears
       its own pending-default-editor marker after setting the default
       (#1623, checks.menu-conditions)" text as the nine editor rows;
   - `data/bin-ledger.nix`: whatever `checks.bin-ledger` names;
   - `pkgs/review.sh`: rows for `folio` and `plain`.
8. **Verification**, by §6 tier, every reachable check, including `main`'s
   pin on a scratch tree, and the §1 breaks listed in the Tests section.

## Rollback

- **The carry:** revert its commits on `edge-candidate` (a new commit, never
  a force-push), or let the next scheduled edge run start from `edge` once
  `edge-candidate` is deleted. Edge keeps `054d75e` until a run passes.
- **The artifacts:** revert the merge on `main`. No code goes to `main`
  from this branch.
- **A deployed host:** roll back to the previous generation, or boot it.
  That does not undo what the two migrations wrote to the home:
  - the markers in `~/.local/state/omarchy/migrations/`;
  - `nvim` in `~/.local/state/omarchy/defaults/editor`, which is harmless,
    since Neovim is installed on both;
  - `folio.desktop` in place of `org.gnome.Nautilus.desktop` in a regular
    `~/.config/mimeapps.list`.

  On a rolled-back generation without Files, reverse the last one only:
  `sed -i 's/^\(inode\/directory=\)folio\.desktop/\1org.gnome.Nautilus.desktop/'`
  on that file. That touches only the line the migration wrote, and leaves
  any other choice made since. Keep the markers, so a later roll-forward
  does not re-run them.

## Deviations during implementation

1. **Step 1, the pin stays at `ceb30ed`, not quattro's head.** At carry time
   quattro was `4211c9f`, ten commits on. They move agent setup into a new
   root Agent menu, rename the `setup.default.agent.*` rows nixarchy
   overrides, and add migration `1794344676`. That is work this plan did not
   approve, so the carry pins `ceb30ed`, the commit the spec describes. The
   next scheduled edge run tries the newer head, and holds with its own issue
   if that fails.
2. **Step 7, the session and coexistence parts were done by Claude.** The
   coder's scripted edit of `tests/session.nix` matched the wrong anchor and
   deleted about 2,100 lines. It stopped rather than restore the file past
   its guard, so Claude restored the file from `HEAD` and wrote those two
   parts with exact-text edits. The migration test cases are the coder's.
3. **Decision 7, no `remove.gaming.moonlight` row.** `checks.menu-actions`
   refused it: "entry for remove.gaming.moonlight, which reaches no hazard:
   stale". The row was deleted. `setup.default.editor.plain` stays.
4. **`tests/review-pins.nix`, not in the plan.** Its hard-coded pin list gets
   `folio` and `plain`. The check counts the pins in `review.sh`, so two new
   rows there make it fail (18 against 16).
5. **The tier rule was broken once.** `checks.omarchy-package-ledger` was
   taken for a cheap check and run while #1751's install job held the host.
   It built the `omarchy` package. That install passed. The tier is now read
   from `nix build --dry-run`'s list before each check.
