# Spec: a greeter stranded by sleep is recovered on edge, as upstream recovers it

## Design

**1. The script names a unit NixOS does not have.** Upstream's script asks `systemctl is-active sddm.service` and restarts `sddm.service`. On NixOS, SDDM runs as `display-manager.service`, and no `sddm.service` alias exists. On p620, `systemctl is-active sddm.service` prints `inactive` while the greeter runs. Shipped unpatched, the script exits 0 on every call.

So `pkgs/omarchy/quattro-script-ports.sh`, the place for patches that span three pins (pkgs/AGENTS.md#quattro-script-ports), gains:

```sh
f=$out/share/omarchy/bin/omarchy-system-sddm-recover
[ ! -e "$f" ] || substituteInPlace "$f" \
  --replace-fail 'is-active --quiet sddm.service' 'is-active --quiet display-manager.service' \
  --replace-fail 'restart --no-block sddm.service' 'restart --no-block display-manager.service'
```

The tag and edge pins before ebd2974 do not ship the file. `data/bin-ledger.nix` gains a `patch` row, `edge = "only"`.

**2. The hook, in modules/nixos.nix, `systemd.services`.** It sits beside the existing `fprintd` entry with the same `lib.optionalAttrs` shape: the comment there explains that `mkIf` on an `attrsOf` entry still defines the unit. It covers `systemd-suspend`, `systemd-hibernate`, `systemd-hybrid-sleep` and `systemd-suspend-then-hibernate`, gated on all of:

- `cfg.displayManager`
- `config.services.displayManager.sddm.enable`
- `builtins.pathExists "${inputs.omarchy}/bin/omarchy-system-sddm-recover"`

The `pathExists` gate is false under the tag and older edge pins. It is the house `registryFile` pattern, on a fetched source, so there is no IFD. Each unit gets:

```nix
enableDefaultPath = lib.mkDefault false;
serviceConfig.ExecStopPost = [ "-${sddmRecover}/bin/omarchy-sddm-recover" ];
```

**3. The wrapper.** `sddmRecover` is a `writeShellApplication` with `runtimeInputs = [ config.systemd.package pkgs.gawk ]` and a body that fails closed before exec:

```sh
# The seat test reads a missing awk as "no seat" and restarts SDDM: refuse first.
for c in systemctl loginctl awk; do command -v "$c" >/dev/null || { echo "omarchy-sddm-recover: $c not found" >&2; exit 1; }; done
exec ${cfg.package}/bin/omarchy-system-sddm-recover "$@"
```

The PATH belongs to the hook process, not the unit:

- **No PATH on the unit.** `enableDefaultPath = false` stops NixOS writing `Environment=PATH=…` into the sleep unit's override. Measured on `nixosConfigurations.vm`, the rendered override then holds only `LOCALE_ARCHIVE`, `TZDIR` (NixOS's global unit environment) and the `ExecStopPost`.
- **User config still wins.** `mkDefault`, so a user's own `enableDefaultPath` does not conflict.
- **Additive.** `ExecStopPost` is a list, so a user's own entries merge with ours, and the rendered drop-in adds a line without replacing the upstream unit.
- **Shebang.** The packaged script's `#!/bin/bash` is already patched to a store bash: `head -1` on p620 shows `/nix/store/…-bash-interactive-5.3p20/bin/bash`.

**4. The rows, in data/etc-overlay.nix.** All four go from `divergent` to `native` and stay `edge = "only"`. Each reason names `systemd.services.<unit>.serviceConfig.ExecStopPost` in modules/nixos.nix, and the `display-manager.service` patch.

**5. The checks: one per layer, each able to fail.**

- **`checks.sddm-recover`, new and cheap (`tests/sddm-recover.nix`).** It runs the shipped, patched script with stub `systemctl` and `loginctl` on PATH, using the real `gawk`. Cases, all asserted on the stub's call log:
  - a `seat0` session → no restart
  - only seatless sessions (`manager`, `sshd`) → exactly one `restart --no-block display-manager.service`
  - DM inactive → no restart
  - `loginctl` fails → no restart
  - the script mentions no `sddm.service`

  It checks our patch and the decision as it runs here, not upstream's logic. On a pin without the script, it prints `skipped` and passes, like `update-available`. It reaches PR CI through `generated-checks.sh`.
- **`tests/options.nix`, the `displayManager` case.** On a script-bearing pin, `on` additionally requires the hook on all four units, and `off` additionally requires it on none, which is the closed Mode A gate. On a pin without the script, `on` requires it on none.
- **`checks.session`, the greeter phase.** This is the highest layer, with real systemd and real SDDM. Right after `loginctl list-sessions | grep -q greeter`:
  - If `/run/current-system/sw/share/omarchy/bin/omarchy-system-sddm-recover` exists:
    - each unit's `systemctl show -p ExecStopPost --value` must hold `omarchy-sddm-recover` and `ignore_errors=yes`.
    - The hook's `path=` is then run as `systemd-run --wait --pipe --collect`, a system service with systemd's environment rather than the test shell's. It must exit 0 with empty stderr, so the wrapper's guard fires red on a missing command.
    - After the restart queue settles (no `display-manager` job in `systemctl list-jobs`), `display-manager.service`'s `InvocationID` must be unchanged. A restart, which `--no-block` queues after the wrapper returns, changes it.
  - If the script is absent, no unit names the hook.

## Alternatives rejected

- **`systemd.services.<unit>.path`:** it changes the sleep unit's own PATH.
- **An `sddm.service` alias on `display-manager.service`:** it changes the display manager unit for every nixarchy machine, to suit one script. The patch is local to that script.
- **Installing upstream's drop-ins via environment.etc:** they name `/usr/bin/…`, which resolves only through envfs and the caller's PATH, the same reason other rows here are `divergent`.
- **Guarding on `isEdge`:** older edge pins are `edge-…` and lack the script.
- **Driving the restart branch in the VM:** a stranded seat needs a real suspend, or a race with SDDM's own greeter respawn. The stubbed check covers that branch deterministically.

## Risks

- **A restart decided wrongly on every resume ends the desktop session**, on p620 and razer. The wrapper's guard, the stubbed check's seated case, and the VM's `InvocationID` check each stand against it.
- **The hook's unit context.** `systemd-run` approximates it but does not replicate the sleep units' context. systemd 262's sleep units carry no sandboxing that would block D-Bus to PID 1 or logind. A future systemd that adds some would make the hook fail, ignored (`-`), without harm.
- **The restart branch is proven only with stubs.** If logind's column layout changes, the seated case in the VM still holds, and the stranded case could stop recovering. That is today's status quo.
- **Unit names.** The four are hard-coded. A fifth upstream drop-in is reported unclassified by `tests/etc-overlay.nix`, which fails closed. If upstream renames `sddm.service` in the script, `--replace-fail` breaks the build, also closed.

## Verification

- **Under the carry's pin:**
  - eval of `nixosConfigurations.vm`'s `systemd-suspend.service` unit text shows the hook and no `PATH=`.
  - `checks.sddm-recover`, `etc-overlay`, `bin-ledger`, `.#omarchy`, the four `options-*` shards and the generated checks all pass.
- **Under `main`'s pin (scratch tree):** the same checks pass. `sddm-recover` reports `skipped`, and the `options` case holds with no hook.
- **Red proofs:**
  1. Drop the patch: `sddm-recover` fails on the seatless case.
  2. Remove `gawk` from `runtimeInputs` and make the wrapper `export PATH=${systemd}/bin` before the guard: `session` fails on the hook's exit status and stderr.
  3. Drop one unit from the list: `session` and `options` fail, naming it.
  4. Restore: green.
- **Edge `verify`:** runs `session` under the carry's pin.
