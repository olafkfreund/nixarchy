# Spec: T3 Code installs on nixarchy

## Design

The patch lives on `main`, guarded by the script's existence (the intent's
option a). It is inert on stable, and edge takes it through its daily merge.

### 1. `pkgs/omarchy/default.nix`: the substitution

Among the other `substituteInPlace $out/share/omarchy/bin/…` edits in the
install phase (around line 451), add:

```sh
# CARRIED (#1368): an AppImage here runs through appimage-run (binfmt), which
# passes --appimage-extract to the app instead of extracting. Quattro only.
if [ -e $out/share/omarchy/bin/omarchy-install-t3code-app ]; then
  substituteInPlace $out/share/omarchy/bin/omarchy-install-t3code-app \
    --replace-fail '  "$download" --appimage-extract t3code.desktop >/dev/null' \
                   '  command -v appimage-run >/dev/null || { echo "Installing T3 Code needs AppImage support: programs.appimage.enable = true;" >&2; exit 1; }
  appimage-run -x squashfs-root "$download" >/dev/null' \
    --replace-fail "  \"\$download\" --appimage-extract 'usr/share/icons/hicolor/*/apps/t3code.png' >/dev/null" ""
fi
```

- The anchors are v81fd2d2's lines 83-84 verbatim. They sit inside
  `( cd "$work" … )`, so the relative `squashfs-root` is
  `$work/squashfs-root`: the path the next lines read (confirmed on an edge
  machine, where `appimage-run -x squashfs-root` produced `t3code.desktop`
  and all nine icons).
- One `-x` extracts the whole image, which replaces both of the old calls.
- `command -v appimage-run` turns "AppImage support turned off" into a
  sentence and exit 1. Without it, the call would hang behind a launched app
  or fail with "command not found". The subshell's failure ends the script,
  because it runs under `set -e`.
- `--replace-fail` makes an upstream rewording of those lines fail the build
  (pkgs/AGENTS.md). The `[ -e ]` guard keeps stable (no such script)
  building.

### 2. A check, so the class of bug cannot return: `checks.appimage-extract`

A `runCommand` over `${omarchy}/share/omarchy/bin`. It fails, naming each
file, if any non-comment line calls an AppImage with `--appimage-extract`:

```sh
hits=$(grep -rn -- '--appimage-extract' ${omarchy}/share/omarchy/bin | grep -vE ':[0-9]+:[[:space:]]*#' || true)
[ -z "$hits" ] || { echo "these scripts self-extract an AppImage, which appimage-run passes to the app (#1368):"; echo "$hits"; exit 1; }
```

This is §2's rule: the subsystem gains a probe at its cheapest layer. A
future quattro script that self-extracts an AppImage fails on the edge
channel's `verify` before it publishes, not on a user's desktop. It is picked
up by the generated-checks step, with no workflow edit.

## Alternatives rejected

- **Add `appimage-run` to Omarchy's runtime inputs.** Extraction would then
  work even with `programs.appimage` off, but the installed app could still
  not run: launching it needs binfmt. So the sentence is the honest answer.
- **Dim the menu row** (#1320's treatment): the app works on nixarchy, so
  hiding it would remove something users can have.
- **Patch only on `edge`:** rejected in the intent (merge conflicts, #1350).

## Risks

- **Coexistence (§14):** nothing new is installed system-wide; the script
  only calls a tool the system may provide. No fixture applies.
- **Stable:** the guard and the check both see no such script, so there is no
  change.

## Verification

- `nix build .#omarchy` on `main` is green (the guard skips).
- **On edge** (a scratch worktree of `origin/edge-candidate` with this branch
  merged): `.#omarchy` builds. Its `omarchy-install-t3code-app` contains
  `appimage-run -x squashfs-root`, and no `--appimage-extract` outside
  comments.
- **The check, §1:**
  - green on `main` and on the merged edge tree;
  - red on edge **without** the substitution, which is the already-built
    `…-omarchy-edge-20261019-81fd2d2` from today's edge work, naming
    `omarchy-install-t3code-app:83` and `:84`.
- **End to end on an edge machine**, once merged and edge has published:
  Install › T3 Code (stable channel) installs, the launcher appears, and the
  app starts.
