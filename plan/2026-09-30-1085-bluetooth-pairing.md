# Plan: Run the Bluetooth auto-accept agent only for an outgoing pair

The approved design removes Nixarchy's permanent `bt-agent` user service. Pinned BlueZ 5.87 makes the adapter bondable when the first/default agent registers and requests non-bondable when the last default agent leaves, with `AlwaysPairable` unset ([agent.c:268-281](https://github.com/bluez/bluez/blob/5.87/src/agent.c#L268-L281), [adapter.c:9151-9173](https://github.com/bluez/bluez/blob/5.87/src/adapter.c#L9151-L9173)). The latter behavior is inferred from source and needs hardware proof. The Omarchy panel already calls `omarchy-bluetooth-device pair <address>`; that command will own a temporary `bt-agent -c NoInputNoOutput`, wait for readiness, and kill and reap only its PID when pairing ends or is interrupted. Do not set `PairableTimeout`: BlueZ clears bondability on expiry ([adapter.c:870-895](https://github.com/bluez/bluez/blob/5.87/src/adapter.c#L870-L895)), and Linux can then negotiate a non-bonding authentication type ([hci_event.c:5248-5279](https://github.com/torvalds/linux/blob/v6.17/net/bluetooth/hci_event.c#L5248-L5279), [smp.c:650-664](https://github.com/torvalds/linux/blob/v6.17/net/bluetooth/smp.c#L650-L664)). New devices are trusted by the existing pair action. Older bonded but untrusted devices may lose service authorization without a permanent agent. Keep Mode A unchanged and leave the pinned panel itself unmodified.
