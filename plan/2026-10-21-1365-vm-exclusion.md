# Plan: an install VM never shares p620 with edge's VM checks

## Decisions (approved intent and spec)

- **`.github/scripts/vm-host-free.sh <install|edge>`**, reading the
  GitHub jobs API with `$GH` (default `gh`, stubbable):
  - `install` is busy when an `omarchy-edge.yml` run has its `verify`
    job `in_progress`;
  - `edge` is busy when an `install-check.yml` run has its `install` job
    `in_progress`;
  - the asker's own run (`$GITHUB_RUN_ID`) is excluded;
  - it prints `free` (exit 0) or `busy: <workflow> run <id> job <name>`
    (exit 1);
  - a failed or empty API answer exits 2. Capture first, then split (§4).
- **The wait loop** polls every 60 s and prints what it waits on. Exit 2
  counts as busy.
  - Install: a new step before "Install onto a blank disk…", bound 60
    min, then `::error::` plus a step-summary line, exit 1.
  - Edge `verify`: before `session`, `coexist` and `plugin` (not
    `options`), bound 120 min per check. On the bound, that check is
    marked failed like a build failure.
- **The scripts run as**
  `nix shell nixpkgs#gh -c .github/scripts/vm-host-free.sh …` with
  `GH_TOKEN: ${{ github.token }}`, because self-hosted shells have no
  `gh`. `install-check.yml` gains `actions: read`.
- **`checks.vm-host-free`:** six cases on a stub `gh`, and two red
  variants (any run counts; API failure read as free).
- **CLAUDE.md §6:** the tier row and its paragraph.

## Repo traps

- **`${{ }}` in a workflow `run:` is pasted text** (#1268). Pass values
  through `env:`, never inline.
- **A self-hosted step's shell has only what the environment provides.**
  The loop uses bash builtins and `sleep`; `sleep` comes from coreutils,
  which the install step already uses (`cut`, `df`, `awk`).
- **Stubs in a `runCommand` sandbox** need a `#!${pkgs.bash}/bin/bash`
  shebang, not `/usr/bin/env` (#1406's lesson). A shell variable named
  `out` clobbers `$out` (#1386's lesson).
- **No `grep -q` on a pipe** (`checks.grep-q-pipefail`); use a
  here-string.
- `actionlint` on both workflows; `nix fmt`.
- These are CI-gate edits. The owner merges (§11), and the PR says so.

## Steps (coder, one at a time: 5 files, so the model-split rule hands off; the lead commits)

1. **The script and its check.** Write `vm-host-free.sh`;
   `tests/vm-host-free.nix` with fixture JSON in the check (`printf`, not
   heredocs, §5); register it in `flake.nix` after `omarchy-newest`.
   - Reds: the two variants, each edited into a scratch copy and proven
     to have landed (`diff`).
   - Green: six cases.
2. **The install wait.** Add the step and the permission.
   - Verify: `actionlint`, and that the step sits before the install
     step.
3. **The edge wait.** Edit the loop.
   - Verify: `actionlint`, and a dry run of the loop body against the
     stub `gh` (the busy, then free sequence) under bash.
4. **CLAUDE.md §6.**
5. **Lead:** the full generated list (cheap tier, and only with no
   install in flight, per today's rule), then the PR. Squash merge. The
   owner signs off the CI gates.

## Rollback

Revert the PR. Edge and installs go back to the one-shot `wait-idle`.

## Deviations during implementation

- **Step 1: the script parses with `jq`** (a stub `gh` cannot apply
  `--jq`), so the workflows run it as
  `nix shell nixpkgs#gh nixpkgs#jq -c …`. Both red variants are built inside
  the check by `sed`, and the check refuses a `sed` that did not land
  (`cmp -s` against the real script).
