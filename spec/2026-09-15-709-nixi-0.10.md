# Spec: Bump nixi to 0.10, the Omarchy overlay card

## Design

Two changes land in **nixi** first (its PR olafkfreund/nixi-nixarchy#9, before
it merges), because they fix behaviour every nixi user has, not only nixarchy's.
Then **nixarchy** pins the resulting commit on nixi's `main` and brings its
checks and docs to the 0.10 layout.

### In nixi (PR #9)

**D1. The `agents` default follows `allowUnfree`.** Answers intent question 1.
`nix/hm-module.nix`: `services.nixi.agents` defaults to
`lib.optional (pkgs.config.allowUnfree or false) "claude" ++ [ "codex" ]`
instead of `[ "claude" "codex" ]`. `claude-agent-acp` pulls in the unfree
`claude-code`; `codex-acp` is Apache-2.0. nixarchy's Home Manager runs with
`useGlobalPkgs = true` (`installer/host.nix:190`), so `pkgs.config.allowUnfree`
is `programs.nixarchy.allowUnfree` (default true, `modules/nixos.nix:411`): a
default nixarchy desktop keeps Claude pinned, and one that turned unfree off
still evaluates, with Claude resolved from PATH if the user installs it.
nixarchy sets nothing.

**D2. `nixi` says when the card is off.** Answers intent question 2 by keeping
nixarchy's rule — plugins are installed, never enabled for you
(`modules/home.nix` ~548-600) — and removing the reason it hurts. Measured on
p620: `omarchy-shell shell toggle <id>` for a plugin that is not enabled or not
installed exits **0 and prints nothing**, so SUPER+H, the Help row and `nixi`
would silently do nothing on a fresh desktop. `bin/nixi` first reads
`omarchy-shell shell listPlugins` (JSON with `"enabled"`, 47 ms) and, if its
plugin is missing or disabled, sends `omarchy-notification-send` "Nixi is
installed but turned off — enable Nixi in Setup > Plugins" and exits 1. If the
shell does not answer, it says that instead of toggling blindly.

### In nixarchy

**D3. Pin.** `flake.nix` `nixi.url` → the merge commit of nixi PR #9 on `main`
(a commit, per the rule above it); update the comment's description of nixi
(no server, an overlay card). `nix flake lock` changes only `nixi`.

**D4. `tests/options.nix`, same on/off shape, 0.10 layout.**
- `nixiTracesIn`: drop `systemd.user.services ? nixi` and
  `xdg.configFile ? "nixi/ui.html"` (0.10 has neither); keep the
  `nixi-manual` timer and the package; add the plugin directory link
  `"omarchy/plugins/io.github.olafkfreund.nixi"` and the grounding asset
  `"nixi/KNOWLEDGE.md"`. Still five mechanisms.
- `nixiUnit`: removed — there is no unit to be on. Its job ("a machine that
  says no has nothing listening") is now vacuous and stated in the comment.
- `nixiPluginFile` → `nixiPluginDir = "omarchy/plugins/io.github.olafkfreund.nixi"`;
  `nixiBarWidget` asks about `"${nixiPluginDir}-button"`, the separate button
  plugin that `barWidget.enable` now controls.
- `nixiLeavesMenuAlone` unchanged.

**D5. Words.** `modules/home.nix` comments that call the bar widget nixi's front
door and mention "a server on 8642"; `docs/manual/getting-started.md` "The
guide" (overlay card, SUPER+H / Help / snowflake, enable **Nixi** and **Nixi
button** once, no server, `services.nixi.port` no longer exists);
`README.md` row. `tests/plugin.nix` needs no change (it only sets
`enable = false`).

**D6. Write-back.** `AGENTS.md` gains the two general traps found here: an
Omarchy IPC toggle for a disabled plugin is a silent success, and a Home
Manager module that moves from per-file links to a whole-directory link fails
`checkLinkTargets` on the old real directory.

## Alternatives rejected

- **nixarchy sets `services.nixi.agents` from `allowUnfree`.** Works for
  nixarchy only; a standalone nixi user with unfree off hits the same eval
  error. The default belongs to the module that owns the option.
- **Drop Claude from nixi's default.** Breaks the common case; most nixarchy
  desktops allow unfree and use Claude.
- **nixarchy enables the card in `shell.json`.** Breaks a stated nixarchy rule
  and the shell owns that file.
- **Track nixi's branch until PR #9 merges.** `flake.nix` forbids it, and every
  nixarchy user would follow a moving target.

## Risks

- **Existing desktops on upgrade.** A 0.9 real plugin directory fails Home
  Manager activation unless removed first; nixi's module does that when it
  holds only Home Manager links (unit-tested, ordered before
  `checkLinkTargets`, seen working by hand on p620 and razer). A directory with
  anything else in it (an old plugin-manager checkout) still fails, with Home
  Manager's collision message — correct, but a user sees a failed switch.
- **`allowUnfreePredicate` users** who allow only `claude-code` have
  `allowUnfree = false`, so they lose Claude from the default and must set
  `agents`. Documented.
- **Anyone who set `services.nixi.port` or `voice`** gets an evaluation error
  naming the removed option (intended; nixarchy sets neither).
- **CI cost.** The install check runs on p620's runners (37-90 min) and p620
  hard-resets after some switches (nixos_config#1820).

## Verification

- nixi PR #9: new node/Python checks for D1 (default with and without unfree,
  both building an activation package) and D2 (`bin/nixi` against a stub
  `omarchy-shell` returning enabled, disabled, missing, no answer), each
  mutation-checked; CI green.
- nixarchy: `nix build .#checks.x86_64-linux.options` (and `doc-options`) pass
  with the new pin; the updated cases fail when put back to the 0.9
  expectations against the 0.10 pin (mutation); `nix flake check` evaluates;
  the install check passes in CI.
- On p620: with nixos_config's override removed and nixarchy bumped, the p620
  toplevel's closure diff against the running system shows no nixi change
  (same nixi commit), then the override is dropped (nixos_config PR).
- By hand on a desktop with the card disabled: SUPER+H shows the "turned off"
  notification.
