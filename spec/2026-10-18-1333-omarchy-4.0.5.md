# Spec: nixarchy follows Omarchy v4.0.5

Measured on a scratch bump in `/mnt/data/vmtest/wt-405`: v4.0.5 is
94a8fbc2, and the probe diff is `/mnt/data/vmtest/405-probe.diff`. With the
edits below, `nix build .#omarchy` is green, and so are `menu-actions`,
`menu-guards` and `menu-verbs`. `bin-ledger` reports exactly the three rows in
§4. A survey by codex (gpt-6-sol) found most of these. Each one was then
checked against `git show v4.0.5:<path>`. One of its findings was refuted, and
one problem it missed was found (§3).

## Design

### 1. The input and the carried patch

- `flake.nix`: `github:basecamp/omarchy/v4.0.5`, and `omarchyVersion = "4.0.5"`
  (the same two edits `omarchy.yml` makes). Then `nix flake update omarchy`.
- `1153-owe-video-backgrounds.patch`: rebased onto v4.0.5 with a three-way
  merge (`git rebase` of the v4.0.4 backport commit), which was clean. It is
  regenerated with the header's own `git diff v4.0.5 backport -- <files>`, and
  the header's three `v4.0.4` references become `v4.0.5`. Upstream's change
  under it is bfac6650e, "Qualify shell palette references for Qt 6.12". The
  patch adds no unqualified `Color.` line, which was checked over every added
  line.

### 2. `--replace-fail` anchors upstream moved (`pkgs/omarchy/default.nix`)

| ~928/930 | the no-browser diagnostic, anchored on `exec setsid uwsm-app -- $(sed -n` | `browser_exec=$(sed … \| head -1)`, then `if ! omarchy-cmd-browser-handoff …; then exec setsid uwsm-app -- $browser_exec …` | **retarget**: insert the same diagnostic, on `$browser_exec`, before `if ! omarchy-cmd-browser-handoff "$browser_exec"`. | ~1456 | `sudo pacman -S --needed --noconfirm --ask 4 libfprint-git …` | the same with `--` before the package names | **retarget** the anchor. The guidance replacement is unchanged |
| ~2019 | `killOld='while timeout 5 quickshell kill …'` | `timeout 30`, plus a 30 s wait on `quickshell list -a -j` | **retarget** to `timeout 30`. Ours (#953) still refuses to start a second shell when the old one never exits, and upstream's wait then finds nothing |
| ~2025 | `for (( attempt = 0; attempt < 20; attempt++ ))` → a deadline | `deadline=$((SECONDS + 60))` | **retarget**: keep upstream's loop, and make its 60 read `${OMARCHY_SHELL_READY_TIMEOUT:-60}`, so #953's knob survives. Codex called this redundant; it is not quite, because it drops the knob |

The edits that still apply untouched are listed in the PR as the build's own
proof: the path list, the `chromium-browser.desktop` fallback and the
`chromium*` case.

### 3. `omarchy-browser.desktop` keeps its name (found here, not by codex)

v4.0.5 adds `applications/omarchy-browser.desktop` (`Exec=omarchy-launch-browser
%U`) and `config/hyprland-mimeapps.list`, which sends `x-scheme-handler/http(s)`
to it. nixarchy seeds the whole of `config/` (`modules/home.nix`, `seed_dir
"${omarchyPath}/config"`), so the list reaches `~/.config`. But
`default.nix:~1270` installs every upstream entry as `omarchy-$base`, so it
ships as `omarchy-omarchy-browser.desktop`. A link opened from an app on
Hyprland would then name an entry that does not exist.

- **Exempt `omarchy-browser.desktop` from the prefix.** The prefix exists so
  no package's entry can collide, and no package ships an entry with
  Omarchy's own name.
- **§2 probe, at build time:** after the install loop, every
  `<id>.desktop` named in `config/*mimeapps.list` must exist in
  `$out/share/applications`, or the build fails and names it. That is
  "anything we ship that names something else needs a check" (CLAUDE.md §2).

### 4. Runtime and ledger

- `procps` joins the runtime list (`pgrep`), for
  `omarchy-hyprland-session-lock-stranded`, which the lock plugin runs at
  start-up. It goes in both the function arguments and the list.
- `data/bin-ledger.nix`, as `bin-ledger` reported:
  - `omarchy-install-ai-hermes`: drop `allow = "systemctl-user"`, and reword
    it, because the unit stop moved to `omarchy-install-hermes-cli`;
  - `omarchy-install-hermes-cli` (new row, `vendor`, `allow = "systemctl-user"`):
    stops `omarchy-hermes-theme.service` on `--now` only;
  - `omarchy-install-openclaw-cli` (new row, `vendor`, `allow = "systemctl-user"`):
    stops, disables and queries the `openclaw-<role>` user units it installed;
  - `omarchy-launch-webapp`: reason reworded. The `env -u BROWSER` edit is
    gone, and the no-browser message is listed.
- `pkgs/AGENTS.md`: the web-app section (`#the-web-app-keybinding-upstream-breaks-and-the-one-word-fix`)
  and #953's restart section say what changed in 4.0.5.

### 5. What the release needs no port for

- **Remove › Browser.** v4.0.5 adds `sudo rm -f /etc/opt/{chrome,edge}/policies/managed/omarchy.json`
  to `omarchy-remove-browser`. Codex flagged it as reachable. It is not: every
  `remove.browser.*` row in the generated menu runs `nixarchy-app-disable`, or
  is hidden (Brave Origin). Measured on the built menu.
- **`omarchy-cmd-browser-handoff`** matches only `/usr/bin/<browser>`, so on
  NixOS it always exits 1, and the launchers fall back to launching the
  browser, as on v4.0.4. It is left as is. The speed-up it brings on Arch is a
  follow-up issue, not part of this bump.
- **The other new scripts:** `omarchy-hw-dell-xps13-dx13260-ptl` and
  `omarchy-hw-nvidia-display` read sysfs and call existing helpers.
  `omarchy-cmd-default-browser` needs `sed`, `awk` and `xdg-utils`, which are
  already listed.

## Alternatives rejected

- **Wait for the nightly to fix itself.** It cannot: every night's bump fails
  the same way.
- **Loosen any anchor to `--replace`.** The intent forbids it. A silent no-op
  is how a port drifts.
- **Drop #953's restart edits for upstream's.** Upstream still launches when
  its 30 s wait expires with the old shell alive. #953 is exactly the "no bar"
  case it fixed.
- **Patch the handoff's `/usr/bin` paths now.** It works without that, and the
  scope is a bump.

## Risks

- **Link handling** changes on Hyprland: links go through
  `omarchy-launch-browser`, as on Arch. An existing user's `~/.config` gets
  the new list on its next seed only where none exists (`seed_dir` never
  clobbers).
- `checks.session` boots a desktop and covers the lock screen and the shell.
  Link opening is not covered by any VM check. That gap goes in
  `tests/AGENTS.md`, and the build-time probe covers the name.
- Codex's survey read the diff. Any anchor it missed fails the build, which is
  why the build is the proof here.
