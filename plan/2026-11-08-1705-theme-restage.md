# Plan: a vanished or stale staged theme is put right on an existing home

## Decisions carried from the approved intent and spec

1. **Vanished theme, at every switch** (`modules/home.nix`, `activation.nixarchySeed`,
   the first-run theme block at `:1401-1414`). Name read with `$(<file)`,
   whitespace stripped. Empty or whitespace, or missing → first-run path
   (apply `cfg.defaultTheme`, no marker). Non-empty and a directory in neither
   `${omarchyPath}/themes/<name>` nor `~/.config/omarchy/themes/<name>` (`-d`,
   which follows a symlink) → fallback `cfg.defaultTheme` if it exists in
   either root, else `tokyo-night`, applied by the same headless
   `omarchy-theme-set` call and `PATH` as the first run.
2. **Success is three tests**: exit 0, `theme.name` now holds the new slug,
   and `~/.local/state/omarchy/current/theme/colors.toml` exists. On success:
   one stdout line `nixarchy: theme '<old>' no longer exists; applied '<new>' (#1705)`,
   then `run mkdir -p ~/.local/state/nixarchy`, the marker written to a temp
   file beside it, `run mv` into `~/.local/state/nixarchy/theme-fallback`
   (two lines: old, new). On failure: stderr line
   `nixarchy: could not apply '<new>' in place of vanished theme '<old>'; trying again at the next switch`,
   exit status of the block 0. A theme that exists: two `-d` tests, nothing else.
3. **The notice** is a post-boot hook `omarchy/hooks/post-boot.d/theme-fallback`,
   gated like its siblings on `osConfig.programs.nixarchy.enable or false`.
   Marker present → one `notify-send` ("Theme changed: '<old>' is no longer
   installed, so '<new>' is in use. Pick another with Super + Shift + Ctrl +
   Space."), and `rm` the marker only if `notify-send` exited 0.
4. **Staged code dropped once**: `1787481315` leaves `predates` for a row
   `decision = "ported"; run = "port";`, run by nixarchy's own script, not
   upstream's file (upstream's Tokyo Night branch is dropped; piece 1 owns
   vanished themes).
5. **Deviation from the approved spec, for sign-off with this plan.** The
   spec's port test, "the staged theme holds a refused file", cannot work:
   `omarchy-theme-set-templates` *generates* `hyprland.lua`, `neovim.lua`,
   `gum_env.lua`, `alacritty.toml`, `foot.ini`, `ghostty.conf` and
   `kitty.conf` into every staged theme (`share/omarchy/default/themed/`), so
   that test is true on every clean home and would restage all of them. The
   deny list applies only to a theme *installed from a repository*
   (`bin/omarchy-theme-set:432-433`). So the port refreshes only when the
   current theme is one: `src=~/.config/omarchy/themes/<name>`,
   `[[ ! -L $src && -d $src/.git ]]`, the same test upstream uses
   (`:356-360`). Bundled themes and plain user themes see nothing, which is
   the intent's third outcome. A repo-installed theme is refreshed once,
   whether or not its staged copy still holds code: the narrow cost of not
   being able to tell generated files from copied ones.
6. Mode A: everything sits inside `config = lib.mkIf cfg.enable`
   (`modules/home.nix:857`) or behind the hook gate. No coexistence fixture:
   no option a user sets is written.

## Steps

1. **The activation trigger** (`modules/home.nix:1401-1414`): replace the
   `if [ ! -e …/theme.name ]` block with decisions 1 and 2. Keep the
   first-run comment above it and the `PATH`/`OMARCHY_THEME_HEADLESS=1` call
   verbatim; it is the comment the step-4 `awk` anchors on. Shell variables in
   the Nix `''` string are written `''${var}` only where braces are needed;
   plain `$var` is literal there (§5). Every write goes through `run`.
   Verify: `nix fmt -- --ci`; `checks.home-activation-writes` still passes on
   today's cases.
   Traps: the editor hook may reformat `.nix` with `nixpkgs-fmt`; run
   `nix fmt` and read `git diff --stat` (§5). No `|| true` on the success
   path; the block must not fail the switch under `set -eu`.

2. **The notice hook** (`modules/home.nix`, beside
   `"omarchy/hooks/post-boot.d/user-migrations"` at `:2485`): decision 3.
   `PATH` from `lib.makeBinPath [ pkgs.libnotify pkgs.coreutils ]`, as its
   siblings build theirs. `#!/usr/bin/env bash` like the siblings (it runs on
   the host, not in a sandbox).
   Verify: `nix fmt -- --ci`; `nix eval` of the vm's home
   `xdg.configFile."omarchy/hooks/post-boot.d/theme-fallback".text` succeeds.

3. **The port** (`pkgs/omarchy/user-migrations/1787481315.sh` new,
   `pkgs/omarchy/user-migrations.nix` `port)` arm, `data/user-migrations.nix`):
   - the script: echo its title line as upstream's do; read `theme.name` as
     in decision 1 (exit 0 if missing or empty); `src=$HOME/.config/omarchy/themes/$name`;
     `[[ ! -L $src && -d $src/.git ]] || exit 0`; then `omarchy-theme-refresh`.
     It runs under the runner's `bash -euo pipefail`.
   - the `port)` arm dispatches by id: `1791479273` → the existing
     `omarchy-migrate-dictation-default`; `1787481315` → `${./user-migrations/1787481315.sh}`
     copied into `$out/scripts`; any other id → `exit 1` with a message.
   - the ledger: remove `"1787481315"` from `predates`, add the row with
     reason "re-stage a repository-installed theme once, so staged code from
     an older install is dropped (#1705)".
   - two lines in `pkgs/AGENTS.md`'s user-file-migrations section naming the
     second port and why it is not upstream's file.
   Verify: `checks.user-migrations-ledger`, `checks.user-migrations` (today's
   cases), `checks.grep-q-pipefail`.
   Traps: `grep -q` under `pipefail` (`checks.grep-q-pipefail`, memory); a new
   file must be `git add`ed before a flake sees it (§5).

4. **Activation and hook cases** (`tests/home-activation-writes.nix`, after
   the #1342 section): the block from the first-run theme comment to its
   closing `fi`, taken from `nixarchySeed`'s generated text, with
   `omarchy-theme-set`'s store path rewritten to a stub that records its
   argument and, unless told to fail, writes `theme.name` and
   `current/theme/colors.toml`. Run under `set -eu`, `$HOME` and both theme
   roots as fixture directories. The spec's eight cases:
   1. missing, empty, whitespace `theme.name` → default applied, no marker;
   2. exists in `$OMARCHY_PATH/themes` → no call, no marker, no output;
   3. exists in `~/.config/omarchy/themes` → no call;
   4. vanished, `defaultTheme` set to a non-`tokyo-night` theme and both
      existing → `defaultTheme` applied, marker old/new, log line;
   5. vanished, `defaultTheme` vanished too → `tokyo-night`;
   6. stub exits 1 → stderr line, block exits 0, no marker; stub exits 0
      without `colors.toml` → the same;
   7. `DRY_RUN=1`, vanished → no marker, no `~/.local/state/nixarchy`, no
      success line;
   8. a resolving symlinked theme dir → no call; a dangling one → repaired.
   And the hook, with a recording `notify-send`: marker → one call, marker
   gone; failing `notify-send` → marker kept; no marker → no call.
   `defaultTheme` comes from the vm's evaluated home; case 4 extends the vm
   with `programs.nixarchy.defaultTheme` set as the file already extends it
   for `defaultAgent` (`:16-18`).
   Verify: `checks.home-activation-writes` passes.
   Traps: every failure via `bad`, never `! grep`; `printf` not a heredoc
   inside the `''` string (§5, nixfmt reindent).

5. **Port cases** (`tests/user-migrations/run`, a `case_1705` beside
   `case_1677`, and its call in the case list at `:776`): staged theme from a
   repo (`~/.config/omarchy/themes/x/.git` present) → `omarchy-theme-refresh`
   stub called once; a bundled theme → not called; a user theme with no
   `.git` → not called; missing `theme.name` → not called. The migration
   marker is set in all four. Use the existing `run_ids` helper and
   `calls.log`.
   Verify: `checks.user-migrations` on `main`'s pin, and cherry-picked onto
   the edge carry under quattro (#1709).

6. **Run, break, commit, PR** (session): cheap tier first (fmt, statix,
   deadnix, `grep-q-pipefail`, `test-registration`, both ledgers,
   `user-migrations`, `home-activation-writes`), `options-*` shards when the
   VM gate is free (the module changed). §1 breaks, each shown failing:
   - drop the vanished trigger → case 4;
   - swap the fallback order → case 4;
   - drop the `colors.toml` test → case 6 second half;
   - drop the hook's success guard on `rm` → failing-notify case;
   - drop the port's `.git` test → bundled-theme case;
   - restore `1787481315` to `predates` → the repo-theme case.
   One commit per step; PR `Closes #1705` with the three artifacts, and
   "@codex review"; squash.
