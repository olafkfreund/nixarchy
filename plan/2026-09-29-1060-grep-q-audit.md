# Plan: No check or script fails because grep found what it was looking for

Line numbers below were re-read on `d4f986f` (the spec's approval commit,
same tree as `main` at `a242d6d`). They will drift as you edit: **find each

## Approved decisions

- **Rewrite 30 sites, allowlist 65.** The 29 exposed sites plus
  `pkgs/omarchy/default.nix:953` are rewritten so nothing pipes into
  `grep -q`. The other 65 stay as they are, each listed in
  `tests/grep-q-allowlist.txt` with the reason it cannot fail on a match. (The
  audit said "66 safe"; that count included `:953`, which is rewritten.)
- **Rewrite forms, and nothing else:**
  - a variable and fixed text: `[[ $v == *'text'* ]]`;
  - a variable and a regex (`-E`, `-x`, `^`, `\b`, `-i`): `grep -q… 'pat' <<<"$v"`;
  - command output: capture it first (`out=$(cmd)`), then one of the above;
  - a VM driver string: `"out=$(CMD); grep -q 'PAT' <<<\"$out\""`.
- **Each site keeps its meaning:** the same pattern, the same polarity and the
  same failure message. Two deliberate changes of meaning, both from the spec:
  - `pkgs/verify.sh`: a failed or timed-out `nix-store --print-roots` reports
    "could not list GC roots" (a `hmm`), not "not a GC root".
  - `release.yml`: a `gh` failure while listing assets fails the step under
    `set -e`, rather than reading as "asset missing". The second check
    re-fetches after the uploads.
  - One more, chosen here: `tests/wifi-hwsim.nix:128` becomes
    `machine.succeed("…; ! grep -q …")` rather than staying `machine.fail`.
    `machine.fail` passes on *any* failure, a failed `journalctl` included;
    the `!` form passes only on "ran, and did not find it".
- **The guard: `checks.grep-q-pipefail`,** in a new `tests/grep-q-pipefail.nix`.
  - It is a `runCommand` over a `lib.fileset` copy of `tests/`, `modules/`,
    `pkgs/`, `installer/`, `.github/` and `flake.nix`.
  - It scans `*.nix`, `*.sh` and `*.yml` for a pipe into `grep` with `-q`,
    `--quiet` or `--silent` in its flags, excluding `||`. It skips lines whose
    trimmed text starts with `#`, which are prose.
  - It compares the matches with the allowlist, keyed on path plus the exact
    trimmed line text. **One allowlist entry is one occurrence:** a line that
    appears twice in one file is listed twice. The comparison is a multiset
    one (`sort` then `comm`, which pairs duplicates one for one).
  - It fails both ways, naming each offender: NEW (in the tree, not listed,
    shown with its line number) and STALE (listed, not in the tree).
  - It refuses a malformed allowlist line (not three tab-separated fields, or
    an empty reason). It refuses fewer than 50 matches, because a broken scan
    must not read as a clean tree.
  - It is wired through `uniformChecks` in `flake.nix`, so the coverage step
    builds it on pull requests with no workflow edit (§4).
- **`tests/demo/screencast/shot-coverage.sh:52` belongs to #1062,** and this
  PR does not rewrite it. At the time of writing, #1062 is an open **issue**
  with no pull request. Step 1 decides how to handle it.
- **Docs:** `tests/AGENTS.md#a-pipe-into-grep-q-can-fail-because-grep-matched`
  gains the masking form, where pipefail holds, the 4 KiB rule, and the guard.
  The existing advice there to "drop `-q` and send the output to `/dev/null`"
  is removed: the spec rejected it (GNU grep's read-to-EOF is an
  implementation detail, and the dev host's `grep` is ugrep).

### Corrections to the audit, measured while writing this plan

None changes an approved decision; the PR states them.

1. **GitHub Actions does not always have pipefail.** A `run:` step with no
   `shell:` runs `bash -e {0}`. Only an explicit `shell: bash` runs
   `bash --noprofile --norc -eo pipefail {0}`. None of the three workflows
   sets `shell:` or `defaults.run.shell`.
   - `release.yml`'s step sets `set -euo pipefail` itself (line 462), so it
     is exposed.
   - `build.yml:390` (the "Every check is run by some workflow" step) and
     `nightly.yml:300` have **no pipefail today**, so they cannot fail this
     way now.
   - They are still rewritten as approved. The change is harmless, and it
     protects the day someone adds `set -o pipefail` to either step.
     `build.yml:448` is allowlisted with that reason.
2. **The NixOS test driver** (pinned nixpkgs,
   `nixos/lib/test-driver/src/test_driver/machine/__init__.py:986`) runs
   `bash -c {shlex.quote("set -euo pipefail; " + command)}`.
   - `shlex.quote` means a driver string needs **no extra shell escaping**
     beyond what Python already requires: `\"` for a double quote inside a
     Python `"…"` literal.
   - The testScripts are Nix `''…''` strings. `$(`, `$out` and `\"` pass
     through untouched. Only `${` (write `''${`) and `''` are special, and no
     rewrite below contains either.
3. **`checks.wifi-hwsim` runs on pull requests** (build.yml's claimed KVM
   job), not only nightly. `install-iso-net` is nightly-only. `demo` is a
   package that no workflow builds (§4).
4. **`session.nix:738`** is not inside `su -c`: `as_user(…)` closes its quote
   before the `+ " | grep -qx loaded"`. It is still safe, because
   `systemctl show` prints one word, and its allowlist reason says so.

4. **`tests/grep-q-pipefail.nix`** (new). No heredocs (§5). Messages never
   contain a pipe into `grep -q`, or the guard would flag its own file.

   ```nix
   { pkgs, ... }:
   # #1060: a pipe into grep -q can fail because grep matched (#1058). Every
   # such line in the tree is either rewritten or listed, with the reason it
   # cannot fail, in tests/grep-q-allowlist.txt. This fails on a new one and
   # on a listed one that is gone. Why: tests/AGENTS.md#a-pipe-into-grep-q-can-fail-because-grep-matched
   let
     inherit (pkgs) lib;
     src = lib.fileset.toSource {
       root = ../.;
       fileset = lib.fileset.unions [
         ../tests
         ../modules
         ../pkgs
         ../installer
         ../.github
         ../flake.nix
       ];
     };
   in
   pkgs.runCommand "nixarchy-grep-q-pipefail" { } ''
     cd ${src}
     allow=tests/grep-q-allowlist.txt
     work=$(mktemp -d)

     rc=0
     grep -rnE --include='*.nix' --include='*.sh' --include='*.yml' \
       '(^|[^|])\|[[:space:]]*grep( +-[-a-zA-Z0-9]+)* +(-[a-zA-Z]*q|--quiet|--silent)' \
       tests modules pkgs installer .github flake.nix >"$work/hits" || rc=$?
     [ "$rc" -le 1 ] || { echo "grep failed (exit $rc), so nothing was scanned" >&2; exit 1; }

     # path TAB trimmed text TAB line number. A comment is prose, not a pipeline.
     awk '{
       p = index($0, ":"); path = substr($0, 1, p - 1); rest = substr($0, p + 1)
       q = index(rest, ":"); ln = substr(rest, 1, q - 1); text = substr(rest, q + 1)
       sub(/^[[:space:]]+/, "", text); sub(/[[:space:]]+$/, "", text)
       if (text ~ /^#/) next
       print path "\t" text "\t" ln
     }' "$work/hits" >"$work/found"

     n=$(wc -l <"$work/found")
     [ "$n" -ge 50 ] || { echo "only $n sites found: the scan is broken, not the tree clean" >&2; exit 1; }

     awk -F'\t' '/^#/ || /^$/ { next } NF != 3 || $3 == "" { print "malformed: " FILENAME ":" FNR }' "$allow" >"$work/malformed"
     if [ -s "$work/malformed" ]; then cat "$work/malformed" >&2; exit 1; fi

     # One entry per occurrence; comm pairs duplicates one for one.
     export LC_ALL=C
     cut -f1,2 "$work/found" | sort >"$work/have"
     awk -F'\t' '/^#/ || /^$/ { next } { print $1 "\t" $2 }' "$allow" | sort >"$work/want"
     comm -23 "$work/have" "$work/want" >"$work/new"
     comm -13 "$work/have" "$work/want" >"$work/stale"

     fail=0
     if [ -s "$work/new" ]; then
       echo "NEW: a pipe into grep -q that nobody has reviewed. Rewrite it, or allowlist it in $allow with a reason:" >&2
       awk -F'\t' 'NR == FNR { new[$0] = 1; next } ($1 "\t" $2) in new { print "  " $1 ":" $3 ": " $2 }' "$work/new" "$work/found" >&2
       fail=1
     fi
     if [ -s "$work/stale" ]; then
       echo "STALE: allowlisted in $allow, but no longer in the tree. Delete the entry:" >&2
       sed 's/^/  /' "$work/stale" >&2
       fail=1
     fi
     [ "$fail" = 0 ] || exit 1
     echo "$n pipes into grep -q, each one allowlisted with its reason"
     touch $out
   ''
   ```

   Notes:
   - Everything it calls (coreutils, grep, gawk, sed) is in stdenv, so there
     are no `nativeBuildInputs`.
   - `\t` inside `''…''` reaches awk as a literal backslash-t, which is what
     awk wants.
   - The regex contains no `${` and no `''`.
   - Prototyped outside Nix against this tree with the allowlist above. It
     reported exactly the 30 sites plus shot-coverage.sh as NEW, and nothing
     STALE.

6. **`tests/AGENTS.md`.**
   - In the section `## A pipe into \`grep -q\` can fail because grep matched`,
     replace its last paragraph ("It only bites where **both** hold: …
     not obviously under `pipefail`.") with the text below.
   - In "Working here", bullet "`printf '%s' "$x" | grep -q` is a race…",
     replace "Use `<<<"$x" grep -q`, or drop `-q` and send the output to
     `/dev/null` so grep reads everything." with "Use `grep -q … <<<"$x"`
     or `[[ $x == *…* ]]` (the section above has the forms; relying on grep
     reading to EOF without `-q` is an implementation detail, and ugrep is
     not GNU grep)."

   ````markdown
   It only bites where **both** hold: `pipefail` is on, and the producer can
   write after the matching line. #1060 read every one of the hundred sites
   rather than assuming. Where `pipefail` holds:

   - **on:** stdenv builders (`runCommand`, every phase: `setup.sh` sets it and
     never restores it); `writeShellApplication`; the NixOS test driver, whose
     `succeed`, `fail`, `execute` and `wait_until_succeeds` all run
     `bash -c 'set -euo pipefail; …'`; a workflow step that says
     `set -o pipefail`, or has `shell: bash` spelled out.
   - **off:** a pipe inside `su user -c '…'` or `sh -c '…'` (a fresh shell);
     a GitHub Actions `run:` with no `shell:`, which is `bash -e {0}`.

   And when the producer can write after the match:

   - bash's `printf` and `echo` write once per line;
   - an external tool buffers, and writes in 4 KiB blocks, so output under
     4 KiB is a single write at exit and cannot be cut off by an early exit;
   - `gh` writes line by line, and `journalctl` is unbounded: always capture.

   **The masking form is the worse one.** Under `! … | grep -q x`,
   `… | grep -q x && fail`, or `machine.fail("… | grep -q x")`, a match
   followed by SIGPIPE turns into a **pass**, with `x` present:

   ```sh
   $ bash -c 'set -o pipefail; ! { printf "x\n"; sleep 0.2; printf "y\n"; } | grep -q x; echo rc=$?'
   rc=0
   ```

   In a VM driver string, capture and use a here-string:
   `"out=$(journalctl -u foo); grep -q 'PAT' <<<\"$out\""`. The driver
   `shlex.quote`s the whole command, so nothing else needs escaping.

   **`checks.grep-q-pipefail` enforces this.** Every pipe into `grep -q`
   under `tests/`, `modules/`, `pkgs/`, `installer/`, `.github/` and
   `flake.nix` is either rewritten or listed in `tests/grep-q-allowlist.txt`
   as `path<TAB>the line, trimmed<TAB>why it cannot fail`. The key is the
   line's text, not its number, so unrelated edits do not touch it. The
   check fails on a new line (rewrite it, or list it with a measured reason)
   and on an entry whose line is gone (delete it). It does not read
   reasons: an entry with a wrong reason is a review failure, not a check
   failure (see "An inventory check cannot check its own reasons" above).
   ````
