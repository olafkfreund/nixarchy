# Intent: edge adopts quattro 255acd9 (Qt theming through qtengine, Papers for Evince)

## Problem

Edge is held on quattro `d9cc361` (#1736). The edge run on 2026-11-10 tried
`df3d01c` and stopped at two failures. 148 more checks did not run, because
each depends on one of the two:

1. **`omarchy-edge-20261110-df3d01c` does not build.** `pkgs/omarchy/default.nix:508`
   replaces upstream's `omarchy pkg-add podman crun` block in
   `bin/omarchy-agent-local` with nixarchy's preflight. It uses `--replace-fail`
   against `pkgs/omarchy/agent-local-use.upstream.sh`. Upstream rewrote that
   block: a `run=` array, and a `--detach` branch that opens a terminal to
   install the packages before running the setup detached. The old text matches
   nothing.
2. **`checks.user-migrations-ledger` refuses** two new migrations that touch
   user files and have no row in `data/user-migrations.nix`:
   - `1792902457` installs `qtengine`, seeds `~/.config/qtengine/config.json`
     and runs `omarchy-theme-refresh`.
   - `1794165002` installs `papers`, rewrites Evince associations in
     `~/.config/mimeapps.list` to Papers, and drops `evince`.

Upstream has since moved to `255acd9`, one commit later (notifications). The
same range carries more that the run never reached, because the build stopped
first:

- **Qt theming.** `default/hypr/envs.lua` sets `QT_QPA_PLATFORMTHEME=qtengine`
  (it was `gtk3`). There is a new `bin/omarchy-theme-set-qt`, a new
  `config/qtengine/config.json`, and `install/user/theme.sh` runs it.
- **The package lists.**
  - `omarchy-base.packages` adds `papers` and `qtengine`, and drops `evince`
    and `xorg-xsetroot`.
  - `omarchy-other.packages` renames the Surface Pro 11 and ProArt P14
    packages, and adds `ath12k-board-fallback`.
  - `checks.omarchy-package-ledger` needs a row for each.
- **New scripts.** `omarchy-hibernation-encrypted`, `omarchy-theme-set-qt`
  and the hardware script `fix-ath12k-board-data.sh` are new; the bin ledger
  classifies every script.
- **Other migrations.** `1793663784`, `1793809102` and `1794088337` are new,
  `1793512402` is removed and `1790973240` changed. The ledger flagged only
  two, so the others touch no user files by its grep. That is to be confirmed
  by reading them. None of the five has a row in `data/user-migrations.nix`
  (checked), so none leaves a stale row.

## Proposed outcome

- Edge moves to quattro `255acd9`, or the newest commit when the carry is made.
  Its checks pass, and #1736 closes.
- On a nixarchy machine, Qt apps take the theme through qtengine as they do on
  Omarchy. If qtengine cannot work on NixOS, Qt keeps the GTK platform theme,
  the env line is left out, and the reason is recorded in the ledger.
- Papers is the document viewer, and opening a PDF opens it. Evince leaves the
  default install.
- The ledgers reconcile with the new pin: every new migration, package and
  script has a row with a reason naming what nixarchy does instead of the Arch
  step. Rows for removed or renamed packages are dropped or renamed: `evince`,
  `xorg-xsetroot`, `asus-proart-p14-speaker-firmware` and the old Surface
  Pro 11 names. The ledger fails a row whose name no list has any more.

## Affected users and systems

- **Edge only, until edge's next merge into `main`.** `main` pins the v4.5.0
  tag, which has none of this. Every edge machine is affected, including p620
  and razer. Today they run `9774fcd`, which is quattro `d9cc361`.
- **An `edge-candidate` carry**, as for #1684: the ledger rows name packages
  and migrations that only the quattro pin has, so they cannot land on `main`
  first.
- **Qt apps on every edge desktop.** Their look changes if qtengine is adopted.

## Constraints

- **§8: a carry that classifies a new quattro commit also pins it.** That is
  the rows, both copies in `flake.nix` (the input `url` and `omarchyVersion`),
  and `flake.lock`, then a `from_candidate=true` dispatch.
- **Mode A.** Nothing new reaches a configuration that has not turned
  nixarchy on.
- **A migration ported here must keep the user's own file.**
  - Upstream's qtengine seed already skips an existing config.
  - The Papers rewrite runs `sed -i --follow-symlinks` on
    `~/.config/mimeapps.list`. On a home-manager machine that file can be a
    link into the store, and there the write fails with a read-only error and
    aborts the migration. Through a link into a dotfiles checkout, it edits a
    tracked file. #1304's lesson applies: test `-L` before the content.
- **`~/.config/qtengine/config.json` must stay writable.**
  `omarchy-theme-set-qt` rewrites its `iconTheme` on every theme switch. A
  copy seeded from the store keeps the store's read-only mode unless the seed
  sets the mode, and theme switching would then fail.
- **Qt apps here are wrapped.** nixpkgs' Qt apps get their plugin path from
  `wrapQtAppsHook`, so installing `qtengine` does not by itself put its
  platform-theme plugin where they look. And if Qt cannot load the plugin
  `QT_QPA_PLATFORMTHEME` names, it does not fall back to `gtk3`: the app is
  left unthemed.
- **No patch for what upstream should fix.** Anything about how Omarchy itself
  behaves goes upstream, and nothing is filed there without the owner's say-so.
- **Run every edge check locally before pushing the carry** (§6 tiers), with
  the VM tier gated on idle runners.

## Open questions

1. **Qt theming: adopt qtengine, or keep `gtk3`?** nixpkgs has `qtengine`
   0.2.3. The decision rests on one measurement: in `checks.session`, a
   packaged Qt 6 app loads qtengine and takes the theme's colours. A plugin
   that is merely present on a path proves nothing. Recommendation: aim for
   qtengine and run that measurement in the spec. If it passes, switch the env
   line. If it cannot pass, keep `gtk3`, give `qtengine` a `skip` row with the
   reason, and do not port migration `1792902457`'s config seed.
2. **Papers for Evince: what happens to a user-managed `mimeapps.list`?**
   Upstream drops `evince` from the list, and the ledger fails a stale row, so
   replacing Evince is the only option the ledger allows. What is open is the
   migration. Recommendation: install `papers` where its desktop file reaches
   `XDG_DATA_DIRS`. Rewrite only a regular, writable `~/.config/mimeapps.list`,
   changing the Evince entries and nothing else. Leave a symlinked one alone,
   and log that it still names Evince.
3. **The `--detach` agent-local path.** Upstream now opens a terminal to
   install podman when the setup starts from the agents panel. nixarchy
   installs nothing at run time, so the preflight's error would go to a
   detached process nobody sees. Recommendation: keep the preflight on every
   `use`, wherever `--detach` sits in the arguments. When it passes, run the
   setup exactly as upstream does with no extra terminal. When it fails in a
   detached run, open the same floating terminal to show the error.

## Decisions (owner, 2026-11-10)

Approved with every recommendation as written: aim for qtengine and decide on the `checks.session` measurement (Q1); replace Evince, rewriting only a regular writable `mimeapps.list` (Q2); keep the preflight on every `use`, with a terminal only for a failed detached run (Q3).
