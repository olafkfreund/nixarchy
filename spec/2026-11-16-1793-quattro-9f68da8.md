# Spec: edge adopts quattro 9f68da8

Line numbers refer to `edge` at `8057e78e` unless a path says otherwise.
Upstream paths refer to quattro `9f68da8`.

## Design

The carry is one branch off the current `origin/edge`, pushed to
`edge-candidate` and dispatched with `from_candidate=true` (CLAUDE.md §8).
It must not branch off an older `edge`. A trial branched off an `edge`
that predates the #1792 merge showed the writer lock as "removed" in its
diff. It has six parts.

### 1. The pin

- `flake.nix:82`: the omarchy input becomes
  `github:basecamp/omarchy/9f68da882545cf4aae8a6c15cce06fada0f116dd`.
- `flake.nix:436`: `omarchyVersion = "edge-20261116-9f68da8"`.
- `flake.lock`: `nix flake lock --update-input omarchy`.

### 2. Patches and substitutions that stopped applying

Each was found by a trial build, one failure at a time. The list is
complete once `.#omarchy` builds; see Verification.

- **`pkgs/omarchy/1625-no-mise.patch`, the `bin/omarchy-agent-account-add`
  hunk.** Upstream replaced the `mise use -g` block with `install_cli` (a
  progress parser for the agents panel), `cli_missing` (`mise where`, then
  a PATH search without mise's shims) and an `if cli_missing` block that
  installs through mise.
  - The new hunk deletes all three and keeps nixarchy's refusal:
    `if PATH=$(omarchy-agent-real-path) omarchy-cmd-missing "$provider";
    then fail "$name is not installed. Install it with: omarchy default
    agent $provider"; fi`.
  - Nothing else in the file calls `install_cli` or `cli_missing`, and the
    patched file names `mise` nowhere.
  - The new `install_launcher`, the "ready to code" notification and
    `omarchy-agent-logo` are kept as upstream wrote them.
- **`pkgs/omarchy/1659-system-authorise-first.patch`, `bin/omarchy-system`
  hunks 1-2.** Upstream added a `firmware` action
  (`systemctl reboot --firmware-setup --no-wall`), a
  `CanRebootToFirmwareSetup` precheck, a delayed OSD, and a status check
  on the final command.
  - The patch's idea is kept: logind authorises a shutdown when it is
    scheduled, before any window closes.
  - The new hunk 1 schedules the action's whole command,
    `"${command[@]}" --when=+5s || return $?`, for every action except
    logout. It goes after the firmware precheck and before the delayed
    OSD, so `firmware` keeps `--firmware-setup`.
  - The new hunk 2 runs the command at the end only for logout:
    `if [[ $action != "logout" ]] || "${command[@]}"; then`. Upstream's
    wait-for-OSD and failure branch are otherwise unchanged.
  - Hunk 3 (`systemd-run`'s `ExecStopPost` notification) applies at an
    offset. It is regenerated so it applies cleanly.
- **`pkgs/omarchy/default.nix:2122`, Menu bug 2 (#1305).**
  `openExistingMenu` now starts with `altHeld = false` (for Alt variants
  such as firmware setup). The anchor and its replacement both gain that
  line, and `root.releaseDisplacedRequest()` still runs before
  `requestSerial += 1`.
- **`pkgs/omarchy/default.nix:1582-1584`, the desktop-icon guard (#1776).**
  App icons are no longer templates under `default/themed/icons/`. They are
  icon sets under `icons/<set>/`, and the default set is `papercraft`
  (`omarchy-icons-current`). The guard accepts
  `icons/papercraft/$icon.svg.tpl` or `.svg`.
  - Under the `original` set, an app without a hicolor icon shows none.
    That is upstream's behaviour on Arch too, so it is not guarded.

- **Checks that encoded imv/mpv.** These are found by the trial's
  generated run. Each describes something upstream removed, not a
  regression (§1, read backwards):
  - `data/etc-overlay.nix`'s `mpv/mpv.conf` row gains `edge = "absent"`,
    because quattro no longer ships `etc/mpv/mpv.conf`.
    `modules/nixos.nix:62` (`installedEtc`) selects rows by `class` alone,
    so on edge it would still point `environment.etc."mpv/mpv.conf"` at a
    file the package lacks. It gets the same `edge` filter
    `tests/etc-overlay.nix:30-32` applies, using the package's version
    prefix (`edge-`). Verified by an edge `vm-toplevel` build and by
    `options-*`, not by the ledger check alone;
  - `tests/remove-preinstalls.nix:70` copies `mpv.desktop` as a stock
    launcher that must survive. Upstream removed that file, so the fixture
    uses `foot.desktop`, which both pins ship. That keeps one line for
    both branches (§8).

### 3. Omaview

- **New `pkgs/apps/omaview.nix`.** Omaview v0.1.0 from `omacom/omaview`,
  MIT.
  - It is built with `cmake` and `qt6.wrapQtAppsHook`, on qtbase,
    qtdeclarative, qtmultimedia, qtimageformats (HEIF/AVIF/JXL), qtwayland,
    wayland and wayland-protocols.
  - Upstream's `install()` rules place the binary, `omaview.desktop` and
    the hicolor SVG.
  - `passthru.updateScript` matches folio's. `pkgs/review.sh` gains the
    pin row `omaview	pkgs/apps/omaview.nix	omacom/omaview`, and
    `tests/review-pins.nix` adds it to `expected`.
  - The trial build succeeded (`/nix/store/yiia8amd…-omaview-0.1.0`).
- **The flake.** `omaview` joins the overlay's `nixarchy-apps` (`flake.nix`,
  beside `folio = final.callPackage ./pkgs/apps/folio.nix { };`), the
  `pkgs/omarchy` call's `inherit (final.nixarchy-apps)` list, and the
  exported packages list.
- **The runtime list** (`pkgs/omarchy/default.nix`):
  - `hasOmaview = builtins.elem "omaview" basePackages`, mirroring
    `hasFiles`;
  - `(if hasOmaview then omaview else imv)` replaces `imv` at :315, so
    `main`'s tag pin keeps imv;
  - `mpv` stays (`owe` plays video wallpapers through it, and upstream
    keeps it);
  - `ffmpeg` (:244) already provides `ffplay`, which the webcam overlay now
    runs. Verification checks this by name;
  - `librsvg` joins the list for `rsvg-convert`, which
    `omarchy-icons-preview` requires (:28) and runs (:53) for a set without
    a prebuilt preview.
- **Upstream's `default/applications/mimeapps.list` is not read here.**
  Arch installs it as `/usr/share/applications/mimeapps.list`. nixarchy
  never installs it, and sets defaults through
  `xdg.mime.defaultApplications` instead. So the guard at
  `pkgs/omarchy/default.nix:1307` is not widened. That file also names
  `google-chrome.desktop` and `HEY.desktop`, which are adapted elsewhere,
  and a widened guard would fail on them for reasons unrelated to
  Omaview.
- **nixarchy's own MIME defaults** (`modules/nixos.nix:2418-2432`):
  - a new `passthru.mediaViewerDesktop = if hasOmaview then
    "omaview.desktop" else null`, beside `fileManagerDesktop` (:2199);
  - when it is non-null, the 45 image, video and audio types upstream's
    list gives Omaview map to it, through the same `mkDefault` as the rest.
    The list is copied into the module, since it is short and readable;
  - when it is null (`main`'s tag pin), the six `video/* = "mpv.desktop"`
    rows stay as they are;
  - `tests/session.nix:2219` expects `video/mp4` from the same passthru
    (`omaview.desktop` on edge, `mpv.desktop` on `main`), as `text/plain`
    already does from `hasPlain`;
  - an evaluation assertion checks that `mediaViewerDesktop`, when set,
    exists in the system's `share/applications`. A missing Omaview fails
    the build there (§1: proven by dropping Omaview from the runtime
    list).
- **The package ledger** (`data/omarchy-packages.nix`, as
  `checks.omarchy-package-ledger` asked in the trial):
  - `"omaview" = { edge = "only"; nix = "nixarchy-apps.omaview"; }`;
  - `imv`, `mpv` and `mpv-mpris` gain `edge = "absent"`, because quattro's

    regardless, for owe;
  - `"microsoft-surface-snapdragon-addresses" = { edge = "only"; skip =

### 4. Folio 0.5.0 and the file chooser

- **`pkgs/apps/folio.nix` moves to v0.5.0.** Upstream switched from qmake to
  CMake, with no `install()` rules (`CMakeLists.txt`). Its Qt components are
  Core Gui Qml Quick QuickControls2 DBus Concurrent Test, plus `gio-2.0` and
  `gio-unix-2.0`.
  - The derivation moves to `cmake` and keeps an explicit `installPhase`,
    which installs:
    - `bin/folio`;
    - `share/folio.desktop` and `share/folio-chooser.desktop`;
    - `share/folio.svg` (hicolor);
    - `plugins/` into `share/folio/plugins`;
    - `share/folio.portal` into `share/xdg-desktop-portal/portals/`;
    - `share/org.freedesktop.impl.portal.desktop.folio.service` into
      `share/dbus-1/services/`, with `Exec=/usr/bin/folio chooser` rewritten
      to `$out/bin/folio chooser`.
  - **Plugins:** `src/plugins.cpp:172-176` reads `FOLIO_PLUGINS_PATH`, else
    `/usr/share/folio/plugins`. The default is substituted to
    `$out/share/folio/plugins` with `--replace-fail`, so the build stops if
    upstream moves it.
  - `libarchive` leaves `buildInputs` (0.5.0 links gio and zlib only).
    `glib` and `zlib` stay.
  - Its plugins (Dropbox, LocalSend, Tailscale) are shell scripts that call
    those tools when present, as upstream ships them. Nothing is added to
    the runtime list for them.
  - Folio is MIT, so it stays in the public cache.
  - The trial build succeeded. Its output has the portal file, the D-Bus
    service with `Exec=<store>/bin/folio chooser`, both desktop entries and
    the three plugins.
- **Registering the portal.** The package gains
  `passthru.fileManager = if hasFiles then folio else null`. No such
  attribute exists today; `hasFiles` and `fileManagerDesktop` do.
  `modules/nixos.nix:2440`'s `extraPortals` appends it when it is non-null.
  - NixOS's `xdg.portal` module links each extra portal's
    `share/xdg-desktop-portal/portals` and adds it to
    `services.dbus.packages`, which installs the `.service` file.
- **The migration's line.** `config/xdg-desktop-portal/hyprland-portals.conf`
  now ships `FileChooser=folio;gtk`. Seeded homes get it from the package.
  Migration `1794775358` adds it to existing homes and is ported as
  upstream wrote it (`run = "upstream"`).
- **Proving it works** (the approved intent: "names FileChooser with a
  working D-Bus activation... If that cannot be made to work, the GTK
  chooser stays"). `checks.session` sends an `OpenFile` request through
  `org.freedesktop.portal.Desktop` with `gdbus`, sees a `folio` process
  start under the portal's D-Bus activation, then cancels the request and
  sees the `Response` signal.
  - If the session harness cannot get there, the carry does not register
    Folio's portal and does not port `1794775358`, and GTK stays. That
    decision is recorded here before the plan is approved.
  - No claim is made that xdg-desktop-portal falls back to GTK when Folio
    misbehaves. It falls back only when the backend cannot be activated.

### 5. `omarchy-install-browser-extensions`

`omarchy-default-browser:48` runs it with `--check`, and it aborts a
browser choice when the repair fails (:55). On NixOS:

- **Chrome's extensions policy is declared** by
  `environment.etc."opt/chrome/policies/managed/omarchy-extensions.json"`
  (`modules/nixos.nix:1791`). The policy is current after any rebuild.
- **The directory is not hardened by design.**
  `chrome_policy_current` also requires the directory and its parents to
  be root-owned and not writable by others (`browser_policy_dir_hardened`,
  `install/helpers/browser-policy.sh:48-60`). With `browserThemeUser`
  set, nixarchy owns those directories by that user
  (`modules/nixos.nix:2008-2017`), so the check would always fail and every
  browser choice would try to repair.

So:

- **`chrome_policy_current` asks only whether the declared file exists.**
  Ownership and content are not compared. The file is
  `filteredBrowserPolicy`'s output (`modules/nixos.nix:12-22`), which drops
  every key the administrator sets through `programs.chromium.extraOpts`.
  A byte comparison with upstream's file would therefore fail forever on a
  machine that overrides `ExtensionInstallForcelist`, and every browser
  choice would refuse. The function body is replaced with a
  `--replace-fail` on its three lines, and the replacement is
  `[[ -e $chrome_policy_dir/omarchy-extensions.json ]]`.
- **The Chrome repair branch.** If the file is missing (a pin without
  `passthru.chromeExtensionsPolicy`, or before a rebuild), it says the policy comes from the system
  configuration and exits 1. It never runs `browser_policy_setup_dir` or
  writes under `/etc`. `omarchy-default-browser` then stops the choice with
  that message, which is correct, because Chrome would not load the
  extension yet.
- **Chromium, Brave and Edge.** `repair_flags` writes the user's own flags
  file, and the native-messaging hosts come from
  `omarchy-install-chromium-copy-url`/`-ytdlp` (already adapted,
  `pkgs/omarchy/default.nix:974-977`). Both stay as upstream wrote them.
- **The bin ledger** (`data/bin-ledger.nix`) gets a row for the command.
  `data/user-migration-commands.nix` gets
  `"omarchy-install-browser-extensions" = { edge = "only"; follow = true;
  reason = "repairs --load-extension in ~/.config/<browser>-flags.conf and
  the native-messaging hosts under ~/.config/<profile>"; }`.

## Alternatives rejected

- **Keep imv/mpv and rewrite upstream's `mimeapps.list`, `system.lua`
  rules, `launcher.hides` and three scripts to them.** This adds four
  patches that drift at every bump, for an app that is MIT and builds in
  minutes.
- **Keep Folio 0.2.0 and drop the portal line.** Every app's Open/Save
  dialog would stay GTK's while edge's Files is upstream's chooser, and
  the migration would advertise a backend that does not exist.
- **Skip `omarchy-install-browser-extensions`.** `omarchy-default-browser`
  would abort every Chromium-family choice.
- **Run Chrome's policy repair under sudo.** `/etc` is NixOS's. A write
  there is lost at the next switch and conflicts with
  `environment.etc`.

## Risks

- **Folio's CMake move** built in the trial. Its runtime (thumbnails, mounts
  through gio, plugins) is not exercised by any check beyond `session`.
  Folio is the default file manager on edge, so a regression is edge-only,
  not `main`.
- **The portal:** if `folio chooser` fails at runtime, the portal falls
  back to gtk only when Folio's D-Bus service fails to start, not when it
  starts and misbehaves. `checks.session` exercises the chooser. If it
  cannot, the hole is named in `tests/AGENTS.md` (§3).
- **Hosts:** p620 and razer follow edge. Both get Omaview and Folio 0.5.0
  at their next edge bump. `main` and its hosts are unaffected.
