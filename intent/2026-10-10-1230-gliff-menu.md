# Intent: Setup > Remote desktop offers gliff

## Problem

#1227 made gliff a default package, and on purpose left the menu alone
(intent `2026-10-09-1226-gliff-preinstall`, open question 3). So the menu still
describes remote desktop as RDP and nothing else:

- **Setup > Remote desktop** has two rows, "Allow connections"
  (`nixarchy-remote serve`, which sets up hypr-rdp) and "Connect to a machine"
  (`nixarchy-remote connect`, an RDP client over an ssh tunnel).
- "Connect to a machine" has a `when` that hides it unless `sdl-freerdp` or
  `xfreerdp` is installed. Neither is a default package, so on a stock machine
  the group offers only the four-step hypr-rdp setup.
- Between two nixarchy machines, gliff already works with nothing to set up.
  The desktop file puts it in the app launcher. The Setup menu, where somebody
  looking for remote desktop actually looks, never mentions it.

## Proposed outcome

- **Setup > Remote desktop** has a row that opens gliff, shown whenever gliff is
  installed. gliff's own window then handles which machine: an address bar, a
  tab per machine, and reconnecting to the last ones.
- The RDP rows still work exactly as they do now. They are still the way in
  from Windows, macOS and phones.
- The new row's label makes the difference clear: gliff is for another nixarchy
  or Omarchy machine.

## Affected users and systems

- `pkgs/omarchy/default.nix`: `remoteMenuRows`, the generated menu.
- Every machine that has gliff (the default) sees one more row. Machines that
  removed it with `preinstallsExclude` see no change.
- The menu checks (`tests/menu-verbs.nix`, `tests/remote-tunnel.nix`) read the
  generated menu. `docs/manual/remote-desktop.md` may get one line about the
  row.

## Constraints

- **The row may name gliff only when gliff exists** (§2): it gets a
  `when = command -v gliff`, the same pattern the connect row uses for its
  client.
- **It may not hide or rename the RDP rows.** Changing those is a separate
  decision, and they serve clients gliff cannot.
- **It may not enable sshd.** gliff needs ssh on the far machine.
  `services.openssh.enable` stays the user's choice, as #1227 decided.
- **The icon must be a glyph that is already proven to render** (the comment
  on `remoteMenuRows`).

## Open questions

1. **Where the row goes.** I recommend a third row in the Remote desktop group,
   "Connect with gliff". The alternative is to make `nixarchy-remote connect`
   ask "gliff or RDP" first. That puts a terminal wizard in front of a GUI that
   already has its own address bar, for no gain.
2. **Whether the row launches gliff bare** (its window with the address bar) or
   asks for a host first. I recommend bare. gliff remembers machines, and a
   prompt in front of it duplicates gliff's own address bar.
