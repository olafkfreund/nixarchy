# Intent: New installs follow Omarchy 4.5's default app set

Part of #1610. The owner has decided the direction. This intent records what
that decision costs and what is still open.

## Problem

Omarchy 4.5 changed its default apps, and nixarchy still ships the old set.

**Apps that should be there and are not.** Omarchy's own apps are behind
`programs.nixarchy.omarchyApps.enable`, which is off (`modules/apps.nix:1358`,
`docs/manual/other-packages.md:65`). The desktop still points at them:

- `Super + Shift + Q` and the calculator key run `omacalc`, in the tree `main`
  pins (rc3, `default/hypr/bindings/applications.lua:14-15`) and in v4.5.0.
- `Super + Shift + W` runs `omawrite` (`applications.lua:23` in v4.5.0).
- The recording notification's `Cut` button runs `omacut`
  (`bin/omarchy-capture-screenrecording:454` in rc3, `:457` in v4.5.0).

So on a default machine, keys and a button run commands that do not exist.
`checks.session` cannot see this: it sets `omarchyApps.enable = true`
(`tests/session.nix:145`), so its check of the binaries the config names only
runs with the apps on.

**Apps that should go.** OBS Studio, Kdenlive and Xournal++ are still in
`preinstalls` (`modules/nixos.nix:1537-1543`). No `install/*.packages` file or
preinstall script names them, in rc3 or in v4.5.0. Upstream's
[4.5 notes](https://omarchy.org/news/2026/11/omarchy-4-5/) give the reason:
Signed replaces Xournal++, and Monologue and Omacut replace OBS Studio and
Kdenlive.

## Proposed outcome

- A new install has Omarchy's default apps. The calculator key,
  `Super + Shift + W` and the `Cut` button work without any configuration.
- A new install has no OBS Studio, Kdenlive or Xournal++.
- Anyone can still opt out of an app, or add a removed one back, with one line.
- Whoever loses an app on rebuild has been told, and told how to get it back.

### What the owner's list means against the code

| App | Today | Note |
|---|---|---|
| Hype, Signed, Monologue, Omacalc | behind `omarchyApps` | the change this issue asks for |
| Disktree | **already on every machine** | runtime dependency, `pkgs/omarchy/default.nix:250`. Nothing to do |
| Omacut | behind `omarchyApps` | not on the owner's list, but the `Cut` button runs it. In upstream's `omarchy-base.packages:100` |
| Omawrite, Aether | behind `omarchyApps` | not on the owner's list. In upstream's base list (`:101`, `:4`), and `Super + Shift + W` runs Omawrite |
| Omarchy Local AI | behind `omarchyApps` | `preinstall = true` (`data/apps.nix:547-555`), but neither upstream tree names `omarchy-local-ai` anywhere. The option text and manual say seven apps; there are eight rows |

The one switch turns on all eight, so what it should cover is an open question.

## Affected users and systems

**New installs.** The change the owner asked for.

**Existing machines.** A NixOS rebuild removes whatever the configuration no
longer lists, so `nixarchy update` takes these away. Upstream's notes say
"Machines that already have any of them keep them", because nothing there
uninstalls them. What actually happens here:

- The three apps leave `PATH` and the launcher. Their settings and the user's
  projects in `$HOME` are not touched, and older generations still have them.
- Getting them back should be `nixarchy pkg add obs-studio`, and the same for
  `kdePackages.kdenlive` and `xournalpp`. Its name check accepts a dotted
  attribute (`modules/apps.nix:2676`); the spec has to try this for real.
- None of the three has a row in `data/apps.nix`, so `apps.nix` cannot offer
  them. Only `nixarchy pkg add` or the user's own config can.
- Existing machines also gain the new apps, unless the switch is limited to
  new installs.

**Can existing machines keep them?** Yes, with a mechanism, and nothing simpler
exists today:

- `system.stateVersion` cannot tell old from new: it is a constant 25.05
  (`installer/host.nix:612`).
- `installerManaged` cannot either: `installer/host.nix:49` sets it, and
  existing machines read that file from the pinned nixarchy
  (`installer/template/host/default.nix:15`).
- The files that do differ are the ones copied into the user's flake at install
  time and never refreshed (`installer/mkFlake.nix:70-71`). A line in
  `template/host/configuration.nix` reaches new installs only. It costs a
  permanent second population, and machines enrolled with `--from` inherit
  whatever their repo has.

**Mode A.** `programs.nixarchy.enable = false` is untouched: both modules are
gated on `cfg.enable` (`modules/nixos.nix:943`, `modules/apps.nix:1523`).
`enable = true` is not the same: `preinstalls` defaults to true
(`modules/nixos.nix:617-619`), so those machines already get Pinta and
LibreOffice, would lose the three apps, and would gain the new ones if the
switch follows `preinstalls` as #1610 proposes. `tests/options.nix:2003-2015`
needs a new off state, because "off" today means no configuration at all.

**Closure and images.** Measured by path-info on a built system at the pinned
nixpkgs (`0bb2eed`, 18,343 MiB, 2,505 paths), removing the packages from the
reference graph, and adding the apps' built paths:

| Change | MiB |
|---|---|
| Remove OBS Studio alone | −702 |
| Remove Kdenlive alone | −780 |
| Remove Xournal++ alone | −10 |
| Remove all three (they share dependencies) | −1,559 |
| Add all eight apps | +80 (Signed 54, Aether 20, the rest under 4 each) |
| **Net** | **−1,479** |
| Lazydocker alone, if it left | −13 |

- `iso` is 6.66 GiB against a 7.50 GiB budget, and `iso-net` 1.79 against 2.00
  (nightly 41764984489, 2026-11-04). This change should shrink `iso` by about
  0.5 GiB. That is an estimate from cd.nix's 2.7x compression ratio, not a build.
- `iso-net` should not move measurably. The desktop's closure reaches only the
  offline image (`installer/cd.nix:655`, `:680`), and the network image's own
  packages are the installer and git (`:298-301`). Not built.
- `installer/cd.nix:634` says the reference host enables no apps "and should
  not start". The numbers no longer support that for this set, so it needs
  rewording rather than breaking silently.
- All eight are in the cache allowlist already, through the `apps` group
  (`.github/scripts/cache-allowlist.sh`). The budget should barely move. The
  difference is that they stop being optional: every network install now
  fetches them, so an evicted path costs every install rather than one opt-in
  user. `cache-budget.sh` has not been run for this.

**Lazydocker.** A runtime dependency (`pkgs/omarchy/default.nix:274`). Upstream's
notes remove it from new installs and keep Docker and Compose, and it is absent
from upstream's package lists. Upstream's binding checks for it first
(`applications.lua:18`), but `default/applications/Docker.desktop` and
`omarchy-launch-docker-tui` still run it, and `tests/session.nix:2000` names
that command. Docker stays on by default here, and there is no `data/apps.nix`
row to install Lazydocker from.

**Things that name the removed apps:**

- `modules/nixos.nix:953-956,971-974,981-982`: the `preinstallsExclude` names.
- `pkgs/verify.sh:1205`: reports `xournalpp` as missing, softly.
- `tests/demo/default.nix:972`: launches `xournalpp`. Nothing builds that scene
  (CLAUDE.md §4), and if a person runs it, the loop at `:975-978` photographs an
  empty desktop rather than failing.

**Checks this changes:**

- `tests/session.nix:145` sets the switch explicitly. While that line stays, the
  session check cannot show that the apps come by default.
- `tests/options.nix:441-450` hardcodes all eight names, and `on` requires every
  one (`:2008`). Taking Local AI out of the switch fails it until that list
  changes.

Stale text once the switch moves: `modules/nixos.nix:622-630` and `:1535`,
`modules/apps.nix:1358`, `docs/manual/other-packages.md:58-72`,
`data/apps.nix:509-511` and `:646`, `tests/options.nix:2000-2002`, `flake.nix:774`.

**Parallel work.** #1611, #1613, #1614 and #1615 also change `modules/nixos.nix`.
#1613 (Superwhisper) is the likeliest overlap, since it also adds a default app
with a Mode A limit. #1606 moves the pin from rc3 to v4.5.0; both trees agree on
everything cited above.

## Constraints

- Must announce the change in the release notes and the Discussions post, with
  the migration step (§14). The notes cannot do this alone: `release-notes.sh`
  reads option defaults and `= lib.mkDefault` lines, so a package leaving a
  literal list is invisible to it. Flipping an option's default is visible only
  if the default expression changes in a way it can show.
- Must not break a rebuild for someone who already opted out. If `obs-studio`
  leaves the known list, `preinstallsExclude = [ "obs-studio" ]` becomes an
  assertion failure (`modules/nixos.nix:946-963`) for exactly the people who
  already did what this change does.
- Must keep every opt-out: `preinstalls = false`, `preinstallsExclude`, and a
  line in `apps.nix` per app (`mkDefault`, `modules/apps.nix:1527`).
- `programs.nixarchy.enable = false` must stay inert, and `tests/options.nix`
  must assert the switch in both states.
- A coexistence fixture and the failing output of any new check are required
  (§1, §14).
- No VM builds for this draft. Nothing here was run on a booted machine.

## Open questions

The owner approved every recommendation below on 2026-11-05.

1. **Do existing machines keep the three apps?** Recommend no: release note and
   migration step only, as #1610 says. A one-command restore does not justify a
   permanent second population that every later default change must test twice.
   The alternative is the template line above.
2. **Which apps does the switch cover?** Recommend upstream's base list:
   Hype, Signed, Monologue, Omacalc, Omacut, Omawrite and Aether. Omacut is
   needed for the `Cut` button, and upstream's notes name it for trimming in
   place of Kdenlive.
   Leave Omarchy Local AI out, since upstream does not install it, by clearing
   its `preinstall` flag.
3. **Does Lazydocker leave?** Upstream's notes say it does. Recommend it stays
   here anyway: it costs 13 MiB, and removing it leaves `Docker.desktop` running
   a missing command on a machine where Docker is on by default. Whether upstream
   hides that launcher when Lazydocker is absent has not been checked.
4. **Does `enable = true` in Mode A get the new apps?** Recommend yes, following
   `preinstalls` as #1610 proposes. Those machines already take the preinstalls,
   and `preinstalls = false` is the existing way out.
