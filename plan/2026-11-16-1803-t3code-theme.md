# Plan: T3 Code follows the Omarchy theme when installed through apps

All work is in the worktree `/mnt/data/vmtest/nixarchy-1803`, on branch
`feat/1803-t3code-theme`, based on `origin/main` at `3bfbc669`. This plan
carries every decision from the approved spec.

## Approved decisions (from the spec)

- **Option.** It is declared in `modules/home.nix`, under
  `options.programs.nixarchy` (`:639`), next to `defaultTheme` (`:719-723`):

  ```nix
  t3code.theme = lib.mkOption {
    type = lib.types.nullOr (lib.types.strMatching "[a-z0-9-]+");
    default = "omarchy";
    example = "omarchy-plus";
  };
  ```

  The description states:
  - the theme is forced back on every activation;
  - `null` publishes the palette but never selects a theme;
  - a missing theme other than `omarchy` falls back to `omarchy`, with a log
    line.
- **Builder.** New file `modules/t3code-theme-script.nix`, called with
  `pkgs.callPackage`:

  ```nix
  { lib, writeShellApplication, coreutils, gnugrep, jq }:
  { publisher, t3, theme, timeoutSecs ? 30, killSecs ? 5 }:
  writeShellApplication {
    name = "nixarchy-t3code-theme";
    runtimeInputs = [ coreutils gnugrep jq publisher t3 ];
    bashOptions = [ "nounset" ];
    text = …;
  }
  ```

  - `bashOptions = [ "nounset" ]` replaces the default `errexit nounset
    pipefail`.
  - ShellCheck still runs at build time.
- **Script steps.** "Stop" means `exit 0`. Logs go to stderr, prefixed
  `t3code-theme:`. The script ends with `exit 0`.
  0. If `HOME` is empty, log and stop. Set `T3CODE_HOME="$HOME/.t3"` and
     `STATE="$T3CODE_HOME/userdata"`.
  1. For `omarchy-theme-set-t3code` and `t3`: if `command -v` fails, log
     `<name> not found` and stop.
  2. If `$HOME/.local/state/omarchy/current/theme/t3code.json` is missing, log
     `no Omarchy palette staged yet; next activation retries` and stop. This
     check comes before `mkdir`.
  3. `mkdir -p "$STATE"`.
  4. Run `omarchy-theme-set-t3code`.
     - Non-zero exit: log `publisher exited <code>` and stop.
     - Exit 0 while the palette contains `{{` (`grep -qF '{{'`): log `palette
       has unresolved colours; kept the previous one`, and continue.
  5. If `theme` is `null` (Nix decides this when building the script), stop.
  6. Set `want=<theme>`. If `$STATE/themes/$want.json` is missing:
     - if `want` is not `omarchy` and `$STATE/themes/omarchy.json` exists, log
       `theme <want> not published; using omarchy` and set `want=omarchy`;
     - otherwise log `theme <want> not published` and stop.
  7. Read the current theme with
     `jq -r '.defaultTheme // empty' "$STATE/settings.json" 2>/dev/null`. If
     it equals `want`, stop.
  8. Run
     `timeout -k <killSecs> <timeoutSecs> t3 theme set "$want" --base-dir "$T3CODE_HOME"`.
     - Output goes to a `mktemp` file.
     - On a non-zero result (124 and 137 included), log `t3 theme set exited
       <code>` and the last 5 lines, each prefixed.
     - Always run `rm -f` on the file.
- **Activation.** In `modules/home.nix`, beside the per-app entries
  (`:1839-1879`):

  ```nix
  t3codeOn =
    (osConfig.programs.nixarchy.enable or false)
    && (osConfig.programs.nixarchy.session or true)
    && appEnabled "t3-code";               # appEnabled is at :137

  home.activation.nixarchyT3codeTheme = lib.mkIf t3codeOn (
    lib.hm.dag.entryAfter [ "writeBoundary" "nixarchySeed" ] ''
      run ${t3codeThemeScript}/bin/nixarchy-t3code-theme
    '');
  ```

  `t3codeThemeScript` is a `let` binding:
  `pkgs.callPackage ./t3code-theme-script.nix { } { publisher = cfg.package;
  t3 = osConfig.programs.nixarchy.apps."t3-code".package; theme =
  cfg.t3code.theme; }`.
  - It is forced only inside the `mkIf`.
  - `cfg` is the Home Manager `config.programs.nixarchy` (`:14`).
  - `nixarchySeed` is at `:1161`, and the first-run theme at `:1417`.

### 3. Behaviour check (codex)

New file `tests/t3code-theme.nix`, taking `{ inputs, pkgs }`. Register it in
`uniformChecks` (`flake.nix:~1820`) as `"t3code-theme"`.

**Part A: the builder.** Call the builder with stub `publisher` and `t3`
packages (`writeShellScriptBin`), `timeoutSecs = 2` and `killSecs = 1`.
- The stubs log to a per-case call log, and their behaviour comes from
  per-case config.
- Each case runs under `env -i HOME=… TMPDIR=… PATH=<coreutils>`, with its own
  `HOME`.

The cases:

1. No palette: no publisher call, no `t3` call, and no `$HOME/.t3` created.
2. The publisher exits 1, with `themes/omarchy.json` present: `publisher
   exited 1` is logged, and `t3` is not called.
3. A `{{` palette with `omarchy.json` present: the warning is logged, and `t3`
   is called.
4. A `{{` palette and no theme file: `theme omarchy not published`, and no
   `t3` call.
5. No `settings.json`: `t3 theme set omarchy --base-dir $HOME/.t3`, and
   `settings.json` then says `omarchy`.
6. `ember` selected: `t3` is called.
7. `omarchy` selected: `t3` is not called.
8. `t3` exits 1 after printing two lines: `exited 1` is logged, with both
   lines prefixed.
9. `t3` runs `trap '' TERM; exec sleep 60`: the script finishes in under 5 s,
   `exited 137` is logged, and no temporary file is left.
10. A `t3` package with no `bin/t3`: `t3 not found` is logged, and no `~/.t3`
    is created.
11. `theme = null`: the publisher is called, and `t3` never is.
12. `theme = "omarchy-plus"`, no `omarchy-plus.json`, `omarchy.json` present:
    the fallback log, then `t3 theme set omarchy`.
13. `omarchy-plus.json` present: `t3 theme set omarchy-plus`.

## Corrections from review (part of the steps above; implementers apply them)

- **K1 (Codex).** Part B's stub writes `settings.json`. Normal and dry runs
  use fresh homes. The `Bad Id` probe forces the option inside `tryEval`.
  These are already folded into steps 2 and 3.
- **K2 (agy). `null` must not leave unreachable code.** ShellCheck in
  `writeShellApplication` fails the build on SC2317. Splicing `${theme}`
  when it is `null` fails evaluation. So:
  - the script gets `theme=${lib.escapeShellArg (if theme == null then "" else theme)}`;
  - step 5 becomes the runtime test `[ -z "$theme" ]` → log `publish only`,
    then stop;
  - steps 6-8 use `$theme`/`$want`, never the Nix value.
  Case 11 builds the `null` script, so ShellCheck runs on it too.
- **K3 (agy). `nounset`.**
  - Step 0 tests `"''${HOME:-}"`.
  - `export T3CODE_HOME`, because the publisher reads it
    (`omarchy-theme-set-t3code:9`).
  - New case 14: `env -i` with no `HOME` at all. It must exit 0 and log
    `HOME unset`.
- **K4 (agy). The `{{` branch.** The real publisher refuses a placeholder
  palette itself: it exits 0 and leaves the previous file
  (`omarchy-theme-set-t3code:20-23`). The script's `grep -qF '{{'` reads the
  staged `t3code.json`, not the published file, and only logs. A new Part B
  case runs the real publisher with a `{{` palette and an existing
  `omarchy.json`: that file must be unchanged, and the warning logged.
- **K5 (agy). Assertions that could stay green.**
  - Every Part A case asserts exit status 0, explicitly.
  - Case 8 prints 7 lines. Only the last 5 appear, each prefixed.
  - New case 15: `theme = "omarchy-plus"` with neither theme file present.
    It must log `theme omarchy-plus not published`, without calling `t3`.
  - New case 16: a publisher package with no `bin/omarchy-theme-set-t3code`.
    It must log `omarchy-theme-set-t3code not found`.
  - The `mktemp` result is checked: on failure, log and stop. Part A creates
    each case's `TMPDIR`.
  - Case 9's bound is under 15 s, not 5 s, which leaves slack on a loaded CI
    builder. 3 s is still clearly not 60 s.
- **K6 (agy). Option scope in `checks.options`.**
  - `t3code.theme` is set at
    `home-manager.users.someone.programs.nixarchy.t3code.theme`, not at the
    NixOS level, where `"Bad Id"` would fail as "option does not exist" and
    pass falsely.
  - The `"omarchy-plus"` comparison enables `apps.t3-code` in both configs,
    with a stub package.
  - Assert that `.after` contains `writeBoundary`.
  - New pair: `programs.nixarchy.enable = false` with `apps.t3-code.enable =
    true` gives no entry. §1 break: drop the `enable` term.
- **K7 (agy). Downstream ordering.** Downstream uses a different key
  (`t3codeOmarchyTheme`), so a bump would not collide; both entries would run
  and select the same theme. The follow-up must still delete the downstream
  module in the same PR as the nixarchy bump, not after it.
- **K8 (agy). No flag-shaped theme ids.** The type becomes
  `strMatching "[a-z0-9][a-z0-9-]*"`. It still accepts `omarchy` and
  `omarchy-plus`, but rejects a leading `-` that `t3` could read as a flag.
  This tightens the approved spec's `[a-z0-9-]+`, and it is recorded here as
  a deliberate deviation. `checks.options` adds `"-x"` as a rejected value.
