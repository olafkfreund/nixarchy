# Spec: Omarchy 4.5's default apps on nixarchy, and a check that catches the next one

The intent's open questions were settled on approval:

- the four apps are opt-in, plus one switch that turns on all of Omarchy's own apps;
- titlebars come on with the session;
- the ledger classifies every name.

## A correction to the intent

The intent says these apps have "menu rows, shortcuts and dock entries"
that open nothing. That overstates it. In v4.5.0-rc3:

- No binding, menu row or dock entry names Hype, Monologue, Signed or
  Disktree.
- Upstream installs them through migrations (`omarchy-pkg-add hype` in
  `migrations/1790542069.sh`, and so on) as *preinstalls*. A user meets
  them only through their `.desktop` files in the app launcher.
- Disktree also replaces the "Disk Usage" TUI: `migrations/1791345484.sh`
  drops `dua-cli` and deletes `Disk Usage.desktop`.

On nixarchy the apps simply do not exist, and those migrations' calls to
`omarchy-pkg-add` print advice about packages nobody can install. The
titlebars plugin is the one silent functional loss, as the intent says.

## Design

### 1. Five packages in `pkgs/apps/`

Each follows `pkgs/apps/omawrite.nix`: `fetchFromGitHub` at the release
tag, and the `.desktop` and SVG from upstream's own `pkgbuild/`
directory. Runtime commands are wrapped onto PATH, as `omacut.nix` does
for ffmpeg. Building against a library is not the same as having its
command at run time.

| file | source | build | runtime commands found in the source |
|---|---|---|---|
| `hype.nix` | omacom/hype `v0.6.0` | `qt6.qmake`, `wrapQtAppsHook`. qtbase, qtdeclarative, qtmultimedia, qtsvg, qtimageformats, zlib, libwebp (`LIBS += -lz -lwebpdemux -lwebp`) | `ffmpeg`, `ffprobe`, `source-highlight` |
| `monologue.nix` | omacom/monologue `v0.3.1` | qmake. qtbase, qtdeclarative, qtmultimedia, libpulseaudio | `ffmpeg`, `ffprobe` |
| `signed.nix` | omacom/signed `v0.3.1` | qmake with `link_pkgconfig`. qtbase, qtdeclarative, qtwayland, poppler (qt6), qpdf | `certutil`, `pk12util` (nss.tools). `noto-fonts` is upstream's font dependency |
| `disktree.nix` | tobi/disktree `v0.11.0`, **the prebuilt Linux tarball** | `autoPatchelfHook`. Needs wayland, libxkbcommon, libxcb, libglvnd, vulkan-loader, fontconfig. `disktree.desktop.in` gets `@BINDIR@` and `@VERSION@` substituted, as the AUR package does | none |
| `omarchy-hyprland-titlebars.nix` | omacom/omarchy-hyprland-titlebars `v0.3.0` | CMake and pkg-config against a **`hyprland` argument**, plus libdrm, libinput, udev, pixman, wayland, libxkbcommon. Installs `lib/omarchy-hyprland-titlebars/titlebars.so` and both licences | none |

Versions checked against the pinned nixpkgs: rustc 1.99 and qtbase
6.12.0. Both clear Hype's Qt 6.9 floor and Monologue's Qt 6.8 floor.
Disktree's 1.97 floor does not matter, because it is not compiled here.

**How they are wired:**

- All five go in the flake overlay, next to `omawrite` (`flake.nix`
  around 752), and in the exported `packages`. `modules/apps.nix:77-82`
  resolves an `ours` app to `nixarchy.packages.${system}.<attr>`.
- Hype, Monologue, Signed and Disktree get `data/apps.nix` rows with
  `ours = true`, like omawrite. That gives each one its own
  `programs.nixarchy.apps.<name>.enable`.

### 2. One switch for Omarchy's own apps

`programs.nixarchy.omarchyApps.enable`, default `false`, sets
`apps.<name>.enable` through `mkDefault` for every `ours` app that
upstream preinstalls. That is omawrite, omacalc, omacut and aether, plus
the four new ones. A per-app `enable = false` still wins.

- The list is the `ours` rows that carry a new `preinstall = true` field,
  so a future one is added in `data/apps.nix` and nowhere else.
- Mode A is untouched, because the default is `false`.

### 3. Titlebars: built against the session's own Hyprland

Building against the flake's `hyprland` input would be wrong whenever a
host overrides `programs.hyprland.package`. Codex's review raised this,
and `modules/AGENTS.md` (the `runtimeDeps` section) documents that hosts
do it.

**What the module does** when the session is on:

- builds the plugin with
  `callPackage ../pkgs/apps/omarchy-hyprland-titlebars.nix { hyprland = config.programs.hyprland.package; }`;
- adds it to `environment.systemPackages`;
- adds `"/lib/omarchy-hyprland-titlebars"` to `environment.pathsToLink`.

**What the tree does:** `pkgs/omarchy/default.nix` rewrites the one
constant at `default/hypr/workspace-modes.lua:26`, from
`/usr/lib/omarchy-hyprland-titlebars/titlebars.so` to
`/run/current-system/sw/lib/omarchy-hyprland-titlebars/titlebars.so`.

The tree is the same for every host, the path resolves to the plugin each
system built, and the plugin's ABI matches the compositor that runs.

**The rewrite does reach the session.** Codex suspected it would not.
`config/hypr/hyprland.lua:4` `dofile`s
`$OMARCHY_PATH/default/hypr/bootstrap.lua`, which puts
`$OMARCHY_PATH/default` on `package.path`. `workspace-layouts.lua:7`
requires `default.hypr.workspace-modes` from there. Home Manager seeds
`config/`, not `default/`. Step-level proof is the VM check below.

**When Hyprland moves:** the plugin rebuilds with it. An upstream API
change then fails the system build, in CI, on the bump's pull request. A
build that succeeds but stops loading is caught by the session check.

### 4. The package ledger: `data/omarchy-packages.nix`

Every name in the vendored tree's `install/*.packages` gets one row:

```nix
hype           = { nix = "hype"; };                        # we package it
bluez          = { module = "hardware.bluetooth"; };       # the NixOS module provides it
limine-snapper = { skip = "NixOS boots through systemd-boot or GRUB, and rolls back by generation"; };
```

**The rows:**

- `nix` names a package. The check evaluates it against nixpkgs plus
  our overlay, so a misspelt attribute fails.
- `module` names the option that provides the thing, as a string. That
  cannot be checked mechanically. It is a claim, the same kind
  `data/arch-extras.nix` makes.
- `skip` holds the reason.
- Exactly one of the three is required.

**The check: `checks.omarchy-package-ledger`.** It is a `runCommand`
that reads every `install/*.packages` in `pkgs.omarchy`'s output. That
is a build input, so no IFD and no network. It fails, naming the
offenders:

- **unclassified:** in the tree with no row;
- **stale:** a row for a name no file lists any more;
- **unresolvable:** a `nix` attribute that does not evaluate.

All 249 names are classified in this change (decision 3). The
architecture-specific files (`aarch64-*`, `x86_64-only`) are included,
because a skip is still a decision. Rows can say "aarch64 hardware this
port does not target".

**Why this catches the next one:**

- On main, the Omarchy bump PR fails the moment upstream lists a new
  package. The bump stops being prose that nobody acts on.
- On edge, the candidate fails as soon as quattro adds one, which is
  before any release.
- The check runs on pull requests through the generated-checks step
  (§4), so no workflow is edited.
- Edge's own `verify` job builds a fixed list of checks. Whether that
  list includes this one is verified in the plan, and added there if
  not. That is a workflow edit, which §11 says needs a human to merge,
  so it would be flagged in the PR.

**`omarchy-package-delta.sh` stays.** The diff it prints is still the
fastest thing to read on a bump. The ledger is what makes acting on it
mandatory.

### 5. The owner's machines

`~/.config/nixos`, which is outside this repo, sets
`programs.nixarchy.omarchyApps.enable = true` once edge carries this
change. Then p620 and razer rebuild, and razer logs out and back in.

## Alternatives rejected

- **Build Disktree from source.** Its UI toolkit is gpui, Zed's GPU
  toolkit: a large crate tree with git dependencies and a Vulkan stack.
  nixpkgs' `zed-editor` expression shows the cost. Upstream's own Arch
  package, `disktree-bin`, is the prebuilt binary, and MIT allows it.
- **Install the apps by default.** That is the omawrite decision again:
  a desktop port should not hand a Mode A machine a slide editor nobody
  asked for. The switch makes the opt-in a single line.
- **Build the plugin against the flake's Hyprland input.** It is wrong
  for any host that sets `programs.hyprland.package` (see 3).
- **Rewrite the plugin path to a store path inside the tree.** That ties
  the tree to one Hyprland, and so to one host's ABI.
- **A baseline file of today's names, checking only new ones.** It would
  have accepted all five of these, because they are already in the
  list. #1278's names were exactly that case.
- **Make `omarchy-package-delta.sh` fail on any added name.** A bump has
  no place to record "knowingly not carried", so it would fail forever,
  or be silenced.

## Risks

- **A Hyprland bump that changes the plugin API breaks every nixarchy
  system build**, not only the plugin, because the plugin is in
  systemPackages with the session. CI's `system` job sees it on the bump
  PR, before main does. On edge, quattro and Hyprland move together, so
  a compile break there means quattro has already updated the plugin
  upstream.
- **A misclassified ledger row** (for example, `module` for something
  the module does not provide) passes the check. Only the `nix` class is
  verified. That is the same limit `data/arch-extras.nix` has.
- **The prebuilt Disktree may need a library autoPatchelf does not
  name.** That shows up at launch, not at build. The verification below
  launches it.
- **The binary cache.** Five new packages are built in CI and not
  pushed, unless they are added to `cache-allowlist.sh`. The four apps
  are small and opt-in, so they stay off it. The plugin is built per
  host anyway.
- **The README counts move.** `data/apps.nix` gains four `ours` rows,
  and `readme-counts.sh --fix` has to run in the same PR (§4).

## Coexistence

- **A user who already packages one of these apps themselves**, say
  `hype` in `environment.systemPackages`: the ours-app path installs
  nixarchy's only when `apps.hype.enable` is set, so the default adds
  nothing.
- **A host with its own `programs.hyprland.package`:** the plugin is
  built against that package (see 3).
- **Fixture:** `tests/coexistence/fixtures.nix` gains one fixture, a
  machine with `programs.hyprland.package` overridden. It asserts that
  the plugin's `hyprland` dependency is that package.

## Verification

1. **Builds.** `nix build` each of the four apps, and the plugin against
   the reference config's Hyprland. This is package tier, under §6's
   rules.
2. **Launches.** Each app starts and reaches a window, or prints
   `--version` where it has a CLI (`hype check`). The run happens in the
   session VM, with `apps.*` enabled in the fixture, so a missing
   library or command shows there.
3. **Titlebars in a real session.** `checks.session` floats a workspace
   and asserts the plugin is loaded (`hyprctl plugin list` names
   `hyprbars`). §1 proof: with the Lua rewrite removed, it fails.
4. **Ledger.** The check is green with all 249 rows. §1 proof, both
   directions: drop the `hype` row and it fails naming `hype` as
   unclassified; add a row for `not-a-package` and it fails naming it as
   stale. Both failing outputs go in the PR.
5. **Options.** `checks.options-*` assert `omarchyApps.enable` in both
   states. Off: no new package in systemPackages. On: all eight `ours`
   preinstalls are present.
6. **Owner hosts.** After edge carries it, p620 and razer run all five
   apps, and a floated workspace has titlebars.
