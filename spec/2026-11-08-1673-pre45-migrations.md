# Spec: machines seeded before Omarchy 4.5 get the 4.5 user-file migrations that still apply

Twenty rows, eleven issues (#1671-#1681), one PR, one commit per issue.

## Design

### 1. Run upstream's own scripts, not rewrites

Of the 20 scripts, 14 call only commands this tree ships: `hyprctl`,
`omarchy-shell`, `omarchy-theme-refresh`, `omarchy-webapp-window-class`,
`omarchy-restart-herdr`, `omarchy-default-dictation`, and plain
`sed`/`jq`/`awk`. Rewriting them in nixarchy's own script would be 14
copies to keep in step with upstream. So they run **verbatim** from the
store, `$OMARCHY_PATH/migrations/<id>.sh`, exactly as upstream's runner
would. Three need a stated edit first, and two are declined:

An edited script is produced at build time by `substituteInPlace
--replace-fail` on a copy, so a source bump that rewords a line fails the
build instead of running stale (the same rule as `--fuzz=0` patches). The
copies live in the `omarchy-migrate-user` derivation, not in the vendored
tree, which stays upstream's.

### 2. `omarchy-migrate-user` grows a runner

Today the script exits unless `.bar.centerAnchor` exists (line 21), and as
soon as the three bar markers exist (line 22). It is restructured into:

- `bar_migrations`: today's body, unchanged, with each `exit 0` that means
  "stop the bar work" made a `return 0`. Its two gates become the
  function's own first lines.
- `run_upstream <id> [script]`: when `$state/<id>.sh` is absent, it runs
  `OMARCHY_PATH=... bash -euo pipefail <script>` (default
  `$OMARCHY_PATH/migrations/<id>.sh`) and writes the marker on exit 0. On
  failure it logs the id to the journal, writes no marker, and **stops the
  run**, so the next login retries from that id. That is upstream's runner
  contract (`bin/omarchy-migrate:88-96`, under `set -e`): a later migration
  may assume an earlier one ran.
- The id list is generated from `data/user-migrations.nix` at build time:
  every row whose decision is `ported` and that names `run = "upstream"` or
  `run = "<edited copy>"`. The ledger then carries which form each row
  takes, and a row cannot be ported without the runner seeing it. The ledger
  check's schema gains the optional `run` field.
- **Order:** upstream ids run in ascending order, as upstream runs them,
  after `bar_migrations`.

**First-run age gate.** A home seeded on 4.5 already has every result. Each
upstream script is idempotent by its own guards (they test for the old
state before changing anything), and a run on a 4.5 home is a no-op that
writes a marker. The runner still writes the markers, so a later bump's new
migration is the only one that runs. No "is this a pre-4.5 home" detector
is needed, which removes a guess.

### 3. #1677 / 1791479273: the dictation default

Upstream writes `voxtype` only when `defaults/dictation` is missing. Here
the seed (`home.nix`) has always written it by then, so the condition never
holds. The port is a `run_upstream` entry with its own script, not an
edited copy, and it writes `voxtype` when all of these hold:

- `defaults/dictation` reads `superwhisper`,
- no marker,
- `command -v voxtype` (the voxtype service is on: `home.nix:960`),
- Superwhisper has never been set up
  (`~/.config/superwhisper/preferences.json` absent).

The last condition keeps a user who chose Superwhisper on it.

### 4. #1681: the option (decision 1)

- `modules/nixos.nix:660-672`: `"agy"` joins the `defaultAgent` enum.
- `gemini` stays in the enum. A `config.warnings` entry fires when it is
  set ("Gemini was replaced by Antigravity in Omarchy 4.5;
  defaultAgent = \"gemini\" now selects agy"), and
  `omarchy-default-agent` maps `gemini` to `agy` (lines 25, 76).
  A configuration that sets `gemini` keeps evaluating and gets a working
  launcher.
- `tests/options.nix` asserts both values, in both states (Mode A, §7).

### 5. The ledger rows

All 20 rows lose the placeholder. Ported rows get `decision = "ported"`
and `run`. The two declines get a reason naming the cause.

## Alternatives rejected

- **Rewrite each migration in nixarchy's script.** That is 14 copies drifting
  from upstream. Verbatim runs are upstream's own code, and the oracle
  comparison becomes unnecessary for them.
- **Detect a pre-4.5 home and run only there.** Detection would be a guess
  (no version stamp exists). The scripts' own guards make running
  everywhere safe.
- **Remove `gemini` from the enum.** It breaks evaluation for anyone who set
  it.
- **Move notification history aside rather than delete.** That keeps the old
  message text (decision 2).

## Risks

- **A verbatim script calls something that behaves differently here.** Each
  one was read for its commands (the table). The test harness runs every
  ported id against fixtures with stubs for the session commands, so a
  missing command fails the check rather than a user's login.
- **Login time:** 18 scripts on a first run, each a few file tests. They run
  from the `post-boot.d` hook, after the session is up, so they do not
  delay it.
- **Deletions** (1787679775, 1792648436) are permanent, by decision.
  The release notes name both.
- **Superwhisper's CLI** is called by 1793477875 only when it is installed and
  configured. The test harness stubs it and never runs the vendor app.

## Verification

- `tests/user-migrations/run` grows per-issue cases. Each builds a fixture
  home in the pre-4.5 shape (from v4.0.6's seed where one exists: herdr's
  `panel_bg = "black"`, a launcher without `StartupWMClass`, a `-98.lua`
  layout, a 4.0 `notifications.json` with `dnd: true`, `defaults/agent`
  of `gemini`, ...). It runs the port and asserts the 4.5 shape: a file, a
  link target, an absence. A second run is asserted to change nothing (the
  markers), and a 4.5-shaped fixture is asserted unchanged, byte for byte
  (no-op on new homes). That fixture carries what each destructive script
  could hit on a new home. 1792648436 deletes only 4.0's `history/`,
  `images/` and numbered popup files, while 4.5's shell keeps `live.json`,
  `history.json` and `quiet.json` (`shell/plugins/notifications/
  Service.qml:1275-1421`), so all three are in the fixture with content. A
  saved positive-id layout (`3.lua`) sits beside `-98.lua`.
- Comparison: for verbatim rows the port **is** upstream's script, so the
  check asserts outcomes rather than diffing against itself. For the three
  edited copies and the dictation port, the harness also runs upstream's
  original under the same stubs and diffs the fixture trees, excluding only
  the removed behaviour. Stubs: `hyprctl`, `omarchy-shell`,
  `omarchy-restart-herdr`, `omarchy-theme-refresh`, `superwhisper`,
  `omarchy-pkg-add`, `omarchy-pkg-drop`, `omarchy-pkg-present`,
  `omarchy-mise-install`. Each is a `patchShebangs`'d script that logs its
  call (the sandbox has no `/usr/bin/env`, as #1670 found), and the diff
  checks the removed calls are absent from the port's log. The nvim
  original's absolute `/usr/share/omarchy-nvim/config` is pointed at the
  fixture's package directory for the oracle run only, and that one path is
  the only difference allowed.
- §1, per issue: the commit's port removed from the id list fails its
  case, and the failing output goes in the PR.
- `checks.user-migrations-ledger` with the new `run` field; a ported row
  with no `run` fails it.
- `checks.options-*` shards (VM-tier gate) for the enum, and
  `checks.plugin` (VM) because it runs the script against the real shell.
- Cheap: `bin-ledger`, `grep-q-pipefail`, statix, deadnix, `nix fmt --
  --ci`. Package tier: `omarchy`, for the substituted copies.
