# Intent: machines seeded before Omarchy 4.5 get the 4.5 user-file migrations that still apply

One intent for #1673, #1674, #1675, #1676, #1677, #1678, #1679, #1680 and
#1681: nine follow-ups from #1610 (PR #1670) covering 18 migration rows, one
PR with one commit per issue.

## Problem

nixarchy does not run Omarchy's migrations, and the seed copies
`share/omarchy/config` into `~/.config` without overwriting anything
(`modules/home.nix:1150,1196`). A home seeded on 4.0.x therefore keeps 4.0's
files after a 4.5 bump. #1670 ported the three bar migrations. The other 18
rows in `data/user-migrations.nix` are `declined` with the placeholder
"needs its own fixture first (#1610 follow-up)": a decision nobody has made
yet.

The seed already carries several 4.5 fixes (OverlayScrollbar in
`chromium-flags.conf:4`, herdr's `panel_bg`, fcitx5's `0=Shift_L`, the
`looknfeel.lua` example). That covers **new homes only**, so it is not a
reason to decline for pre-4.5 homes.

One row hides a live bug rather than a stale file. `omarchy-agent` in 4.5
has no `gemini` case and exits with "Unsupported default agent"
(`bin/omarchy-agent:201-203`). But `programs.nixarchy.defaultAgent` still
accepts `gemini` (`modules/nixos.nix:667`), maps it to `gemini-cli`
(`pkgs/omarchy/nix-bin/omarchy-default-agent:25,76`), and rewrites
`defaults/agent` at every activation (`home.nix:1522-1539`). Setting that
option breaks the agent launcher on any machine, new or old (#1681).

## Proposed outcome

Every one of the 18 rows ends `ported`, `partial` or `declined`, with a
reason that is a decision rather than a placeholder. The ported ones run for
a pre-4.5 home and leave a 4.5 home untouched.

## Affected users and systems

- Every home seeded on 4.0.x: the owner's machines and any early user.
- `pkgs/omarchy/nix-bin/omarchy-migrate-user`, `data/user-migrations.nix`,
  `tests/user-migrations*`, and for #1681 `modules/nixos.nix` and
  `omarchy-default-agent`.

## Constraints

- `omarchy-migrate-user` exits early unless `.bar.centerAnchor` exists
  (line 21) and when the three bar markers exist (line 22). Neither gate
  fits the new rows, so each migration needs its own condition. That
  restructure is the first commit, before any port.
- The script is IPC-only because the running shell owns `shell.json` (#847).
  None of these files is owned that way, so direct edits are allowed, but
  each must skip a symlink (a home-manager link is the user's, §1 "a content
  test is not an ownership test", #1304) and a file the user customised.
- Upstream's markers (`$OMARCHY_MIGRATION_STATE/<id>.sh`) are written only
  after the result is re-read, as #1670 does.
- Every port is compared with upstream's own script on the same fixture
  (`tests/user-migrations/run`, `compare_oracle`; `run_oracle` hard-codes
  the bar ids today). §1: each port's fixture is proven to fail with the
  port removed.
- Never run `mise`. #1681's upstream script installs `agy` through mise;
  that half is not ported.
- One PR, one commit per issue, merged with a merge commit, stacked on
  #1670 until it merges.

## Open questions

1. **#1681:** the `defaultAgent` enum keeps `gemini` (and maps it to
   something that works), or `gemini` goes, with an option rename warning
   pointing at `agy`? Either way the launcher must not reject a value the
   option accepts.
2. **#1680:** deleting old notification history is a data deletion in the
   user's home. Port as upstream does, or move the files aside?
3. The table's three declines (1791123731, 1792474908, 1791479273): agree?
4. **#1677 / 1793477875:** this writes the user's own `bindings.lua`. Port
   it, or decline and say in the release notes that dictation moved to
   Alt+Space?
