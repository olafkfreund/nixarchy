## What this plan changes from the spec

Both verified while writing this. **The owner should confirm them when approving.**

1. **The no-node case becomes its own `checks.agent-no-node`,** rather than a case in
   `default-agent-routes`. Measured from cache.nixos.org: pi's closure is **401 MiB**
   and omp's **2.0 GiB**. `build-unless-proven.sh` skips a check whose proof is cached,
   so on its own this one fetches them only when nixpkgs moves. Inside the routes check,
   every edit to the script would fetch 2.4 GiB on `omarchy`'s hosted runner, in a
   60-minute job.
2. **`default-agent-routes` reads the source script and `omarchy.src`'s menu,** not the
   built package. The script ships unpatched (`default.nix:1059` copies `nix-bin`, and
   no `substituteInPlace` names it), and `omarchy.src` evaluates with no build and holds
   the 24 rows, as `agent-attrs` already reads the source. A package dependency would
   rebuild `omarchy` for each of about 15 §1 breaks. `check-menu.py` still covers
   shipped rows against accepted ids, and `stale-scripts` still runs the shipped script.

## Risks carried from the spec

- The keybinding on a recorded, absent agent is silent; #1625 decides.
- Between the two merges, a working mise-installed agent re-clicked from the menu is told
  "not installed", because `bash -lc` has no shims. The default stays recorded and launches.
- A machine that installed kimi through mise with no `node` keeps `exec: node: not found`
  from an activated shell until #1625. New choosers cannot reach it.
- A script calling `omarchy-default-agent <id>` with no terminal and no display fails to
  open one rather than rebuilding unattended. No shipped caller does.
- llm-agents attribute names can go stale, and nothing here can see that repository.
- Hardware: none; p620 is unaffected until someone clicks.
