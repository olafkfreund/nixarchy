# Spec: Superwhisper arrives when the person chooses it

## Design

**Superwhisper stays the engine nixarchy recommends and preselects, but its package reaches a machine only after the person has chosen it.** The package isn't in any closure nixarchy builds before that, so nixarchy starts nothing and contacts the vendor for nothing, including the download. A person's own portable copy on `PATH` is theirs, and it behaves as it does today.

> **The owner needs to confirm this.** The approved intent says "Superwhisper is the selected engine and Alt+Space and Right Alt work" on an unfree-on machine. Here that becomes true after one choice and one rebuild, not at first boot. See "Alternatives rejected" for why first boot can't also meet the rule that nothing reaches the vendor first.

### What the capture decided

The daemon opened TLS connections to five vendor hosts within 8 seconds of starting, with no account and no key press, and no setting stops that (#1613 comment, v1.2.0, 2026-11-06). So the service must not run before the choice. The CLI also starts the service when it is absent, so every launcher would need gating too. Not having the binary gates them all at once.

### The package

- `pkgs/apps/superwhisper.nix`: the vendor's v1.2.0 x86_64 archive with a pinned hash, marked unfree, built the way `pkgs/apps/once.nix` is. Its URLs are the GitHub release and `tux.superwhisper.com`, which hold the same hash.
- `data/apps.nix`: a `superwhisper` row mapped to this package, with `unfree = true` and `prebuilt = true`, so `cache-allowlist.sh`'s `apps` filter leaves it out. It stays off in every reference, VM and runner, and a check proves that for every allowlist entry. `data/omarchy-packages.nix:721` stops saying it isn't packaged.
- **Updates:** no `passthru.updateScript`, because `.#update` would build a vendor binary on every run. A bump is a reviewed change to the version and hash. The vendor's updater doesn't run: the store path is read-only, and step 1 of the plan measures how the app reacts.

### The choice

- `setup.default.dictation.superwhisper` stays in the menu, and `omarchy-install-dictation-superwhisper` is replaced in `pkgs/omarchy/nix-bin`. It shows where audio goes, what the vendor's terms say and links to them, and asks for Cloud or Offline. If the person agrees, it opens a floating terminal the way `omarchy-default-agent` does, runs `nixarchy-app-enable` and `nixarchy-apply`, and writes the selection only after the rebuild succeeds. `omarchy-pkg-add` isn't enough: for a missing app it prints those commands and exits 1. Crash reports are set off in the app's settings before its service first starts, unless the person opts in.
- **First login:** `install/user/first-run/superwhisper.sh` is replaced with one that shows a notification pointing at that menu row, once. It never installs anything, and it records that it ran, so #278's repeat-every-login failure can't return.
- **Keys:** `default/hypr/bindings/dictation.lua` already binds only when the selected backend's command exists, so the seeded `superwhisper` file binds nothing until the binary arrives. Today's behaviour stays until the choice is made.
- **Service and integration:** enabling the app adds a user unit with store paths, in place of upstream's `setup-user`. It does not link into `~/.agents`, `~/.claude`, `~/.codex` or `~/.pi/agent`; a person can do that from the app's own instructions. The panel's `~/.local/bin/superwhisper` lookup falls through to `PATH`, which the plan checks.

### Selection

- **A machine with `dictation.enable` on keeps Voxtype.** Its F9 and Super+Ctrl+X don't read the selection file. Superwhisper arrives only if that person chooses it, and then the selection is theirs. Alt+Space and Right Alt stay unbound until then, as they are today.
- **Unfree off:** as the intent says, Voxtype is the engine with the same keys. `dictation.enable` defaults to on when `programs.nixarchy.allowUnfree` is false, which downloads its ~150 MB model on activation. A home activation step writes `voxtype` to the selection file when it reads `superwhisper` and no such command exists, since that name can't work there. `checks.stable-eval`'s Home Manager has no `services.voxtype`, so the existing name guard leaves that branch without a daemon. The Superwhisper row says it needs unfree software and how to turn that on.
- **Mode A:** nothing changes without `programs.nixarchy.enable`.

### Docs and release

`docs/manual` gains a dictation section with what the cloud mode sends, the release notes and Discussions post say how to choose, and `data/bin-ledger.nix` and `tests/session.nix:2180-2181` move with the new command.

## Coexistence

`tests/coexistence/fixtures.nix` gets fixtures for:
- a user's own portable Superwhisper on `PATH` with the app off (nixarchy doesn't touch it, and the keys bind to it as upstream's check does);
- a user's own binding on `ALT + SPACE`;
- `dictation.enable` with a seeded `superwhisper` file;
- an `x-scheme-handler/superwhisper` association from a user's config. The nixarchy unit sets none unless the plan's measurement shows sign-in needs it.

## Alternatives rejected

- **In every `enable = true` closure, service gated until the choice.** This is what "default at first boot" needs. An install would download from the vendor before anyone chose, which reaches the vendor. Reference images, VM and MicroVM runners would need it forced off to stay out of the public cache, so every check would test a machine unlike a real one, and `install`'s offline VM couldn't fetch it. A vendor outage or a withdrawn version would also fail every rebuild on every machine.
- **Fetch on first key press.** Same download-before-choice problem, and it asks for sudo mid-keystroke.
- **Carry it on the image or in the cache.** The licence text gives no permission to redistribute.
- **Run upstream's `setup-user`.** Its links point at `/usr/bin` and `/opt`, which don't exist here, and it writes into agent directories.

## Risks

- **Fewer people use it than with a silent default.** That's the price of the approved rule, and the first-login notification is there to limit it.
- **The vendor withdraws the pinned version.** Only people choosing or rebuilding with the app on are affected: their build fails naming the URL. Two mirrors reduce this, and a bump fixes it.
- **Audio is still unmeasured.** The VM's virtual microphone was refused, so what the cloud sends is the vendor's policy text, not a capture. The screen says what the policy says and doesn't claim more.
- **The binary may misbehave on a read-only store path,** or its updater may loop. The plan's first step runs it in a disposable VM, never on the host.
- **Five releases in two weeks.** Bumps fall to us, and a stale pin keeps working until the service refuses it.

## Verification

- **§1, unfree off:** `env -u NIXPKGS_ALLOW_UNFREE -u NIXPKGS_ALLOW_INSECURE`, `programs.nixarchy.allowUnfree = false` evaluates, and the row refuses in words. Enabling the app with unfree off fails with nixpkgs' message.
- **Closures:** a check that no output in `cache-allowlist.sh` has a `superwhisper` path, red when the app is forced on in the reference.
- **`session`:** a default machine has no `superwhisper` on `PATH`, no unit and no dictation keys. The first-login notification fires once and the first-run marker completes.
- **Stubbed `runCommand`:** the new command, with stub `nixarchy-app-enable`, `nixarchy-apply` and `gum`: declining writes and installs nothing, agreeing does both in that order, a failed rebuild leaves the selection unchanged, and crash reports are off before the first start.
- **Keys, in `session` or a stub of `dictation.lua`:** an unfree-off machine binds Alt+Space to Voxtype, and a `dictation.enable` machine keeps F9 and doesn't bind to a missing backend.
- **`options-*`:** the row in both states. **`coexistence`:** each fixture above, each with a break.
- **Disposable VM, not in CI:** the real archive, chosen through the real command, starts, its keys work, and traffic starts only after the choice. Named in `tests/AGENTS.md` as what no check covers, because CI must not depend on a vendor download.
- **Not covered by any layer:** audio content, and real hardware.
