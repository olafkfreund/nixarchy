# Spec: T3 Code follows the Omarchy theme when nixarchy installs it

## What `t3` does (measured)

Measured with nixpkgs' `t3code-0.1.8` (`bin/t3`), against a temporary
`--base-dir`, on 2026-11-16:

- **Untouched profile.** `t3 theme show` prints `Environment theme: not
  set.`, and `userdata/settings.json` is absent or has no `defaultTheme`.
- **After `t3 theme set omarchy`.** `settings.json` holds
  `"defaultTheme": "omarchy"` and a `defaultThemeSetAt` timestamp.
- **After the user picks another theme** (`set ember`).
  `"defaultTheme": "ember"`.
- **`set` refuses an unpublished id.** `set omarchy` before
  `userdata/themes/omarchy.json` exists fails with `ThemeIdUnknownError`
  and writes nothing. Publishing comes first.
- **An invalid palette is ignored.** `show` warns, and `set` treats the id
  as unknown. `omarchy-theme-set-t3code` already refuses to publish a
  palette with unresolved `{{` placeholders.
- **Cost:** each call takes about 0.4 s, headless, with no display, and
  each ran in a shell with only `HOME` and the XDG variables set.

The CLI therefore tells an untouched profile from a chosen one. That
removes the intent's "one overwrite": activation selects only when
`defaultTheme` is absent, so it never replaces any choice. The marker
still records that nixarchy has made its one decision, so a user who later
runs `t3 theme clear` is not re-selected.

## Design

One `home.activation` entry in `modules/home.nix`, beside
`nixarchyChromiumHosts` (:1651):

```nix
home.activation.nixarchyT3CodeTheme = lib.mkIf (appEnabled "t3-code") (
  lib.hm.dag.entryAfter [ "nixarchySeed" ] ''…''
);
```

`appEnabled` (:137) reads `osConfig`, so standalone Home Manager never
runs it. `entryAfter [ "nixarchySeed" ]` orders it after the current theme
is seeded.

Home Manager runs activation under `set -eu -o pipefail`, so "non-fatal"
is built into the script's structure, not added at the end. Every step
that can fail is the condition of an `if`, or carries `|| { warn; }`, so
the shell never exits partway. `warn` prints `nixarchy: T3 Code: <what>`
on stderr. The steps, in order:

1. **Profile.** When `config.home.sessionVariables.T3CODE_HOME` is set, the
   profile is `t3home=${lib.escapeShellArg <it>}`, so a path with spaces or
   metacharacters is one word. Otherwise it is `t3home="$HOME/.t3"`. A
   user who sets `T3CODE_HOME` only in a shell rc file does not reach
   activation, and a one-line comment names that limit.
2. **Directories:** `run mkdir -p "$t3home/userdata"
   "${config.xdg.stateHome}/nixarchy"`. If this fails, warn and skip every
   later step.
3. **Publish.** It runs `omarchy-theme-set-t3code` (`run env
   PATH=<coreutils, gnused, gnugrep>:$PATH OMARCHY_PATH=${omarchyPath}
   T3CODE_HOME="$t3home" ${omarchyPath}/bin/omarchy-theme-set-t3code`).
   That script skips when the current theme has no `t3code.json`, or has
   unresolved colours. No `omarchy-theme-refresh` runs.
   - **Published this time** means three things hold: the script exited 0,
     the source `~/.local/state/omarchy/current/theme/t3code.json` exists,
     and `cmp -s` of the source with `$t3home/userdata/themes/omarchy.json`
     succeeds.
   - Selection below needs published-this-time. A palette left over from an
     earlier theme, or from a failed publish, is never selected.
4. **Select once.** The marker is
   `${config.xdg.stateHome}/nixarchy/t3code-theme-selected`. If it is
   absent and the palette was published this time, read the setting with
   `jq -e 'has("defaultTheme")' "$t3home/userdata/settings.json"`. It has
   three outcomes:
   - **The file is missing, or jq exits 1 (no key):** untouched. Run `run
     timeout -k 5 20 "$t3" theme set omarchy --base-dir "$t3home"`, and
     only on its success, `run touch` the marker;
   - **jq exits 0 (a choice exists):** `run touch` the marker and select
     nothing;
   - **anything else** (unreadable file, malformed JSON, jq exit 2 or more):
     warn, select nothing and write no marker. A broken read never counts
     as "untouched".
   - If the palette was not published this time, nothing is selected and no
     marker is written, so a later activation tries again.
5. **`$t3`** is `${osConfig.programs.nixarchy.apps.t3-code.package}/bin/t3`.
   That is the package `modules/apps.nix:131` installs for the app,
   including a user override of `apps.t3-code.package`. It is never `t3`
   from `PATH`, and never `pkgs.t3code` (Home Manager builds its own `pkgs`,
   `modules/home.nix:80`).

**Dry-run:** mutating commands go through Home Manager's `run`, as
`nixarchyChromiumHosts` does. The `jq` read does not.

## Alternatives rejected

- **The downstream rule, "set whenever it differs".** It replaces a theme
  the user picks in T3 Code at every activation.
- **"Select while it is T3 Code's built-in default".** There is no
  built-in id in `settings.json` to compare with. An untouched profile has
  no `defaultTheme` at all, which is the clean signal used above.
- **Patch `omarchy-theme-set-t3code` to create the directory.** That
  script runs on every theme switch, on machines with and without T3 Code.
  Its early exit is deliberate.
- **Running `omarchy-theme-refresh` when the palette is missing.** It
  re-renders every app's theme, which is wider than this change.

## Risks

- **T3 Code changes its settings format.** If `defaultTheme` moves, the
  read sees "absent" and selects `omarchy` once on a profile that may have
  a choice. The marker limits that to one time per home. The check uses
  the real `t3` from nixpkgs, so a format change in a nixpkgs bump turns
  it red.
- **Hosts:** any machine with `apps.t3-code.enable`. On the owner's hosts
  the downstream workaround also runs. Both select only `omarchy`, so they
  agree until the owner removes theirs.

## Verification

- **New check `tests/t3code-theme.nix`** (cheap tier), registered in
  `flake.nix`'s `uniformChecks`. It builds a standalone Home Manager
  configuration in the shape of `tests/home-manager-writers.nix`, with
  `osConfig.programs.nixarchy.apps.t3-code = { enable = true; package =
  <fixture>; }`.
  - The fixture package's `bin/t3` appends its arguments to `$T3_CALLS`
    and then execs the real `pkgs.t3code`'s `t3`. Calls are counted, not
    inferred from timestamps.
  - **The harness runs Home Manager's own code.** It sources the pinned
    home-manager input's `modules/lib-bash/activation-init.sh`, for `run`
    and `DRY_RUN`, under `set -eu -o pipefail`, the shell the activation
    script runs in, then the entry's `.data`. Every run is wrapped in an
    outer `timeout 120`, so a broken entry fails the check instead of
    hanging it.
  - The fixture writes a valid rendered
    `~/.local/state/omarchy/current/theme/t3code.json`, unless a case says
    otherwise.
  - An evaluation assertion checks the entry's `after` list contains
    `nixarchySeed`.
  - Cases:
    1. **fresh home:** the palette is published, `defaultTheme` is
       `omarchy`, the marker exists, and there is exactly one `theme set`
       call;
    2. **second run:** no further `theme set` call;
    3. **user has `defaultTheme = "ember"`, no marker:** it stays `ember`,
       the marker is written, and there are no `set` calls;
    4. **marker present, then `t3 theme clear`:** no `set` call, and
       `defaultTheme` stays absent;
    5. **no current `t3code.json`, fresh profile:** a publish was attempted
       (the publisher ran, which the harness records by running it under a
       `PATH` wrapper), but there is no palette, no `set`, no marker, and
       status 0;
    6. **stale palette:** `userdata/themes/omarchy.json` exists from before,
       and the current `t3code.json` is missing. No `set` and no marker;
    7. **malformed `settings.json`** (`{`): no `set`, no marker, a warning,
       status 0;
    8. **unwritable profile** (`$t3home` is a file, not a directory): a
       warning, nothing else runs, status 0;
    9. **marker parent absent** (`~/.local/state/nixarchy` missing): case 1
       still writes the marker;
    10. **`T3CODE_HOME` with a space**, through `home.sessionVariables`:
        case 1 holds in that directory;
    11. **`DRY_RUN=1`:** no file is created under the temporary home, and no
        `set` call is made;
    12. **a `t3` that ignores TERM** (a fixture whose `t3` runs `trap ''
        TERM; sleep 600`): the entry finishes within 20 s plus the kill
        delay, with status 0.
- **§1, one named mutation per case:**
  - 1: the entry removed;
  - 2: the marker test removed (a second `set` call appears);
  - 3: the `jq` read removed;
  - 4: the marker test removed;
  - 5: the publish step removed (no publisher call recorded);
  - 6: the `cmp` "published this time" test removed;
  - 7: the "anything else" branch folded into "untouched";
  - 8: the `|| skip` on the directory step removed (the shell exits);
  - 9: the marker parent's `mkdir` removed;
  - 10: the `escapeShellArg` removed;
  - 11: `run` dropped from `touch` (a marker appears under dry run);
  - 12: `timeout -k 5 20` reduced to `timeout 20` (TERM is ignored, so the
    outer deadline trips).
- **Mode A:** `tests/options.nix` gains the case that
  `home.activation.nixarchyT3CodeTheme` is absent with the app off and
  present with it on.
- The generated checks and `options-files` are built locally. No VM is
  needed.
