# Plan: 32 GiB is the minimum disk, and everything agrees on it

## Approved decisions

This section carries the spec over so the plan stands on its own.

- **Why.** The owner set 32 GiB as the minimum supported disk. Today the installer
  accepts 8 GiB, install tests target 20–24 GiB, and garbage collection runs from
  5 GiB free toward an unreachable 20 GiB. On a small disk Nix 2.34.8 then
  segfaults mid-switch (NixOS/nix#15614, fixed in 2.35). That reverted #702.
- **D1. Installer floor.** `installer/install.sh` gets one constant,
  `MIN_DISK_GIB=32`:
  - `ask_device` (`:770`, message `:791`) and free-space mode (`FREE_MIN_GIB`,
    `:822`, `:947`) both use it;
  - `validate_answers` (`:1199-1202`) checks block device and type but **not
    size**; it gains the same size refusal, before formatting.
- **D2. Collection.** `installer/host.nix:170-171`: `min-free` 3 GiB and
  `max-free` 8 GiB, with the comment giving the 32 GiB arithmetic.
- **D3. Nix 2.35.** `installer/host.nix`: `nix.package = pkgs.nixVersions.nix_2_35;`,
  with a comment naming #15614 and when to remove it. Installed machines only;
  Mode A untouched.
- **D4. Test targets at 32 GiB:**
  - `tests/install.nix:463` and `tests/install-encrypted.nix:351`:
    `emptyDiskImages` 20480 → 32768;
  - `tests/install-iso.nix:410` and `tests/reinstall-vm.nix:309`:
    `qemu-img` 24G → 32G;
  - `installer/vm.nix:145`: 24576 → 32768;
  - `installer/try.sh:50`: `DISK_MB` 24576 → 32768;
  - `tests/installer-wizard.nix:42`: disks `[ 1024 12288 ]` → `[ 1024 16384 32768 ]`.
    The summary row (`:352`) moves from `/dev/vdc` to `/dev/vdd`, and the hidden
    list (`:359`) becomes `vda vdb vdc`. The 16 GiB `vdc`, over the old floor, must
    be hidden.
- **D5. Free-space check.** `tests/install.nix`, right after the installed target
  boots (`target.wait_for_unit("multi-user.target")`, `:727`): print
  `df --output=avail -B1 /` in GiB and assert at least 8 GiB.
- **D6. Manual.** `docs/manual/getting-started.md:86`, `the-iso.md:208` and
  `dual-boot-install.md:19` say 32 GiB for both modes.

## Steps

Each step is one commit with a full-sentence subject. A deviation updates this
file in the same commit.

1. **`installer/install.sh`: D1.**
   - Add `MIN_DISK_GIB=32` beside the existing `FREE_MIN_GIB` and replace
     `FREE_MIN_GIB` with it.
   - One function, `disk_under_floor <dev>`, reads `lsblk -bdno SIZE` and returns
     0 when the disk is under `MIN_DISK_GIB`. It is the single place the floor is
     compared.
   - `ask_device`: filters with `disk_under_floor`, and the message names
     `${MIN_DISK_GIB} GiB`.
   - `validate_answers`: after the block-device and type checks, refuses with
     `device: $device is under ${MIN_DISK_GIB} GiB` when `disk_under_floor` holds.
   → verify: `bash -n`; shellcheck; `grep -n "8 GiB\|8 \* 1024"` finds nothing in
   `install.sh`.

2. **`tests/installer-wizard.nix`: D4 (wizard).**
   → verify: `checks.installer-wizard` passes locally. Then put step 1's floor
   back to 8, re-run, and see it fail because `/dev/vdc` (16 GiB) is offered.
   Restore. The failing output goes in the PR (§1).

3. **`tests/installer-store-space.nix`: `disk_under_floor` driven directly.**
   Extract it with `sed` (that file's existing pattern), with `lsblk` stubbed to
   print a byte size. Cases:
   - a 16 GiB disk is under;
   - exactly 32 GiB is not;
   - a 1 TiB disk is not;
   - an `lsblk` that prints nothing counts as under, because refusing is the
     safe answer.

   `validate_answers` itself needs a real block device (`[ -b ]`), which the
   build sandbox does not have. So the shared function is what is tested, and a
   `grep` asserts `validate_answers` calls it.
   → verify: the check passes; with the comparison inverted it fails on the
   16 GiB case; with the call removed from `validate_answers` the grep fails.

4. **`installer/host.nix`: D2 and D3.**
   → verify:
   - `nix eval .#nixosConfigurations.vm.config.nix.package.version` prints 2.35.x;
   - `nix.settings.min-free` and `max-free` evaluate to 3 GiB and 8 GiB;
   - `checks.stable-eval` passes;
   - `checks.vm-toplevel` builds.

5. **`tests/options.nix`: one case `installedHostDiskPolicy`.**
   - `on`: the `vm` configuration's `nix.package` is 2.35 or later, and
     `min-free`/`max-free` are 3/8 GiB.
   - `off`: `loaderOff` has neither the pin nor these thresholds.
   → verify: `checks.options` passes; with the pin removed it fails naming the
   case.

6. **D4, the rest:** `install.nix`, `install-encrypted.nix`, `install-iso.nix`,
   `reinstall-vm.nix`, `installer/vm.nix`, `installer/try.sh`.
   → verify: every one evaluates (the driver of each install check builds
   locally); shellcheck on `try.sh`; `checks.try-preflight` passes, since it
   reads `try.sh`'s size.

7. **`tests/install.nix`: D5.**
   → verify: the driver builds, which lint- and type-checks the Python. Seen red
   in CI in step 9.

8. **Docs: D6.**
   → verify: `grep -rn "8 GiB" docs/manual` finds nothing that is a disk minimum;
   `readme-counts.sh --check` passes.

9. **Seen red in CI, once, for D5.** Open the PR as a **draft**, since `install`
   runs only on pull requests. Push a temporary commit that raises D5's bar
   above any plausible free space (for example 30 GiB).
   → verify: `install` fails at the D5 assertion, printing the measured free
   space. Capture that number: it is also the spec's 16 GiB estimate checked.

10. **Restore and prove green.** Revert step 9's commit and push. Never cancel or
    override `install` (the process rule from 2026-09-15).
    → verify: `install` passes, including the D5 print, the rebuild that builds
    nothing, and `install-encrypted` and `free-space`. `lint` and every build job
    are green.

11. **PR ready.**
    - Squash away steps 9–10.
    - The description gives the measured free space, the red outputs from steps
      2, 3, 5 and 9, and a release-note line saying installs now need 32 GiB.
    - Mark it ready, with auto-merge (squash) on `install` passing.
    - `Closes #708`.
    → verify: merges on green; `main`'s next install passes.

12. **Nightly.** `install-iso` and `reinstall-vm` are nightly-only.
    → verify: the next nightly passes both on 32 GiB targets. If one fails, it is
    reported, not re-run until it passes.

## Rollback

- **Revert.** Revert the squash commit: the installer accepts 8 GiB again,
  thresholds return to 5/20, Nix returns to nixpkgs' default, and test disks
  return to 20–24 GiB. Nothing on user machines depends on the change beyond
  their next rebuild.
- **Nix 2.35 only.** If only the pin misbehaves, drop D3's line in a small
  follow-up. The thresholds alone still keep collections off minimum-size
  machines.
