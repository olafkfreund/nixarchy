# Intent: Voice's manual entry says what Voice is, with the media to show it

## Problem

Voice's entry in the manual predates three releases' worth of the plugin, and
parts of it are not true. Every claim below was re-read on `main` at
`0ebabe4`.

**It describes a menu row that does not exist.** `docs/manual/plugins.md:404-405`:
"A **Set up voice** menu row installs it and asks which backend to use."
There is no such row anywhere in the code, and nothing asks for a backend.
`data/apps.nix` deliberately gives Voice no `menuId`: its comment says there is
no `install.ai` submenu, and that Voice "is found through Install > Search". A
reader following the manual looks for a row that is not there. The plugin's
own page copied this claim and had to be corrected (olafkfreund/nixarchy-voice#165).

**It says it is "coming", in four places.** Voice is opt-in and has been
since #774:
- `plugins.md:40`: "**opt-in**, coming";
- `README.md:470`: "Opt-in, and coming";
- `docs/index.md:90`: "Voice will be opt-in";
- `docs/llms.txt:115`: lists it as opt-in, which is right, but beside the
  others' stale wording.

**It gives three different sizes.**
- `plugins.md:403`: "about 1 GiB with its speech models".
- `plugins.md:396`: "a ~150 MB whisper model of its own, separate from the
  6.7 GiB here", which mixes two figures.
- `flake.nix` (the comment above the input): "about a gigabyte".
- `data/apps.nix:361,385` and `modules/nixos.nix:269,272`: **6.7 GiB,
  measured**.

The same `flake.nix` comment also names an option that does not exist,
`services.omarchy-voice.enable`. It is `programs.nixarchy.voice.enable` here,
and `programs.omarchy-voice` upstream.

**It has no media.** `plugins.md:408` says "*Not recorded yet*". Every other
shipped plugin has a GIF or a still.

**It pins a version that lacks what the plugin now is.** `flake.nix:227`
and the lock pin nixarchy-voice at `647f9e5`. Upstream `main` is `7c51dfb`,
which adds:
- **actions**: named recipes you can say, click in Voice ▸ Actions, or run
  from the CLI, and make by asking;
- **routines**: actions on a schedule, as systemd user timers;
- approve-once for steps that need confirmation;
- commands run in Oma's own tmux session, pasted, with their exit status
  read (nixarchy-voice#161);
- uptime answered from `/proc` (nixarchy-voice#162).

#936's nightly review already flags this pin.

## Proposed outcome

- The Voice section describes Voice as it is:
  - what it solves and what it does, including actions and routines;
  - how to turn it on here (**Install ▸ Search**, find **Voice**, apply; or
    `programs.nixarchy.voice.enable`);
  - what it costs and why it is opt-in;
  - a link to the plugin's page, which now has a three-minute recording with
    its voice.
- It carries media in this site's formats:
  - a feature GIF (900x563, 4 fps, under 1 MB);
  - a Voice ▸ Actions still, composed onto `00-desktop.jpg` per
    `docs/AGENTS.md`;
  - both made from the plugin's recording on razer, not re-staged.
- One size, the measured one, stated the same everywhere it appears.
- "coming" and "will be" are gone from the four places, with the three-lists
  rule still holding: `_config.yml` nav, `llms.txt`, and `manual/index.md`.
- The pin is `7c51dfb`, so a machine that turns Voice on gets what the
  manual describes.

## Affected users and systems

- **Docs:** `docs/manual/plugins.md` (the table row and the Voice section),
  `docs/index.md`, `README.md`, `docs/llms.txt`, and new files under
  `docs/img/`.
- **Build:** `flake.nix` (the pinned URL, and the comment's size and option
  name) and `flake.lock`. That changes the closure of any machine with Voice
  on; none in this repo has it on (`tests/options.nix` `voiceIsNotADefault`).
- **Readers deciding whether to turn Voice on,** and nixarchy's own AI agents,
  which read `llms.txt`.

## Constraints

- **No `<!-- id -->` on the Voice table row.** Voice is not in
  `defaultPluginSet`, and "Every default plugin has a row in the manual"
  (`build.yml`) fails both ways.
- **Media rules** (`docs/AGENTS.md`):
  - GIFs at 4 fps, 900 px, under 1 MB, via `tests/demo/encode-gif.sh`
    settings;
  - stills composed onto the default desktop at 16:10;
  - nothing private in frame.
- **Status is changed everywhere it is claimed, in one change.**
- **The README's derived numbers** must still pass `readme-counts.sh --check`.
- **Bumping the pin is a version change** for anyone who has Voice on. Its
  checks (`checks.options`, the unit suite) must pass on the new pin.
- **No CI-gate edits.**

## Open questions

*Decided at approval (2026-09-27, approved without answers): all three
recommendations taken. Re-measure the size at the new pin; bump the pin here;
use the plugin's menu-Run GIF.*

1. **Size.** 6.7 GiB was measured at an earlier pin. Re-measure the closure
   Voice adds at `7c51dfb` and use that number, or keep 6.7 GiB?
   **Recommended:** re-measure. The plugin changed, and the number is quoted
   in five places.
2. **Pin scope.** Bump the pin in this issue, or leave it to the nightly bump
   and fix only the docs? **Recommended:** bump here. The docs would
   otherwise describe features the pinned version does not have.
3. **The GIF.** Use the plugin's 0.94 MB GIF of the menu *Run*, or cut one
   showing an action made by asking? The readback is spoken, and a silent
   GIF cannot carry that. **Recommended:** the menu Run, which reads without
   sound. The page's video carries the rest.
