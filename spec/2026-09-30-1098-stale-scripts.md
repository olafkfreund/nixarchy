# Spec: Make the stale desktop scripts work on NixOS

## Design

1. **Installed apps open through PATH.** The pinned Omarchy source (`flake.lock:1121-1135`, revision `c668141`) contains `setsid uwsm-app -- /usr/bin/{spotify,signal-desktop,chatgpt}` in the three install commands. Add three narrow `substituteInPlace --replace-fail` edits to `pkgs/omarchy/default.nix` beside the launcher edits at `:963-984`, replacing only those execution paths with the command names. Keep `omarchy-pkg-add` and the rest of upstream's install flow. Remove these three commands from the `/usr` allowlist at `tests/session.nix:1542-1544` so a future reintroduction fails the session scan. The packaged commands, not the already-fixed `omarchy-launch-{spotify,signal}` scripts, are the subject of the check.

2. **Antigravity's installed-command probe uses `agy`.** `pkgs/omarchy/nix-bin/omarchy-default-agent:64` already maps the mise package to `agy`, and `pkgs/omarchy/default.nix:1197-1199` teaches the launcher to run `agy`. At `omarchy-default-agent:143-148`, use that installed command for the Antigravity id while retaining `antigravity` as the stored/menu id (`:96`). This prevents a working `agy` on PATH from triggering an unnecessary install.

3. **Cursor theme changes use supported runtime IPC, with a persistent fallback.** Keep GTK settings and `hyprctl setcursor` at `pkgs/omarchy/nix-bin/omarchy-cursor-set:27-35`. Replace `hyprctl keyword env XCURSOR_THEME,...` at `:36` with Hyprland's current Lua IPC, `hyprctl eval 'hl.env("XCURSOR_THEME", "<theme>")'`, using the script's fixed Bibata theme names. [Current Hyprland documentation](https://wiki.hypr.land/configuring/core/advanced-configuration/using-hyprctl/) documents `eval` and no longer lists `keyword`; its [cursor guidance](https://wiki.hypr.land/hypr-ecosystem/user/hyprcursor/) requires `XCURSOR_THEME` for legacy Xcursor clients. The runtime path is chosen only if a session check proves a new compositor-launched process inherits the selected value. **If that proof fails**, instead have `omarchy-cursor-set` write `export XCURSOR_THEME=<fixed Bibata theme>` to its own `${XDG_CONFIG_HOME:-$HOME/.config}/uwsm/env.d/90-nixarchy-cursor` file and tell the user to log in again. [UWSM's environment contract](https://github.com/Vladimir-csp/uwsm#4-environments-and-shell-profile) sources `env.d/*` at session startup; the pinned Omarchy source already ships `default/uwsm/env.d/10-omarchy`. This fallback intentionally takes effect at the next login and must not claim an immediate client update.

4. **Snapshot 0 is not a restore choice.** `pkgs/omarchy/nix-bin/omarchy-snapshot:174-180` feeds Snapper's rows to `gum choose`, then assumes every selected number has `/home/.snapshots/<number>/snapshot`. Filter number 0 out of the restore picker, while retaining the headers and the `list` command at `:155-162`. Do not change the explicit copy-back flow or touch any user's files.

5. **KVM advice is declarative.** Replace the `sudo usermod` hint in `pkgs/omarchy/nix-bin/nixarchy-preview:94-101` with `users.users.<name>.extraGroups = [ "kvm" ];`, followed by rebuild and a fresh login. The rest of `detect_kvm` and the software-emulation warning remain. Extend the existing stubbed `tests/preview.nix:120-144` check to assert this text in the `nogroup` result.

Record the affected packaged commands in `data/bin-ledger.nix` if their classifications or reasons need updating. Wire a cheap command check through `flake.nix` beside `preview` at `:1950-1957`; `tests/AGENTS.md` and root `AGENTS.md` §4 say a new flake check is picked up by CI without editing workflows. This remains a partial `Refs #1098` change.

## Alternatives rejected

- Pinning store paths into the three install scripts: user package overrides should remain usable, and PATH command names match the already-patched launchers.
- Changing the Antigravity saved id to `agy`: the menu and launcher use `antigravity` as their common id; only the executable differs.
- Deleting cursor environment propagation because `hyprctl setcursor` exists: Hyprland's guidance says legacy Xcursor clients need `XCURSOR_THEME`; the requested behavior includes new clients.
- Showing snapshot 0 and letting the missing-directory check reject it: this offers a choice the command already knows cannot work.
- `sudo usermod` as a quick fix for KVM: NixOS declarative user membership can replace it on rebuild.

## Risks

- The pinned Omarchy source may change on an upstream bump. `--replace-fail` must stop a mismatched patch rather than silently restore `/usr/bin` launches.
- `pkgs/omarchy/default.nix`'s install phase is close to the shell argument-size limit; keep the patch short and use its existing install-phase budget check.
- A PATH command might resolve to a user-provided alternative, which is intentional; the existing `omarchy-pkg-add` path still decides what to install.
- Hyprland Lua `hl.env` is documented as configuration syntax; its effect when called through runtime `hyprctl eval` has not yet been measured. The new-client session proof is a release gate, not a decorative assertion.
- If that proof fails, the UWSM fallback delays the Xcursor change for newly launched clients until login. The script must say so, write only its own shell fragment with fixed theme values, and avoid replacing a user or Home Manager managed symlink.
- Snapper's table format may change; filter the numeric snapshot field, not any row merely containing the character `0`.
- The preview hint must use the configured username placeholder, not copy a literal user name or imply `home-manager switch` is sufficient.
