# Spec: mise installs and controls nothing on a nixarchy machine

Line numbers are at `main` (Omarchy v4.5.0, `3c7da2c6`). Upstream paths are in the
v4.5.0 tree. #1622 lands first and owns every `mise` line in
`nix-bin/omarchy-default-agent`; this spec edits one other line there (§6).

## Design

The rule that shapes everything: nixarchy does not ship, run or activate mise. A
person's own mise is theirs. Only the row 12 probes still look for it.

### 1. Typed agents keep their account (rows 6, 7; decision 3)

`$out/share/omarchy/agent-dispatch/{claude,codex,grok}`, written at build by
`printf`, one line each: `exec <store>/bin/omarchy-agent-account-exec claude "$@"`.
The exec is called by absolute path, so an old shell runs its own generation.

- **PATH.** `default/bash/init` (patched in place of the mise lines), `zsh-rc` and
  `fish-rc` prepend `$OMARCHY_PATH/agent-dispatch` once, guarded so a nested shell
  does not repeat it. They are behind the existing `bashIntegration` and
  `shellIntegration` switches, so nothing else needs an option.
- **No recursion.** mise stripped its own directory for the exec (upstream `:22`).
  Now the exec has to. A small `omarchy-agent-real-path` (`nix-bin`, `# nixarchy:new`)
  prints `$PATH` without any entry ending `/agent-dispatch`. **By suffix, not by
  store path:** after a rebuild a long-lived shell still holds the old generation's
  directory, and an exact match would leave it in place and loop forever.
- **The exec** resolves the CLI under that PATH, then sets
  `PATH=<this generation's dispatch>:<real path>`, so an agent's subprocesses are
  routed too. That replaces `:50-55`, including the shims line. The 127 refusal from
  #1386 stays.
- **A dispatch entry is not an installed agent.** Exactly as with today's links,
  `command -v claude` now answers from the directory. At
  `nix-bin/omarchy-default-agent:172` that would record the agent and launch into a
  refusal telling the person to run the same command, a loop. So that check, and
  `omarchy-cmd-missing "$provider"` in `account-add`, run under the real path.
  This is the one edit in #1622's file, and it is not a mise line.

### 2. Adding an account (row 9)

`omarchy-agent-account-add:120-126` becomes one `fail`: "`$name` is not installed.
Install it with: omarchy default agent `$provider`". `fail` already prints the
`@@omarchy error` event and sends the notification, so the panel shows the cause
instead of the generic "install failed". `say installingCli` goes with it, because it
would be false. English only, like the exec's message since #1386.

### 3. Rails, Laravel, Phoenix (row 10; decision 2)

`install.development.rails`, `install.development.php.laravel`,
`install.development.elixir.phoenix`, `remove.development.rails` and
`remove.development.php.laravel` are overridden beside the existing rows at
`modules/apps.nix:887`: `disabled = "true"`, `action = "true"` (the
`omacom/omarchy#15742` reason at `:1048`), description "Not available on NixOS —
use `languages.ruby` (or php, elixir) in a project's devenv.nix". Phoenix's remove
row stays hidden. `data/menu-actions.nix:19-24` and `data/menu-exceptions.nix:67-69`
are updated to say so; `remove.development.*`'s stale "unreached" reasons go.

### 4. Typed commands (row 11)

The ledger's promise "nixarchy drops no upstream command" (`check-bin-ledger.py`,
rule 1) stays true: each becomes a `replace` in `nix-bin` that refuses with exit 1.

| Command | Says |
|---|---|
| `omarchy-install-dev-env` (all 18 arms) | Install > Development for a machine, `nixarchy dev init <lang>` for a project |
| `omarchy-remove-dev-env` | Remove > Development; for something your own mise installed, your own `mise rm` |
| `omarchy-update-mise` | nixarchy does not ship mise; if you installed it, `mise up` |
| `omarchy-mise-install`, `omarchy-mise-default-tools` | nixarchy does not ship mise. Hidden from `omarchy` help |

- `omarchy-install-hermes-cli`: delete `mise_retired`; `retire_mise` becomes one line
  saying the Hermes that mise built stays in `~/.local/share/mise`. Otherwise `--now`
  would tell a person to `omarchy pkg add mise`. Class moves `vendor` → `patch`.
- `default/bash/aliases:57` (`mup`) and `default/bash/fns/worktrees:13` (`mise trust`,
  from `ga`) are deleted at build. `ga` no longer prints an error.
- `nix-bin/omarchy-remove-preinstalls`: its stub loop and `is_mise_stub` are deleted.
  Activation has already removed every launcher (§5), so the loop can only print "Kept".

`omarchy-upgrade-to-quattro` is unreachable (`data/bin-ledger.nix:704`); it stays
vendored and recorded.

### 5. Existing machines (decision 4)

**Launchers.** `nix-bin/omarchy-mise-unshadow`, still run by
`home.activation.nixarchyMiseUnshadow`, loses its Nix-twin requirement and its grep.
A file is removed only if it is a regular file, not a link, at most 1024 bytes, and
`cmp`-identical to one of upstream's five shipped templates, rendered from the
package on its own `mise use` line and its own file name:

```
quiet, cooldown-export, bail-on-failure, mise-exec, bare-exec
```

These are the five forms in `migrations/1791382872.sh:legacy_wrapper_template`.
Today's grep only knows the first, so the older forms would have stayed and blocked
their own replacement. A file that differs by one byte, including a binary name other
than its own, stays. Each removal is printed by name.

**`~/.local/share/mise`, `~/.config/mise`, shims and wrappers are never touched.**

**The notice.** The same script writes `~/.local/state/nixarchy/mise-notice` when
`~/.local/share/mise/installs` is not empty, or it removed a launcher, or a file in
`~/.local/bin` still calls `mise` (a launcher left because it is not exact, and the
retired Hermes wrapper): tools found, launchers removed, launchers left, and the
optional cleanup.

**The activation line alone would reach nobody.** The NixOS module runs activation
in `home-manager-<user>.service`, so its stdout lands in the journal rather than on
the rebuild's terminal (a `oneshot` unit; `nixos/default.nix` sets no other output).
So the script also prints the line, for standalone Home Manager and for the record,
and a `post-boot.d` hook, the mechanism `modules/home.nix:2432` already uses, shows
the file once with `omarchy-notification-send` at next login, marking it shown. The
file stays as the record. **This goes one step past the intent's "one line at
activation", so the owner should confirm it.**

### 6. A person's own mise (decision 1)

They install it and add `eval "$(mise activate zsh)"` to their own rc. The manual
gets that line. nixarchy's rcs no longer run it, even when `mise` is on PATH.

**The intent's open question, answered from source (mise 2026.10.17, read, not run;
`checks.agent-account-routing` case 8 runs it):** their activation does put the stale
directory back. `src/cli/activate.rs:141-161` prepends `command-wrappers/bin` whenever
the directory exists, whatever the config says. That is harmless:
`src/shims.rs:979-981` states a leftover shim "falls through to the next PATH entry",
and the next `mise reshim` with no wrappers configured removes the directory
(`:1003-1007`). After a garbage collection the link dangles, and a shell skips it. So
the fall-through reaches the dispatch directory and routing still holds. Without
`/etc/mise` they also lose `upgrade.auto_prune = false` and the `cursor-agent` alias;
the manual says so.

### 7. A future bump cannot bring it back

New `checks.mise-free` (`tests/mise-free.nix`, `.github/scripts/check-mise-free.py`,
`data/mise-allow.nix`). It is a new `checks.<name>`, so `generated-checks.sh` builds it
on pull requests and `edge-build.sh` builds it on every edge run, with no workflow
edit (§4). A red edge run names it through `HELD_BY`, like `bin-ledger`.

1. **The scan.** Everything a machine runs: the reference config's `programs.nixarchy.tree`
   (the mirror, so generated menu rows count), `find -L`, roots `bin default install
   shell config applications`; plus `pkgs/omarchy/{zsh-rc,fish-rc}` and `modules/`.
   `default/i18n` is excluded with its reason (French "mise à jour"), and so is
   `migrations/`, which the replaced `omarchy-migrate` does not run. `#` comments
   stripped, then `\bmise\b|MISE_`. That over-matches on purpose: `omarchy-mise-install`
   and `.local/share/mise` both hit, and a false positive costs one row.
2. **The allowlist is per line, not per file.** `data/mise-allow.nix` maps a path to
   its exact stripped lines and one reason. A per-file row would let a recorded file
   gain a real call and stay green. It fails both ways, each naming file and line: a
   match with no row, and a row with no match, so an upstream cleanup is reported.
3. **It proves itself.** On every run it scans a fixture tree holding one new script
   that calls `mise use`, and fails if the scanner says clean. It refuses below a
   minimum file count (§5: `find` and the `result` link). So a blind scanner cannot
   stay green.
4. **The shells, with a `mise` present (§3: vary the variable).** A logging stub named
   `mise` on PATH, then `bash -ic`, `zsh -ic` and `fish -ic` through the shipped rcs.
   The log must be empty and PATH must hold the dispatch directory.
5. **`etc`.** No `mise/` row in `data/etc-overlay.nix` is `installed`. A new upstream
   file under `etc/mise` already goes red in `checks.etc-overlay`.

Recorded rows are comments in non-`#` languages, the row 12 probes, the path lookups
in `omarchy-install-openclaw-cli` and `shell/plugins/agents/collectors.py:101`,
`omarchy-upgrade-to-quattro`, `install/config/ssh-command-path.sh` and
`default/uwsm/env.d/10-omarchy` (both unread here, with that reason),
the `install/omarchy-base.packages` name, and this spec's own refusal strings.

### Release note and migration (§14)

Goes in the PR body for the release, and the Discussions post at release:

> **mise is no longer part of nixarchy.** It is off the machine, off PATH, and out of
> your shell. Anything you installed with `mise use` stops being found at your next
> shell. If your `node` disappears, that is why.
>
> Nothing you own is deleted, with one exception: launchers Omarchy generated in
> `~/.local/bin` that can only fail now are removed, and each is listed in
> `~/.local/state/nixarchy/mise-notice`.
>
> To move: see what you have with `ls ~/.local/share/mise/installs`. Turn languages on
> in Install > Development, or per project with `nixarchy dev init`. Agents:
> `omarchy default agent <agent>`.
> To keep mise: add `pkgs.mise` to your configuration, and
> `eval "$(mise activate zsh)"` to your own rc.
> To clean up, if you want to: `rm -rf ~/.local/share/mise ~/.config/mise`.

### Mode A

A configuration that imports the module without enabling anything gets no rc lines, no
activation and no `/etc/mise`, as today. `tests/options.nix` keeps both states:
`etcMise` and `etcMiseAccounts` become "not installed", and `agentWrappersReshim`
becomes "the activation step does not exist". A new `agentDispatch` case asserts the
rc names the directory when on, and not when off.

### Coexistence

New fixture `mise-own` in `tests/coexistence/fixtures.nix`:

```nix
mise-own = { pkgs, ... }: {
  environment.systemPackages = [ (pkgs.mise.overrideAttrs (o: { pname = o.pname + "-coexist"; })) ];
  environment.etc."mise/conf.d/omarchy.toml".text = "# theirs\n";
};
```

`checks.coexistence` asserts their package is in `systemPackages`, nothing else there
has pname `mise`, no nixarchy assertion fires, and `/etc/mise/conf.d/omarchy.toml` is
theirs. **It can fail:** the file name is the one nixarchy used to own, so restoring
the etc row gives a conflicting definition, and restoring the runtime package gives a
second `mise`. `environment.systemPackages` resolves a clash silently (§14), which is
why it asserts by name rather than by build.

## Alternatives rejected

- **A `drop` class and deleting the commands.** It changes `check-bin-ledger.py` and
  the "ships all of them" claim to save five small files, and a typed command would
  say "unknown" rather than why.
- **Shell functions for routing.** A function does not reach an agent's subprocesses.
- **Extending `check-bin-ledger.py`'s `PATTERNS`.** It is `bin/`-only and per-command,
  and rows 2, 5 and 11 live in `default/` and `install/`.
- **A per-file allowlist.** See §7.2.
- **`command -v mise` guards on `ga` and `mup`.** Still running mise from shipped code,
  which the rule forbids.
- **A system activation script for the notice,** which would reach the rebuild's
  terminal. It runs as root reading a person's home, for one line.

## Risks

- **New users and p620:** a failed `all.sh` edit aborts first login silently. Covered
  by `provision-launchers` and `session`.
- **`nix develop` or devenv providing `claude`** prepends ahead of the dispatch
  directory, so that `claude` runs unrouted. mise's hook kept wrappers first. Accepted:
  a project's own pin is the person's choice.
- **`command -v claude` in a terminal** answers from the dispatch directory, as it does
  from today's links. `omarchy menu` started from a terminal can dim a row for a missing
  agent; `omarchy-agent-usage-codex`'s `find_command` may see the dispatch entry. Not
  measured; the plan checks the second.
- **Tools installed through mise vanish at the next shell,** p620's `node` among them.
  Every npm-backed tool there stops. That is the ruling; the notice names them.
- **Order.** #1622 first, or `pi` and `omp` regress and `checks.mise-free` is red on
  `omarchy-default-agent`. #1612 edits `modules/nixos.nix:946-982,1537-1543` and
  `data/apps.nix`, not these lines; rebase after it (§9). #1608's carries meet the guard.
- **Edge** carries `agent-account-routing` and the account-exec patch; `--replace-fail`
  turns any upstream move into a loud build failure rather than a silent one.
