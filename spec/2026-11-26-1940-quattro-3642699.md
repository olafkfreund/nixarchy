# Spec: edge takes Omarchy quattro 3642699

Approved by the owner's standing pre-approval (2026-11-26).

## Design

From Codex's diagnosis on #1940's team (2026-11-26):

1. **Channel script.** Retarget the `omarchy-version-channel` substitution to
   the ARM-mirror comment immediately before the first lookup, which is
   unchanged in v4.5.0, `58cf525` and `3642699`. Keep `--replace-fail` and the
   existing `nixos-version` handling. `tests/channel.nix` already asserts the
   behaviour.
2. **Swappiness.** Keep 150: with swap in RAM (zram), values above 100 prefer
   cheap swap I/O to dropping file cache. Upstream's 1 fits its own 8 GiB zram
   cap plus a disk swapfile. Record `differs."vm.swappiness"` with that reason
   on the sysctl row of `data/etc-overlay.nix`, scoped so v4.5.0 and `58cf525`,
   where both say 150, still get the plain parity check.
3. **New and removed upstream files.** Classify
   `systemd/user/session.slice.d/10-omarchy.conf` and retire the HP ZBook USB
   rule's row, both held under v4.5.0 too.
4. **Pin.** `flake.nix`'s input url and `omarchyVersion`
   (`edge-20261125-3642699`) and `flake.lock`.

## Alternatives rejected

Adopting swappiness 1: it would stop zram being used until memory is nearly
gone, the opposite of why zram is on.

## Risks

The retargeted anchor is a comment; if upstream rewords it the build fails
loudly (`--replace-fail`), which is the intended signal.

## Verification

The generated checks under the quattro pin and again under v4.5.0 (§8);
`checks.channel`, `checks.etc-sysctl`, the package ledger, `omarchy` build.
Then a `from_candidate=true` edge dispatch.
