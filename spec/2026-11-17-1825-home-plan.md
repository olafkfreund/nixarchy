# Spec: `nixarchy-apply --home-plan`

All code is in `nixarchy-apply` (`modules/apps.nix`, the `text` of the
writeShellApplication; anchors below are by name because lines move).

## Design

**Contract** (binding; from olafkfreund/nixarchy-pkg#103 spec section 1).

- `nixarchy-apply --home-plan [--json]`, nothing else on the line. Any other
  flag with it (`--yes --no-preview --detach --release-home --status --log
  --follow --invocation --expect-sha256`) exits 2 with the usage text, which
  gains `nixarchy-apply --home-plan [--json]`. Bare `--json` without either
  `--status` or `--home-plan` is unchanged (not in scope).
- Success, exit 0, one line on stdout, for every decision including `refuse`.
  With `--json`, in this key order, all seven always present:
  `{"version":1,"owner":S|null,"caller":S,"state":"seed|edited|absent",
  "action":"claim|copy|keep|refuse","renderUser":S|null,"message":S|null}`.
  `owner` is `null` for `""`. `renderUser`: `claim`/`copy` the caller, `keep`
  the owner (`null` when none), `refuse` `null`. `message` is the refusal text
  exactly as apply prints it (with the `nixarchy-apply: ` prefix, no newline)
  for `refuse`, else `null`. Without `--json`: one human line
  `home owner: <o|none>; caller: <c>; home.nix: <state>; apply would: <action>`
  (not a contract).
- Failure, exit 1, one line on stdout under `--json`:
  `{"version":1,"error":"<text>"}` and the same text on stderr. Without
  `--json`, the text on stderr only. `<text>` is what apply prints on stderr
  for the same failure, trailing newline stripped (multi-line texts keep inner
  newlines). Cases: `read_owner` fails, the snapshot cannot be read or copied,
  the seed cannot be compared, the caller name is invalid, the flake directory
  is missing, `mktemp` or `id` fails. An error is never `action: "keep"`.
- Strictly read-only: no lock, no `mkdir` outside a private `mktemp -d`
  (removed by the same `trap` apply uses), nothing written under `$base`,
  `~/.config/nixarchy`, `$applied` or `$XDG_STATE_HOME`. `apps.nix` need not
  exist; the flake directory must.

**Code shape.**

1. Parse: add `--home-plan) homeplan=1`. After the loop, if `homeplan` and any
   of `yes nopreview detach release_home status wantlog follow asked`, or a
   non-empty `expect`, are set, print the usage and exit 2. The `--home-plan`
   branch sits with the other read-only modes, so the branch guard
   `[ -n "$detach" ] || nixarchy-branch-guard "$flake"` also skips it
   (`|| [ -n "$homeplan" ]`).
2. Move the pure function definitions `select_home_src snapshot_home
   classify_home valid_user read_owner home_decide` from after the lock to
   just after `dest=...`, and the `srcdir=` assignment with them. Definitions
   only: apply's calls keep their place and order, under its lock (so apply
   still decides under the lock; `--home-plan` is advisory, not a reservation,
   and the manual says so). `tests/home-selection.nix` extracts functions by
   name with `sed`, which keeps working.
3. Three new small functions beside them, used by apply AND `--home-plan` so
   there is one copy of each rule:
   - `home_refusal_text <owner> <user>`: prints apply's refusal text, no
     newline. Apply's refuse arm prints it with `echo ... >&2`.
   - `home_decision <user>`: requires `owner` and `home_state` set. Runs
     `valid_user "$user"` (error `nixarchy-apply: invalid user name: <user>`),
     then `home_decide`, then sets `home_action`, `render_user` (the `case`
     now in apply: claim/copy the user, keep the owner, else empty) and
     `home_message` (refusal text for `refuse`, else empty). Returns 1 on any
     failure. Apply's non-release arm calls it instead of its inline
     `home_decide` and `case`; its refuse arm prints `$home_message`; its
     `render_user` validity line stays as is (test 11 greps it).
   - The flake-missing text, as a variable `no_flake_msg` used by apply's
     existing `[ -d "$flake" ]` branch and by `--home-plan`.
4. The `--home-plan` branch goes after `dest=` and the function definitions,
   before `[ -f "$file" ]`: check `$flake`, `pinned=$(mktemp -d)` with the
   existing `trap`, `user=$(id -un)`, then
   `{ snapshot_home && classify_home ${homeTemplate} && read_owner &&
   home_decision "$user"; } 2>"$pinned/err" || plan_fail "$(cat err)"`, then
   print. `plan_fail` prints the JSON error when `--json`, the text on stderr,
   exits 1, and substitutes a generic text for an empty one. Every step runs
   inside the `||` context so `set -e` cannot skip the JSON. The render-user
   validity line is not repeated: `render_user` is the caller (checked), the
   owner (checked by `read_owner`) or empty.

**Hardenings in the shared code (apply gets them).**

- `classify_home`: `cmp -s` exit 0 `seed`, 1 `edited`, above 1 an error
  (`nixarchy-apply: cannot compare home.nix with the seed`, return 1). A
  non-empty `home_snap` that no longer exists is the same error, not `absent`
  (drop the redundant `[ -f ]`). Apply's call becomes `classify_home ... ||
  exit 1`.
- Caller name: `home_decision` validates the caller on every decision. The
  one deliberate tightening: a user whose name fails `valid_user` (dotted or
  upper-case) can no longer run apply on the `keep` path. `--release-home` is
  exempt (not a `home_decide` decision), and such a user could never be an
  owner. Stated in the manual.
- `read_owner`: a `grep -c` exit above 1 (unreadable `nixarchy-apps.nix`) is an
  error `nixarchy-apply: cannot read <dest>`, not `|| true` followed by bash
  integer errors and the "several owners" text.

**Docs.** `docs/manual/configuration.md`, in the home-owner section: the
command, the JSON shape and exit codes, "advisory, apply decides again under
its lock", and the caller-name tightening. `modules/AGENTS.md`: a paragraph in
the existing home-owner area (find with `grep -n "release-home"`) on the
single decision path, read-only, and the moved definitions. Also add
`--home-plan` to the usage text.

## Alternatives rejected

- A copy of `home_decide` in nixarchy-pkg: drifts (rewritten once by #1820).
- A separate script/binary for the plan: would need the function bodies
  duplicated or sourced out of the apply script, and a second bin-ledger row.
- Moving apply's calls before the lock to share one code path: apply must
  decide under the lock (concurrent applies would decide from stale state).
- `--capabilities` marker: `version` serves; the consumer does not use one.
- Exempting `--release-home` from nothing / checking the caller in release
  too: release is not a decision; stricter would lock users out of the cure.
- Reporting `message` without prefix: the contract says "exactly as apply
  prints it".

## Risks

- Moving definitions: behaviour-neutral for bash, but a function used before
  its definition would fail. All six are only called after the lock; the
  existing tests plus case 8 (end to end) cover it.
- `valid_user` on the caller can refuse a previously working caller (named
  above, documented, release exempt).
- A read-only plan could drift from apply if someone edits one path: they
  share `home_decision`, and the new test drives both from the same fixtures.
- Unsearchable directories (EACCES on `$flake`) make `[ -f ]` quietly false in
  plan and apply alike. Residual, unchanged from apply's read side; not
  addressed here.
- `--home-plan --invocation` with no argument exits 1 via `${1:?}` before the
  JSON path. Pre-existing parser behaviour for every flag; not changed.
- Coexistence (CLAUDE.md s14): no merged env or option is touched; none.

## Verification

All in `tests/home-selection.nix` (cheap tier, runCommand). Callers other than
the real one use real `id -un` as caller and `alice`-style owners that differ
from it, because apply's own coreutils beat a PATH stub.

1. Every row of the contract table end to end through `nixarchy-apply
   --home-plan --json` against a fixture flake: owner none/self/other times
   file seed/edited/absent (9 rows), each with exact JSON compared by `jq -S`
   and key order by `jq -c` string equality; plain `--home-plan` human line;
   malformed owner (two owner lines) gives exit 1 and the error object with
   the "several home owners" text on stdout and stderr.
2. Usage: `--home-plan --yes`, `--status`, `--detach`, `--release-home` exit 2;
   missing flake exits 1 with the error object; no `apps.nix` needed.
3. Read-only: a checksum of the flake tree, `$XDG_CONFIG_HOME` and
   `$XDG_STATE_HOME` (file list and hashes) before and after each run is
   identical, and `$XDG_STATE_HOME/nixarchy` still does not exist.
4. Function level: `classify_home` on a nonexistent seed returns 1, not
   `edited`; `home_decision` with caller `Bad.User` returns 1; `read_owner`
   on an unreadable file returns 1 with "cannot read" (skipped as a root-run
   no-op is not allowed: use a directory path as `dest`, so `grep` exits 2).
5. Apply still works: the existing cases 8 to 11 and own-* pass; the refusal
   text apply prints is byte-identical (an existing assertion, kept).
6. Break proofs (CLAUDE.md s1), output into the PR: revert the `cmp` rc>1
   branch, make the plan print `keep` for `refuse`, drop the read-only
   (`mkdir` the state dir), drop the caller check; each makes a named case
   fail. Then restore and see green.
7. Build every `generated-checks.sh` target and the claimed checks the files
   reach (`bin-ledger`-like, options shards: `modules/apps.nix` is options-
   reachable), statix, deadnix, `nix fmt`.
