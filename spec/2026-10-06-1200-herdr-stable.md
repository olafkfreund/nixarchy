# Spec: stable machines evaluate with the default herdr widget

## Design

### 1. The fallback reads Hyprland's nixpkgs pin

`modules/home.nix:2031` changes from

```nix
(pkgs.herdr or inputs.nixpkgs.legacyPackages.${pkgs.stdenv.hostPlatform.system}.herdr)
```

to

```nix
(pkgs.herdr or inputs.hyprland.inputs.nixpkgs.legacyPackages.${pkgs.stdenv.hostPlatform.system}.herdr)
```

and the comment above it says why: on an installed stable machine
`inputs.nixpkgs` is the user's 26.05 (the template's `follows`), while
Hyprland's pin is never overridden and stays nixos-unstable. In `flake.lock`
Hyprland's `nixpkgs` is its own node, not the root's, and on 2026-10-06 it has
herdr 0.9.1. `modules/nixos.nix:14` (`hyprPkgs`) already reaches that pin.

Unstable machines are unchanged, because `pkgs.herdr` exists there and the
fallback is never evaluated.

### 2. `stable-eval` evaluates the way an installed machine is wired

`stableVm` (`flake.nix:586`) is built from nixarchy's own inputs, so its
`inputs.nixpkgs` is unstable, which hides this bug. It becomes the template's
wiring: nixarchy's modules built from inputs whose `nixpkgs` is
`nixpkgs-stable` and whose `home-manager` is `home-manager-stable`:

```nix
stableInputs = inputs // {
  nixpkgs = nixpkgs-stable;
  home-manager = home-manager-stable;
  self = self // {
    nixosModules = self.nixosModules // { nixarchy = import ./modules/nixos.nix stableInputs; };
    homeManagerModules = self.homeManagerModules // { nixarchy = import ./modules/home.nix stableInputs; };
  };
};
stableVm = nixpkgs-stable.lib.nixosSystem {
  system = "x86_64-linux";
  specialArgs = { inputs = stableInputs; };
  modules = [ stableInputs.self.nixosModules.nixarchy ./vm/configuration.nix ];
};
```

`self` is overridden as well, because `installer/host.nix:210` (which
`vm/configuration.nix` pulls in) takes the Home Manager module from
`inputs.self.homeManagerModules.nixarchy`, and `modules/home.nix` is where
herdr lives. Overriding only `nixpkgs` still evaluates the herdr line against
unstable.

`stable-eval` runs on every pull request, so this bug class is caught at PR
time. Its existing assertions keep working under the new wiring: quickshell
evaluates to 0.3.1 (floor 0.3.1), and `herdrInstalled` now has to hold through
the real fallback.

The comment above `stableVm` is updated to say that it mirrors
`installer/template/flake.nix`'s `follows`, and that the bug in #1200 is why.

## Alternatives rejected

- **Package herdr in this flake.** A Rust build on every stable machine and
  another package to bump, when an unstable pin is already in the closure.
- **A new non-followed `nixpkgs-unstable` input.** That means another input
  to lock and keep fresh, and users can override it by accident. Hyprland's
  pin is already locked, already fetched, and deliberately not followed.
- **Drop herdr on stable.** It reverses #792, and stable-eval's #790
  assertion exists to stop that.
- **Rely on #1199's weekly stable session test.** That catches it a week
  late. The intent asks for PR time.

## Risks

- **A future Hyprland bump moves to a pin without herdr, or Hyprland starts
  following nixarchy's nixpkgs.** stable-eval then fails on the PR that does
  it, which is the point of 2.
- **Stable users get herdr 0.9.1 rather than 0.9.3.** The version follows the
  Hyprland pin's date. Acceptable for an optional CLI.
- **The rewired `stableVm` surfaces other stable-only failures** that the old
  wiring hid. The probe on 2026-10-06 found none besides herdr: the system
  evaluates once the fix is applied. If one appears later, it is a real bug
  of the same kind and gets its own issue.
- **Closure growth on stable machines**: herdr from another nixpkgs brings its
  own runtime closure, which is small and glibc-matched to Hyprland's.

## Verification

- `nix build .#checks.x86_64-linux.stable-eval -L` fails before 1 and passes
  after it, with the 2 rewiring in place. Both results are recorded in the PR.
- `nix eval .#nixosConfigurations.reference.config.system.build.toplevel.drvPath`
  (or whichever unstable configuration CI evaluates) is identical before and
  after: the unstable closure does not change.
- The repository's PR checks pass.
