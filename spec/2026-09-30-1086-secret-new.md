# Spec: Guard system secret creation and the editor environment

## Design

1. In `pkgs/secret.nix:499-521`, reject `new` for a system secret unless `$FLAKE/hosts/$HOST` already exists as a directory. Do this before `require_host_key`, policy creation, `sudo`, or editor launch. Print that this flake uses the older flat layout and must be migrated to a per-host layout before using system secrets. Do not create that directory. The user-secret branch at lines 501-509 remains available. This preserves the existing layout decision in `modules/apps.nix:3529-3537` and the owner's decision to refuse rather than support system secrets on flat flakes.

2. Replace the substring `grep` in `pkgs/secret.nix:330-333` with a read-only structural policy query shared with `pkgs/sops-policy-add.nix:59-77`. Match the exact `hosts/$HOST/secrets\\.yaml$` creation rule and compare its first age recipient with `ssh-to-age -i "$HOST_KEY.pub"`. Keep `enroll`'s existing append behavior and refusal codes; `new` must never append to an existing policy or rewrite an encrypted file. On a missing rule, direct the user to `nixarchy secret enroll`; on a different recipient, refuse with the current-vs-policy mismatch and tell the user to correct the rule and rekey existing secrets. A matching rule may proceed. The shared query must not treat a comment, another host's path, or a second rule after an earlier conflicting rule as coverage.

3. For both system `new` and `edit` (`pkgs/secret.nix:521,558`), keep `SOPS_AGE_KEY` in the root-side SOPS process but launch its editor through an `env -u SOPS_AGE_KEY` boundary. Preserve SOPS's editor order: `SOPS_EDITOR`, then `EDITOR`, then its `vim`, `nano`, `vi` fallback. `pkgs/secret.nix:76-78` currently exports the key and `exec`s SOPS. Upstream SOPS [`cmd/sops/edit.go`, `runEditor`](https://github.com/getsops/sops/blob/main/cmd/sops/edit.go) selects `SOPS_EDITOR` before `EDITOR`, tokenizes it with `shlex.Split`, and calls `exec.Command(...).Run()` without setting `Cmd.Env`; therefore the editor inherits `SOPS_AGE_KEY` today. Set an editor command that unsets the key only in the editor child, without placing the key in argv or changing the environment SOPS itself needs. Preserve editor arguments and report a missing editor as an error.

## Alternatives rejected

- Create `hosts/$HOST` or silently migrate the flat flake: that changes where `nixarchy-apply` writes and can leave a root-owned destination. The owner requires refusal before side effects.
- Keep substring matching or parse YAML with `grep`: a stale recipient or comment can satisfy it. The existing policy helper already uses `yq` for the exact rule.
- Call the existing append helper from `new`: a missing rule would be added without the user's explicit `enroll` action.
- Remove `SOPS_AGE_KEY` before starting SOPS, or put the private key in arguments: the first breaks decryption and the second exposes the identity through process arguments.
- Scrub `EDITOR` alone: SOPS gives `SOPS_EDITOR` precedence, and a root environment may set it.

## Risks

- Older flat-layout users can no longer use `new` for system secrets; the refusal must explain migration before they change their flake. User secrets remain usable.
- A policy with multiple matching rules is ambiguous because SOPS uses the first. The query must refuse a conflicting first rule, even if a later rule matches this host key.
- Wrapping the editor can change command parsing or fallback selection. Match SOPS's current preference and exercise an editor with arguments.
- The private identity remains in SOPS's root process environment by design; the security boundary here is the editor and its children.
