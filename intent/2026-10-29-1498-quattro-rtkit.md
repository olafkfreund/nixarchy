# Intent: edge follows Omarchy quattro's rtkit change

## Problem

Edge stopped at quattro `d11c3c7`. The next commit, `8478247`, is red in two
guards, so edge kept its last good pin (run 40827243812):

- `checks.bin-ledger`: a new command, `omarchy-realtime-repair`, calls
  pacman and `systemctl`, and has no row.
- `checks.etc-overlay`: two new files,
  `pipewire/client.conf.d/50-omarchy-rtkit.conf` and
  `pipewire/jack.conf.d/50-omarchy-rtkit.conf`, have no row.

Behind both is one upstream change. quattro now installs **rtkit**, so
PipeWire gets realtime priority (omacom/omarchy#9390: without it, audio runs
at normal priority and drops out under load). The two files make PipeWire
clients ask rtkit directly rather than through xdg-desktop-portal. A portal
started before rtkit existed reports a budget of 0, which becomes a hard
`RLIMIT_RTTIME` of 0, and the kernel kills the process once rtkit makes one
of its threads realtime. The repair command installs rtkit with pacman and
raises those zero limits. Only a migration and `omarchy-upgrade-to-quattro`
call it, and nixarchy runs neither.

nixarchy enables PipeWire (`modules/nixos.nix:1591`), but not rtkit:
`security.rtkit.enable` evaluates to `false` on the reference VM.

## Proposed outcome

- Edge publishes quattro `8478247` and later.
- Both guards are green, with a row for each new item that records the
  decision.
- The decision on realtime audio is written down: follow upstream with
  rtkit, or decline it with a reason.

## Affected users and systems

- Edge users now.
- `main` users at the next stable bump that contains this commit.
- Anyone who already set `security.rtkit.enable` themselves (Mode A).

## Constraints

- A row for a file or command that main's pin (v4.5.0-rc2) does not ship is
  stale on main. So the ledger and `/etc` rows are edge carries on
  `edge-candidate`, followed by a `from_candidate` dispatch, as earlier edge
  fixes were.
- Mode A: anything set in a module is `lib.mkDefault`, and a user's own
  `security.rtkit.enable = false` wins.
- No `/usr` paths and no pacman calls reachable at runtime.

## Open questions

1. **rtkit.** Should nixarchy turn on `security.rtkit.enable` (as
   `mkDefault`), following upstream?
   - If yes: on edge only for now, or on `main` as well? On main, without
     the two PipeWire files, a session that was already running when the
     switch added rtkit could hit the zero-budget kill until the user logs
     in again.
   - If no: the two PipeWire files are classed `divergent`. They do nothing
     useful without rtkit, though they are harmless.
2. **The two PipeWire files.** Installing them as they are (`installed`, a
   symlink at upstream's path) is my default. The alternative is declaring
   the same setting through `services.pipewire.extraConfig.client` and
   `.jack` (`native`).
