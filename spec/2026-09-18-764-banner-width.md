# Spec: the NIXARCHY banner fits the window it is printed in

## Design

**Redraw only NIX so that ARCHY sits exactly where upstream's does.** Upstream's
banner is O and M in columns 1-26, a gap, then ARCHY in columns 28-81. Ours puts
N, I and X in columns 1-31 and ARCHY in 34-87. Two gaps of 3 between N, I and X
drop to 1, the same single-column gap upstream leaves between its own letters.
The I drops from 7 columns to 5: its flared cap (`▄█████▄` over `▀███▀`) becomes
`▄███▄`, and its foot likewise. N and X keep their exact glyphs.

(Shown without the file's leading blank line. The first line is the fixed
10-line shape, 81 columns wide.)

**Columns 28-81 of every line are upstream's own `logo.txt`, byte for byte.**
That fixes a bug in the current banner along the way. Its bottom-row descender
(`███   █▀`) sits under the A, at column 34, where upstream draws it under the
R, at column 40. The ARCHY half was sliced from a copy that had been shifted, so
"sliced from upstream" was true of the letters but not of where they sit.

**One file changes: `pkgs/omarchy/branding/logo.txt`.** The same file feeds the
banner (`default.nix:474`), the Plymouth frames (`default.nix:1728`) and the
seeded screensaver (`modules/home.nix:807`). The intent decided that one file
serves all three.

**The assertion is part of the omarchy package build**, next to the `install`
at `default.nix:474`. Upstream's `${src}/logo.txt` is in scope there, so the
build fails if:

1. any line of ours is wider than upstream's widest line (81 today). This tracks
   upstream's width rather than hard-coding 81, because upstream's window rule
   is sized for upstream's banner;
2. the line count differs from upstream's (10);
3. columns 28 onward of any line differ from upstream's. This catches both
   drift in the sliced half and an upstream redesign of ARCHY, and says which.

A build-time failure in the package is where this file's siblings already fail
(the Plymouth frame count at `:1729`, the script hash at `:1779`). The package
is built by every workflow that builds the system, so no new `checks.<name>`
and no workflow edit.

## Alternatives rejected

- **Widen the shared floating-window rule.** It sizes every floating window,
  including ones that are not ours. It also breaks again at the next font-size
  increase. Rejected in the intent.
- **Generate the banner at build time** from upstream's file plus a NIX glyph
  table, as `nixarchy-logo.py` does for the SVG wordmark. That tracks an upstream
  ARCHY redesign automatically, but it adds a generator to guard ten lines. The
  assertion's check 3 gets the same protection by failing loudly instead, and a
  person redraws. Revisit if upstream changes its banner more than once.
- **Narrow X instead of I.** X's diagonals need 9 columns to read as an X at
  this height. The I is the only glyph with width to spare.
- **Keep the 7-column I and shrink only the gaps.** That comes to 82 columns,
  one over.

## Risks

- **Plymouth handoff.** The frames are rendered on a fixed 90-column canvas
  (`default.nix:1726`), so every frame keeps the same pixel size and the
  same-size assertion (`:1755`) still holds. But the wordmark's ink is 6 columns
  (~54 px at `-pointsize 15`) narrower. At the end of the animation, `logo.png`
  (the SVG wordmark, a different drawing) replaces the last frame, and the
  comment at `:1740-1743` says their widths were matched so the handoff does not
  jump. Verified by rendering both and comparing ink bounds. If the jump is
  visible, the lever is the frames' `-pointsize`, not the text.
- **The frame count assertion** (`frames=128`) depends on ttfx's effect for this
  input. A different banner may give a different count. If it does, the build
  fails as designed and the number moves in the same commit, after checking
  the animation.
- **Existing homes keep the old screensaver art.** `seed_file` does not
  overwrite, which is its point. Only new homes get the narrower one. This is
  expected and not worth a migration.
- **`tests/session.nix:926`** compares the seeded screensaver with the package's
  `logo.txt` byte for byte. It follows the new file on its own.
- **The installer's banner** (`installer/brand/logo.txt`, 92 columns) is a
  different file in a different window. It is out of scope here.
