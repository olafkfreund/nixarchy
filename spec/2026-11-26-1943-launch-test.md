# Spec: a bumped app is launch-tested, so the bump merges itself

Approved by the owner's standing pre-approval (2026-11-26). The design is Codex's read-only pass, taken as written. Branch protection is not changed by this work: the arming is conditional, inside update.yml.

## Design

Use a dedicated hosted KVM launch job in `update.yml`. Open the bump PR as a draft, test the exact PR head, and make it ready and arm auto-merge only when every changed app has a passing launch result and the full diff contains only approved version and hash replacements. Keep the existing required repository checks in force. [Issue #1943](https://github.com/olafkfreund/nixarchy/issues/1943)

### 1. Select and launch the changed apps

- **Select from the final PR diff.** Once the updater and build steps have reverted failures, take the PR number and head SHA from `create-pull-request`. Fetch the head and its merge base with `main`, then inspect the complete Git tree diff. Use the modified `pkgs/apps/*.nix` files as the launch list. Resolve each path through the existing `.#update.pinned` package set and verify the definition path using `meta.position`, as the build step already does for reverts. Use `meta.mainProgram` or the shipped desktop entry for the command. For example, `hey-cli.nix` exports `.#hey-cli`, whose executable is `hey`. An empty diff, unknown mapping, or missing launcher yields an explicit reason and no merge eligibility. - **Boot one small guest for the GUI apps.** Build the selected packages from the pinned head and include them in a single NixOS guest with a normal unprivileged Hyprland session, D-Bus, XWayland as needed, and software rendering. Reuse `session.nix`’s real login seat and compositor dispatch pattern. Launch each app through its shipped launcher, allow up to 45 seconds for a new mapped `hyprctl clients -j` window, then require the same window and its owning process to survive another 10 seconds. Match the expected app class and associate the client PID with that launch. This catches both a crash before the window appears and a crash after a splash window. Clean up each process tree and record per-app results, launcher logs, and client JSON on failure. ### 2. Runner and budget

Put `launch` after the existing hosted `bump` job and before a separate `arm` job. Run it on `ubuntu-26.04` with read-only permissions and keep `BUMP_TOKEN` out of the launch job. Reuse the hosted `box` job’s Nix setup, disk cleanup, and writable `/dev/kvm` preflight. Start with a **15-minute warm-run target and a 40-minute job cap**, including closure builds. Measure both warm and cold runs before enabling auto-merge. Missing KVM or a timeout leaves the PR in draft. This uses neither p620 install slot and needs no `vm-host-free.sh` change. That script currently coordinates only install and edge jobs, so moving this to p620 would require explicit shared-host coordination. ### 3. Merge gate

- **Prove the content.** Follow `pin-fix.sh --only-nixpkgs`: inspect the actual head against its merge base and compare the complete before/after content. Require a nonempty diff of in-place modifications to regular, existing `pkgs/apps/<name>.nix` files. At approved pin locations, allow only the literal value to change. Cover `version`, source hashes, dependency hashes such as `cargoHash`, `npmDepsHash`, and `vendorHash`, and the architecture-keyed SHA-256 maps in `hey-cli` and `once`. Validate literal formats and require everything else to be byte-identical after replacing those values with placeholders. This rejects changes to URLs, wrappers, Nix expressions, file modes, and paths outside the app directory. ### 4. Login, hardware, and non-windowed apps

Keep a small checked-in table of probe commands and expected window classes or documented exceptions. For an explicitly approved Electron or AppImage package, a stable app-owned login or onboarding window can count. Run normal launchers with a fresh profile and no credentials. Use software rendering where it exercises the shipped launcher. An app that needs external connectivity, an authenticated session, or hardware to reach the observable startup state gets a named **manual check required** result that blocks automatic merge. Apply the same rule to non-windowed packages until their real entry point has a probe. The titlebars package is a Hyprland plugin, and the screensaver is installed under `lib/omarchy-screensaver`. The existing body’s claim about two proprietary Electron bundles should go. The inspected catalogue includes native Qt, Wails, CLIs, plugins and a wrapped proprietary Superwhisper binary without an updater.
