# Spec: Setup > Remote desktop offers gliff

## Design

### 1. One row, appended to `remoteMenuRows`

`pkgs/omarchy/default.nix`, `remoteMenuRows` (line 174). The awk step that
already splices this file in before `"setup.default":` carries the new row
with it, so nothing else in the install phase changes. The new row goes after
`setup.remote.connect`:

```jsonc
"setup.remote.gliff": {"icon":"󰐲","label":"Connect with gliff","aliases":["gliff","remote","connect","omarchy","hyprland"],"when":"command -v gliff >/dev/null","action":"uwsm-app -- gliff"},
```

- **The action is `uwsm-app -- gliff`.** That is how the generated menu
  already launches a GUI app (`uwsm-app -- localsend`). gliff is a GTK window
  with its own address bar and a tab per remembered machine (gliff's README,
  "Use"). Launched bare, it either reconnects to the machines it had open or
  opens with the address bar ready. No terminal and no host prompt, as the
  intent decided.
- **`when` is `command -v gliff`**, the same shape the connect row uses for
  its RDP client (§2). A machine that dropped gliff with
  `preinstallsExclude` does not get a row that names a missing command.
- **The icon is 󰐲**, which the connect row already uses. It is proven to
  render, and both rows mean "connect out". Choosing a new glyph risks tofu
  (the comment above `remoteMenuRows`).
- **The label says "with gliff"**, and the row sits beside "Connect to a
  machine", so the two read as two ways to connect.
- The comment above `remoteMenuRows` gains two lines: why this row has a
  `when`, and that it opens gliff's own window rather than a wizard.

### 2. A check that the row exists, is gated and launches gliff

`tests/remote-tunnel.nix` already reads the generated menu
(`${omarchy}/share/omarchy/default/omarchy/omarchy-menu.jsonc`) and asserts
the connect row's `when`. A sibling block asserts three things about the
gliff row:

1. a `"setup.remote.gliff"` row exists;
2. its `"when"` names `gliff`;
3. its action runs `gliff`.

Each failure prints the row it read. This is cheap, a grep of a file the
check already has. It does not go in `checks.options`, which costs about
8 minutes and 11.5 GB.

### 3. The manual

`docs/manual/remote-desktop.md`, section "Between two nixarchy machines:
gliff", gets one sentence: **Setup → Remote desktop → Connect with gliff**
opens it, the same as the app launcher does. This mirrors how the RDP section
names its rows at lines 121 and 257.

## Alternatives rejected

- **A gliff branch inside `nixarchy-remote connect`.** That puts a gum wizard
  in a floating terminal in front of a GUI that already picks the machine.
  It also means more script, more `runtimeInputs` and a new verb for
  `tests/menu-verbs.nix`, for no gain. The intent rejected it too.
- **Replacing or relabelling "Connect to a machine".** Out of scope (intent
  constraint). RDP is still the only way in from Windows, macOS and phones.
- **A host prompt before launching.** It duplicates gliff's address bar and
  loses its remembered tabs.
- **`omarchy-launch-or-focus gliff`.** Focusing an existing gliff window would
  be nice. But no generated row uses it for an app, and gliff already keeps
  every machine as a tab in one window. `uwsm-app` is the house idiom.

## Coexistence

None. The change adds one menu row inside nixarchy's own generated menu. It
sets no NixOS option and touches no merged environment, so there is nothing
for `tests/coexistence/fixtures.nix` to vary.

## Risks

- **The row shows but gliff fails to reach a host:** the far end has no sshd
  or no logged-in session. That is gliff's own error in its own window, and it
  was documented by #1227 in the manual section this row links into. The row
  does not make it worse.
- **`omarchy-menu.jsonc` stops parsing:** `check-menu.py` already parses the
  generated file at build time, so a bad row fails the `omarchy` build rather
  than shipping a menu that does not open.
- **The `omarchy` package rebuilds.** Its output changes, so the cache gets a
  new `omarchy` path. That happens on every commit anyway (#212). No new
  allowlist entry.

## Verification

- `checks.remote-tunnel`, green. **Break proof (§1):** delete the gliff row
  from `remoteMenuRows` and the check fails on "no setup.remote.gliff row".
  Remove its `when` and it fails on the gating assertion. Restore it with
  `git checkout HEAD --` and it is green again. Build each by drvPath (§5).
- The `omarchy` build's `check-menu.py` parses the menu.
- On p620, after the merge and a rebuild: Setup → Remote desktop shows
  "Connect with gliff", and clicking it opens the gliff window. This is
  manual; the PR says so.
