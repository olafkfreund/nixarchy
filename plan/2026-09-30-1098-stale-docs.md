# Plan: Correct stale hypr-rdp and snapshot descriptions

Refs #1098. This is a documentation-only correction. `flake.nix:127-129` and `flake.lock` pin hypr-rdp v0.1.6. Its pinned `src/config.rs` supports `password_file` and refuses a missing or empty **named** file. It still warns and serves without authentication when no credentials are configured; a username with an empty **inline** password likewise gets only a `HalfCredentials` warning and continues instead of refusing startup. The module's `password = ".+"` guard at `modules/services/hypr-rdp.nix:142-143` catches that third case. Keep the whole guard and its runtime secret rendering; migrating to `password_file` is separate work. `omarchy-snapshot create` and `restore` operate on `/home`; the installer separately takes a boot-time root snapshot that includes `/var/lib`, which the command can list but does not create or restore. Neither service behavior nor snapshot behavior changes.

Risks: confusing a named password file's refusal with either fail-open case could encourage removal of the security guard; a malformed quoted ledger reason could break Nix evaluation; and the upstream facts must be rechecked if the pin moves. Do not add a permanent test that only checks chosen wording or broaden this issue into a runtime migration.
