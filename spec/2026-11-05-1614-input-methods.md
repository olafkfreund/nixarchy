# Spec: Omarchy's input methods can be chosen and used on nixarchy

Upstream paths are in the v4.5.0 tree. "Measured" means I ran it on 2026-11-05 at
this branch's nixpkgs pin. "Read" means source only, not run. Nothing here booted a
VM or built an ISO: CI had runs in flight, so §6 forbade both.

## Design

### 1. The addon list

Add beside `modules/nixos.nix:2297`, as a plain list (§7):

```nix
i18n.inputMethod.fcitx5.addons = lib.mkIf usingFcitx5 [
  pkgs.fcitx5-mozc
  pkgs.fcitx5-hangul
  pkgs.fcitx5-chewing
  pkgs.fcitx5-table-extra
  pinyinWithoutBrowser # §2
];
```

The option is a merging list, so #1613 needs no edit here: its own
`i18n.inputMethod.fcitx5.addons = lib.mkIf … [ addon ]` joins this one. The two
branches touch different lines.

Measured: a `fcitx5-with-addons` with these five, run headless on a private session
bus, lists `mozc`, `hangul`, `pinyin`, `chewing` and `cangjie5` from
`AvailableInputMethods`, both with the stock Pinyin and with the one in §2. These are
upstream's preset keys (`default/input-methods/presets.json`). It evaluates with unfree
off.

The ledger rows at `data/omarchy-packages.nix:347-362` for the five engines change to
`module = "i18n.inputMethod.fcitx5.addons"`. `fcitx5-gtk` and `fcitx5-qt` stay as they
are, because `fcitx5-with-addons` always includes them. `modules/AGENTS.md:812-814`
gets corrected.

### 2. Pinyin and `qtwebengine`

**Yes, it can.** Upstream has `option(ENABLE_BROWSER … On)` (`CMakeLists.txt:35`), and
only `gui/pinyindictmanager` uses it, for the dialog that browses online dictionaries.

```nix
pinyinWithoutBrowser = pkgs.qt6Packages.fcitx5-chinese-addons.overrideAttrs (o: {
  buildInputs = lib.remove pkgs.qt6Packages.qtwebengine o.buildInputs;
  cmakeFlags = (o.cmakeFlags or [ ]) ++ [ "-DENABLE_BROWSER=OFF" ];
});
```

Measured:

| | Stock | Override |
|---|---|---|
| Builds | From cache.nixos.org | Yes, in about 40 s |
| `qtwebengine` in the wrapper's closure | Yes | No |
| `pinyin` in `AvailableInputMethods` | Yes | Yes |
| Closure beyond a local reference toplevel | 577 MiB | 155 MiB |

The composition itself has not been run on either; `checks.session` does that.

**Decision: ship the override.** It removes 422 MiB, 73% of the cost, from every
machine, most of which will never type Chinese. What it costs:

- the online dictionary dialog in the configuration tool. Importing a dictionary file
  still works (read);
- one path not on cache.nixos.org. nixarchy.cachix.org gets it with
  `reference-toplevel`, and a Mode A user who does not trust that cache compiles it
  once;
- an override to carry. If a bump makes it stop applying, nothing would fail by itself,
  so `checks.input-methods` asserts `qtwebengine` is absent from the wrapper's closure.

A user who wants the dialog sets `addons = lib.mkForce [ … ]` with the stock package.

### 4. `omarchy-pkg-present` and `omarchy-pkg-add`

An engine has no command, so both stubs answer wrongly. Measured: both exit 1.
`bin/omarchy-setup-input:27` stops there under `set -e`, and `typing_setup.py:113`
reports "Install fcitx5-mozc" instead of reaching the restart at `:119`.

Give the stubs a true answer for engines, in `pkgs/omarchy/nix-bin/omarchy-pkg-present`:

```sh
# An engine has no command; it is present if the daemon on PATH carries its file.
case $pkg in fcitx5-*)
  engine=$(jq -r --arg p "$pkg" 'to_entries[] | select(.value.packages | index($p)) | .key' \
    "${OMARCHY_PATH:-}/default/input-methods/presets.json" 2>/dev/null)
  if [ -n "$engine" ]; then
    fcitx5=$(readlink -f "$(command -v fcitx5)")
    [ -e "${fcitx5%/bin/fcitx5}/share/fcitx5/inputmethod/$engine.conf" ] || exit 1
    continue
  fi ;;
esac
```

- A `fcitx5-*` name that is not a preset, such as `fcitx5-gtk`, falls through to the
  command test as it does today. With no `fcitx5` on PATH, the test fails and the answer
  is "absent", which is true.
- Measured: `sw/bin/fcitx5` resolves to the `fcitx5-with-addons` store path, and each
  engine's `.conf` is under that path's `share/fcitx5/inputmethod/`.
- `/run/current-system/sw/share/fcitx5` does not exist (measured): `pathsToLink` has
  no `/share/fcitx5`. That is why this goes through the binary.
- `omarchy-pkg-add`'s first loop (`nix-bin/omarchy-pkg-add:69`) does not call this
  today. It gains a branch for `fcitx5-*`, inside an `if` because the script runs under
  `set -e`: `omarchy-pkg-present` true counts as present, false counts as missing.
- When an engine really is absent (`lib.mkForce [ ]`), `pkg-add` today would advise
  `nixarchy-pkg-add`, which cannot help. Add five `kind = "nixos-option"` rows to
  `data/arch-extras.nix`. That kind prints `$attr;` (`omarchy-pkg-add:138`), so `attr`
  is the whole line: `i18n.inputMethod.fcitx5.addons = [ pkgs.fcitx5-mozc ]`, and
  `pkgs.qt6Packages.fcitx5-chinese-addons` for Pinyin.
- `omarchy-pkg-missing` has no caller for these names (read), so it stays as it is.
  `grep` over `bin/`, `default/`, `install/` and `shell/` finds these names only in
  `presets.json` and the Arch package list.

Update the two reasons in `data/bin-ledger.nix` (`:390`, `:415`).

### 6. The profile, and what a non-US machine types

**What "the machine's layout" means here.** Hyprland reads
`~/.config/omarchy/keyboard-layouts`, then `XKBLAYOUT` from `/etc/vconsole.conf`
(`default/hypr/input.lua:12-14`). NixOS writes only `KEYMAP=` there (measured on p620),
and nothing in this repo writes either source (`git grep`). So a machine installed with
keymap `de` appears to get a `us` desktop. This is outside this task; see Open
decisions. Here, the machine's layout is whatever `hyprctl getoption input:kb_layout`
says.

**The effect of a `us` group on a `de` compositor.** What is known so far:

| Case | Result | How known |
|---|---|---|
| No profile, no X11 | Group `us`, `keyboard-us` | Measured, headless |
| X11 display present | Default group taken from `_XKB_RULES_NAMES`, else `us` (`fcitx5 instance.cpp:284-325`) | Read. What Xwayland reports under Hyprland is not measured |
| Item layout equals group default | Fcitx uses the system keymap (`instance.cpp:544-549`), so `keyboard-us` on a `de` compositor should type German | Read, **not run live** |
| `hangul`, `chewing`, `cangjie5` on a `us` group | `engine_layout` returns `""`, so they follow the compositor and keys move on QWERTZ or Dvorak | Measured for the function's output. On a `de` group it returns `us` |
| Bar label | Reads "Keyboard - English (US)" while typing German | Measured for the label |
| Profile naming `de` | Fcitx honours it; an unknown layout falls back to `us` | Measured, headless |

So the source predicts plain typing is already right, and the real faults are the
position-based engines and the label. The session VM below settles the first part.

**Design: align a stock profile before the daemon starts.** Add an `ExecStartPre` to
`omarchy-fcitx5` (`modules/nixos.nix:2037`), a few lines reusing upstream's own
functions so nothing forks:

```python
layout = typing_setup.keyboard_selection()[0].replace(":", "-")   # asks hyprctl
if (layout != "us" and layout.split("-")[0] not in setup.NON_LATIN
    and re.fullmatch(r"[A-Za-z0-9_-]+", layout) and setup.stock_profile(setup.read(path))):
    setup.atomic_write(path, setup.profile_text(layout, "none"))
```

- Measured: `stock_profile` is true for the file the daemon itself writes, and false
  for a profile with an engine or a non-US group. So a user's engine list stays.
- `stock_profile` ignores `DefaultIM` and `GroupOrder` (`configure.py:184-194`). With
  one group holding only `keyboard-us`, neither can hold another real choice, and typing
  follows the compositor either way, so nothing a user chose is lost.
- `NON_LATIN` keeps a hand-set `ru` from becoming the group's Latin layout, as
  upstream's `selection()` does (`configure.py:176`).
- Measured: a profile naming an unknown layout loads as group `us` with `keyboard-us`,
  so a bad value cannot leave a group with no keyboard.
- Known limit: this acts once. After it writes `de`, the profile is no longer stock, so
  a later hand edit of Hyprland's layout does not follow. The Keyboard Layouts picker
  still does (`typing_setup.py:207`).
- Written with `-` so a failure, such as `hyprctl` not answering, cannot stop fcitx5.
- Left out when `i18n.inputMethod.fcitx5.settings.inputMethod != { }`: a file in
  `~/.config` would shadow that user's `/etc/xdg/fcitx5/profile`.
- The script needs `hyprctl` on PATH, `OMARCHY_PATH` set before import
  (`configure.py:15`) and `default/input-methods` on `PYTHONPATH`. A
  `pkgs.writeShellScript` sets these, because a unit's `Environment=` and `path` would
  also reach the daemon.

### 7. Rebuilds and the running daemon

Read: this pin's `switch-to-configuration-ng` runs a user-scope pass for each logged-in
user (`main.rs:2427`) that restarts an active `/etc/systemd/user` unit whose file
changed (`main.rs:1297`). `omarchy-fcitx5` does not set `restartIfChanged = false`. Its
`ExecStart` names the wrapper, which changes when addons change. So `switch` should
restart it. **Not measured live.**

Nothing depends on this. If the old daemon survives, `save_inputs` finds the engine
missing, `load_engines` passes once §4 is in place, and `omarchy-restart-xcompose`
(`typing_setup.py:119`) restarts the unit, which `wait_ready` then waits for. The
session VM exercises that branch. It also measures the `switch` case once, for the PR.

## Alternatives rejected

- **Run upstream's `omarchy-input-method configure`.** `selection()` reads
  `XKBLAYOUT` from `/etc/vconsole.conf` (`configure.py:167-169`), so on NixOS it always
  answers `us`. `defaults()` also edits an existing `config` (`:95-122`), which breaks
  a constraint in the intent.
- **A static profile, in `config/fcitx5/` or `settings.inputMethod`.** The layout is
  known only at run time. The console keymap is a different namespace (`uk`, not `gb`).
- **No profile step at all.** Smaller, but leaves position-based engines wrong on any
  machine whose layout was set by hand, with nothing to tell the user.
- **Patch `typing_setup.py:113`.** A patch is carried at every bump. The stub is ours
  and wrong for this name, so the fix belongs there.
- **Add `/share/fcitx5` to `pathsToLink`.** Also works, but it adds a system-wide link
  and is harder to fake in a stubbed check than a `fcitx5` on PATH.
- **`/run/current-system/sw/share/systemd/` for `kbd-model-map`.** It exists, but a
  store path fails at build time if it moves.
- **A new VM check for layouts.** `checks.session` can change layout at run time, and
  a new VM costs 10-20 minutes on every PR.

## Risks

- **Every machine gets 155 MiB more,** including those that never type CJK. The owner
  accepted up to 577 MiB, and the ISO decides it.
- **A daemon restart during the first `switch`** drops any composition in progress,
  once.
- **`fcitx5` in the build sandbox is not proven.** The headless runs used an isolated
  environment outside the sandbox. If it does not work inside, those assertions move
  to `checks.session`, losing the per-PR speed.
- **Composition strings are not yet known.** Each engine's expected output comes from
  its first green run, then gets checked by hand against what the engine is meant to
  produce.
- `modules/nixos.nix` is shared with #1611, #1612, #1613 and #1615. This change adds
  new lines and edits the one unit block.

## Open decisions

1. **Drop `qtwebengine`?** *Recommended: yes (§2).* It saves 422 MiB on every machine
   and loses one dictionary dialog. A 40-second build and an override to carry are the
   price. The alternative is the stock package, at 577 MiB and 0.15 GiB more ISO.
2. **Non-US installs appear to get a US desktop (§6).** Outcome 3 says leaving an engine
   types "the machine's own layout". Here that means the layout the session already
   uses, so on such a machine it types US, as it did before the engine. The installer's
   keymap does not reach Hyprland, and this task does not change that. *Recommended: a
   separate issue, after a VM confirms it,* since it affects every non-US install with
   or without an engine.
3. **The patched theme path may be dead.** `pkgs/omarchy/default.nix:906-908` points at
   `/run/current-system/sw/share/fcitx5/themes/default`, and `sw/share/fcitx5` does not
   exist on the reference (measured). *Recommended: a separate issue.*
