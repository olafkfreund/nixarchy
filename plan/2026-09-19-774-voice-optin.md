# Plan: voice becomes an app in the catalogue

Branch `feat/774-voice-optin`, already carrying the intent and the spec. One
commit per step, subjects as full sentences (§8).

## Approved decisions, copied so this file stands alone

- **A `data/apps.nix` entry with an `option` path**, the shape `firefox`,
  `_1password` and `steam` already use. That is the whole "Set up voice" row,
  and it puts voice in Install ▸ Search rather than in a corner of the menu.
- **The module comes from upstream**, imported as `inputs.nixarchy-voice`'s
  `homeModules.default`, the way `inputs.nixi`'s already is
  (`modules/home.nix:479`).
- **nixarchy sets no overrides.** `desktopControl` false, notification logging
  off and the Jenny attribution are all upstream defaults as of
  nixarchy-voice#19 and #21. Restating them here would create a second place to
  change and would hide an upstream regression.
- **Nothing is added to `defaultPluginSet`.** Voice's plugins install through
  `programs.nixarchy.plugins` when the module is enabled.
- The intent's "about 1 GiB" is **measured**, not repeated.

## Steps

1. **`flake.nix`: the input.** `nixarchy-voice`, `inputs.nixpkgs.follows`, with
   the comment saying why it is an input on every machine while the app is on
   none — the catalogue is data, and the module only takes effect when the
   option is set.
   → verify by `nix flake metadata` listing it, and by step 5's measurement.

2. **`modules/home.nix`: import the module.** Beside the `nixi` import, same
   reasoning, same shape.
   → verify by `nix eval` on a default home: no `services.omarchy-voice` unit
   and nothing named `omarchy-voice` in `home.packages`, which is step 4's red
   case run early.

3. **`data/apps.nix`: the row.** `omarchy-voice`, category `AI`, `menuId
   install.ai.voice`, `option = [ "services" "omarchy-voice" "enable" ]`, and a
   `note` carrying the size measured in step 6.
   → verify by the menu check seeing the row, and by `readme-counts.sh`, which
   counts this catalogue and refuses an implausible number (§4: it fails closed,
   and the new count needs its word in the table if it crosses one).

4. **`tests/options.nix`: `voiceIsNotADefault`.** On the default home nothing
   named `omarchy-voice` is in `home.packages` and no such unit exists; `off` is
   the same predicate against a home that enables it, so deleting the catalogue
   entry cannot make the case pass. Mode A asserted in the same case.
   → **verify red first**: add voice to `defaultPluginSet`, build `options`,
   quote the failure; remove it, watch it pass. Restore from a copy, not
   `git checkout --` (§5).

5. **Measure the input's cost.** `nix eval` on `nixosConfigurations.vm`, wall
   clock and peak RSS, before and after the input. Report both in the PR, and if
   it moves `checks.options` materially say so against #747 rather than quietly
   adding to a check already at 11.7 GiB of a 16 GiB runner.
   → verify by having two numbers rather than an assurance.

6. **Measure the closure.** `nix path-info -Sh` on the voice package, so the
   catalogue note states what it costs.
   → verify by the number appearing in `data/apps.nix`.

7. **Whole-branch verification.** `nix fmt -- --ci`, statix, deadnix, then
   `options` and the menu check by name.
   → verify all green.

8. **PR.** Against `main`, closing #774, linking the three artifacts, carrying
   step 4's red output and steps 5 and 6's measurements.

## Rollback

- **Before merge:** drop the branch.
- **After merge:** revert. Nothing on an installed machine changes unless
  somebody chose voice; for them the option leaves their own flake and the next
  rebuild removes it, which is the ordinary path for any app in the catalogue.
