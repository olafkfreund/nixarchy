# Spec: the config writers take apply's lock and keep the files they edit

Line numbers are `modules/apps.nix` at the intent's approval commit unless
another file is named.

> [!IMPORTANT]
> **One intent outcome changes here, and needs approval with this spec.**
> The intent said a write to one file "either completes, or leaves that
> file's previous content, including when interrupted or when the disk is
> full". An in-place write cannot promise that for a full disk. Truncation
> frees blocks that another process, a copy-on-write filesystem or a quota
> can take before the restore runs, and both reviews showed it.
>
> This spec delivers:
> - **Interrupted (Ctrl-C, TERM, HUP):** all or nothing, as the intent said.
> - **A failed write (ENOSPC, EFBIG):** the previous content is restored.
>   When even the restore fails, a full copy is kept at a path the refusal
>   names.
>
> That is nixarchy-pkg#65's bar: recoverable, with a findable backup. The
> alternative that would keep the stronger promise, `rename(2)`, gives up
> the inode, which the intent's other outcome requires.

## Design

### 1. One shared helper file, `pkgs/writer-lock.sh`

No lock or put helper exists today; apply's lock is inline (4424-4437).
The helper is a file so the new check can source it on its own. In
`modules/apps.nix` it is spliced into each writer's `text` with
`builtins.readFile`, the way `insertMissingAppRow` is (166-182). Into
`pkgs/pkg-new.sh` it goes through an `@writerLock@` token. Both apps.nix
(3405) and `tests/pkg-new.nix` replace the token with `lib.replaceStrings`
at evaluation. The test's `sed` (31) cannot splice a multi-line file.

The functions:

- **`nx_lock`** takes the lock.
  - If `NIXARCHY_LOCK_HELD=1`, it returns. A parent holds the lock, and a
    new open of the file would deadlock against it: `flock` locks per open
    file description.
  - Otherwise: `mkdir -p` the state directory
    `${XDG_STATE_HOME:-$HOME/.local/state}/nixarchy/applied`, then
    `exec 9>>lock` (never truncating), then `flock -w 5 9`. A failure at any
    of the three refuses with its own cause, so nothing is ever written
    unlocked.
  - On success it exports `NIXARCHY_LOCK_HELD=1` and sets `NX_OWNER=1`.
- **`nx_unlock`** always unsets `NIXARCHY_LOCK_HELD`, so no later child of
  this process inherits a stale handshake. It runs `exec 9>&-` only when
  `NX_OWNER=1`.
- **Calls made while the lock is held** run with `9>&-`, so no child holds
  the open file description:
  - **Nested writers** see `NIXARCHY_LOCK_HELD=1` and do not lock again.
  - **Notifications** run only after `nx_unlock`. `nx_refuse` calls it
    first.
  - **`exec`** always follows `nx_unlock`.
- **`nx_put SRC DST`** puts SRC's bytes into DST in place, then removes SRC,
  mirroring the `mv` it replaces.
  - It refuses unless DST resolves to a regular file that is writable. That
    covers a symlink into `/nix/store` and a 0444 file. An absent DST is
    created; pkg-new's draft is the only case.
  - It copies DST to a backup in the state directory with
    `cp --reflink=never`, so the backup holds its own blocks. A failed copy
    refuses before DST is touched.
  - With `INT TERM HUP QUIT XFSZ` ignored, it runs `cat SRC > DST`, then
    resets those dispositions.
  - On success it removes the backup.
  - On failure it runs `cat backup > DST`. If that succeeds, it removes the
    backup and refuses. If it fails too, it refuses with
    `<file> could not be written or restored; its previous content is at
    <backup>`.
- **`nx_sed DST SCRIPT...`** runs `sed SCRIPT DST` into a temp file in the
  state directory, then `nx_put`. A writer that ran two `sed -i` passes in a
  row (app-enable 2331-2332, app-disable 2394-2395) runs one `nx_sed` with
  both expressions, so the file changes once and cannot be interrupted
  between the two.
- **`nx_commit SNAPSHOT WORK DST`**, under the lock: if DST is no longer
  byte-identical to SNAPSHOT, it refuses with `<file> changed while
  <command> was running; nothing was written. Run it again.`. Otherwise it
  runs `nx_put WORK DST`.
- **`nx_refuse MSG`**:
  - calls `nx_unlock`;
  - prints MSG to stderr;
  - sends a critical notification when `omarchy-notification-send` is on
    PATH, as app-enable's `fail()` does (2309-2315), with `9>&-`;
  - exits 75 (EX_TEMPFAIL), so a caller can tell a refusal from its own
    errors.

A busy lock refuses with `a write or an apply is running -- try again when
it finishes. Nothing was changed.`, the same wording as nixarchy-pkg#65.

Temp files, the backup and nx_sed's output, go to the state directory, never
`~/.config/nixarchy/`. Every writer's EXIT trap runs `nx_unlock` and removes
its temp files. A writer that already has an EXIT trap folds both into one;
service-enable's at 2023 is replaced, not stacked.

### 2. Where each writer locks

Each writer's notification, `cfg.package`, joins its `runtimeInputs` where
it is missing (service-disable, catalogue-diff, language-select, opt-remove,
search), along with `util-linux` for `flock`.

**Lock first, then read, edit and write.** No prompt, fetch or build falls
between the read and the write:
- **catalogue-diff:** lock only under `--add`/`--add-one`. The plain report
  reads without locking, so it never refuses.
- **language-select** (2219-2247).
- **service-disable** (2278-2287).
- **app-enable:** before `insertMissingAppRow` (2323).
- **app-disable:** before 2383, so `insertMissingAppRow` (2389) is inside.

**Prompt first, then lock, re-read and decide again:**
- **pkg-remove, pkg-undraft, opt-remove:** the fzf picker runs unlocked.
  Then lock, back up, re-check the row (2570, 2667, the `#@opt` row), edit,
  and parse-check. `restore()` (2553, 2652, 2757) becomes `nx_put` of the
  backup.
- **service-enable:**
  - `openssh_gate` (gum, curl, `authorized_keys`) runs unlocked, when the
    unlocked read says openssh is off.
  - Under the lock, the decisive read (2006) is repeated. If it now says the
    gate was needed and the gate did not run, it refuses with "services.nix
    changed while service-enable was asking; run it again". The gate is
    never skipped.
  - The nested `catalogue-diff --add-one` (1990) moves under the lock and
    runs with `9>&-`. Its exit status 75 is passed through as a refusal, not
    reported as "no service '$id'".

**Work on a copy, then commit if nothing changed underneath:**
- **pkg-add:**
  - `target` holds the real path, for every message: 2874, 3011, 3021,
    3057, 3146, 3161, 3253, 3285, 3296, 3315-3316, 3322 and 3327.
  - `file` becomes a private copy in the state directory, taken with the
    snapshot at 2976-2977. Every edit, parse check and `restore` (2876,
    3016, 3111, 3145, 3161, 3287, 3295, 3321, 3331) then works on the copy
    unchanged. A restore now means re-copying the snapshot into the work
    file.
  - The diff and the `[Y/n]` prompt come before anything is written. Today
    the prompt comes after the write.
  - Then `nx_lock` and `nx_commit snapshot work target`.
  - Both `exec nixarchy-search` sites (2957, 3220) and the success
    notification run after `nx_unlock`.
- **pkg-new:**
  - nix-init writes to a draft in the state directory, not to `packages/`,
    and both builds read it there. That covers the new draft and `--update`
    (pkg-new.sh:100-155).
  - The `--update` backup at 102-107 goes. The real draft is never touched
    until commit, so a failed build has nothing to restore.
  - Its draft `sed -i` (151) acts on that temp file.
  - Then, under the lock:
    - refuse if `packages/<name>.nix` now exists and this is not `--update`
      (pkg-new.sh:93 races today);
    - `nx_put` the draft into `packages/<name>.nix`;
    - insert the `apps.nix` row (177-186) with `nx_put`.

  So `nixarchy-apply` never sees a placeholder-hash draft, and a symlinked
  draft keeps its link.
- **search:**
  - It holds no lock across its picker or its batch, so a nested `pkg-new`
    build never holds it. Each nested writer locks for itself.
  - `insert_line` (3688-3695) takes the lock, repeats the `#@opt $path`
    duplicate check from `add_option` (3716) under the lock, edits,
    parse-checks with `nix-instantiate --parse` (milliseconds), runs
    `nx_put`, and `nx_unlock`s before it returns.
  - The batch-level restore of the pre-loop backup (3678, 3913-3914) is
    removed. It reverted nested writers' changes, and per-insert validation
    replaces it.

### 3. `nixarchy-apply`'s messages

- **The `--yes` refusal** (4432) becomes `nixarchy-apply: a write or another
  apply is running (it may be waiting at a prompt); try again when it
  finishes`.
- **The interactive message** (4435) becomes `nixarchy-apply: waiting for a
  write or another apply to finish...`.
- **Unchanged:** apply's own locking. It does not read `NIXARCHY_LOCK_HELD`
  (intent question 2).

## Alternatives rejected

- **Hold the lock for the whole writer.** pkg-add's eval, its prompts and
  pkg-new's builds would block every writer and apply for minutes.
- **`rename(2)` from a same-directory temp file, as today.** It is atomic,
  but it replaces the inode, breaks a symlink and resets the owner. The
  intent requires the inode.
- **Overwrite with `dd conv=notrunc`, then truncate.** It avoids freeing
  blocks before the write, but copy-on-write filesystems allocate on
  overwrite anyway, so it buys no guarantee for its complexity.
- **`sed --follow-symlinks -i`.** It keeps the link, but still replaces the
  target's inode.
- **Search holds the lock across its batch.** A nested pkg-new build would
  hold it for minutes.
- **A lock per file.** It does not exclude `nixarchy-apply`, which copies
  them all under `applied/lock`.

## Risks

- **pkg-add is the largest edit:** 9 restore sites and 12 message sites. The
  new checks run pkg-add through cancellation and a commit refusal, and the
  existing checks run its success path and a curated-name refusal. Its other
  restore branches are covered only by those branches running on the copy
  unchanged.
- **Optimistic refusal.** A pkg-add, or a service-enable at the SSH gate,
  that is left at a prompt while something else edits the file refuses at
  commit and asks for a re-run. Intended: the alternative is a silent
  overwrite.
- **app-remove runs several writers, each locking for itself.** If apply
  starts between two of them, the later one refuses and the earlier ones'
  edits stay. app-remove's summary must not say "Nothing was changed" then;
  it reports which steps ran.
- **The full-disk outcome is weaker than the intent's wording,** as stated
  at the top.
- **Hosts:** none directly. Every machine gets the new writers at its next
  switch, and Mode A users never run them.

## Coexistence

None of these touch an option a user sets. The files edited are nixarchy's
own (`~/.config/nixarchy/*.nix`, `packages/*.nix`), and no
`tests/coexistence` fixture applies.

## Verification

### A new cheap check, `checks.writer-lock` (`tests/writer-lock.nix`)

It runs with a temporary `HOME` and `XDG_STATE_HOME` and is in no workflow
list, so the generated step runs it (§4).

**Helper cases** source `pkgs/writer-lock.sh` under bash:

1. **Contention:** a holder `flock`s the lock and sleeps. `nx_lock` exits 75
   within 5-7 s, with the busy message, and the target is unchanged.
2. **Nesting:** the same holder, with `NIXARCHY_LOCK_HELD=1`. `nx_lock`
   returns at once.
3. **Stale handshake:** after `nx_unlock` in a non-owner, a child sees no
   `NIXARCHY_LOCK_HELD`.
4. **Fail closed:** the state directory is unwritable. `nx_lock` refuses and
   nothing is written.
5. **Keeps the file:** through a symlinked 0640 target, `nx_put` leaves the
   link, the inode number and the mode unchanged.
6. **Read-only target:** a 0444 target is refused and left unchanged.
7. **Interrupted write:**
   - The put runs under `set -m`, so it is its own process group, and its
     SRC is a FIFO.
   - The test writes half the content, sends SIGINT to the process group
     (`kill -INT -$pgid`), then writes the rest.
   - DST then holds all of the new content.
   - With the signal-ignore removed, DST is cut short, which is the red
     proof.
8. **Failed write, restored:**
   - In a subshell with `ulimit -S -f` between the old and new sizes (EFBIG
     stands in for ENOSPC: the same write-failure branch), the write fails.
   - DST then holds all of the old content, and the call exits 75.
   - With the restore removed, DST is truncated, which is the red proof.
9. **Commit refusal:** the target no longer matches the snapshot.
   `nx_commit` exits 75, and the target is unchanged.

**Writer matrix.** It builds the twelve writers as `app-selection.nix` does
(`vmPackage`), with the same template and stub setup. For each writer, with
a representative argument:

- **Lock held** by a holder: the writer exits 75, and its target is byte-
  and inode-unchanged.
- **`NIXARCHY_LOCK_HELD=1`** with the holder still running: the writer
  succeeds without waiting.
- **Through a symlinked target:** after a successful run, the link and the
  inode are unchanged.

A writer that skips `nx_lock`, or keeps a `mv` or `sed -i`, turns its own
row red. That is the per-writer proof the intent asks for.

### Changes to existing checks

- **`app-selection.nix`:**
  - The assertions that encode the rename model (56-59, 73-76) become "same
    inode". The PR says why (§1 read backwards).
  - The apply-lock case (202) greps the full new `--yes` text, starting at
    `a write or another apply`. A case for the interactive message is added.
  - New pkg-add cases: answering `n` leaves `apps.nix` unchanged, and
    editing `apps.nix` before commit refuses.
- **`pkg-new.nix`:** `util-linux` joins its inputs, `XDG_STATE_HOME` is
  set, and `@writerLock@` is replaced with `lib.replaceStrings`. A new case
  covers `--update` through a symlinked draft.
- **`language-select.nix`, `sshd-enable.nix`:** set `XDG_STATE_HOME` (§4,
  #802). `sshd-enable` gains the gate-changed refusal, with `services.nix`
  edited between the gate and the commit.

### §1 proofs

Each guard is removed in turn, and the case it covers must go red:
- `nx_lock` made a no-op;
- `nx_put` reverted to `mv`;
- the signal-ignore removed;
- the restore removed;
- `nx_commit`'s comparison removed;
- the gate re-check removed.

The failing outputs go in the PR.

### Also run

The generated checks, the `options-*` shards, and `session`, which runs
app-enable and apply as a user.

### Not reachable here

A real ENOSPC, and a copy-on-write filesystem. EFBIG drives the same
branch. Both are named in the PR.
