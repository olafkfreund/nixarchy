# Spec: the Shure MV7+ udev rule reaches a NixOS system

## Design

Ship the packaged rule through `services.udev.packages` in `modules/nixos.nix`,
next to the module's other udev handling: a small derivation placing
`share/omarchy/default/udev/shure-mv7plus.rules` from the configured Omarchy
package at `lib/udev/rules.d/62-shure-mv7plus.rules` (upstream's name and
order, so `uaccess` is applied before `73-seat-late`). Only when the package
ships the file: evaluated with `builtins.pathExists` on the package's output,
or the derivation tolerating its absence, so the 4.5 tag is untouched. Gated
by whatever already enables the desktop's other udev rules (follow the
neighbouring code), so Mode A stays untouched.

`data/user-migrations.nix`'s row for 1795709363 keeps `declined` but its
reason points at this rule as what answers the udev half.

## Alternatives rejected

- `services.udev.extraRules` with the text copied: drifts from upstream.
- Writing `/etc/udev/rules.d` from the migration: NixOS generates it.

## Risks

`pathExists` on a package output forces a build at evaluation (IFD-like). If
the neighbours avoid that, use a derivation that copies the file when present
and is empty otherwise.

## Verification

A check (in the existing coexistence or a new runCommand) asserts the system's
udev rules contain `14ed`/`1019` with `uaccess` on rc1, and that the 4.5 tag
evaluates. Its failing output with the rule removed goes in the PR (§1).
