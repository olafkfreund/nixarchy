# Spec: Correct Docker and shell PATH guidance

## Design

1. Replace `docs/manual/security.md:46-50` with the actual default: `modules/nixos.nix:1507-1514` disables the rootful daemon and enables rootless Docker unless the user overrides it. Remove the rootful iptables and published-port assertions. Refer readers to the already-correct rootless explanation in `docs/manual/development-tools.md:271-276`; its “enabled by default” wording remains. Do not add loopback-binding guidance without verifying how this pinned rootless Docker publishes ports.

2. Correct **every** claim that `writeShellApplication` supplies a strict PATH. The pinned nixpkgs revision in `flake.lock:1048` defaults `inheritPath` to true in `pkgs/build-support/trivial-builders/default.nix:292` and constructs PATH from `runtimeInputs` **followed by** the caller’s `$PATH` at line 321. State the two consequences precisely: declared commands beat same-name PATH stubs; undeclared commands may work through the caller’s PATH and therefore are environment-dependent. Update `AGENTS.md:748-750`, `modules/AGENTS.md:41-42`, `pkgs/AGENTS.md:42-50`, `tests/AGENTS.md:478-480,545-560`, and `docs/internals/flake.md:835-839`, along with the matching comments in `modules/nixos.nix:158-161`, `modules/apps.nix:3353-3359,3531-3536`, `pkgs/doctor.sh:625-629`, `flake.nix:924-928`, `tests/apply-detach-interface.nix:47-52,80-85,118-122`, `tests/shell-ipc-resolve.nix:8-11`, and `tests/shell-restart-tree.nix:19-22`. `CLAUDE.md` points to the root `AGENTS.md`, so one edit covers both names.

3. Declare the missing executable providers: add `xdg-utils` to the doctor’s `runtimeInputs` in `flake.nix:583-605` because `pkgs/doctor.sh:556,573-574` executes `xdg-settings`; add `git` and `gnused` to `nixarchy-apply` in `modules/apps.nix:3336-3360` because that script calls `git` at line 3677 and `sed` at line 3421. Keep the other runtime inputs and behavior intact.

4. Add a cheap `tests/shell-runtime-inputs.nix` check, registered in `flake.nix` beside the existing doctor and apply checks. Give it the already-built doctor package and obtain `nixarchy-apply` through `tests/lib.nix`’s evaluated `vmPackage`, as `tests/apply-staging.nix:14-28` does. Inspect each built wrapper’s PATH declaration for the exact `${pkgs.xdg-utils}/bin`, `${pkgs.git}/bin`, and `${pkgs.gnused}/bin` entries, with explicit failure messages. This tests the packages that the module actually ships; a copied list would miss a module regression. Keep prose review separate from this executable check.

## Alternatives rejected

- Keep the rootful Docker warning and change only `mkDefault true` to false: the iptables explanation would still describe the wrong daemon.
- Add unverified loopback or NixOS-firewall promises for rootless published ports: the owner authorized such guidance only after verification; omitting it is more accurate.
- Set `inheritPath = false` globally: that changes wrapper behavior and stub compatibility to make inaccurate prose true, instead of correcting the prose and declaring dependencies.
- A check that greps the Nix source for dependency names: it could pass while the evaluated module ships a wrapper without them.

## Risks

- Adding runtime inputs changes the wrapper closure and PATH precedence for `xdg-settings`, `git`, and `sed`; scripts that accidentally used another version will now use the pinned one.
- Correcting old test comments must preserve their valid finding that a declared command shadows a PATH stub. No existing test behavior should change.
- Rootless Docker port exposure is not established by the current documentation; the replacement must avoid a false security guarantee.
- `tests/lib.nix` evaluates the VM configuration to find `nixarchy-apply`; the new check must build only the script and not the VM or system profile.
