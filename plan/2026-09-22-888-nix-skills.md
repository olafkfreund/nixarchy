# Plan: the Nix skills in olafkfreund/nix-skills reach nixarchy's agents

Branch `feat/888-nix-skills`, carrying the approved intent and spec. Step 0 is a
PR in **nix-skills** (ours). Steps 1–6 are nixarchy, one commit each, citing
`plan step N` and `(#888)`. A deviation updates this file in the same commit as
the code. The PR says `closes #888`.

## Approved decisions

Copied from the spec so this file stands alone.

- **Depend, don't vendor.** `nix-skills` is an input pinned to a commit
  (`nixpkgs.follows`). Its package lays skills out at
  `$out/share/nix-skills/<name>`.
- **Linked by nixarchy's own relink step, as a second source**, into the same
  four directories nixarchy's skills reach: `.agents/skills`, `.claude/skills`,
  `.codex/skills` and `.pi/agent/skills`. nix-skills' Home Manager module is
  **not** used, because its `home.file` would clash with a user who enables it
  themselves.
  - **Cleanup** also removes links into `/nix/store/*/share/nix-skills/*`.
  - **A nix-skills name is linked only where nothing else is**, and an occupied
    one is reported and left alone.
  - nixarchy's own skills keep `ln -sfn`.
- **devenv:** keep both skills. nixarchy's `devenv` gains a *Hand-offs* line to
  `devenv-project` for `devenv.nix` syntax and options.
- **Counted apart:** `skills` stays sixteen (nixarchy's own). The input's own
  count is stated beside it wherever the sixteen is.

  **Deviation, measured 2026-09-23:** the spec said *six*, and
  `skills.json` has **eight** -- `devenv-project`, `home-manager`,
  `microvm-nix`, `nix-darwin`, `nix-language`, `nix-workflow`, `nixos-wiki`,
  `nixpkgs-development`. `nix-darwin` merged there the same morning this was
  being planned, with three more pull requests open. A hand-written number in
  five places would have been stale before this merged, which is §4's shape
  exactly. So the number is **derived from the input's `skills.json`** by
  `readme-counts.sh`, like every other quantity it guards -- not stated.
- **On by default:** `programs.nixarchy.nixSkills`, a NixOS bool, default
  `true`, read as `osConfig.programs.nixarchy.nixSkills or false`. Mode A is
  inert.
- **Licence: MIT** (owner, 2026-09-22), in nix-skills before the pin.

## Steps

**0. nix-skills: the licence** (a PR in olafkfreund/nix-skills).

- `LICENSE`: MIT, `Copyright (c) 2026 Olaf Krasicki-Freund`.
- `nix/packages.nix` installs it into every output at
  `$out/share/doc/nix-skills/LICENSE`, as ai-mirror does, so a shipped copy
  carries its licence.
- A check in `nix/checks.nix` asserts that it is there, for every package.

→ verify:

- `nix flake check` in nix-skills;
- **break:** skip the install line, and the check goes red.

Merge it. The merge commit is the pin for step 1.

**1. The input.** `flake.nix` gains `nix-skills`, pinned to step 0's commit,
with `inputs.nixpkgs.follows = "nixpkgs"`. Then run `nix flake lock`.

→ verify: `nix eval` of `inputs.nix-skills.packages.x86_64-linux.default`
builds, and holds the six skills and the licence.

**2. The relink, as a package.** Add `pkgs/skills-relink.nix`, a
`writeShellApplication` with `coreutils` and `findutils` as runtime inputs:

```
nixarchy-skills-relink <home> --own <dir> [--guarded <dir>]
```

- For each of the four agent directories: remove links into
  `/nix/store/*/agents/skills/*` **and** `/nix/store/*/share/nix-skills/*`.
- `ln -sfn` every skill in `--own`, exactly as today.
- For each skill in `--guarded`, link it only if the destination does not
  exist. Otherwise print `nixarchy: ~/<dir>/<name> is not ours; leaving it`.

`home.nix`'s activation calls it in place of the inline loop, passing
`--guarded ${nix-skills}/share/nix-skills` only when `nixSkills` is on. The
`# Why:` pointer stays.

→ verify by step 6's stubbed check, which runs this package.

**3. The option.** In `modules/nixos.nix`,
`nixSkills = lib.mkOption { type = bool; default = true; }`. Its description
names the six and nix-skills, and says off takes them away at the next switch.
In `home.nix`, `nixSkills = osConfig.programs.nixarchy.nixSkills or false;` in
the `let`.

→ verify by step 6's options cases.

**4. The devenv boundary.**

- `pkgs/omarchy/skills/devenv/SKILL.md` *Hand-offs* gains: *the syntax and
  options of `devenv.nix` itself (languages, tasks, services) → the
  `devenv-project` skill.*
- The omarchy build asserts that line survives: after the skills are copied,
  `grep -q devenv-project "$skills/devenv/SKILL.md"`, or fail naming #888.
  This follows the tree's existing asserted anchors.

→ verify:

- `nix build .#omarchy`;
- **break:** remove the line, and the build fails naming it.

**5. The words and the counts.**

- Each of the five places that says *sixteen* gains the six beside it, for
  example *"…and six Nix skills from
  [nix-skills](https://github.com/olafkfreund/nix-skills)"*.
- `docs/manual/ai.md` gets a short table of the six, and the off switch.
- `readme-counts.sh` gains a `nix_skills` value: the length of `skills.json` in
  the pinned input. It is read through `NIX_SKILLS_TREE` if set, else
  `nix eval --raw` of the input's `outPath`, like `OMARCHY_TREE`, and **refused
  if under 1** (§5).
- One quantity per stated place (five), so the floor moves **31 → 36** in the
  check and in its comment. `word_for` already spells six.

→ verify:

- `readme-counts.sh --check` passes with 36;
- **break:** one place says *five*, and that quantity goes red naming it.

**6. The checks.** Each is broken first and seen red, and each break is
confirmed in the file (§1).

- **`tests/skills-relink.nix`** runs the step 2 package against a fake home
  with a fake `--own` (two skills) and `--guarded` (two skills):
  - all four skills are linked in all four directories;
  - a guarded name already present as a real directory is left alone, and
    reported;
  - a second run **without** `--guarded`, as when the option is turned off,
    removes the guarded links and keeps the own ones;
  - a link the user made to somewhere else is untouched.
  - **Breaks:** drop the "only if absent" guard, and the real directory is
    replaced. Drop the `share/nix-skills` cleanup pattern, and off leaves them
    behind.
- **`tests/options.nix`, both states**, on evaluations already bound where
  possible (#747):
  - the activation text names the nix-skills store path when `nixSkills` is on,
    and does not when it is off;
  - Mode A: nothing.
  - **Break:** pass `--guarded` unconditionally.

## Rollback

- `git revert` the squash. The input, the option, the second source and the
  counts go.
- On the next activation, the relink step (reverted to the inline loop) no
  longer knows the `share/nix-skills` pattern. So links made while this was on
  stay until the user deletes them. The PR's rollback note says so, with the
  one-line `find` that removes them.
- The nix-skills licence stands on its own.
