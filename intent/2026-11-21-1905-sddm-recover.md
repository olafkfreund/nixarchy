# Intent: a greeter stranded by sleep is recovered on edge, as upstream recovers it

## Problem

Quattro (edge's pin since ebd2974) ships four drop-ins, on `systemd-suspend`, `systemd-hibernate`, `systemd-hybrid-sleep` and `systemd-suspend-then-hibernate`. Each adds `ExecStopPost=-/usr/bin/omarchy-system-sddm-recover`. After sleep, the script restarts SDDM when SDDM is active but no session holds a local seat. That is the state left when autologin or the greeter hit `UnitAllocationFailed` while systemd-sleep had `user.slice` frozen.

nixarchy ships the script but not the drop-ins. `data/etc-overlay.nix` classes all four `divergent`. nixarchy uses SDDM, with a greeter and optional autologin, and its systemd freezes user sessions during sleep the same way, so the same stranding is possible. If it happens, the user resumes to a black screen with no login and nothing recovers it.

## Proposed outcome

On a pin that ships the script, with nixarchy's SDDM enabled, the four NixOS sleep units run the script after sleep. The commands it calls resolve in the unit's environment. A healthy session or greeter is left alone. Under `main`'s tag pin, and under any edge pin without the script, nothing changes. The four rows say what answers them, and a check fails if the hook goes missing.

## Affected users and systems

Edge users with `programs.nixarchy.displayManager` on, which is the default. That covers p620 and razer once deployed. `main` (tag v4.5.0) is unaffected.

## Constraints

- Mode A: a machine whose display manager is not nixarchy's SDDM gets no sleep-unit change.
- The change must hold under both pins (CLAUDE.md §8), so it lands as a carry on `edge-candidate`.
- It must not change systemd-sleep's own environment or behaviour beyond adding the hook.
- The hook stays failure-tolerant (`-`), as upstream's is, so a failing hook never fails a resume.
