# Spec: edge adopts Omarchy quattro be54892

Pre-approved by the owner, 2026-10-22 ("approved make this happen now push
this").

## Design

This is an edge carry on `edge-candidate`, published by a `from_candidate`
run (`omarchy-edge.yml`). That run keeps the candidate's quattro pin.

1. **Pin.** `flake.nix` gets `omarchy.url` = quattro
   `be54892f36b2803f1b798b0c0603cf8b25e4093c` and `omarchyVersion` =
   `edge-20261022-be54892`. `flake.lock` follows (`nix flake update
   omarchy`). This has the same shape as the bot's pin commit (5d22ce0e).
2. **Re-anchor #1339.** Upstream #15966 extends the `cardWidth` line with
   `|| root.activeMenu === "update.kernel"`. Both the `--replace-fail`
   pattern (`pkgs/omarchy/default.nix:2054`) and its replacement
   (`pkgs/omarchy/1339-menu-fit-width.qml`) gain that clause, so the new
   kernel menu keeps upstream's 520 width.
3. **Ledger row for `omarchy-kernel`** (`data/bin-ledger.nix`). It is a new
   upstream command, and it matches `initrd-boot`. The row is `vendor` with
   `allow = "initrd-boot"`. Its reason says why it is unreachable: the
   Update > Kernel row's `when` needs `omarchy-kernel list` to print more
   than one kernel. That list reads `/usr/lib/modules/*/pkgbase`, which
   NixOS does not have, so the row never shows.

Measured on the pinned tree: `.#omarchy` builds. Every menu check,
`etc-overlay`, `rollback-kernel` and, with the row, `bin-ledger` pass.

## Alternatives rejected

- **Patching `omarchy-kernel` to refuse:** nothing reaches it, so a patch
  would be one more anchor to re-apply at every bump.
- **Dropping `update.kernel` from the anchor** (matching the old line some
  other way): the kernel menu would silently lose its width.
- **Leaving edge on 087f73d:** it would stop following upstream, which is
  edge's whole purpose.

## Risks

- Further drift could show only under the VM checks. The `from_candidate`
  run's `verify` boots them, and nothing is promoted unless they pass.
