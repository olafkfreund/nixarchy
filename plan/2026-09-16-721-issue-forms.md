# Plan: a form for every kind of report, not only bugs

Three new GitHub issue forms beside `bug.yml`. No code, no check, no CI change.

## Decisions, carried from the approved spec

- **D1. `install.yml`** — "Install or ISO failure", label `iso`: what happened
  and where it stopped; how you installed (dropdown: release ISO,
  `nixarchy-reinstall-iso`, `--from-repo`, other); which image; disk mode
  (dropdown: whole disk, free space); encrypted (dropdown); the machine
  (firmware, `lsblk`, VM or not); then `bug.yml`'s versions and existing-issues
  fields. States the 32 GiB minimum (#708) above the disk fields.
- **D2. `request.yml`** — "Feature or package request", label `enhancement`:
  what you want and why; what Omarchy does today; whether it is in nixpkgs;
  existing issues. No versions field.
- **D3. `docs.yml`** — "Documentation", label `documentation`: which page (as a
  link); what it says and what it should say; existing issues. Notes that the
  wiki is a separate repository no check here can see (AGENTS.md §12).
- **D4.** `config.yml` unchanged: the routing links stay above the forms.
  `install.yml` and `request.yml` repeat the "would this happen on Arch?"
  question; `docs.yml` does not.
- **D5.** Only existing labels: `iso`, `enhancement`, `documentation`.
- **D6.** Milestones stay a triage step; forms cannot set one.

## Steps

1. **`.github/ISSUE_TEMPLATE/install.yml`: D1.**
   → verify: `python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))"`
   parses it; the label matches `gh label list`.
2. **`.github/ISSUE_TEMPLATE/request.yml`: D2.** → verify: same.
3. **`.github/ISSUE_TEMPLATE/docs.yml`: D3.** → verify: same.
4. **Cross-check the shared fields** — versions and existing-issues wording is
   `bug.yml`'s, not a paraphrase.
   → verify: `diff` the two blocks against `bug.yml` by eye and state it in the
   PR.
5. **PR:** link all three artifacts, say the verification is deliberately thin
   and why, `Closes #721`. Squash auto-merge.
   → verify: `build` green (no check touches these files).
6. **After merge, open the chooser** at `/issues/new/choose` and confirm four
   forms plus the three routing links, and that each form carries its label.
   → verify: stated in the PR as a human step; report the result.
