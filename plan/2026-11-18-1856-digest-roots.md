# Plan: a nightly failure always reaches its issue

Approved decisions, carried from the spec so this file stands alone:

- **Roots** are derivations in a target's build closure whose log file
  exists locally, in nix's layout
  `${NIX_LOG_DIR:-/nix/var/log/nix}/drvs/<2 chars>/<rest>[.bz2]`, with an
  mtime between the failed job's `started_at - 60 s` and `completed_at +
  60 s`, and whose outputs are not valid. The path test is pure bash; only
  survivors get `outputs_valid`. `read_log` becomes
  `nix log --option substituters '' "$1"`. Measured on p620 for 2026-11-18's
  `keyboard-boot`: 16,745 closure derivations, 169 invalid with a local log,
  **1** inside the window (the real one). Heading text: "built during this
  job".
- **Target fallback** (no roots): read the target's own log as today, but
  label it `(log from outside this job's run: may be an earlier build)` when
  its mtime is outside the window.
- **Byte cap.** `LC_ALL=C` for length arithmetic. Every job heading always
  survives, each cut to 300 bytes; `DIGEST_MAX` below 4,096 is invalid. Then,
  counting every framing byte and reserving one omission line per level
  first: (1) target labels; (2) each target's first root with excerpt, the
  budget split evenly between targets, unused shares returned; (3) further
  root names then `(N more derivations not shown)`; (4) further excerpts then
  `(N more excerpts not shown)`. Excerpts cut at whole lines, fences always
  closed. `emit` keeps a backstop on any body: cut within the cap, close an
  open fence, append `(digest cut at N bytes: this is a bug in
  nightly-digest.sh)`. `DIGEST_MAX` stays 50,000.
- **Report step** (`nightly.yml`, "Open or update an issue"): a `fit()`
  helper with no pipeline: under `LC_ALL=C`,
  `${s:0:$((60000 - ${#note} - 1))}`, drop the partial last line with
  `${x%$'\n'*}`, append `$'\n'$note`; unchanged if already within 60,000
  bytes. Both payloads, `issue create --body` and `issue comment --body`, go
  through it. The digest stays an env var; the byte cap makes that safe.

  files change (none expected: `nightly-digest` is generated)

Not run locally: the nightly itself. After merge, the next failing nightly
files its issue and its digest job takes minutes; until one fails, a
`workflow_dispatch` of `nightly.yml` is not a substitute (it would spend
the night's VM budget), so the PR says so.
