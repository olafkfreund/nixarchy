# Plan: agents on nixarchy can look up nixarchy's own options and manual

## Approved decisions (self-contained)

- **The `nixos` MCP server becomes mcp-nixarchy.**
  - A new flake input, pinned to a commit and following our `nixpkgs`.
  - Set as `programs.nixos.package` in `modules/home.nix` `mcpConfig`.
  - The server key stays `nixos`, so tool names and permissions are unchanged.
  - The command comes from `lib.getExe`, and mcp-nixarchy's `mainProgram` is
    `mcp-nixarchy`.
- **`/etc/nixarchy/options.json`:**
  - built with `nixosOptionsDoc` over `options.programs.nixarchy`, plus the
    Home Manager options from
    `options.home-manager.users.type.getSubOptions [ "home-manager" "users" ]`,
    giving names `home-manager.users.<name>.programs.nixarchy.*`;
  - declarations under nixarchy's source rewritten to
    `https://github.com/olafkfreund/nixarchy/blob/<self.rev or "main">/<path>`;
  - installed under `programs.nixarchy.enable` only (Mode A stays inert).
  - Measured: 1.4 s, 230 MB, 180 KB, 300 options.
- **`/etc/nixarchy/docs`:** `docs/manual` plus `docs/llms.txt` only, about
  430 KB, not the 23 MB `docs/`.
- **Three fixes the catalogue needs:**
  - `defaultText` on `modules/services/microvm.nix:166` (`shares.*.tag`), or
    the build aborts;
  - `_file` on the two flake module exports (`flake.nix:1382-1390`), or 269
    options are "declared in" nixpkgs' `flake.nix` or HM's `common.nix`;
  - the HM prefix above.
- **The release attaches `options.json`,** also listed in `SHA256SUMS`, so the
  existing "promised assets are attached" check covers it (owner signed off).
- **Skills and `docs/manual/ai.md`:** the MCP tool comes first for nixarchy
  questions (`source=nixarchy`, `source=nixarchy-docs`), then
  `nixarchy-search` and `nix search`.
- **Checks:**
  - `tests/options.nix:5702` greps for `mcp-nixarchy`;
  - a new cheap `checks.nixarchy-options`;
  - `tests/ai-mirror-mcp-remove.nix` is unchanged, since its `mcp-nixos` is
    fixture data.
- **One PR** (owner).

## A refinement of the spec (recorded)

The spec put the builder in `flake.nix` as a package, which the module then
reads back. The plan puts it **in the module instead**:
- the module already takes `options` (`modules/nixos.nix:4`);
- it exposes the result as `system.build.nixarchyOptions`;
- `packages.<system>.nixarchy-options` re-exports
  `nixosConfigurations.reference.config.system.build.nixarchyOptions` for the
  release.

That gives one builder, no module-to-flake back-reference, and the same file
on the machine and in the release.

## Repo traps

- **Work only in `/mnt/data/vmtest/wt-1166`.** Scratch trees are
  `git worktree add --detach`, never `cp -a` (it shares the index).
- **After any `.nix` edit:** `nix fmt`, then `git diff --stat`, because a hook
  may reformat with `nixpkgs-fmt` (AGENTS.md §5). statix and deadnix before
  committing.
- **New files are invisible to the flake until `git add`.**
- **No heredoc inside a Nix `''` string** (§5); use `printf '%s\n'`. Capture
  exit status with `if …; then`, never through a pipe.
  `checks.grep-q-pipefail` rejects `grep -q` in a pipe.
- **Build tiers (§6):**
  - cheap evaluation and `runCommand` builds any time, under
    `flock /mnt/data/vmtest/codex-build.lock`;
  - the mcp-nixarchy package build needs the load below 12 and no p620 system
    build running (`pgrep -fc '^(nix build|nh os build|nixos-rebuild).*p620'`
    is 0);
  - **`checks.options` runs in CI only.**
- **§1:** commit a baseline before each break. Restore with
  `git checkout HEAD -- <path>`, never `git checkout -- <path>`. `grep` that
  each break landed.
- **`release.yml` is a CI gate (§11):** only the signed-off asset lines.
  actionlint takes `-shellcheck=` and a `timeout` (it hangs otherwise).
