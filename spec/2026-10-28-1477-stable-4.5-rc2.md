# Spec: stable moves from Omarchy v4.5.0-rc1 to v4.5.0-rc2

## Design

Route (a) from the approved intent: one task branch,
`chore/1477-stable-4.5-rc2`, does the #1405 sequence again.

1. **Bring the branch up to `main`.** `main` moved to a0c223eb (#1476)
   after the branch was cut, so merge `origin/main` first.
2. **Merge `origin/edge` for real** (`git merge`, no squash). A trial
   merge in a scratch worktree on 2026-10-28 was clean, with no
   conflicts. It brings the 143 commits over 33 files from #1423, #1428,
   #1431 and #1447, each with its own approved spec on edge.
3. **Pin the tag.** In `flake.nix:82`, edge's
   `github:basecamp/omarchy/58858aec…` becomes
   `github:basecamp/omarchy/v4.5.0-rc2`. In `flake.nix:432`,
   `omarchyVersion = "edge-20261028-58858ae"` becomes `"4.5.0-rc2"`.
   `flake.lock`'s `omarchy` node is the bump's own: rev 5978d93,
   narHash `sha256-spu9b69…`, the same as commit c6d28ef4 on #1473. Edge's
   `omarchy-edge` merge un-pins and re-pins this pair on its own, which is
   how #1405 left it.
4. **Classify the one new `/etc` file.** Add a row to
   `data/etc-overlay.nix`, beside the other `mkinitcpio.conf.d` rows:

   ```nix
   "mkinitcpio.conf.d/i2c_hid_of_module.conf" = {
     class = "na";
     reason = "MODULES+=(i2c-hid-of) for mkinitcpio, only when omarchy-hw-aarch64-qualcomm detects a Snapdragon laptop, so its internal keyboard can type the disk passphrase. nixarchy builds x86_64-linux only, and NixOS builds its initrd from boot.initrd.*; there is no MODULES list to append to.";
   };
   ```

   `na` rather than `covered` because nothing here answers it. The
   platform it is for is one nixarchy does not build. If aarch64 is ever
   added, this row is where the question gets asked again.

That is the whole change set the trial found. With steps 2 and 3 in
place, `packages.omarchy` for 4.5.0-rc2 **builds**, so no `pkgs/omarchy/`
edit is needed beyond what edge already carries. `checks.bin-ledger`
passes. `checks.etc-overlay` fails on that one row and nothing else.

### What the 30 commits past edge did not need

- **New `bin/` scripts** (n1x GPU memory, clamshell, speedtest, dev-font,
  bar-text-color): `data/bin-ledger.nix` lists only commands that behave
  differently here, so a new upstream command needs no row.
  `checks.bin-ledger` passes. Whether any of them misbehaves on NixOS is
  a question for the VM checks, not the ledger.
- **`sudoers.d/omarchy-locale-generate`**: edge already has its row.
- **Moved shortcuts** (decision 2): I grepped `data/`, `docs/manual/`,
  `tests/demo/`, `pkgs/`, `modules/` and `README.md` for every key in
  rc2's "Some shortcuts moved" and "Notification shortcuts changed"
  lists, in the `Super + Ctrl + T`, `SUPER CTRL, T` and `Super+Tab`
  spellings. The pattern was first checked against five sample strings,
  and matched all five. Nothing names a moved key. The one near miss,
  `SUPER + ,` at `docs/manual/getting-started.md:223`, is a key inside
  nixi's own card, not a Hyprland bind. No edit.
- **New upstream binds versus nixarchy's own.** nixarchy binds 13 keys
  of its own (`SUPER + ALT + {A,D,E,H,N,O,P,U,V}`, `SUPER + CTRL + ALT +
  {A,P}`, `SUPER + PERIOD`, `SUPER + SHIFT + ESCAPE`). None is among the
  206 keys in rc2's `default/hypr/bindings/`.

### Coexistence (§14)

This change adds no NixOS or Home Manager option, and changes no default
that a user would set. The option and module changes it brings are
edge's, and each was answered under its own spec. The one that touches a
setting users commonly set, NetworkManager's connectivity check, is
`mkDefault` and has its fixture, `nm-connectivity-own`, from #1428. The new `/etc` row is
`na`, so `modules/nixos.nix` installs nothing from it. No new fixture is
needed.

### Afterwards

- Close #1473 as superseded by this PR. Its branch belongs to the bump
  workflow, which recreates or deletes it.
- Edge's next `main` merge picks up only the rc2 pin pair and the new
  row. The row also clears #1475 for the part of quattro that rc2
  shares.

## Alternatives rejected

- **Retarget the failing patterns on #1473's branch by hand.** The first
  three fixes reproduced edge's `pkgs/omarchy/default.nix` line for
  line, and the next failure (#1447's nine agents) was edge's too. That
  copies edge's carries without edge's history, so the nightly edge
  merge would replay them as conflicts. That is the exact failure #1405
  left, and §8 records it. It would also mean pushing to a branch the
  bump workflow owns.
- **Fix edge first, route (b).** Rejected by decision 1.
- **Class the new row `covered`**, arguing all-hardware brings
  `i2c-hid-of`. That would be a claim about an aarch64 initrd that no
  nixarchy configuration builds. `covered` has to name a mechanism that
  answers the file *here*, and there is none.
- **Pin rc2 by sha.** #1403 decided on the tag. The nightly bump,
  `review-pins` and the release notes all reason in tags.

## Risks

- **VM checks see what a package build cannot.** rc2 changes shell QML
  (agents panel, bar, clock, notifications service, BackgroundIntro) and
  adds migrations. `session`, `coexist`, `plugin` and `install` boot it
  for the first time on CI. Edge's `verify` booted 58858ae, not rc2's
  30 later commits. A red VM check here means a new carry, found by the
  check and fixed in this PR with its own §1 proof, not a retry (§10).
- **p620 load.** The PR runs `install check` and every `build` VM job.
  Push once, after the cheap checks pass locally, so the run is not
  cancelled and restarted (§6).
- **The merge must stay a merge.** If the PR is squash-merged, edge
  conflicts on its next run, as it did after #1405. The PR body says
  `gh pr merge --merge`, and the merge is done that way.
- **`release` is untouched**, as decided for rc1 (#1403 decision 1).
  Only machines following `main` or an RC tag get rc2. Cutting a
  `v4.5.0-rc2-1` tag is the owner's separate call and is out of scope.
- **Upstream's breaking notes and NixOS.** Limine's 1-second timeout
  does not apply here, because nixarchy does not use Limine. The
  shortcut and notification moves reach users as upstream ships them,
  and the PR description links rc2's release notes for the people who
  follow `main`.

  `install check` green on the PR head, with
  `gh pr view --json headRefOid` checked against the pushed commit
  first (§6).
- **After merge:** `main`'s own `build` and `install check` runs are
  green. The next `omarchy-edge` run merges `main` without conflict.
  #1473 is closed.
