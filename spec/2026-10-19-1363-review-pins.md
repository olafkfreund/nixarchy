# Spec: the nightly review watches every package the daily bump updates

## Design

1. **`pkgs/review.sh`, the `pins` heredoc (lines 114-123).** Add two rows,
   tab-separated, keeping the same alphabetical-by-repo-owner order the list
   has:
   ```
   aether	pkgs/apps/aether.nix	omacom/aether
   owe	pkgs/apps/owe.nix	omacom/owe
   ```
   Both pin `version = "x"` at the top (aether `4.32.0` at line 20; owe
   `0.2.11` at line 26), which is what `pinned_version` reads. Both repos
   publish releases with `v`-tags (`gh api …/releases/latest`: `v4.32.0`,
   `v0.2.11`), which is what `latest_tag` and the `${latest#v}` strip
   (lines 269-279) expect. No probe code changes.

2. **`tests/review-pins.nix`.**
   - `expected` gains `"aether"` and `"owe"`. The existing count check
     (`got` versus `want`) moves to 8 by itself, since `want` is
     `builtins.length expected`.
   - **The comparison.** After the per-name loop, every `pkgs/apps/*.nix` in
     the copied tree that contains `updateScript` must appear in column 2 of
     `pins.txt`:
     ```sh
     for f in pkgs/apps/*.nix; do
       grep -q updateScript "$f" || continue
       cut -f2 pins.txt | grep -qxF "$f" || {
         echo "review: $f has an updateScript (the daily bump updates it) but review.sh does not watch it" >&2
         fail=1
       }
     done
     ```
     That reads the same attribute `.#update` selects on
     (`lib.filterAttrs (_: p: p ? updateScript)`, `flake.nix:1335`), from
     source, which is the intent's open question resolved as grep. It is
     independent of review.sh's list, so it can disagree with it. The
     `grep -q` calls each read a single file, not a pipe, so `pipefail` does
     not apply. The `cut | grep -qxF` pipe is a pipe, so it is written as
     `grep -qxF "$f" <(cut -f2 pins.txt)` or as a captured variable instead
     (tests/AGENTS.md, the `grep -q` SIGPIPE rule).
   - The comparison sits before the existing `if [ "$fail" -ne 0 ]` block,
     so a failure prints review.sh's list as the other failures do.

## Alternatives rejected

- **Derive review.sh's list from the flake.** The review would then agree
  with the bump by construction. The point of a separate, readable list
  (review.sh's own comment) is lost, and review.sh would need nix.
- **Evaluate `nixarchy-apps` in the check for the comparison.** That is
  exact, but it turns a seconds-long `runCommand` into a nixpkgs evaluation.
  The grep reads the same attribute name from the same files.

## Risks

- **A file that mentions `updateScript` only in a comment** would be demanded
  by the comparison. That fails closed (a named failure, fixed by a row or by
  rewording the comment), so it is acceptable.
- **The nightly table gains two rows.** owe will read `ok` at 0.2.11 until
  owe ships 0.2.12, which then shows as **bump**. That is the signal #1359's
  patch waits for, and its guard fails the bump once the fix is upstream.
