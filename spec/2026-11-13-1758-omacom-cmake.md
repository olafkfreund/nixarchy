# Spec: build the six omacom apps with CMake

## Design

Each of `pkgs/apps/{hype,monologue,omacalc,omacut,omawrite,signed}.nix`:

1. **Build system.** Replace `qt6.qmake` in `nativeBuildInputs` with `cmake`
   (nixpkgs' setup hook configures in `build/` and builds there). Add
   `pkg-config` where upstream's CMakeLists calls `pkg_check_modules`: hype
   (libwebp), monologue (libpulse, libturbojpeg), signed (poppler-qt6,
   libqpdf). Keep `qt6.wrapQtAppsHook`.
2. **Install.** Upstream's CMakeLists has no `install()` rules, so the
   existing hand-written `installPhase` stays. It runs in the build directory,
   where CMake leaves the binary under the same name, so `install -Dm755 <app>`
   is unchanged. `$src/pkgbuild/<app>.{desktop,svg}` still exist at every new
   tag (checked against the GitHub trees).
3. **Version and hash.** `nix-update --flake <app>` (the package's own
   `updateScript`) writes the new version and hash.
4. **Hype's version.** Its CMakeLists takes `HYPE_VERSION` from a source
   directory named `hype-<version>`, else `git describe`, else `dev`. Name the
   fetch `hype-${finalAttrs.version}` (`fetchFromGitHub { name = ...; }`), so
   the unpacked directory matches upstream's own regex.
5. **Tests.** `doCheck` stays unset (off), as today. CMake's `find_package(Qt6
   ... Test)` is satisfied by qtbase; hype's optional `Qt6::Pdf` is absent and
   only disables its test target, with a warning.
6. **Comments** that describe qmake (`QT += ... in <app>.pro`, "bin/build is
   qmake + make") are corrected to CMake.

omacalc now ships `pkgbuild/` too, but its package's own desktop entry stays:
switching to upstream's is a behaviour change nobody asked for here.

## Alternatives rejected

- **Run upstream's `bin/build`.** It writes `$root/build` and adds nothing the
  hook does not.
- **Pin the old versions and silence the review.** Leaves the default apps
  behind upstream indefinitely.
- **Patch `HYPE_VERSION` with `substituteInPlace`.** A string patch on a file
  upstream edits often; the directory name is upstream's own supported input.

## Risks

- A dependency CMake now requires that qmake did not (Qt components, pkg-config
  modules): the build fails loudly, on every host, before anything ships.
- Hype's link-time optimisation (`INTERPROCEDURAL_OPTIMIZATION ON`) may need
  binutils' LTO plugin; a failure is again a build failure.
- Nothing runtime-specific: the same binary names and installed paths.

## Verification

- `nix build .#{hype,monologue,omacalc,omacut,omawrite,signed}` at the new
  versions (package tier).
- `strings result/bin/hype | grep -x 0.7.1` (or its `--version`) shows the
  version, not `dev`; break proof: drop the fetch `name` and see `dev`.
- `checks.session` (runs `hype check --help` offscreen and puts all six on
  PATH) and every check `generated-checks.sh` prints, by tier.
- `nix run .#update` leaves these six unchanged afterwards (already newest).
