# Plan: the NIXARCHY banner fits the window it is printed in

The approved decisions, restated here so they do not have to be looked up:

- Only `pkgs/omarchy/branding/logo.txt` changes shape. NIX is redrawn: N and X
  keep their glyphs, and the I goes to 5 columns (`▄███▄` cap, ` ███ ` stem,
  `▀███▀` foot). Gaps are 1 column between N-I and I-X and 2 before the A.
  That is 81 columns and 10 lines.
- Columns 28 onward of every line are upstream's `logo.txt`, byte for byte.
  That moves the R's descender back under the R, fixing a bug that ships today.
- One file serves the banner, Plymouth and the seeded screensaver (decided on
  approval of the intent).
- The assertion is in the omarchy package's `installPhase`, beside the `install`
  of `logo.txt` (`pkgs/omarchy/default.nix:474`). There is no new
  `checks.<name>` and no workflow edit.
- Out of scope: the shared window rule and `installer/brand/logo.txt`.

## Steps

1. Run `gh run list --limit 8 --json status -q '[.[]|select(.status!="completed")]|length'`.
   If an install is in flight, wait before any local build (AGENTS.md §6).
2. **The assertion first, against the old file** (§1).
   `pkgs/omarchy/check-logo.py`, called from `pkgs/omarchy/default.nix` right
   after the `install -Dm444 ... logo.txt` line as
   `python3 ${./check-logo.py} ${./branding/logo.txt} ${src}/logo.txt`
   (the precedent is `nixarchy-plymouth-frames.py`). It fails with a message
   naming which of the three is wrong.
   *Deviation, made during implementation:* the plan had an inline heredoc.
   This `installPhase` has a 4-space line, so Nix strips only 4 columns from
   the indented string. The heredoc's Python would have kept 16 spaces of
   indentation and its `EOF` would never terminate. A file avoids both, and
   avoids `\n` escaping inside `''` strings. The checks it makes:
   - width: `max(len(line))` in **characters**, which must be at most
     upstream's. Not awk: `length()` in the builder's C locale counts bytes,
     and every block glyph is 3 bytes, so an awk check would read 87 columns
     as about 250;
   - line count equal to upstream's;
   - `line[27:]` equal to upstream's `line[27:]` for every line, naming the
     first line that differs.

   Then verify by building `.#omarchy` (the package attribute; confirm the name
   in `flake.nix`) with the **old** 87-column file. It must fail on the width.
   Save the log to `$scratch/fail-width.log`. Do not pipe the build (§1).
3. **The new banner.** Replace `pkgs/omarchy/branding/logo.txt` with the
   prototype (`$scratch/logo81.txt`, generated by slicing N and X from the
   current file, the new I, and upstream's `line[27:]`). Keep the leading
   blank line and the trailing newline the current file has. Verify with
   `python3` that there are 81 columns in characters and 10 lines, and that
   `git diff --stat` touches only that file.
4. **Prove check 3 bites** (§1). Temporarily move the bottom-row descender back
   under the A. Confirm the break landed with `git diff`. The build must then
   fail on the ARCHY columns; save that log as `$scratch/fail-archy.log`.
   Restore with `git checkout HEAD -- pkgs/omarchy/branding/logo.txt`
   (§5: HEAD, not the index), after committing step 3's file as the baseline.
5. **Green build.** Build `.#omarchy`. It must pass the new assertion and the
   existing Plymouth assertions (frames=128, all frames the same size, the
   frame count matching the script). If `frames=128` moves, look at the
   animation and move the number in the same commit (the spec's risk).
6. **Plymouth handoff.** With `magick`, trim the last kept `frame-*.png` and
   `logo.png` from the new build and from the current system's theme, and
   record the ink widths before and after. If the new frame's ink is visibly
   narrower than `logo.png` at the handoff, the fix is the frames'
   `-pointsize` (`default.nix:1747`), and it gets asserted the same way.
7. **By eye.** On the owner's machine, run
   `omarchy-launch-floating-terminal-with-presentation true` with the built
   tree's logo (`OMARCHY_PATH` pointed at the result, or after the switch).
   Take a screenshot for the PR.
8. Run `nix fmt -- --ci`, `statix check .` and `deadnix --fail .`.
9. Give the commit a real subject (§8), then push and open the PR. The PR links
   intent, spec and plan, fills the template's failing-output section with
   `fail-width.log` and `fail-archy.log`, and closes #764.

## Rollback

Revert the one commit. The previous `logo.txt` returns, and the assertion goes
with it. Machines that already seeded the new screensaver keep it, because
`seed_file` never overwrites. That is harmless.
