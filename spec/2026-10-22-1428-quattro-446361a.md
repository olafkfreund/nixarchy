# Spec: edge on Omarchy quattro 446361a

Both open questions in the intent were approved as recommended:
- drop our keybindings timeout in favour of upstream's;
- follow upstream's connectivity check, (a).

## Design

A carry on `carry/1428-quattro-446361a`, cut from `edge-candidate`
(6b851e70). It reaches `edge-candidate` by fast-forward, and edge's own run
verifies it and promotes it, as #1423 did.

1. **Pin.** `flake.nix` gets `github:basecamp/omarchy/446361a5f75bc835fe85da7a499b82351e6eb596`
   and `omarchyVersion = "edge-20261022-446361a"`, and `flake.lock` is
   updated with `nix flake update omarchy`. This is the same edit edge's
   `prepare` makes, so its next run finds the pin already there.
2. **Keybindings.** In `pkgs/omarchy/default.nix` (about lines 450–452),
   delete the `timeout 3 lua` substitution and its comment. Upstream bounds
   the scan itself (`timeout 10` plus a `debug.sethook` instruction limit).
   In the next substitution, `printf 'v17\n'` → `v17-submaps` becomes
   `printf 'v19\n'` → `v19-submaps`, so our submap filter still changes the
   cache key, and a cache written before it is not reused.
3. **Connectivity check, as a native setting.** In `modules/nixos.nix`'s
   `networking` block (line 1761 onwards, next to `wifi.powersave`):
   ```nix
   # etc/NetworkManager/conf.d/omarchy-connectivity.conf: the captive-portal
   # flow waits on `nmcli networking connectivity check`.
   networkmanager.settings.connectivity = {
     uri = lib.mkDefault "http://ping.omacom.io/nm-check.txt";
     response = lib.mkDefault "";
   };
   ```
   `mkDefault` on each scalar, plain assignment on the attrset (the
   `modules/services/default.nix` rule), inside the block that is already
   gated on nixarchy, so Mode A is untouched.
4. **`data/etc-overlay.nix`.** Add a `native` row for
   `NetworkManager/conf.d/omarchy-connectivity.conf`. Its reason names the
   setting in step 3, why it exists (captive-portal sign-in), and how to turn
   it off (`networking.networkmanager.settings.connectivity.enabled = false`).
5. **Coexistence fixture.** Add `nm-connectivity-own` to
   `tests/coexistence/fixtures.nix`: a user module that sets
   `networking.networkmanager.settings.connectivity.uri` to its own URL and
   `enabled = false`. Then add a check in `tests/coexistence/default.nix` that
   the merged config carries the user's values. A plain assignment in step 3
   would make this fixture fail to evaluate with conflicting definitions,
   which is the red that proves the fixture can fail (§14).
6. **Release notes.** The edge brief, or the next release's notes, says that
   NetworkManager now checks connectivity against Basecamp's
   `ping.omacom.io` over plain HTTP, and how to turn that off. Per §14 this
   is a changed default. The note goes wherever edge's existing user-facing
   change notes live. The plan names the file.

## Alternatives rejected

- **Class the file `installed`** (ship upstream's file into
  `/etc/NetworkManager/conf.d`). That is one row and no module code, and it
  would follow upstream's URL automatically. But NetworkManager reads
  `conf.d` after `NetworkManager.conf`, so the shipped file would override a
  user's `networking.networkmanager.settings.connectivity`, and the user
  could not turn the check off the NixOS way. That breaks §14.
- **Class it `na` (no check).** Rejected in the intent: the new captive-portal
  feature never works.
- **Keep our `timeout 3` on top of upstream's `timeout 10`.** Re-anchoring it
  on `    timeout 10 lua -E - <<'LUA'` would work, but it is a patch carried
  for a bound upstream already enforces better.

## Risks

- **The URL is a second copy of upstream's.** If upstream changes the
  endpoint, `etc-overlay` stays green (the file still exists, and the row
  still classifies it), so ours goes stale silently. Mitigation: the row's
  reason quotes the URL, and a content change to an `/etc` file shows in the
  edge brief's file list. A mechanical comparison would need the Omarchy
  source inside a module check, which nothing reads today. Not done here; an
  issue if wanted.
- **Edge's VM checks (`session`, `coexist`, `plugin`) have not run on
  446361a.** Edge's `verify` runs them before promoting, so a red there
  fails before anything is published.
- **Privacy:** this is a new outbound request on every nixarchy machine
  (NetworkManager's default interval is 300 s). Upstream Omarchy makes the
  same request. Announced in step 6.
