# Spec: A red bump pull request is fixed by Claude instead of Copilot

Approved by the owner's standing pre-approval (2026-11-26). The design is Codex's (read-only design pass on #1944's team, 2026-11-26), taken as written except where noted.

Lead's change to the design: the publisher authenticates with the existing BUMP_TOKEN (it already opens bump PRs and starts their CI), not a new GitHub App installation, so the owner has nothing new to set up.

## Design

**For #1944, use Claude Code Action to propose the fix and a separate job to publish it to the existing bump PR.** A direct branch checkout in the Claude job would put PR files in the workspace while `CLAUDE_CODE_OAUTH_TOKEN` is in scope. Running the failing Nix command there would also execute code from the bump. Separate proposal, verification, and publication jobs preserve both guards. [Current handoff workflow](/mnt/data/vmtest/wt-1944/.github/workflows/copilot-handoff.yml:9) · [Anthropic’s `workflow_run` security guidance](https://github.com/anthropics/claude-code-action/blob/v1/docs/security.md#using-this-action-with-pull_request_target-or-workflow_run)

1. **Trigger and eligibility.** In `.github/workflows/claude-handoff.yml`, keep `workflow_run` on `build` with `types: [completed]`. Require `conclusion == 'failure'`, an `update/` branch, and an upstream head repository matching `github.repository`. Start with workflow-level `permissions: {}` and grant access per job. The gate checks out the default-branch event SHA with `persist-credentials: false` and passes event values through `env`. Require exactly one open, non-draft PR whose head repository, branch, and SHA match the failed run. Ignore the `system` aggregator and classify the actual failed steps. Stop on cancellation-only, VM or self-hosted failures, or a failure with no known cheap reproducer. Serialize handoffs per bump branch, retain one attempt per SHA and two per PR, and count only markers written by the trusted handoff identity. Preserve the fail-closed nixpkgs auto-merge check before publication. [Workflow guards](/mnt/data/vmtest/wt-1944/.github/workflows/copilot-handoff.yml:18) · [Existing script guards](/mnt/data/vmtest/wt-1944/.github/scripts/copilot-handoff.sh:8) · [VM step](/mnt/data/vmtest/wt-1944/.github/workflows/build.yml:1692) · [Cancellation rules](/mnt/data/vmtest/wt-1944/CLAUDE.md:710)

2. **Claude invocation and branch publication.** Use `anthropics/claude-code-action@v1` with a nonempty `prompt` and `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`. `workflow_run` uses agent mode. Leave `track_progress` off, keep forks disabled, and retain the action’s actor checks. For the proposal job, pass `github_token: ${{ github.token }}` with `contents: read` and `pull-requests: read`. That override skips GitHub App OIDC, so this job needs neither `id-token: write` nor an installation of Anthropic’s Claude GitHub App. With the action’s default GitHub authentication, the Claude App **must** be installed and the job **does** need `id-token: write`. The subscription token authenticates to Claude in either case. Allow named bot actors only if the actual bump or follow-up run requires them. [Mode detector](https://github.com/anthropics/claude-code-action/blob/v1/src/modes/detector.ts#L79-L96) · [Token selection](https://github.com/anthropics/claude-code-action/blob/v1/src/github/token.ts#L158-L184) · [Actor checks](https://github.com/anthropics/claude-code-action/blob/v1/docs/security.md#using-this-action-with-pull_request_target-or-workflow_run)

   For a direct agent push, the action would need a local branch at the verified upstream head, `CLAUDE_BRANCH` set to the validated `workflow_run.head_branch`, and a GitHub credential with Contents write. The downstream `github.ref` identifies the default branch, so relying on it would select the wrong branch. In this design, Claude instead sees the bump diff and needed file contents as text and returns a bounded patch. The publisher takes the **same patch** that passed validation, rechecks PR state and auto-merge, and appends the fix to the original branch using `createCommitOnBranch` with `expectedHeadOid` set to the failed SHA. The publisher uses a separate repository-scoped GitHub App installation token with Contents write and the PR access needed to disable auto-merge. It uses the API without checking out the bump. An installation-token write starts normal PR CI. A `GITHUB_TOKEN` write can leave the resulting PR workflows awaiting approval. [Agent branch selection](https://github.com/anthropics/claude-code-action/blob/v1/src/modes/agent/index.ts#L120-L143) · [GitHub commit mutation](https://docs.github.com/en/graphql/reference/commits#createcommitonbranch) · [GitHub workflow trigger rules](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow#triggering-a-workflow-from-a-workflow)

3. **Prompt and checks.** Give Claude the PR number, verified SHA, failed jobs and steps, run URL, and a bounded excerpt from `failure-excerpt.sh` with cleanup removed. Treat the log and diff as diagnostic data. Ask for the smallest in-repo fix that keeps the dependency bump, plus the exact failing check to reproduce. Require the same check to fail for the reported reason before the patch and pass afterward. Forbid CI gate edits, workflow edits, repository settings changes, upstream writes, and merge actions. If reproduction requires a VM, a self-hosted runner, or an unknown command, return the blocker and leave the branch untouched. Use a bounded structured response for the patch and selected check. The validator maps that selection to a trusted command rather than executing a command supplied by Claude or a log. [Existing prompt and digest](/mnt/data/vmtest/wt-1944/.github/scripts/copilot-handoff.sh:71) · [Shared excerpt filter](/mnt/data/vmtest/wt-1944/.github/scripts/failure-excerpt.sh:1) · [Repository rules](/mnt/data/vmtest/wt-1944/CLAUDE.md:1184) · [Structured output](https://github.com/anthropics/claude-code-action/blob/v1/action.yml#L177-L192)

4. **Replace the setup job with Nix in the validator.** On a fresh hosted runner, use `./.github/actions/setup-nix` from the trusted checkout before placing the bump SHA in a separate checkout. Keep the metadata smoke test. Give this job no repository secrets, OIDC, cache-write token, or persisted checkout credentials. Allow targeted commands such as `nix fmt -- --ci`, `statix`, `deadnix`, and named fixtures such as `options-shards`, `bin-ledger`, `package-delta`, `config-delta`, and `patched-files`. Only publish after the reproducer goes red and then green. [Composite action](/mnt/data/vmtest/wt-1944/.github/actions/setup-nix/action.yml:20) · [Existing smoke test](/mnt/data/vmtest/wt-1944/.github/workflows/copilot-setup-steps.yml:74) · [Check costs](/mnt/data/vmtest/wt-1944/CLAUDE.md:601)

5. **Remove the old handoff.** Delete `copilot-handoff.yml`, `copilot-setup-steps.yml`, and the `@copilot` posting path. Carry the guard and digest logic forward from `copilot-handoff.sh`, then retire that path. Remove the `COPILOT_AGENT_TOKEN` references and retire the repository secret after cutover. Update the workflow table and handoff docs, the stale comments in `build.yml`, `flake-update.yml`, and `cachix-push.sh`, and the Copilot instructions and agent-bus onboarding text that point to the removed setup. The direct test dependency is `tests/copilot-handoff.nix` and its `tests/copilot-handoff/gh` stub, registered in `flake.nix`. Port those cases to the replacement. `tests/failure-digest.nix` mentions the old name through a historical log fixture, so removing the workflow does not break that check. [Workflow docs](/mnt/data/vmtest/wt-1944/docs/internals/workflows.md:414) · [Agent-bus onboarding](/mnt/data/vmtest/wt-1944/share/agent-bus/COPILOT.md:41) · [Check registration](/mnt/data/vmtest/wt-1944/flake.nix:2532) · [Digest fixture assertion](/mnt/data/vmtest/wt-1944/tests/failure-digest.nix:45)

6. **Prove the guard fails.** Register `checks.claude-handoff` and parse the actual workflow YAML using the pattern in `tests/root-flake.nix`. Assert the exact watched workflow and completion event, failure and same-repository/prefix predicates, trusted checkout in the OAuth job, absence of secrets and write permissions in the validator, and publisher dependency on successful validation. In fixtures, remove the same-repository predicate and move the bump checkout into the OAuth job in separate mutations. Both must fail, and the intact YAML must pass. Keep the shell fixture cases for drafts, stale SHAs, cancellation, VM refusal, deduplication, and unreadable auto-merge state. Under §4, the flake check enters generated PR coverage. Under §11, the workflow change goes through human review. [Existing YAML guard](/mnt/data/vmtest/wt-1944/tests/root-flake.nix:87) · [Generated check coverage](/mnt/data/vmtest/wt-1944/CLAUDE.md:241) · [Human review rule](/mnt/data/vmtest/wt-1944/CLAUDE.md:1189)

Read-only review. The live acceptance check is an installation-token commit to a disposable bump PR that starts `build` on the new head, with the publisher’s auto-merge permissions verified on that repository.
