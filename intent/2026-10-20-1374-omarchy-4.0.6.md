# Intent: nixarchy ships Omarchy 4.0.6

## Problem

Omarchy v4.0.6 was released on 2026-10-19. The nightly `omarchy` bump job
tried it at 04:08 UTC on 2026-10-20 (run 39367966381) and stopped at "needs
manual work", so `main` and stable users are still on 4.0.5.

`.#omarchy` fails while applying the carried patch
`pkgs/omarchy/1153-owe-video-backgrounds.patch`, on its first hunk in
`shell/plugins/lock/Service.qml`. Upstream's fix for the screen sometimes not
locking before suspend (#14978) adds a `currentlyLocked()` function between
the `locked` and `authenticating` properties. The patch applies with
`--fuzz=0`, so the hunk's context no longer matches. Measured in a scratch
copy: with that hunk rebased to include the new function, the whole patch
dry-runs cleanly against v4.0.6.

The build stops at the first failure, so nothing after this patch has been
tried against 4.0.6. Upstream changed 19 files. Most are Arch-only:
migrations, `mkinitcpio`, and tests. Two areas could also need work:

- `bin/omarchy-agent`, which nixarchy patches (`data/bin-ledger.nix`,
  `class = "patch"`);
- the OpenClaw scripts (`omarchy-install-openclaw-cli`,
  `omarchy-launch-openclaw`, `omarchy-remove-ai-openclaw`), which are
  vendored unchanged.

## Proposed outcome

- `main` builds Omarchy 4.0.6: `omarchyVersion` is `4.0.6`, and the input
  is pinned at `v4.0.6`.
- Every carried patch and `--replace-fail` substitution applies, and every
  bin-ledger row still describes what ships.
- The lock-before-suspend fix reaches nixarchy users, since it lives in the
  shell QML that nixarchy ships.
- CI is green, including the install and session checks.
- The edge channel merges the change cleanly.

## Affected users and systems

- Stable-channel users, through the next release (v4.0.6-1). Edge already
  runs quattro, but it takes `main`'s carried patches and ledger rows when
  `main` is merged into `edge-candidate`.
- The files: `flake.nix`, `flake.lock`,
  `pkgs/omarchy/1153-owe-video-backgrounds.patch`, and any other carried
  patch, substitution or ledger row the full build shows has drifted.

## Constraints

- **Rebase our patches; do not change upstream behaviour.** A hunk is
  re-anchored on 4.0.6's lines, and what it adds stays the same.
- `--fuzz=0` and `--replace-fail` stay. They are how drift like this shows
  up at all.
- The patch's header says to delete it at the quattro bump. 4.0.6 is not
  quattro, so the patch stays.
- **Edge:** `flake.nix` lines 82 (the `omarchy` input URL) and 537
  (`omarchyVersion`) differ on `edge`, and so does the lock's `omarchy`
  node. Merging `main` into `edge-candidate` must keep edge's values, and
  the trial merge happens before the PR.
- §6 tiers:
  - `.#omarchy` is a package build, run only when no p620 system build is
    running and the load is below 12;
  - VM checks are left to CI.

## Open questions

- **Release notes.** Upstream's fixes that reach nixarchy are the lock
  before suspend (QML) and possibly OpenClaw. The rest are Arch migrations
  and drivers, which nixarchy does not run. I propose the v4.0.6-1 notes
  name only what reaches nixarchy. Does that fit how you want the release
  worded?
- **Scope.** If the full build shows more drift than this one hunk, I
  propose fixing it all in this one PR, because 4.0.6 cannot ship
  partially. Splitting it would leave `main` unable to build 4.0.6.
