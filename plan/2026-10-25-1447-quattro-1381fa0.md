# Plan: edge takes Omarchy quattro 1381fa0

- Pin quattro `1381fa0` as `edge-20261025-1381fa0`.
- Delete the launcher search-path substitution and our no-browser block,
  which upstream's #16422 makes redundant. On NixOS, `XDG_DATA_DIRS` holds
  `/run/current-system/sw/share`, `/etc/profiles/per-user/$USER/share` and
  `~/.nix-profile/share`. This was checked in a live session's
  `systemctl --user show-environment`.

- Rewrite the two ledger rows.
- Upstream's `omarchy install browser chromium` hint is a follow-up, not
  part of this.

## Deviations

The first build stopped at the launcher, which is why the plan saw only
that break. Two more appeared after it, both from upstream's #14040, which
added nine agents (amp, commandcode, devin, dsh, freebuff, kilo, kiro-cli,
mcode, qwen) to the default-agent menu.

- **2a.** `pkgs/omarchy/default.nix`, the `for a in …` list that adds
  `command -v $a` to each agent row's `checked`. The nine ids are added.
  `check-menu.py` caught the gap, and every id is also its command, as
  upstream's own `agent_present` assumes.
- **2b.** `pkgs/omarchy/nix-bin/omarchy-default-agent` (#1386's
  replacement). Case arms for the nine, with upstream's aliases, plus the
  usage line and `omarchy:args`.
  - Six are installed through nixpkgs, each with `mainProgram` equal to its
    id in the pinned nixpkgs: `amp-cli` (`amp` is a text editor),
    `qwen-code`, `kilocode-cli`, `devin-cli`, `deepseek-harness` and
    `kiro-cli`.
  - The three npm-only agents (`mcode`, `freebuff`, `commandcode`) take the
    mise route with upstream's package names, as `kimi` does, with the same
    node caveat.

- **2c.** Edge's `verify` (run 40205097837) failed `checks.session`'s /usr
  scan. Once our search-path edit was gone, upstream's
  `${XDG_DATA_DIRS:-/usr/local/share:/usr/share}` default left `/usr/` in
  both launchers' code. They join `tests/session.nix`'s "fallback default"
  exceptions, beside `omarchy-cmd-default-browser`, which reads the same
  variable. That is a VM check, so the local run of generated checks could
  not reach it.
- Upstream's `omarchy install browser chromium` hint is right here: it goes
  through `omarchy-pkg-add`, which nixarchy routes declaratively.
- **2d.** The rerun (40210052451) failed all three VM checks, for two
  upstream reasons:
  - `session`: "the locked screen does not move (spread 0)". Upstream
    2a1ff8d (#15289) deleted the lock feed (`LockFeedSurface.qml`, the
    Loader, `owe-lockfeed`), and the lock now shows the video's still. The
    check was asserting a feature that no longer exists, so it is retargeted:
    `settle()` still requires a saturated video frame, and the series must
    now hold still (`spread <= 60`). The import-error assertion is dropped,
    since nothing imports `Owe.LockFeed` and it can no longer fail. §1:
    on e1891c9 the same series read spread 429 (run 40167994040), on
    1381fa0 it reads 0.
  - `coexist`, `plugin`: guest kernel panic, "Out of memory: compulsory
    panic_on_oom". At the OOM, 47 `omarchy-agent-usage-*` processes held
    about 500 MB. `omarchy-agent-usage-update` forks every collector at once,
    and #14040 took them from 5 to 23. Both VMs ran on the 1024 MB default,
    so they now set `virtualisation.memorySize = 2048` (`session` has 6144).
    This is upstream's design and costs a real machine a short spike, so
    nothing is patched.
  - Not done here: `modules/nixos.nix`'s `QML_IMPORT_PATH` for
    `Owe.LockFeed` and its `checks.options` row are now unused on edge.
    They are harmless, and `main`'s pin still loads the feed. They retire
    when this quattro reaches `main`.

Follow-ups, not done here:
