# Intent: edge's tree builds and passes its checks under main's Omarchy pin

## Problem

`main` pins Omarchy at the tag `v4.5.0`, and `edge` pins a quattro commit.
CLAUDE.md §8 describes two kinds of edge→main merge:

- one that keeps `main` on its tag. It restores `main`'s pin on edge's tree,
  as #1477 did, so every line edge carries must hold under both pins;
- one that moves `main` to quattro, where quattro-only lines are correct.

This issue is about the first kind. Measured during #1750 on the unchanged
`edge-candidate` (`b654130`) with `main`'s pin restored (the commands are in
#1752):

1. **The package does not build.** `pkgs/omarchy/default.nix` (from #1485)
   runs `--replace-fail 'exec /usr/lib/omarchy-screensaver/omarchy-screensaver "$@"'`
   on `bin/omarchy-launch-screensaver`. quattro's launcher has that line and
   v4.5.0's does not (1 match against 0, by `gh api` on both refs). So the
   build stops there, and with it every check that needs the package.
2. **More checks fail once the build is unblocked:**

   | check | failure | cause |
   |---|---|---|
   | `checks.user-migrations` | `1794165002 is not in the runner's list` | cases for quattro-only migrations run on every pin |
   | `checks.coexistence` | `qt-own-platform-theme` wants two `/lib/qt-6/plugins` | the fixture assumes qtengine, which v4.5.0 does not ship |
   | `checks.menu-actions` | `install.ai.herdr` "reaches no hazard: stale" | a row for a quattro-only menu entry |
   | `checks.bin-ledger` | allowances "no longer match" for `omarchy-agent-local`, `omarchy-install-dictation-hex` and `omarchy-keyboard-toprow` | rows describing quattro's text of those commands |
   | `checks.user-migrations-ledger` | nine rows "that the pinned source does not need" (`1787481314` … `1794341736`) | rows for quattro-only migrations |
   | `checks.omarchy-package-ledger` | rows for quattro-only packages, for example `folio` and `plain` | #1750 and earlier carries |
   | `readme-counts.sh` | counts derived from the pin (#1537) | edge's README describes quattro |

   The last three were missed when #1752 was filed. During #1750 the
   scratch tree took `main`'s copies of the two ledgers, which hid them. agy's
   review found them. There is also a latent sixth: gating the screensaver
   substitution turns edge's `class = "patch"` row for
   `omarchy-launch-screensaver` stale under v4.5.0.

Nothing fails on either branch today. The cost arrives at the next merge of
the first kind, which would meet these one red check at a time.

## Proposed outcome

- **Code and tests read the pin.** The package, `checks.user-migrations` and
  `checks.coexistence` derive what they do from the pinned source, as
  `hasPapers`, `hasQtengine` and #1750's `hasFiles` do. Under each pin they
  build and pass. Coverage stays: whether a migration applies is decided
  from the pinned source independently of the runner's list, so a migration
  that applies but is missing from the list still fails. The coexistence
  fixture keeps asserting the user's own platform theme under both pins, and
  asserts both contributions where qtengine exists.
- **Ledger rows can differ by pin, field by field.** In
  `data/menu-actions.nix` and `data/bin-ledger.nix`, a value that differs
  between pins (a `bin-ledger` row's allowances, say) can say so. Everything
  that holds on both pins is still checked on both. A stale value is still an
  error under the pin it claims, and an unknown pin is refused.
- **The property is checked.** Edge's own CI builds the package and runs the
  cheap tier against `main`'s exact Omarchy pin, and a failure there blocks
  edge's promotion. That catches a new carry that breaks the property when it
  lands, not at merge time.
- **What ships stays the same.** Each pin's package and system keep the
  behaviour they have now. The plan proves it with builds under both pins and
  a comparison of what each installs. A changed derivation hash alone is not
  a failure, since gating code changes it.
- #1752 closes.

## Affected users and systems

- No change a user can see, on either pin.
- Edge CI gains the both-pins check (Open question 2).
- Files: `pkgs/omarchy/default.nix`, `tests/user-migrations/run`,
  `tests/coexistence/default.nix`, `data/menu-actions.nix`,
  `data/bin-ledger.nix` and the checks that parse them, and the check or job
  for the property.

## Constraints

- The work lands on `edge` through an `edge-candidate` carry, as #1750 did.
  The artifacts go to `main` by their own PR.
- A workflow change is a CI-gate change (CLAUDE.md §11). It is proposed in
  the PR, and the owner merges it.
- `--replace-fail` stays exact. A substitution gated on the pin keeps failing
  loudly under the pin it is meant for (pkgs/AGENTS.md, "Patching upstream").
  So the gate is keyed on a fact other than the needle itself. Testing
  "does the launcher contain this line" would be `--replace-quiet` in
  disguise, and would skip the patch silently on quattro the day upstream
  rewords it.
- **It lands in two phases.**
  1. The package, test and ledger fixes go `edge-candidate` → `edge`.
  2. Then the gating job lands in `omarchy-edge.yml` through a PR to
     `main`, which the owner merges.

  The other order would turn edge red the moment the gate merged.
- Every new or retargeted check is shown to fail first (§1), and that
  includes the both-pins check.

## Open questions

1. **How a ledger value names its pin.** Option A (my recommendation): a
   per-field form, for example an allowance listed under `pins.quattro`, with a
   schema the parser in `tests/` reads. Unknown pin names are refused. It has
   to fit within the regex-parser limits `data/bin-ledger.nix` documents at its
   top. Option B: a list of rows the merge drops, which is simpler but
   unchecked between merges.
2. **Where the both-pins check runs.** Option A (my recommendation): a step in
   `omarchy-edge.yml`'s run that restores `main`'s pin, then runs what an
   edge→main PR would meet: the package, the cheap tier, both toplevels, the
   `options-*` shards and statix, with `readme-counts.sh` either run with
   `--fix` first or excluded, as decided in the spec. It gates promotion. A `checks.<name>` cannot do this on
   its own, because it cannot swap a flake input. Option B: nightly only. That
   finds a break a day later, and it is not obviously cheaper, since edge
   already builds most of it.
