# Intent: Correct stale hypr-rdp and snapshot descriptions

## Problem

Both stale-doc findings in the issue hold up, with narrower facts than the review stated:

- `modules/services/hypr-rdp.nix:26-36` says the password-file change is merged but not tagged and that v0.1.5 is the newest release. The same file at `:382-389` says nothing is merged. Both conflict with `flake.nix:127-129` and `flake.lock`, which pin v0.1.6. The pinned upstream `src/config.rs` has `password_file`, rejects a missing or empty named file, but still warns and serves without authentication when no credentials are configured. Thus the claim at `modules/services/hypr-rdp.nix:30-31` that upstream now fails startup for the empty-credentials case is also false.
- `data/bin-ledger.nix:554` says `omarchy-snapshot` snapshots `/home` and `/var/lib` and restores from the running system. The command at `pkgs/omarchy/nix-bin/omarchy-snapshot:147-197` creates and restores only `/home` snapshots. The installer separately takes a root snapshot at boot (`installer/host.nix:347-356`), which includes `/var/lib`. The ledger obscures that difference.

No item in this group is already fixed; neither finding is dropped. The snapshot claim is misleading rather than wholly false because the boot-time root snapshot does cover `/var/lib`.

## Proposed outcome

The hypr-rdp comments describe the pinned release and its actual fail-open boundary without contradictory migration advice. The command ledger distinguishes manual `/home` snapshots and restore from boot-time root snapshots containing `/var/lib`.

## Affected users and systems

Maintainers reading the hypr-rdp module, and users or reviewers relying on the command ledger. These are documentation corrections; no service, snapshot schedule, restore action, or host configuration changes.
