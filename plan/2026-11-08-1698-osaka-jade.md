# Plan: a machine on Osaka Jade keeps a working theme after Omarchy dropped it

## Decisions carried from the approved spec (and the Codex reviews)

1. **Bundled again, filtered as upstream filters an installed theme.**
   `pkgs/omarchy/default.nix` fetches
   `omacom/omarchy-osaka-jade-theme` at
   `bc18781cdd0102f86cbc3e82c6bd6d420c8025b9`, hash
   `sha256-4BGYncJ7a0/qHNTAs91x3C9ciEx+9/tioGMg5fR+siQ=`. It copies it to
   `$out/share/omarchy/themes/osaka-jade` **without** the files upstream
   refuses from a theme installed from a repository
   (`bin/omarchy-theme-set:25-35,290-294`): any `*.lua`, `alacritty.toml`,
   `foot.ini`, `ghostty.conf`, `kitty.conf`, `vscode.json`, and any
   symlink. Here that drops `neovim.lua` and `vscode.json`. This is a
   deviation from the spec's "as any bundled theme" (Codex intent review,
   finding 1): the repository is no longer one upstream bundles, so it gets
   the trust upstream gives it today, the same files a user gets by
   installing it from the menu.
2. **Refuse on collision.** If `themes/osaka-jade` already exists in the
   tree, the build fails with "upstream ships osaka-jade again; drop the
   #1698 carry".
3. **No migration, no network.** `omarchy-theme-list` and
   `omarchy-theme-set` read `$OMARCHY_PATH/themes/` (`bin/omarchy-theme-list:8`;
   staging at `pkgs/omarchy/default.nix:481-482`), so the directory is the
   whole integration. An already-staged copy keeps working, and the fix
   is that a refresh or a re-select finds the source again. It does not
   force a re-stage (Codex finding 3).
4. **Hand-refreshed pin**, stated in `pkgs/AGENTS.md`: the nightly review
   watches `flake.lock`, not `fetchFromGitHub` revisions.
5. **Edge:** quattro's `1787481314` exits 0 when
   `$OMARCHY_PATH/themes/osaka-jade/colors.toml` exists. Its declined row's
   reason is updated in the next edge carry; `main` has no such row.

## Steps

1. **The theme** (`pkgs/omarchy/default.nix`, `pkgs/AGENTS.md`):
   - add `fetchFromGitHub` to the function's arguments if absent, and an
     `osakaJadeTheme` binding in the `let` (decision 1's values);
   - in the install phase, after the vendored tree is in `$out`, add one
     `# Why: pkgs/AGENTS.md#osaka-jade-is-bundled-again-1698` line, the
     collision refusal, a `cp -r --no-preserve=mode ${osakaJadeTheme}/.`
     into the theme directory, and the removal of the denied names and
     any symlinks (`find -type l -delete`, and `find -name '*.lua' -delete`);
   - a 6-8 line `pkgs/AGENTS.md` section: what, why (#1698, upstream
     a1ea6096d), the filter and its source lines, and how to refresh or
     drop it.

   Verify: `nix build .#omarchy` (package tier) has
   `share/omarchy/themes/osaka-jade/colors.toml`, has no `neovim.lua` or
   `vscode.json`, and `checks.install-phase-budget` passes.
   Traps: keep the install-phase comment to the `Why:` pointer
   (install-phase-budget). In a Nix `''` string only `${` interpolates.

2. **The check** (`tests/osaka-jade-theme.nix`, `flake.nix` beside the other
   tree checks): a `runCommand` taking the omarchy package that asserts:
   - `themes/osaka-jade/colors.toml` exists;
   - no `*.lua`, no denied file and no symlink under the theme;
   - `omarchy-theme-list`, run with an empty `HOME` (and `OMARCHY_PATH` at
     the tree), prints `osaka-jade`.

   Each failing assertion prints its reason with an explicit `if ... exit 1`
   (never `! grep`). Verify: build passes. §1: with step 1's copy line
   removed, the check fails on `colors.toml`; with the filter removed, it
   fails on `neovim.lua`.

3. **Run, commit, PR** (session): cheap checks (fmt, statix, deadnix,
   `grep-q-pipefail`, `test-registration`), and the package tier for
   `omarchy`, `install-phase-budget` and `osaka-jade-theme` when the gate is
   open. Then the two breaks, one commit per step, and a PR saying
   `Closes #1698`, "@codex review", merged with a merge commit.
