**Verification of the facts before writing:**
- #1: `release` resolves and has `defaultPlugins`
  (`git grep defaultPlugins origin/release -- modules`).
- #2: the Setup ▸ Defaults ▸ Menu label in `data/` or `modules/apps.nix`.
- #8: the summary-line wording in `pkgs/verify.sh`.

## Alternatives rejected

- **Pinning a tag:** decided against (intent decision 1). It goes stale,
  as `v4.0.3-2` did.
- **Stating the upstream skill count:** it changes with every Omarchy
  release and no check guards it, so it would drift again. "A few" stays
  true.
- **A new page for `nixarchy-verify`:** it would need all three lists, and
  a subsection next to the doctor is where a reader with a problem already
  is.

## Risks

- `build.yml`'s docs guards (the page lists, `readme-counts.sh`, the
  rdp-docs check) could trip on a reworded count. Mitigation: run
  `readme-counts.sh` and the docs checks locally before pushing.
- Wording drift between README and the manual for #1. The same sentence
  goes in all three places.

- `grep -n 'one palette' docs/index.md` is empty.
- `.github/scripts/readme-counts.sh` and the generated docs checks
  (`checks.*` naming docs or rdp) pass.
- The "Every manual page is in the sidebar" step passes. No list changed.
- §1: this changes prose, not a check. No new check is added, because
  "does the prose describe the behaviour" has no mechanical test. The
