# Spec: the config writers take apply's lock and keep the files they edit

Line numbers are `modules/apps.nix` at the approval commit unless another
file is named.

## Design

### 1. One shared helper, `pkgs/writer-lock.sh`

There is no lock or put helper today; apply's lock is inline (4424-4437).
One new file holds four functions. It is spliced into each writer's `text`
with `builtins.readFile`, the way `insertMissingAppRow` (166-182) is spliced
today. `pkgs/pkg-new.sh` gets it through an `@writerLock@` token, which
apps.nix (3405) and `tests/pkg-new.nix` (31) both replace. A file, not a
let-bound string, so the new check can source it on its own.

- **`nx_lock`** takes the lock for this process:
  - If `NIXARCHY_LOCK_HELD=1`, it returns at once. A parent holds the lock,
    and re-opening the file would deadlock: `flock` locks per open file
    description.
  - Otherwise it creates `${XDG_STATE_HOME:-$HOME/.local/state}/nixarchy/applied`,
    opens `lock` on fd 9 (`9>>`, so it never truncates), and runs
    `flock -w 5 9`. Each failure, at mkdir, open or flock, calls `nx_refuse`
    with its own cause. Nothing is written unlocked.
  - On success it exports `NIXARCHY_LOCK_HELD=1` and records that this
    process owns the lock.
- **`nx_unlock`** releases it if this process owns it (`exec 9>&-` and
  `unset NIXARCHY_LOCK_HELD`), and does nothing otherwise. Every writer calls
  it before a success notification, before any `exec`, and in its EXIT trap,
  so no child outlives the edit holding fd 9.
- **`nx_put SRC DST`** puts SRC's bytes into DST in place:
  - It refuses unless DST is a writable regular file, after following
    symlinks. That covers a link into `/nix/store`.
  - It copies DST to a backup under the state directory.
  - With `INT TERM HUP XFSZ` ignored, it writes `cat SRC > DST`. That keeps
    the inode, mode, owner and any symlink.
  - If the write fails (ENOSPC, EFBIG), it writes the backup back (it fits,
    because those bytes fit before) and refuses. Ignoring the signals is what
    makes Ctrl-C all or nothing: the write takes milliseconds.
- **`nx_sed DST ARGS...`** is `sed ARGS DST > tmp` then `nx_put tmp DST`. It
  replaces every `sed -i` on a user file.
- **`nx_refuse MSG`** prints to stderr. When stderr is not a terminal and
  `omarchy-notification-send` is on PATH, it also sends a critical
  notification, as app-enable's `fail()` does (2309-2315). It exits 1. This
  covers the menu rows (intent question 3).

The refusal text for a busy lock is: `a write or an apply is running -- try
again when it finishes. Nothing was changed.` That is the same wording as
nixarchy-pkg#65.

### 2. Where each writer locks

**Lock first, then read, edit and write.** These have no prompt, network
fetch or build between their read and their write:
- catalogue-diff (1742-1818)
- language-select (2219-2247)
- service-disable (2278-2287)
- app-enable (2321-2332)
- app-disable (2390-2409)

**Prompt first, then lock, re-read and write:**
- **pkg-remove, pkg-undraft, opt-remove:** the fzf picker runs before the
  lock. Inside the lock: backup, re-check (2570, 2667 and the opt row), edit,
  parse check and restore. The re-checks already exist, so a row removed
  during the picker is refused, not corrupted.
- **service-enable:** `openssh_gate` (gum, curl and `authorized_keys`) runs
  unlocked. The lock is taken before the decisive re-read at 2006. The nested
  `nixarchy-catalogue-diff --add-one` call (1990) moves after the lock and
  runs with `9>&-`; it sees `NIXARCHY_LOCK_HELD=1`.

**Work on a copy, then commit if nothing changed underneath:**
- **pkg-add:** its slow eval (3079-3108) and both prompts (3255, 3328) sit
  inside its edit window today.
  - It snapshots `apps.nix` once at 2977, where the backup is taken now, and
    points `file` at a private working copy.
  - Every existing edit, restore and parse check then acts on the copy,
    unchanged.
  - The diff and the `[Y/n]` prompt come before anything is written. Today
    the prompt comes after the write.
  - Then, under the lock, it checks `apps.nix` is still byte-identical to the
    snapshot. If it is not, it refuses: `apps.nix changed while pkg-add was
    running; nothing was written -- run it again`. If it is, `nx_put`
    commits the copy.
  - Every "restore" becomes "discard the copy", so no backup can overwrite
    someone else's change.
  - Both `exec nixarchy-search` sites (2957, 3220) run after `nx_unlock`.
- **pkg-new:** nix-init and the builds run unlocked. Only the `apps.nix`
  insert (pkg-new.sh:177-186) runs under the lock. Its awk temp goes to
  `nx_put`, not `mv`. The draft's own `sed -i` (151) becomes `nx_sed`, with
  no lock: the draft is pkg-new's own new file.
- **search:** it holds no lock across its picker or its batch, so a nested
  `pkg-new` build never holds it.
  - Each nested writer locks for itself, as when run directly. search does
    not export the handshake, because it does not hold the lock.
  - Its own edit, `insert_line` (3688-3695), takes the lock, re-reads the
    file, and runs the parse check (`nix-instantiate --parse`, milliseconds)
    on the result before `nx_put`.
  - The batch-level restore of the pre-loop backup (3678, 3913-3914) is
    removed. It reverted the nested writers' changes along with search's
    own, and per-insert validation makes it unnecessary.

**Applying to all twelve:**
- Every `mv "$tmp" "$file"` and `sed -i` on a user file becomes `nx_put` or
  `nx_sed`.
- `util-linux` joins every writer's `runtimeInputs` (§7).
- Each writer's EXIT trap calls `nx_unlock`, and keeps the temp-file cleanup
  it has today.

### 3. `nixarchy-apply`'s messages

- The `--yes` refusal (4432) becomes `a write or another apply is running
  ... try again when it finishes`.
- The interactive message (4435) becomes `waiting for a write or another
  apply to finish...`.
- Apply's own locking is unchanged, and it does not read `NIXARCHY_LOCK_HELD`
  (intent question 2).

## Alternatives rejected

- **Hold the lock for the whole writer.** pkg-add's eval, its `[Y/n]`
  prompts and pkg-new's builds would block every other writer and apply for
  minutes, and a 5 s wait would then refuse every concurrent call.
- **`rename(2)` from a same-directory temp file, as today.** It replaces the
  inode, which breaks symlinks and drops the owner. nixarchy-pkg#65 rejected
  it for the same reason.
- **`sed --follow-symlinks -i`.** It keeps a symlink, but still replaces the
  target's inode and resets its owner.
- **Search holds the lock across its batch.** A nested `pkg-new` (nix-init
  and up to three builds) would hold it for minutes.
- **A lock per file (`apps.nix.lock`).** It does not exclude
  `nixarchy-apply`, which copies all of them under `applied/lock`.

## Risks

- **pkg-add's control flow is the largest edit.** Every restore path (2876,
  3016, 3111, 3145, 3161, 3287, 3295, 3331) must act on the copy.
  `app-selection.nix` already runs pkg-add through these paths, so a missed
  one fails there.
- **Optimistic refusal.** A pkg-add left at its prompt while something else
  edits `apps.nix` refuses at commit and asks for a re-run. Intended: the
  alternative is a silent overwrite.
- **search no longer reverts a bad batch as a whole.** Its own inserts are
  validated one at a time, and each nested writer validates its own edit, so
  a broken file cannot result. What is lost is "undo everything this run
  did", which already undid other writers' changes.
- **A user holding apply at its prompt** blocks writers for that time, and
  each refuses after 5 s with the message above. Intended (intent question
  1).
- **Hosts:** none directly. Every machine gets the new writers at the next
  switch. Mode A users never run them.

## Coexistence

None of these touch an option a user sets. The files edited are nixarchy's
own (`~/.config/nixarchy/*.nix`). No `tests/coexistence` fixture applies.

## Verification

A new cheap check, `checks.writer-lock` (`tests/writer-lock.nix`), sources
`pkgs/writer-lock.sh` under bash, with a temporary `HOME` and
`XDG_STATE_HOME`. It is in no workflow list, so the generated step runs it
(§4). Its cases:

1. **Contention:** a holder `flock`s the lock and sleeps. `nx_lock` refuses
   within 5-7 s, the file is unchanged, and the message names "a write or an
   apply".
2. **Nesting:** the same holder, with `NIXARCHY_LOCK_HELD=1`. `nx_lock`
   returns at once, so there is no deadlock.
3. **Fail closed:** the state directory is unwritable. `nx_lock` refuses and
   nothing is written.
4. **Inode, symlink, mode:** a symlinked target at mode 0640. After `nx_put`,
   the link, the inode number and the mode are all unchanged.
5. **Read-only target:** a symlink into a read-only directory is refused, and
   the file is unchanged.
6. **Interrupted write:** SRC is a FIFO the test feeds slowly. SIGINT goes to
   the put mid-write. DST then holds all of the new content.
7. **Full disk:** a `ulimit -f` between the old and new sizes makes the write
   fail. DST then holds all of the old content, and the call refuses.
8. **Commit refusal:** the snapshot no longer matches the target, and pkg-add
   refuses. The commit step is a helper function in `writer-lock.sh` so it is
   reachable here.

Changes to existing checks:

- **`app-selection.nix`:** the assertions that encode the rename model
  (56-59, 73-76) become "same inode", and the PR says so (§1 read
  backwards). New cases:
  - app-enable through a symlinked `apps.nix`;
  - app-enable refused while a holder holds the lock (next to apply's
    existing case, 197-203);
  - pkg-add refused when `apps.nix` changes before commit.
- **`language-select.nix`, `sshd-enable.nix`:** set `XDG_STATE_HOME` to a
  temporary directory (§4, #802).

Each new assertion is proved red with its guard removed:
- `nx_lock` made a no-op;
- `nx_put` reverted to `mv`;
- the signal-ignore removed;
- the commit-unchanged check removed.

Then green with it restored, and the failing output goes in the PR.

Also run: the generated checks, `options-*`, and `session` (it runs
app-enable and apply as a user).
