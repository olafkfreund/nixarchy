# Plan: Repair stale desktop scripts

This is a partial **Refs #1098** change for the five Stale scripts findings only. The pinned Omarchy source is `c668141` (`flake.lock:1121-1135`). Its Spotify, Signal and ChatGPT install scripts still launch `/usr/bin` app paths, even though the separate Spotify/Signal launchers are patched. The other affected scripts are nixarchy replacements. Preserve package overrides, the saved `antigravity` menu id, GTK cursor settings, Snapper's list output and copy-back-only restore, and preview's software-emulation warning. No workflow edit, VM run locally, or criticals-owned file edit is authorized. The push hold remains until lifted.

The cursor change has a **decision gate**. First try the supported `hyprctl eval 'hl.env("XCURSOR_THEME", "<theme>")'` call with the two fixed Bibata names. A real session check must prove a process launched by the compositor **after** the call inherits the selected value. If it does, keep the runtime implementation. If it does not, use the approved persistent fallback instead: `omarchy-cursor-set` writes a valid `export XCURSOR_THEME=<theme>` shell fragment to `${XDG_CONFIG_HOME:-$HOME/.config}/uwsm/env.d/90-nixarchy-cursor`. Create the directory, use a temporary file in that same directory and `mv` it into place atomically. Compare the desired content first, and notify **only when it changes**, using `notify-send` or stderr, never stdout; the message says the change takes effect after the next login. Refuse an existing symlink. Under the script's `set -euo pipefail`, a refused symlink or write failure must warn and continue the GTK and `setcursor` work/unit rather than abort it. UWSM reads `env.d/*` during session startup, as the pinned Omarchy `default/uwsm/env.d/10-omarchy` demonstrates. Verify the fallback after a fresh login; do not claim immediate propagation. Record which branch the proof selected in the implementation commit and PR.
