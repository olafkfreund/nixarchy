## Decisions carried over from the approved spec

All were approved by the owner on 2026-11-05.

1. **Only the menu route is hardened.** A rebuild does not tell two identical
   lines apart. The two routes write different options:

   | how sshd was turned on | line in `services.nix` | passwords |
   |---|---|---|
   | hand-uncommented old row, or a menu pick before this change | `services.openssh.enable = true;` | on, unchanged |
   | own config | `services.openssh.enable = true;` | on, unchanged |
   | menu, after this change | `programs.nixarchy.services.openssh.enable = true;` | off |

2. **The catalogue row becomes `kind = "bundled"`, in new files too.** A
   hand-uncomment in a new file gets passwords off and no key check. Accepted.
3. **No key the machine can see: ask, and do not turn on without one.**
4. **Already-enabled machines stay on passwords.** A live row is never
   rewritten. The "already enabled" exit says passwords are still on and points
   at the manual. Turning the row off and on again is a new pick: it goes through
   the key check and comes out hardened. The prompt says passwords go off for
   every account.
5. **A user's `lib.mkDefault true` is an evaluation error.** Accepted, recorded
   by a fixture. Not a weaker priority.
6. **`checks.sshd-login` runs on pull requests.** It needs KVM, so it joins
   `claimed` and gets a step in `build.yml`. **This CI-gate edit is approved by
   the owner in spec decision 2** (§4, §11 otherwise require a human).
7. **The hand-written release note goes in the PR body**, and is added to the
   release and its Discussion by hand at release time. No new slot in `release.yml`.
8. `openFirewall` stays at nixpkgs' `true`. Rate limiting is out of scope.
   `data/arch-extras.nix:126-127` and the vendored
   `bin/omarchy-setup-security-sshd` do not change.

**Stop condition.** If `hardened` accepts a password in step 1, the spec is wrong.
Stop and take it back for review. No further step.

**A refinement of the spec, found in review.** The spec subtracts nixpkgs' two entries
from `authorizedKeysFiles`. That leaves a hole: a user who forced the list to
`[ "/etc/ssh/authorized_keys.d/%u" ]` shows no other source, and a home key sshd will
not read passes the gate. Nothing needs subtracting, because the two defaults are absent
at every point the gate reads this. So any entry counts as a source the gate cannot
see, and it asks. The cost is one extra question for a user who wrote a default entry by
hand. Evaluated on the reference config with sshd off: `{"declaredUsers":[],"homeRead":true,"otherSources":[],"sshdOn":false}`.

```bash
live_row="^[[:space:]]*[^#[:space:]].*#@ $id([[:space:]]|\$)"

# No terminal, a cancel and a refused prompt are all a non-zero gum, so all refuse.
refuse() {
  echo "nixarchy: $1" >&2
  echo "  $file is unchanged." >&2
  exit 1
}

authorize_key() {
  # Called as an `if` condition, where set -e is off, so each step says so itself.
  ssh-keygen -lf /dev/stdin <<<"$1" >/dev/null 2>&1 || return 1
  mkdir -p "$HOME/.ssh" || return 1
  chmod 700 "$HOME/.ssh" || return 1
  touch "$HOME/.ssh/authorized_keys" || return 1
  chmod 600 "$HOME/.ssh/authorized_keys" || return 1
  if ! grep -qxF "$1" "$HOME/.ssh/authorized_keys"; then
    echo "$1" >>"$HOME/.ssh/authorized_keys" || return 1
  fi
}

openssh_gate() {
  local facts="''${NIXARCHY_SSH_FACTS:-${sshFacts}}"
  local keys="$HOME/.ssh/authorized_keys" me sshd_on home_read sources declared
  local github paste user key fetched added=0
  me=$(id -un) || refuse "cannot tell who is running this"
  sshd_on=$(jq -r .sshdOn "$facts") || refuse "cannot read $facts"
  home_read=$(jq -r .homeRead "$facts") || refuse "cannot read $facts"
  sources=$(jq -r '.otherSources | join(", ")' "$facts") || refuse "cannot read $facts"
  declared=$(jq -r --arg u "$me" '.declaredUsers | index($u) != null' "$facts") || refuse "cannot read $facts"

  # 1. The lockout case: other accounts may be logging in with passwords, and a
  # yes from this person cannot show that nobody loses access.
  if [ "$sshd_on" = true ]; then
    echo "sshd is already on, and not from this menu row." >&2
    echo "To turn passwords off, add these to your own config:" >&2
    echo "  services.openssh.settings.PasswordAuthentication = false;" >&2
    echo "  services.openssh.settings.KbdInteractiveAuthentication = false;" >&2
    refuse "if you just turned the row off, run nixarchy-apply first"
  fi

  echo "Passwords go off for every account, not only yours."

  # 2. First, because a forced authorizedKeysFiles may omit the two defaults.
  if [ -n "$sources" ]; then
    echo "sshd also reads keys from: $sources. This cannot see those."
    gum confirm "Do they hold a key for $me?" ||
      refuse "no key confirmed in $sources"
    return 0
  fi

  # 3. ssh-keygen and not -s: a comment-only file holds no key.
  if [ "$declared" = true ]; then
    echo "Using the key declared for $me in users.users.$me.openssh.authorizedKeys."
    return 0
  fi
  if [ "$home_read" = true ] && ssh-keygen -lf "$keys" >/dev/null 2>&1; then
    echo "Using the key in $keys."
    return 0
  fi

  # 4. A key written to the home file would not be read.
  if [ "$home_read" != true ]; then
    refuse "sshd does not read $keys here. Add a key to users.users.$me.openssh.authorizedKeys and run nixarchy-apply first"
  fi

  # 5. Ask, in upstream's order.
  echo "sshd needs a key from you first."
  github=$(omarchy-i18n sshd.keyFromGithub) || refuse "cannot read the prompts"
  paste=$(omarchy-i18n sshd.keyPaste) || refuse "cannot read the prompts"
  no_key="no key added. Keys go in $keys or users.users.$me.openssh.authorizedKeys. If you only want sshd's host key for sops, declare services.openssh yourself"
  case $(gum choose "$github" "$paste" --header "$(omarchy-i18n sshd.howToAddKey)" || true) in
    "$github")
      user=$(gum input --prompt "$(omarchy-i18n sshd.githubUserPrompt)" --placeholder "username") || refuse "$no_key"
      case "$user" in
        "" | -* | *[!A-Za-z0-9-]*) refuse "'$user' is not a GitHub username" ;;
      esac
      fetched=$(curl -fsSL "https://github.com/$user.keys") || refuse "could not fetch keys for '$user'"
      while IFS= read -r key; do
        [ -n "$key" ] || continue
        if authorize_key "$key"; then added=$((added + 1)); fi
      done <<<"$fetched"
      ;;
    "$paste")
      key=$(gum input --prompt "$(omarchy-i18n sshd.publicKeyPrompt)" --placeholder "ssh-ed25519 AAAA... you@host") || refuse "$no_key"
      if authorize_key "$key"; then added=1; fi
      ;;
    *) refuse "$no_key" ;;
  esac
  [ "$added" -gt 0 ] || refuse "$no_key"
  echo "Added $added key(s) to $keys."
}

if [ "$id" = openssh ] && ! grep -qE "$live_row" "$file"; then
  openssh_gate
fi
```

## Rollback

Revert the merge commit, **and keep the option declared.** Once a user's
`services.nix` has `programs.nixarchy.services.openssh.enable = true;`, a nixarchy
without that option fails to evaluate with "option does not exist". So a revert after a
release must leave `modules/services/openssh.nix` in place, or add a
`mkRemovedOptionModule` with the migration text, as `hypr-rdp` at
`modules/services/default.nix:70`. Before a release, a plain revert is enough.

Booting an older generation needs nothing. A user who wants passwords back sets
`services.openssh.settings.PasswordAuthentication = true;`, which the coexistence
fixture proves wins.
