- **PR 2 pin:** `nixarchy-hyprsettngs` (line 372) 2157e889 → 367ca99e
  (main's head). Its manifest says `nixarchy.hyprlandsettings`, and its
  LICENSE still says `Copyright (c) 2026 Aziz`.
- **Packaging:** `hyprforgePlugin` (`modules/home.nix:429-437`) also strips
  the repo-only files the head ships: `.github`, `.gitignore`, `AGENTS.md`,
  `CLAUDE.md`, `devenv.*`, `flake.*`, `intent`, `plan`, `skills`, `spec`.
  Its own module and keybindings are not imported.
- **Id:** `aziz.hyprforge` → `nixarchy.hyprlandsettings` everywhere
  nixarchy names it. The option name `defaultPlugins.hyprforge` stays.
- **Migration, through the shell's writer only:** `shell.json` is read
  with `jq`, never written.
  - Old marker present and new absent, old id on: the new id is enabled.
  - Old id off: the marker moves, and the new id stays off.
  - The old id is then disabled through `omarchy-plugin-disable || true`.

**Two refinements of the spec's mechanism, same behaviour:**

1. **The table is a field, not a literal.** `defaultPluginSet` entries gain
   `renamedFrom` (str, default `""`). The hook builds its table from the
   resolved defaults. The spec's VM test cannot otherwise run, because the
   `plugin` VM turns Hyprforge off (`tests/plugin.nix:193`); with the field,
   its own fixtures carry a rename.
2. **"On" drops the old marker, and the hook's existing default path
   enables the new id.** The spec had the migration call
   `omarchy-plugin-enable <new>` itself, which is the same command the
   default path already runs. That path also passes the placement, and
   writes the marker only once the enable has worked. "Off" moves the
   marker as the spec says.

**Who implements:** PR 1 is a pin bump, so the lead does it. PR 2 touches
about 8 files, so the `coder` agent does steps 4-6 and the lead does the
rest.

5. **Coder: the migration** in the `default-plugins` hook
   (`modules/home.nix:2190`ff). It goes before the `todo=()` loop, so a
   moved marker keeps the new id out of `todo`:
   ```bash
   # A default whose id changed: its once-marker and the user's on/off move
   # to the new id (#1391). shell.json is read, never written (see above).
   declare -A renamed=(${…[new]=old for each resolved default with renamedFrom != ""…})
   cfgjson="''${XDG_CONFIG_HOME:-$HOME/.config}/omarchy/shell.json"
   retired=()
   for new in "''${!renamed[@]}"; do
     old=''${renamed[$new]}
     [ -e "$state/$old" ] && [ ! -e "$state/$new" ] || continue
     jq -e --arg id "$old" \
       'any(.plugins[]?; (if type == "object" then .id else . end) == $id)' \
       "$cfgjson" >/dev/null 2>&1
     case $? in
       0) rm -f "$state/$old"; retired+=("$old") ;; # on: enabled below as a new default
       1) mkdir -p "$state"; mv "$state/$old" "$state/$new" ;; # off: stays off
     esac # unreadable: left for the next login
   done
   ```

   ```bash
   for old in "''${retired[@]}"; do
     omarchy-plugin-disable "$old" 2>&1 | systemd-cat -t nixarchy-default-plugins || true

   ```

## Rollback

- PR 1: revert. The pins go back to the `qt612-on-pin` commits, which is
  why those branches stay until both PRs are on main.
- PR 2: reverting restores `aziz.hyprforge`. A user migrated in between
  has no old marker any more, so the old id comes back on as a fresh
  default, even for a user who had it off. A revert therefore needs the
  reverse table row (`renamedFrom = "nixarchy.hyprlandsettings"`), not a
  plain revert.
