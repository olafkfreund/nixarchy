# Plan: edge's tree builds and passes its checks under main's Omarchy pin

Self-contained: it carries every approved spec decision. Builds, checks,
commits, pushes and dispatches are Claude's. Codex and the coder edit files
only, and agy reviews only, because `agent-run agy` cannot reach `/mnt/data`
worktrees. All file paths below are on edge, read with
`git show origin/edge:<path>`.

## Decisions (from the approved spec)

1. **The pin signal.** An edge pin is `lib.hasPrefix "edge-" omarchy.version`.
   Python checks get it as `--edge`; Nix reads it directly.
2. **The screensaver gate.** `hasScreensaverPackage = elem
   "omarchy-screensaver" basePackages`. The `omarchy-launch-screensaver`
   `--replace-fail` is spliced in with `lib.optionalString` on that flag, so
   the install phase text, and therefore the drvPath, is unchanged on quattro.
3. **The migration test** decides per migration, from `$ORACLE_SOURCE`. A
   helper `applicable <ids…>` lists the ids whose script exists there. Cases
   pass only those ids to `run_ids`, and loop their assertions over the same
   set. A case left with none prints `skip` and returns. `$oracle` is not
   used, because `run:648` reassigns it.
4. **The coexistence check:** the user's `/lib/qt-6/plugins` appears at least
   once under both pins, exactly twice when `hasQtengine`, and exactly once
   otherwise.
5. **The markers:**
   - whole-row: `edge = "only"`, active only under an edge pin, and
     `edge = "absent"`, active only without one;
   - per-allowance, in the bin-ledger: `edge_allow` and `tag_allow`.

   Every reader validates every row under both pins first:
   - the marker value is `"only"` or `"absent"`;
   - no unknown or duplicate field, and no non-string syntax. The bin-ledger
     keys are `class`, `reason`, `allow`, `pacman`, `stub`, `edge`,
     `edge_allow` and `tag_allow`;
   - `allow`, `edge_allow` and `tag_allow` groups are checked against
     `PATTERNS` and are pairwise disjoint.

   Only then does it drop inactive rows, from both directions of every
   comparison. Each ledger serialises all of its rows for validation (`dupes`,
   `bad`, `bad_run` in `user-migrations-ledger.nix`; `wellFormed` in
   `omarchy-package-ledger.nix`), and filters after that.

   The effective allowance is `allow` plus `edge_allow` or `tag_allow`,
   whichever is active. It feeds both the biconditional and the vendor-row
   guard (`check-bin-ledger.py:311`).

   The migration bundle builder filters the same way.
6. **The `main-pin` job** in `omarchy-edge.yml`:
   - hosted, `needs: prepare`, starting with `Free disk space`;
   - it checks out the candidate, restores `main`'s pin, and commits it
     locally;
   - it then builds, one by one: `.#omarchy`, the cheap tier plus the
     claimed non-VM checks, both toplevels, every `options-*` shard from
     `nix eval`, statix, deadnix and `nix fmt -- --ci`, then runs
     `readme-counts.sh --fix` without committing;
   - the job checks out with `fetch-depth: 0`. It reads both pin copies
     from `origin/main:flake.nix`, runs `nix flake update omarchy`, and
     commits locally;
   - its builds accumulate failures, so one red build does not stop the
     rest. It fails at the end and names each failed build;
   - wiring:
     - `verify` gains `needs: main-pin`, and the promote step requires its
       success;
     - `report` gains `needs: main-pin` and reads `needs.main-pin.result`
       directly, because `verify` is skipped when `main-pin` fails and its
       outputs are then empty;
     - `.github/scripts/edge-report.sh` gains a `MAIN_PIN` input and names
       that failure;
   - **a `dry_run` input**, which any ref other than `main` also implies:
     - the candidate goes to a scratch ref, `edge-dryrun/<run_id>`, instead
       of `edge-candidate`, and later jobs fetch it from there;
     - an optional `candidate_ref` input selects a scratch carry to verify;
     - the promote step and the issue edits are skipped;
     - the scratch ref is deleted at the end.
7. **It lands in two phases:**
   - phase 1, steps 1 to 8, is a carry on `edge-candidate`;
   - phase 2, step 9, is a workflow PR to `main` that the owner merges.

   #1752 closes when phase 2 merges, and the artifacts PR says `Refs #1752`.

## Rollback

- **Phase 2 first, if both are going.** Revert the workflow PR on `main`.
  The job is additive, and removing it restores the old promotion path.
  Then revert phase 1. In the other order, the reverted carry fails
  `main-pin` (the tag-pin build breaks again), and the rollback can never
  promote.
- **Phase 1 alone, before phase 2 merges:**
  - before promotion, delete `edge-candidate`;
  - after it, `git revert <base>..<carry-head>`, which reverts the whole
    seven-commit range, on `edge-candidate`;
  - then a dispatch. Edge stays on its last good commit until
  a run passes.
- **The artifacts:** revert the merge. No code goes to `main` from that
  branch.

Step 1's drvPath equality holds only if the `optionalString` splice leaves
the post-indent-stripped install phase byte-identical under quattro. The
verify in step 1 is what proves it. If it differs, the cause is whitespace,
and the splice is moved until it matches.

## Deviations during implementation

1. **Two more pin-derived files took the markers:** `data/apps.nix` and
   `data/menu-exceptions.nix`. Under `main`'s pin, the menu generator
   refused the Moonlight catalogue row (`upstream menu has no rows:
   install.gaming.moonlight`), and `options-files` named `install.ai.herdr`
   and `install.gaming.moonlight` as stale. So:
   - `modules/apps.nix` and `tests/options.nix` drop catalogue rows and menu
     exceptions marked for the other pin, and `tests/options.nix` refuses a
     bad marker value;
   - `check-menu-mapping.py` needs no change: it checks only the other
     direction, and still reads the `install.ai.herdr` reason;
   - two more `data/menu-actions.nix` rows, `install.ai.herdr` and
     `setup.default.editor.plain`, were marked once the Moonlight error no
     longer hid them.
2. **Step 1 was finished by Claude.** The coder's splice changed the drvPath:
   interpolated text is not indent-stripped by the outer string, so its
   explicit indentation had to be 16 and 18 columns, and the last segment
   needed no trailing newline. The drvPath is now identical.
3. **Codex ran steps 3, 5 and 9 in their own worktrees.** `agent-run`
   refuses a dirty tree, and the carry held the coder's uncommitted work.
   Each diff was applied to the carry and verified there. Step 2's run
   reported `HEAD moved` only because Claude committed step 1 while it ran.
4. **Step 9 was corrected by Claude.** Codex's `main-pin` built every
   generated check, VM tests included, on a hosted runner. It now builds
   every non-VM check: those without `driverInteractive`, generated and
   claimed alike, 190 today. The VM tier stays with `verify`.
5. **Two "unchanged" baselines are `main`'s own.** The edge base cannot
   build its menu or its migration bundle under v4.5.0, which is the defect
   being fixed. So the generated menu and the bundle `list` were compared
   with `main`'s, and both are identical. The package tree and
   `vm-toplevel`'s package names were compared with the base, and both are
   identical once the package's own store path is normalised.
6. **§1 break h was re-run.** The first attempt renamed the row and failed
   for the wrong reason (`invalid migration row`). Deleting the row gave
   the intended `1794330979 is not in the runner's list`.
7. **`main-pin` stops early when the package fails** (owner, 2026-11-11). Dry
   run #1 against the broken carry showed the job working through every
   dependent check, each repeating the package's one error, which costs up to
   its 180-minute timeout on every red run. The job now exits right after a
   failed `.#omarchy` and says the dependent checks were not run. Failures
   that do not involve the package are still collected in full.
8. **Four more checks read the markers, and `main-pin` links its build**
   (2026-11-11). Dry run #2 on the real carry passed the package and failed
   five checks that steps 1 to 8 had built only under the edge pin:
   - `etc-overlay` and `mise-free` held quattro-only rows. Those rows now
     carry `edge = "only"`, and both readers validate every row first;
   - `skill-parity` pinned quattro's digest of `## Example Requests`, which
     the tag words differently. The row gains `tag_upstream`, read under the
     tag, and the script gains `--edge`;
   - `agent-local-detach` tests a script the tag does not ship. Under the
     tag it asserts the script is absent, so it fails once a tag ships it;
   - `readme-counts` found no `result`, because `main-pin` built the package
     with `--no-link`. The build now writes `result`.
