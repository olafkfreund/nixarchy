# Plan: Bump nixi to 0.10, the Omarchy overlay card

## Decisions carried from the approved spec

- **D1 Claude Code is the default agent.** With no Omarchy default agent and no
  card selection, the bridge uses `claude` instead of failing. `services.nixi.agents`
  defaults to `lib.optional (pkgs.config.allowUnfree or false) "claude" ++ [ "codex" ]`:
  Claude first and pinned when unfree is allowed (nixarchy's default), not
  pinned (found on PATH) when it is not, so unfree-off configurations still
  evaluate.
- **D2 The card is enabled for you, once.** nixi's module
  (`services.nixi.autoEnable`, default `true`) writes the card's id into
  `shell.json` `plugins[]` on the first activation and leaves a marker so a
  user who turns it off stays off. An overlay id found only in `bar.layout.*`
  (0.9's slot, present on p620) is moved to `plugins[]`; the button is added
  to the bar unless it is already there. A missing or unparsable `shell.json`
  is left alone and reported. `bin/nixi` checks `listPlugins` first and
  notifies "Nixi is turned off — enable Nixi in Setup > Plugins" instead of
  the silent no-op.
- **D3** nixarchy pins the merge commit of nixi PR #9 on `main`.
- **D4** `tests/options.nix` keeps its on/off shape against the 0.10 layout:
  traces drop the unit and `ui.html`, add the plugin directory and
  `nixi/KNOWLEDGE.md`; `nixiUnit` removed; `nixiBarWidget` asks about the
  `-button` plugin; new `nixiEnablesCard`.
- **D5** Words: `modules/home.nix` comments, `docs/manual/getting-started.md`,
  `README.md`.
- **D6** `AGENTS.md` write-back: the silent toggle, and the per-file-to-directory
  link collision.
- Constraints: pin a commit, never a branch; `services.nixi.enable = false`
  removes every trace; no behaviour change beyond nixi.

**One refinement of D2, found while planning (measured, not assumed).** The
spec said the running shell would be asked over IPC. Omarchy's `shell.qml`
reads the user `shell.json` through a `FileView` with `watchChanges: true`,
`atomicWrites: true` and `onFileChanged: reload()`, so an atomic JSON
replacement is picked up live by a running shell. And the Home Manager
activation unit runs with a bare environment (no `XDG_RUNTIME_DIR`, no
`OMARCHY_PATH`), where IPC would need the live shell's environment rebuilt
from `/proc`. So the step edits the file atomically and uses no IPC. Same
outcome, one mechanism.

**Deviation recorded during A3 (measured).** A valid user `shell.json`
replaces Omarchy's defaults outright (`shell.qml` `applyShellConfig`: "a valid
user shell.json overrides defaults entirely ... We do not deep-merge"), and
nixarchy seeds none. So "a missing `shell.json` is left alone" would leave the
card off on every fresh desktop, and writing a file with only `plugins` would
remove the bar. A missing file is therefore created from Omarchy's defaults
(`/run/current-system/sw/share/omarchy/config/omarchy/shell.json`, identical to
the shell's own), exactly as the shell writes one; with no defaults file it is
still left alone. Broken, unversioned and symlinked files are never edited.

Omarchy's own default for a bar widget without `barWidget.defaultSection` is
`center` (`PluginRegistry.qml` `defaultBarWidgetSection`); the button has
none, so it goes to `center`, entry `{"id": "io.github.olafkfreund.nixi-button"}`.
