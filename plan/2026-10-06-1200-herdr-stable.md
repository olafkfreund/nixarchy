# Plan: stable machines evaluate with the default herdr widget

## Approved decisions (from the spec)

- The herdr fallback in `modules/home.nix` reads Hyprland's own nixpkgs pin
  (`inputs.hyprland.inputs.nixpkgs`), not `inputs.nixpkgs`. On an installed
  stable machine `inputs.nixpkgs` is the user's 26.05 through the installer
  template's `follows` (`installer/template/flake.nix:65`). Hyprland's pin is
  never overridden and has herdr. Unstable machines keep `pkgs.herdr`.
- `stableVm` in `flake.nix` is built the way an installed stable machine is
  wired: nixarchy's NixOS and Home Manager modules imported with inputs whose
  `nixpkgs` is `nixpkgs-stable`, whose `home-manager` is
  `home-manager-stable`, and whose `self` carries those rebuilt modules
  (`installer/host.nix:210` takes the HM module from `inputs.self`).
- `stable-eval` (every PR) is the regression check. The unstable closure must
  not change.

## Steps

1. **`modules/home.nix:2028-2031`.** Replace `inputs.nixpkgs` with
   `inputs.hyprland.inputs.nixpkgs` in the herdr fallback. Rewrite the
   two-line comment above it to say why: the template makes `inputs.nixpkgs`
   26.05 on a stable machine, while Hyprland's pin stays unstable
   (`modules/nixos.nix:14` uses it too). Cite #1200.
   → verify by step 2's check passing. Before step 1, step 2's check must fail
   with `attribute 'herdr' missing`.
   Traps: none.

2. **`flake.nix:579-592` (`stableVm`).** Add a `stableInputs` binding in the
   same `let`, exactly as in the spec, and build `stableVm` from it with
   `specialArgs = { inputs = stableInputs; }` and
   `modules = [ stableInputs.self.nixosModules.nixarchy ./vm/configuration.nix ]`.
   Extend the comment above `stableVm`: it mirrors the template's `follows`,
   and building it from nixarchy's own inputs is what hid #1200.
   `tests/stable-eval.nix` needs no change: `stableRev` still reads
   `inputs.nixpkgs-stable`, which `flake.nix:2184` passes unchanged.
   Order: do this step first, confirm the check fails, then do step 1.
   → verify by `nix build .#checks.x86_64-linux.stable-eval -L`: red without
   step 1, green with it. Keep both outputs for the PR.
   Traps: `stableInputs` refers to itself (through `self`), which is fine in
   a `let`. Do not add `stableVm` to `nixosConfigurations`; the existing
   comment says why.

## Tests

- `nix build .#checks.x86_64-linux.stable-eval -L` → passes.
- Unstable is unchanged: the herdr store path in every Home Manager user's
  packages, for `reference` and `vm`, is identical before and after
  (`herdr-0.9.3`, same path).
  *Deviation:* the plan first compared whole-system `drvPath`s. Those can
  never match across a change, because the omarchy derivation embeds the
  nixarchy revision (`@nixarchyrev@`) and the flake source path. The herdr
  path is the part this change could affect.
- `nix flake check --no-build` is not a usable gate here: it stops on the
  unfree `grok-bot` package on `main` as well, and CI does not run it.
