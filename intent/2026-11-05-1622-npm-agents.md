# Intent: Agents installed through mise's npm backend can actually run

## Problem

Setup > Defaults > Agent offers four agents that install, say nothing is wrong,
and then cannot start. On a machine with no `node` on `PATH`, all four give:

```
.../node_modules/.bin/kimi: line 18: exec: node: not found    (rc 127)
```

`omarchy-default-agent` routes each agent one of three ways:

| Route | Agents | Runs without node? |
|---|---|---|
| nixpkgs, `attr_for` (:44-65) | claude, codex, opencode, crush, gemini, copilot, grok, openclaw, agy, amp, qwen, kilo, devin, dsh, kiro-cli | not touched by this issue |
| named only, `elsewhere_attr_for` (:236-243) | cursor-agent, hermes, muse | not installed by this script |
| mise, not npm, `mise_pkg_for` (:69-80) | pi (`aqua`), omp, ori (`github`) | yes: `--version` rc 0 for all three (ori's output was truncated, so its exit status is the evidence) |
| mise, npm, `mise_pkg_for` (:69-80) | **kimi, mcode, freebuff, commandcode** | **no: rc 127 for all four** |

None of the four has a nixpkgs attribute under this flake's pin, by the names
tried: `kimi-cli`, `kimi-code`, `mcode`, `minimax-code`, `freebuff`,
`command-code`, `commandcode`.

Why it was not noticed: the variable (§3) is whether the machine already has
`node`. The maintainer's machine does, and there `freebuff --version` passes in
an `env -i` shell. The failure only appeared once `node` was removed from `PATH`.

### Install and run are separate failures

Measured with mise 2026.10.17, in a throwaway `HOME` under `env -i`, with
`PATH` holding this host's system packages minus node and, from the "`mise
install node`" row on, compilers:

| Step | Result |
|---|---|
| `mise use -g npm:<agent>`, all four, no node | rc 0. mise installs through its own `aube`, which does not need node |
| Run any of the four | rc 127: the launcher is `#!/bin/sh` ending in `exec node` |
| `mise use -g 'npm:@minimax-ai/code[allow_builds=better-sqlite3]'`, no node | rc 1: `lifecycle script install failed for better-sqlite3 ... Some(127)` |
| The same with `node` resolvable | rc 0. A prebuilt binding appears and loads through nix-ld, no compiler |
| Plain `npm:@minimax-ai/code`, as we install it today | `mcode --version` passes, but `better-sqlite3` has no binding: `Could not locate the bindings file` |

So the comment at `omarchy-default-agent:25-28`, that an npm agent "could not
install at all", is out of date for three of them; the install half is now only
mcode's build script. The comment at :67-68, that the mise group are all `aqua`
backends that "install without node", is false for four of its seven rows.

What mcode loses without the binding was not measured: `--version` passes either
way, and using the agent would need a sign-in.

### Upstream's answer does not carry over

Upstream (`bin/omarchy-default-agent:114-125`) runs `mise install node` first
and relies on `etc/mise/conf.d/omarchy-tools.toml` declaring `node` as a lazy
tool. Nixarchy installs neither that file nor any other `node` declaration
(`/etc/mise/conf.d` holds `omarchy.toml` and `omarchy-agent-accounts.toml`).

| Attempt | Result | User's node or config |
|---|---|---|
| `mise install node`, defaults, no compiler | rc 1. `all_compile` is `true` on this host with nix-ld on and `NIX_LD` set, so it compiles from source | untouched |
| The same with a compiler on `PATH` | compiles V8; unfinished after 200 s at 80% of its steps, and took the host's load to 113 | untouched |
| `MISE_ALL_COMPILE=false mise install node` | rc 0 in 2 s. The prebuilt ELF runs through nix-ld with `NIX_LD` set and unset | config unchanged; adds `node`, `npm`, `npx` shims |
| Then `kimi` through its shim, nothing declared | `No version is set for shim: node`, rc 1 | a user's own `node` behind the shims is still used and works |
| `PATH=$(mise where node)/bin:$shims kimi` | the same error: the shim does not keep that directory | none |
| `PATH=$(mise where node)/bin:$PATH <real launcher>`, no shim | rc 0 | none outside that process tree |
| `mise x node -- <agent>`, all four | rc 0 | none outside that process tree |
| Lazy `node` declaration (tested in the user's `conf.d`) | rc 0 | **shadows** a user's `node` behind the shims, and joins `mise env`'s `PATH` |
| `mise use -g node` | rc 0 | **writes** `node = "latest"` into the user's config, and joins `mise env`'s `PATH` |

So mise's `node` plus `mise where node` is not a clean answer as it stands. The
default install fails or compiles, and a `PATH` prefix does not survive the shim
`omarchy-agent` launches through (`pkgs/omarchy/default.nix:1149`). It works only
with `all_compile` off and without the shim in the way.

envfs is not involved: the launcher is `#!/bin/sh`, and `/bin/sh` is on bare
NixOS. nix-ld is required: the prebuilt `node` names
`/lib64/ld-linux-x86-64.so.2`.

## Proposed outcome

- Choosing kimi, mcode, freebuff or commandcode on a machine with no `node`
  gives an agent that starts, with no compiler and no compile.
- Launching it works from the menu and from a shell where mise is activated.
- A machine that already installed one of them starts working without choosing
  it again. A fix only on the install path skips them, because
  `command -v "$agent_cmd"` (:165-169) returns early once the command is found.
- mcode installs with its native binding.
- If `node` cannot be provided, for example with nix-ld turned off, the user is
  told so instead of seeing rc 127.
- The comments at :25-28 and :67-68 say what is true.

## Affected users and systems

Anyone with no `node` of their own who picks one of these four agents, on any
nixarchy machine. Files expected: `pkgs/omarchy/nix-bin/omarchy-default-agent`,
possibly `pkgs/omarchy/default.nix`'s `omarchy-agent` patch, and a new check.

Not affected: the agents routed through nixpkgs, and pi, omp and ori. Machines
that already have `node` work today and must keep working.

## Constraints

- **A user's own node and mise config stay as they are.** Nothing is written to
  `~/.config/mise/config.toml` beyond the agent's own row, which is what
  `mise use -g` already does, and a `node` the user provides keeps winning.
- **Mode A:** nothing system-wide changes for someone who never picks one of
  these agents. That rules out an unconditional `node` in the closure or an
  unconditional declaration in `/etc/mise/conf.d`.
- **nix-ld and envfs are `mkDefault`** (`modules/nixos.nix:1154,1580`), so a user
  can turn them off. The no-nix-ld case could not be run here.
- **No compile on a user's desktop**, ever, from this path.
- **§1 and §3:** the check runs with no `node` on `PATH`, because that is the
  variable that hid this, and is proved to fail with the fix removed. A check on
  this host's normal `PATH` passes with the bug present.

## Open questions

1. **How do these agents get node?** Options as measured above:
   - (a) mise's prebuilt node, per launch, only when `node` is missing
     (`all_compile` off for that one install, launched through `mise x` or a
     direct `PATH`). Touches no config. An agent's child processes see that node.
   - (b) `nixarchy-pkg-add nodejs`, the route this script already uses. Recorded
     and reproducible, but needs a rebuild and puts node on `PATH` for good.
     Not measured.
   - (c) Upstream's lazy declaration. Rejected unless gated, because it shadows a
     user's node.

   **Recommendation: (a).** It is the only one measured to leave a user's node
   and config alone, and it fits the "imperative, and honest about it" route
   these agents already take.

2. **Does mcode get `allow_builds=better-sqlite3`?** Recommendation: yes, to match
   upstream, with node available for that install.

## Not in this issue

`modules/AGENTS.md`'s `#mise-is-in-omarchys-base-packages-and-its-dev-env-` says
nix-ld makes mise use precompiled binaries. Here `all_compile` stays `true` with
nix-ld on, so `omarchy install dev-env` may be affected. Not tested; worth its
own look rather than a line in this fix.
