# Intent: edge on Omarchy quattro 446361a

## Problem

Upstream quattro moved from be54892 to 446361a: 12 commits. Edge's run
39794628205 could not build the new tree, so its fallback published `main` on
be54892 and filed #1428. Edge users are fine, but they are stuck one upstream
step behind.

A scratch tree pinned to 446361a (not pushed) found everything that breaks.
It built `.#omarchy` and all 151 checks edge builds, with `--keep-going`.
There are two causes:

1. **Our keybindings patch lost its anchor, because upstream adopted it.**
   `pkgs/omarchy/default.nix:450-452` wraps the Lua bind scan in
   `omarchy-menu-keybindings` with `timeout 3`. Upstream's b12539b now does
   this itself, with `timeout 10` plus a Lua instruction limit (#7564,
   #16276), so our `--replace-fail` finds nothing. Upstream also bumped the
   menu cache key from `v17` to `v19`, which the next substitution
   (`printf 'v17\n'` → `v17-submaps`) keys on.
2. **`etc-overlay`: upstream ships a new `/etc` file that no row
   classifies.** It is `NetworkManager/conf.d/omarchy-connectivity.conf`
   (3357f90, #16186), which turns on NetworkManager's connectivity check
   against `http://ping.omacom.io/nm-check.txt`. Upstream's new captive-portal
   flow depends on it: the network panel and
   `omarchy-network-captive-portal`, which waits for
   `nmcli networking connectivity check` to say `full`. NixOS's NetworkManager
   module sets no connectivity URI, so on nixarchy that check never runs.

With (1) fixed, the package and the other 150 checks build. Only
`etc-overlay` stays red.

## Proposed outcome

Edge publishes quattro 446361a, and #1428 closes on the next edge report.

## Affected users and systems

- Edge users: they get the 12 upstream commits, including captive-portal
  sign-in, Tailscale panel paging, the battery and Stay Awake wording, and
  notification trims.
- `pkgs/omarchy/default.nix`, `data/etc-overlay.nix`, and possibly a
  NetworkManager setting in `modules/`.
- The carry reaches `edge-candidate` by fast-forward only, as #1423's did.
  `main` is untouched until the next release.

## Constraints

- Mode A: nothing changes for a configuration that imports the module
  without nixarchy enabled.
- A changed default a user may set (`networking.networkmanager.settings`)
  is announced in the release notes (§14), and uses `mkDefault` per scalar
  so the user's own setting wins.
- The `etc-overlay` row needs a reason, per the check's rule.

## Open questions

1. **The keybindings fix: drop our `timeout 3` and move the cache key to
   `v19-submaps`.** Upstream's bound is wider (10 s against 3 s) but adds an
   instruction limit that stops loops well before the timeout. Recommendation:
   drop ours, since upstream's fix is the better one and carries for free.
2. **The connectivity check: follow upstream or not?**
   - **(a) `native`:** set
     `networking.networkmanager.settings.connectivity.uri` (and an empty
     `response`) at `mkDefault`, to the same URL. That is two lines.
     Captive-portal sign-in then works as upstream intends. The cost is that
     NetworkManager polls Basecamp's `ping.omacom.io` over plain HTTP, every
     few minutes by default, which nixarchy does not do today.
   - **(b) `na`, with a reason:** leave NixOS's default (no check). The
     captive-portal flow then never triggers, and the panel stays as it is
     today. File an issue if wanted later.

   Recommendation: **(a)**. It matches what Omarchy users get, it is the
   only way the new feature works, and a user who wants no polling sets
   `connectivity.enabled = false`. The privacy point goes in the release
   notes.
