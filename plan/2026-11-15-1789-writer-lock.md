# Plan: the config writers take apply's lock and keep the files they edit

## Approved decisions

- **One helper file, `pkgs/writer-lock.sh`.**
  - It defines `nx_lock`, `nx_unlock`, `nx_put SRC DST`, `nx_sed DST
    SCRIPT...`, `nx_commit SNAPSHOT WORK DST` and `nx_refuse MSG`.
  - It is spliced into each writer's `text` with `builtins.readFile`, and
    into `pkgs/pkg-new.sh` through an `@writerLock@` token replaced with
    `lib.replaceStrings`.
- **The lock** is `${XDG_STATE_HOME:-$HOME/.local/state}/nixarchy/applied/lock`
  on fd 9, opened `9>>`, with `flock -w 5`.
  - `NIXARCHY_LOCK_HELD=1` skips taking it. `nx_unlock` always unsets the
    handshake, and closes fd 9 only in the process that owns the lock.
  - Children started while the lock is held get `9>&-`.
  - A refusal exits 75 with `a write or an apply is running -- try again
    when it finishes. Nothing was changed.`
- **`nx_put`** writes in place:
  - It refuses a DST that is not a writable regular file once symlinks are
    followed. An absent DST is created.
  - It backs DST up to the state directory with `cp --reflink=never`.
  - It runs `cat SRC > DST` with `INT TERM HUP QUIT XFSZ` ignored, then
    restores those dispositions.
  - On failure it writes the backup back. If that fails too, it refuses and
    names the backup.
  - It removes SRC and the backup on success.
- **Lock placement:**
  - **Lock first:** catalogue-diff (only with `--add`), language-select,
    service-disable, app-enable, app-disable (before `insertMissingAppRow`).
  - **Prompt first, then lock and re-check:** pkg-remove, pkg-undraft,
    opt-remove, and service-enable, whose SSH gate is re-checked under the
    lock.
  - **Copy and commit:** pkg-add, through `nx_commit`. pkg-new builds its
    draft in the state directory and commits the draft and the apps.nix row
    under the lock.
  - **search:** locks inside `insert_line` only, and its batch-level restore
    is removed.
- **Two `sed -i` passes in a row** become one `nx_sed`.
- **`runtimeInputs`:** every writer gets `util-linux`. Those missing
  `cfg.package` (for `omarchy-notification-send`) get it too.
- **`nixarchy-apply`'s messages** become "a write or another apply is
  running ..." (4432) and "waiting for a write or another apply to
  finish..." (4435).
- **Full-disk outcome (approved with the spec):** the write is restored, or
  a full backup is kept at a named path.

## Steps

Every step leaves the tree evaluating. Line numbers are `modules/apps.nix`
at the spec's approval commit, and they drift as the steps land, so match
on the quoted code, not the number.

1. **`pkgs/writer-lock.sh` (new).** Write the six functions exactly as the
   approved decisions above describe. It is `bash`, sourced, with no
   top-level side effects.
   - Verify: `bash -n pkgs/writer-lock.sh`; `nix run nixpkgs#shellcheck --
     -s bash pkgs/writer-lock.sh`.
   - Traps:
     - an EXIT trap reads its variables at exit, so use globals (§5);
     - `set -e` does not reach inside `$(...)`, so write `out=$(cmd) ||
       return` (§5);
     - reset signal dispositions with `trap - INT TERM HUP QUIT XFSZ`;
     - `cp --reflink=never` must abort the put before DST is opened.

2. **`tests/writer-lock.nix` (new), helper cases 1-9** from the spec's
   Verification section, and its entry in `flake.nix`'s `uniformChecks`
   (1820).
   - The runCommand's inputs: bash, coreutils, util-linux, gnused, diffutils.
   - `HOME` and `XDG_STATE_HOME` point into `$TMPDIR`.
   - **Case 7:** `set -m`, `kill -INT -$pgid`, and a FIFO SRC fed in two
     halves around the signal.
   - **Case 8:** a subshell with `ulimit -S -f`.
   - Verify: `nix build .#checks.x86_64-linux.writer-lock`, then the §1
     proofs: `nx_lock` made a no-op, the signal-ignore removed, the restore
     removed, `nx_commit`'s comparison removed. Each must go red.
   - Traps:
     - `git add` the new files before building (§5);
     - a heredoc in a `''` string reindents the file, so use `printf` (§5);
     - in a `''` string, `\$` is a literal backslash (§5);
     - `grep -q` after a pipe can fail because it matched, and
       `checks.grep-q-pipefail` catches that.

3. **Five lock-first writers:** catalogue-diff (1693-1841), language-select
   (2188-2256), service-disable (2258-2291), app-enable (2293-2350),
   app-disable (2357-2423), and `insertMissingAppRow` (166-182).
   - Splice the helper.
   - Place `nx_lock` per the decisions.
   - Turn each `mv "$tmp" ...` into `nx_put` and each `sed -i` into
     `nx_sed`; the two pairs (2331-2332, 2394-2395) each become one call.
   - Temp files move to the state directory.
   - The EXIT trap runs `nx_unlock` and cleans up.
   - `fail()`, in app-enable and app-disable, calls `nx_unlock` before it
     notifies.
   - `runtimeInputs` per the decisions.
   - Verify: `nix build .#checks.x86_64-linux.{app-selection,language-select,sshd-enable}`.
     The rename-model assertions in `app-selection.nix` (56-59, 73-76) go
     red here as expected, and step 9 retargets them.
   - Traps:
     - `nix fmt`, then read `git diff --stat`: a hook may reformat with
       nixpkgs-fmt (§5);
     - every `''${` in the spliced file must survive `readFile`
       (`readFile` does no interpolation, so plain `${` is fine).

4. **Three picker writers:** pkg-remove (2521-2601), pkg-undraft (2612-2701)
   and opt-remove (2724-2824).
   - The picker stays unlocked.
   - After it: `nx_lock`, backup, the existing re-check, edit with `nx_sed`
     or `nx_put` (opt-remove's `remove_one` at 2764-2798), and the parse
     check.
   - `restore()` becomes `nx_put` of a copy of the backup.
   - Verify: `nix build .#checks.x86_64-linux.app-selection`.
   - Traps: same as step 3.

5. **service-enable (1843-2042):**

   - Under `nx_lock`: repeat the decisive read (2006). If the gate was

   - Verify: `nix build .#checks.x86_64-linux.sshd-enable`, plus its new

7. **pkg-new (`pkgs/pkg-new.sh`, the apps.nix wrapper at 3390-3406, and

## Tests

- Every step's check, then `.github/scripts/generated-checks.sh generated`
  at the package tier.
- `options-system`, `-home`, `-microvm` and `-files`, plus `session`, at the
  VM tier, two at a time with no busy runner.
- `nix fmt -- --ci`, statix, deadnix, and `checks.grep-q-pipefail`.
- The PR carries the §1 failing outputs, and names what is not reachable
  here: a real ENOSPC and a copy-on-write filesystem.

## Rollback

Revert the PR. No state format changes: the lock file already exists for
`nixarchy-apply`, and the backups and temp files live in the state directory
and are removed after each write. A user's `~/.config/nixarchy` files keep
their format throughout.
