# Intent: edge adopts quattro ceb30ed (Files for Nautilus, Plain as the editor)

## Problem

Edge is held on quattro `054d75e` (#1750). The edge run on 2026-11-11
(run 42970037867) tried `ceb30ed`, 47 upstream commits later, and stopped
at two failures; 149 more checks did not run because they depend on them:

- `omarchy-edge-20261111-ceb30ed`: the `--replace-fail` in
  `pkgs/omarchy/default.nix` that routes Setup > Default > Editor through
  `nixarchy-default-install` no longer matches. Upstream added a
  `plain) omarchy-pkg-add plain ;;` row to the `case` in
  `bin/omarchy-default-editor`, and our copy in
  `default-editor-install.upstream.sh` is the old text.
- `nixarchy-user-migrations-ledger`: two new migrations touch user files
  and have no row in `data/user-migrations.nix`: `1794330979` (Nautilus to
  Files: rewrites `~/.config/mimeapps.list` and the dock pins in
  `~/.config/omarchy/shell.json`) and `1794341736` (pins Neovim for existing
  installs in `~/.local/state/omarchy/defaults/editor` and
  `~/.config/mimeapps.list`).

Behind those two failures, the batch changes what a user gets:

- **Files replaces Nautilus.** `folio` (omacom/folio, MIT, Qt/C++) becomes
  the file manager. `inode/directory` opens `folio.desktop`, and the new
  `omarchy-launch-files` and `omarchy-launch-files-cwd` commands launch it, and the
  Nautilus launchers stay as hidden aliases to them. Nautilus, nautilus-python, sushi and nautilus-dropbox
  leave the base set, and `xdg-user-dirs`, which Nautilus used to pull in,
  becomes an explicit package. nixpkgs' `folio` is a different program (a
  GNOME notes app), so the name cannot be used as-is.
- **Plain is the default editor on new installs.** `plain` (omacom/plain,
  MIT, Qt/C++) is not in nixpkgs. The 17 text MIME types open
  `plain.desktop`, and existing installs are pinned to Neovim by migration.
- **Moonlight is no longer installed by default.** It moves to an Install >
  Gaming row, with an `omarchy-remove-gaming-moonlight` command.
- Smaller items: the herdr autostart runs under `setsid`, the agents panel
  gets a DGX Spark offer, notifications show the sender's glyph, Gliff can
  override screen-sharing protection, plus aarch64 hardware setup (Surface
  Laptop 8, ASUS ProArt PZ13, Vivobook S 15) and translations.

## Proposed outcome

- Edge builds and passes its checks on quattro `ceb30ed`, and #1750 closes.
- On edge, the file manager is Files and new installs edit text in Plain,
  as upstream ships them. Both are packaged here the way `owe` is, from
  omacom's source. `main` (tag v4.5.0) keeps Nautilus and Neovim, with the
  choice derived from the vendored tree, so both pins hold one copy of the
  code.
- A machine that moves to the new edge keeps the editor it already used,
  as upstream intends. The two new migrations have ledger rows saying what
  each one does on NixOS.
- Moonlight follows upstream: it is no longer in the default set, and it is
  offered under Install > Gaming.
- The aarch64 hardware scripts get the same skip treatment that existing
  Qualcomm entries have.

## Affected users and systems

- Edge users, and p620 and razer, which deploy edge.
- `pkgs/omarchy/default.nix` (the editor patch, runtime inputs, Nautilus),
  `modules/nixos.nix` (the default set, MIME defaults, Moonlight), new
  `pkgs/apps/folio.nix` and `pkgs/apps/plain.nix`, the ledgers in `data/`,
  and the checks that read them (`patched-files`, `user-migrations`,
  `session`, the menu-row mapping).
- `main` only through code that has to hold under both pins. Nothing there
  should change behaviour.

## Constraints

- One copy of each line works under both pins (CLAUDE.md §8): `main` must
  not gain Files or Plain until it moves to a tag that ships them.
- The carry goes on `edge-candidate` and pins quattro in both copies in
  `flake.nix` plus `flake.lock` (§8). The artifacts merge to `main` by
  their own PR.
- Packaging Files and Plain cannot add anything unfree, and the new
  packages go on the cache allowlist only if the budget allows (§6).
- A coexistence fixture covers the new MIME defaults (§14), because a user
  who sets their own `inode/directory` or `text/plain` handler must keep it.
- Every check I add or retarget is proven to fail first (§1).

## Open questions

1. **Package Files and Plain, or keep Nautilus and Neovim on edge?** My
   recommendation is to package both. Upstream wrote them and they are MIT
   Qt apps like `owe`. The alternative patches upstream's new defaults
   back to Nautilus and Neovim, and every later quattro would re-break
   that patch.
2. **Should existing machines keep Neovim?** Upstream's `1794341736` pins
   Neovim for machines installed before Plain. On NixOS the MIME default is
   declarative, so "existing" would have to mean a saved editor choice in
   `~/.local/state`. My recommendation is to follow upstream: write the
   `nvim` default only when no choice is saved, and leave a user's own
   `mimeapps.list` alone.
3. **Should Moonlight leave the default set?** My recommendation is yes,
   following upstream, with the Install > Gaming row mapped to
   `moonlight-qt`.
