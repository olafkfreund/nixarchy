# Intent: T3 Code installs on nixarchy

## Problem

Omarchy quattro (the edge channel) adds `omarchy-install-t3code-app`, the
menu's T3 Code installer. It downloads T3 Code's AppImage and pulls two files
out of it with the AppImage runtime's own flag:

```sh
"$download" --appimage-extract t3code.desktop
"$download" --appimage-extract 'usr/share/icons/hicolor/*/apps/t3code.png'
```

On nixarchy an AppImage never runs its own runtime: `modules/nixos.nix:1219`
enables `programs.appimage` with binfmt, so executing it goes through
`appimage-run`, which passes unknown options on to the app. **Confirmed on an
edge machine with T3 Code 0.1.0:** the installer's call launched the Electron
app and extracted nothing. With no display it exited (`Missing X server`). In
a desktop session it would open T3 Code and leave the installer blocked
behind it. `appimage-run -x squashfs-root <file>` extracted `t3code.desktop`
and all nine icons, at the exact paths the installer reads next.

So on edge, Install › T3 Code never installs, and on a desktop it hangs.

## Proposed outcome

- On nixarchy, the installer extracts with `appimage-run -x`, writes its
  launcher and icons, and T3 Code appears in the app launcher and runs
  (through binfmt, which already works).
- A check fails if the installer ever calls an AppImage's `--appimage-extract`
  again (an upstream rewrite), so this cannot silently return.
- Stable is unaffected: 4.0.5 has no such command.

## Affected users and systems

- Edge-channel machines (razer is one). Stable picks the command up when it
  moves to quattro.
- `pkgs/omarchy/default.nix` (where the vendored scripts are patched) and a
  check.

## Constraints

- Patch with `--replace-fail` (pkgs/AGENTS.md), so an upstream rewording
  fails the build rather than silently restoring the broken call.
- `appimage-run` must be reachable from the script. It is on the system PATH
  by default because `programs.appimage` is on, but a user can turn that off.
  The script must then fail with a sentence, not hang.
- §1: the check must go red with the upstream script and green with the
  patched one.
- Upstream: this is a NixOS-specific behaviour (binfmt plus appimage-run), not
  an Omarchy bug, so it is fixed here and not reported upstream.

## Open questions

- **Where does the patch live?**
  - **(a) On `main`, guarded by `[ -e …/omarchy-install-t3code-app ]`.** Inert
    on stable, active on edge through its daily merge of `main`, and already
    in place when stable reaches quattro. No edge-only diff, so no merge
    conflict. That is the lesson of #1350, and the route #1357 took. I
    propose (a).
  - (b) On the `edge` branch's own `default.nix`, where its other quattro
    patches live. That matches the existing pattern, but adds to the diff
    that conflicts.
