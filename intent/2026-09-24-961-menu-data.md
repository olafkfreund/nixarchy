# Intent: the Ask topics can be found in plain words, and Nixi has a real row

## Problem

Two gaps in the menu **data** nixarchy generates
(`pkgs/omarchy/default.nix` -> `$OMARCHY_PATH/default/omarchy/omarchy-menu.jsonc`).
This is the data, not the palette: nixarchy-menu renders what we emit, so the
fix is here even though the symptom is seen there.

**1. The nine Ask topics cannot be found by describing the problem.**
`trigger.ask.*` at `pkgs/omarchy/default.nix:144-152` carry a label and nothing
else:

```
"trigger.ask.optimize": {"icon":"󰓅","label":"Make it faster","action":"…"}
```

The palette ANDs query terms, so a user typing what they actually have -- "system
slow", "why is it slow" -- matches nothing, because no token of either appears
in "Make it faster". The labels are written as answers; people search with
symptoms.

The parent row already knows this. `trigger.ask` (`:143`) carries
`"aliases":["ai","agent","help","fix"]`, and `setup.local-ai` (`:153`) carries
`["ollama","local model"]`. So the mechanism exists and is used twice; the nine
children were simply never given any.

**2. Nixi has no generated row.** The only way to reach it from the menu is a
hand-written "Help" row that Nixi's own installer writes into the user's
`~/.config/omarchy/extensions/omarchy-menu.jsonc`. That is a user file, so it is
unguarded -- it stays after the plugin is disabled or removed, and it is invisible
to every check here.

## Proposed outcome

- Typing the symptom finds the topic. "slow", "lag", "why is it slow" reach
  *Make it faster*; "hacked", "ports", "firewall" reach *Am I exposed?*; and so
  on for the nine.
- Nixi has a generated row in `modules/apps.nix`, labelled **Nixi**, aliased
  help/how/ask/nixi, running `nixi`, and **guarded** on
  `nixarchy-plugin --enabled io.github.olafkfreund.nixi` -- so it appears only
  where the plugin is enabled, and disappears when it is not.
- `checks.menu-verbs` and the menu build checks stay green.

## Affected users and systems

- Anyone using nixarchy-menu as their palette; the stock Omarchy menu shows
  labels rather than searching them, so it is unaffected either way.
- `pkgs/omarchy/default.nix` (the Ask rows) and `modules/apps.nix` (the new
  row). Both ours.

## Constraints

- **The guard mechanism already exists and must be reused, not reinvented.**
  `modules/apps.nix:362`, `:374` and `:385` each use
  `when = "nixarchy-plugin --enabled <id>"`. The Nixi row is a fourth in that
  shape.
- **The existing agent-row check must keep passing.** `pkgs/omarchy/default.nix`
  :1173 parses this same file and asserts things about `trigger.ask` rows --
  including that there are at least ten of them, and that each one's action
  opens a floating terminal. Adding aliases must not disturb either.
- Aliases are free-text and unverifiable: no check can say whether "lag" is a
  word a user would type. That is a judgement, and it should be stated as one
  rather than dressed up as covered.
- The follow-up in nixi-nixarchy (stop writing the user-file row) is **not**
  ours to make and is not in this scope -- filing or changing another
  repository unprompted is out (section 11).

## Open questions

1. **Does the new Nixi row collide with the hand-written one?** Nixi's installer
   writes a "Help" row into the user's extensions file. On a machine that has
   run that installer, both would exist until nixi-nixarchy stops writing it.
   I do not know whether the palette de-duplicates by id, label or not at all.
   Worth establishing before the spec, because "two Nixi rows" is a worse
   outcome than one unguarded one.

2. **Which aliases?** The issue proposes a starting set. I would rather write
   them from the symptom wording than from the topic name -- "why", "broken",
   "error" are the words people type -- but a list invented by me is a guess
   about your users. Your call whether to take the issue's set, mine, or yours.

## Not in scope

- Anything in nixarchy-menu itself (#946 wires it in; this issue is only data).
- Changing what `nixarchy-ask <topic>` does.
- The unguarded row Nixi's installer writes, which is nixi-nixarchy's to stop.
