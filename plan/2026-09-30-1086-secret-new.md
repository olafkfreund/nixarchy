# Plan: Guard system secret creation and the editor environment

System `new` must refuse an older flat-layout flake before any side effect and direct its owner to migrate to a per-host layout; no flat-layout system-secret path is supported. An existing policy must match the exact host rule and current age recipient, while `enroll` keeps its explicit append semantics. SOPS retains the host key in its root-side environment, but its editor and children must not inherit it. User secrets, encrypted files, and `nixarchy-apply`'s layout rule stay unchanged. Use one cheap check for the new behavior; no VM check.
