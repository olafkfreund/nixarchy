# Plan: Make the remaining robustness paths predictable

Refs #1098 (Robustness only). This plan covers the eleven confirmed findings; the VM lock item, stale scripts, stale docs, installer validation, and CI hygiene are separate work. No step touches the criticals PR's installer, MicroVM, or options-test files before that PR merges. Each check added below must fail when its corresponding fix is removed, then pass after restoration.

## Decisions and boundaries

- Syncthing's data and config directories follow the selected user's resolved NixOS home. Bind `home` with a guarded lookup, then assert `svc.user == null || (config.users.users ? ${svc.user} && home != "/var/empty")`: a missing user or `/var/empty` home fails with a useful message, while the existing null-user assertion handles null. The guarded lookup prevents an undeclared attribute from throwing before the assertion. Scalar overrides remain `mkDefault`.
- Open WebUI brackets a specific IPv6 literal once after the existing wildcard-to-loopback conversion. Hostnames, IPv4, already bracketed literals, telemetry defaults, and the opt-in gate remain as before.
- Flatpak `enable` is a scalar `mkDefault true`; an explicit user `false` wins, even with selected apps. Remotes and packages stay plain list assignments.
- All four Home Manager JSON/TOML writer paths avoid every direct write during `DRY_RUN`, including temp files, visibly name the skipped destination, and keep live merge errors non-fatal. `run` alone cannot guard shell redirection because redirection happens first.
- The channel switcher edits only nixarchy's own `inputs.nixpkgs.follows` in the shipped template shape, refuses ambiguity, keeps its `.pre-channel` backup and current relock behavior. The version-channel patch fails if `nixos-version` fails or prints no version, and never falls through to pacman on success.
- Owned skills replace symlinks but leave real files and directories unchanged; guarded skills and the four-clean/three-link split remain. Detached apply forwards effective `XDG_STATE_HOME` as well as config home.
- Every panel log action uses `nixarchy-apply --log`; follow actions add `--follow`. The command's existing invocation choice and 200-line fallback own log scoping. `systemctl show` properties are read as data from one call, never evaluated as shell. Both JSON status emitters guarantee a numeric `exit` for empty or malformed status (`0` when idle/running, `1` when failed); valid state, invocation, and timestamp behavior is retained.
- Keep this issue open with `Refs #1098`. No VM builds, local `checks.options`, PR, or push occur before their separate authorization. New checks must be red/green proven; workflow edits are out of scope.
