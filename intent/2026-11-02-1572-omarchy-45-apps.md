# Intent: Omarchy 4.5's default apps on nixarchy, and a check that catches the next one

## Problem

Omarchy 4.5 ships five things nixarchy has no package for. All five are
in upstream's `install/omarchy-base.packages`:

| upstream package | what it is |
|---|---|
| `hype` | Markdown presentations with a slide editor |
| `monologue` | the 4.5 recorder app |
| `signed` | sign and fill in PDFs |
| `disktree-bin` | a treemap for finding what fills the disk |
| `omarchy-hyprland-titlebars` | the Hyprland plugin that draws titlebars on floating workspaces |

On a machine running v4.5.0-rc3 or edge, their menu rows, shortcuts and
dock entries open nothing. Floating workspaces have no titlebars:
`default/hypr/workspace-modes.lua:26` loads the plugin from
`/usr/lib/omarchy-hyprland-titlebars/titlebars.so`, which does not exist
on NixOS, and the Lua skips it quietly.

**Why nobody noticed.** The rc1 bump did report it. `v4.5.0-rc1-1`'s
release notes list all five under "Added", produced by
`.github/scripts/omarchy-package-delta.sh`. But that output is prose:

- **No decision is recorded.** The script's own header says "each line is
  a decision this port either mirrors or knowingly does not", and nothing
  records which.
- **Nothing fails.** The bump merged and every check stayed green.
- **Nothing remembers it.** rc2 and rc3 compared themselves only to the
  previous rc, so the five never appeared again.

This is AGENTS.md §4's "a hand-maintained list fails OPEN", and §2's "a
bug found by hand is not fixed until something can see it". #1278 had
already named these packages in October and closed without them.

## Proposed outcome

1. **The five packages exist and are usable.**
   - Hype, Monologue, Signed and Disktree build as Nix packages, and
     `programs.nixarchy.apps.<name>` installs each one.
   - The titlebars plugin builds against the session's own Hyprland, and
     floating workspaces get titlebars.
   - The owner's machines (p620, razer) run all five. This is done
     through their own config at `~/.config/nixos`, which is not in this
     repository.
2. **A new upstream package cannot be adopted silently again.**
   - Every package name in the vendored tree's `install/*.packages` has a
     recorded decision: packaged here, provided by the NixOS module, or
     knowingly not carried, with the reason.
   - A check fails while any name is unclassified, on main's bump pull
     requests and on edge alike.
   - So a new app turns the bump red, and someone has to decide about it
     before it merges.

## Affected users and systems

- Everyone on v4.5.0-rc3 or edge: the missing apps and titlebars.
- `pkgs/apps/` and the flake overlay; `data/apps.nix`; `pkgs/omarchy/`
  for the plugin path.
- CI: one new `checks.<name>`, which runs on pull requests through the
  generated-checks step (§4). No workflow edit is needed.
- The owner's `~/.config/nixos`, for p620 and razer.

## Constraints

- **Mode A.** Nothing new installs on a machine that imports the module
  and did not ask for it (AGENTS.md §7). The `omawrite` precedent makes
  Omarchy's own apps opt-in for that reason.
- **The plugin's ABI must match the running Hyprland.** Hyprland here
  tracks hyprwm's main branch, so a mismatched plugin crashes or refuses
  to load.
- **The check reads the vendored tree, not the network**, so it is
  hermetic and runs against whatever Omarchy the branch pins. That covers
  both main's tag and edge's quattro commit.
- **§1:** the check is proven red by dropping one decision row, and the
  failing output goes in the pull request.
- **The decision rows are data, not prose**, and can be wrong in both
  directions. A row for a package upstream no longer lists is stale and
  fails too, the same way `data/bin-ledger.nix` does.

## Open questions

1. **Opt-in or default for the four apps?** The `omawrite` precedent and
   Mode A say opt-in. Omarchy ships them by default, though, and its dock
   and menu rows point at them.
   - My proposal: opt-in through `programs.nixarchy.apps.<name>`, plus
     one switch that turns on all of Omarchy's own apps.
2. **Is the titlebars plugin on by default?** It is not an app: it is
   how floating workspaces look, and it loads only when a workspace
   floats.
   - My proposal: on with the session, the same way the rest of
     Omarchy's desktop is.
3. **How big is the ledger's first version?** There are 249 names across
   all `install/*.packages` files today. Two options:
   - Classify all of them once, as the bin ledger did for 444 commands.
   - Record today's set as a baseline and require a decision only for
     names added after it.

   The baseline is smaller. The full classification also catches a name
   that was never carried, which is exactly #1278's case.
