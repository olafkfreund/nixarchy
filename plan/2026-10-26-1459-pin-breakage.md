# Plan: a nixpkgs bump that breaks a commit-pinned input is caught, said out loud, and its fix proposed

This file stands alone: the coder needs nothing else. It carries:

- the approved spec's decisions;
- the owner's three intent decisions;
- every finding from two read-only reviews of the approved spec, by Codex
  (gpt-6-sol) and agy (model not reported), verified against the tree or
  GitHub before use;
- measurements taken on p620 on 2026-10-26.

Where this plan departs from the spec, the deviation says why, under
"Deviations from the spec".

## What exists today (verified)

**The pre-PR gate is blind.**

- `.github/workflows/flake-update.yml` (07:00, hosted, `timeout-minutes:

  evaluate" (~line 140-179) evaluates `checks.x86_64-linux.{vm,reference}-toplevel`

  **exits 0 with no PR**.

## Decisions

From the spec, refined by review:

1. **The gate set is derived, never hand-listed.** It is
   `cache-allowlist.sh`'s output plus every probe target in
   `data/pin-fix.nix`. `checks.microvm-template` and `checks.options` stay
   out, for their cost.
2. **The auto-fix table is data, `data/pin-fix.nix`,** read by both the
   script (`nix eval --json -f`) and the check. The check can then assert at
   evaluation time that each probe target exists in `self.packages` or
   `self.checks` (agy B10: a sandboxed check cannot run `nix eval`).
3. **Every move is measured from the nixpkgs-only baseline.** Never
   `git checkout HEAD --`, which would also drop the nixpkgs bump (Codex
   blocker 3, agy B1). After `nix flake update nixpkgs`, copy `flake.nix` and
   `flake.lock` to `$RUNNER_TEMP/base/`. Every revert is a copy back from
   there.
4. **Candidates are tried one at a time from the baseline, then minimised**
   (Codex, agy B7):
   - try each candidate alone, in table order; the first that makes the
     batch pass is the proposal;
   - if none passes alone, try all candidates together;
   - if that passes, remove each move in turn and keep it out whenever the
     batch still passes;
   - only the moves the passing set needs are proposed.
5. **The move guard, per candidate.** Old sha = the root node's
   `locked.rev`, always the full sha. Assert that the url's ref is a prefix
   of it (zen's short sha). Then resolve the target:
   - the default branch comes from `gh api repos/R --jq .default_branch`,
     and its sha from `gh api repos/R/commits/<branch> --jq .sha`, resolved
     once;
   - it must match `^[0-9a-f]{40}$`;
   - `compare/<old>...<new>` must have `status == "ahead"` and
     `1 <= ahead_by <= 100`;
   - the owner must not be `olafkfreund`.

   Any failure is a refusal with a reason.
6. **Editing the url and re-locking.** Replace the whole ref in that
   input's exact `github:<owner>/<repo>/<ref>` string. Assert exactly one
   occurrence before and after, and that `git diff --numstat flake.nix`
   reads `1 1`. Run `nix flake lock`.
7. **Lock guard, after any move** (Codex blocker 4, agy B2/B3), in
   `pin-fix.sh --moved BASE_LOCK NEW_LOCK`:
   - for every root input, resolve its node in each lock and compare
     `locked`, and print the inputs that differ;
   - the root's input set must be unchanged.

   For a move of input X, the moved set must be exactly {X}. The nixpkgs
   baseline is the comparison, so nixpkgs itself does not appear. Transitive
   nodes, like microvm's `spectrum`, may change only under X: inputs
   unchanged, `nixpkgs` follows intact.
8. **The auto-merge guard**, `pin-fix.sh --only-nixpkgs MAIN_LOCK PR_LOCK`
   (Codex blocker 4, agy B3):
   - take the PR lock;
   - replace the `locked` of the node `nodes.root.inputs.nixpkgs` resolves
     to with main's `locked` for main's resolved node;
   - require the result to be `jq -S`-equal to main's lock;
   - require `flake.nix` to be byte-equal;
   - require the PR's changed-file list to be exactly `flake.lock`.

   Any renamed or added node makes them unequal, so it fails closed. It
   runs before every `gh pr merge --auto`, against
   `git show origin/main:flake.lock` and the PR head's files, fetched by
   sha.
9. **Ownership of `update/nixpkgs-blocked`, before EVERY write to it**
   (Codex blocker 1, agy B4). The branch is the job's to write when either:
   - it does not exist on the remote; or
   - it has no open PR; or
   - it has an open PR that is a **draft**, authored by the `BUMP_TOKEN`
     identity, and every commit in `origin/main..origin/update/nixpkgs-blocked`
     carries the exact trailer line
     `Generated by .github/workflows/flake-update.yml.`, with the period,
     copied from the existing commit message.

   Otherwise a person, or Copilot, has taken it. The job then never pushes
   to it:
   - on a failing night it only writes the step summary and a one-time PR
     comment per nixpkgs rev (marked `<!-- flake-update:<rev> -->`);
   - on a clean night it opens the normal dated PR as today and comments
     on the draft once.

   The check is re-run immediately before the create-pull-request step.
10. **Draft state.** Failing nights pass `draft: always-true` (Codex
    blocker 2). Promotion runs `gh pr ready` and **fails loudly** if it
    fails: no `|| true`, unlike `omarchy.yml`.
11. **Outcome wiring** (agy B6). The gate step never fails the job: it
    writes `steps.gate.outputs.ok`. The draft path uses
    `if: steps.bump.outputs.changed == 'true' && steps.gate.outputs.ok == 'false'`.
    A handled blocked night concludes **success**, and the review's
    blocked-draft row is what makes it loud. A broken script, meaning an
    infrastructure error (exit 2), still fails the job.
12. **`eval-gate.sh`'s contract** (Codex should-fix, agy S2/S5). It has
    three exit statuses:
    - **0:** all evaluated;
    - **1:** at least one target failed, and stdout lists one
      `target<TAB>message` row per failure;
    - **2:** infrastructure (the allowlist failed or came back empty, the
      table failed to read, or the batch failed but no single target could
      be confirmed failing). Callers never turn 2 into an "upstream broke
      it" draft.

    The rules it follows:
    - the target list is captured with `out=$(cmd) || exit 2`, never
      `mapfile < <(...)`;
    - `--batch-only` skips the per-target pass, for pin-fix's trials and
      minimisation;
    - the message is the **last** `error:` block of that target's stderr,
      with ANSI stripped, joined to one line and cut to 300 characters;
    - full stderr goes to `$EVAL_GATE_LOG_DIR/<sanitised target>.log` when
      the variable is set.
13. **Time.** Worst case: batch 2 min, per-target 2.3 min, four single
    trials of 2 min, one combined trial and up to four minimising trials,
    plus setup. That is 20-25 min.
    - `flake-update.yml`'s `timeout-minutes` goes **30 to 45**: a workflow
      change, owner-approved at this gate.
    - `pin-fix.sh` also has a 28-minute deadline (`PIN_FIX_DEADLINE`,
      seconds since the job started). Past it, it stops trying, reverts to
      the baseline and records "not tried: deadline" per candidate, so a
      draft still opens.
14. **PR bodies are sanitised** (agy S3, §8). Every body this workflow
    writes passes through `pin-fix.sh --sanitize`:
    - the five skip-CI markers, matched case-insensitively with any inner
      spacing, become `(skip-ci marker removed)`;
    - upstream subjects are wrapped in backticks after removing backticks,
      so `@user` and `#123` do not link or notify.
15. **The copilot handoff skips draft PRs** (agy B5). `copilot-handoff.sh`
    reads `isDraft` with the PR number and exits 0 for a draft, with a
    message. `pin-fix` is the fixer for the blocked draft, and Copilot's
    commit would otherwise take ownership of it (decision 9).
16. **The review** (`pkgs/review.sh`, D):
    - **One decision for both healthy `rev` cases.** Both "no version tags"
      and "`ahead` of the newest tag" route through `rev_verdict`, which
      asks the default-branch HEAD (resolved as in decision 5). The verdict:
      - `identical`: ok, "at <branch>";
      - `ahead` N: a **finding** only when the owner is not `olafkfreund`
        AND the oldest commit we lack (`commits[0]`'s committer date in
        `compare/<pin>...<head>`) is more than 7 days old. Otherwise ok,
        "N behind <branch>".

        This measures how long a newer upstream has existed, not the pin's
        own `lastModified` (Codex, agy N3), and is the owner's decision 2
        read as "behind for more than 7 days".
      - `diverged` or `behind`: finding, "pin is not on <branch>";
      - an API error: ok, "not comparable", guarded by `|| x=""`, the
        #1006 pattern.

      A pure `--rev-row` mode takes the fields as arguments, for fixtures.
    - **`ci flake-update.yml 30`** joins `ci()` at ~548.
    - **A blocked-draft row.** It asks REST
      `repos/$SELF/pulls?head=<owner>:update/nixpkgs-blocked&state=open`:
      - a finding when the PR's `created_at` is more than 3 days ago, as
        "nixpkgs bump blocked since <date>, #<n>". `created_at` is when the
        stall began: failed nights update the PR, not recreate it;
      - ok, "no blocked bump", otherwise;
      - an API error is a finding, "cannot read pull requests".

      It is guarded under errexit, and a `--blocked-row` pure mode exists
      for fixtures.
    - **`review.yml` gains `pull-requests: read`** (agy B8).
17. **`flake-pins.py`.** An `original.ref` that is all lowercase hex, 7 to
    40 characters, is `rev`, with `at = locked.rev`. Date-shaped refs stay
    `ref` (agy B9; see "Deviations from the spec").

## Deviations from the spec

- **Dated refs are not reclassified as tags.** The `tag` arm has no grace
  period, and nix-index-database tags weekly, so it would be a finding
  every week (agy B9). It stays in the `ref` arm, whose 120-day rule and
  newest-tag test already handle it.
- **"Pin older than 7 days" is measured as the age of the oldest upstream
  commit we lack,** not the pin's `lastModified`, which is upstream's
  commit date and would flag a pin adopted yesterday (Codex).
- **Ownership is checked before every write to the blocked branch,** not
  only before promotion, and a human-held draft is never written to
  (Codex blocker 1, agy B4).
- **Failing nights write the blocked branch with `draft: always-true`.**
- **The rollback copies from a saved baseline,** never from git (Codex
  blocker 3, agy B1).
- **Candidates are tried from the baseline and minimised,** not kept
  cumulatively (B7).
- **The auto-merge guard is a lock equivalence on the resolved root
  `nixpkgs` node,** not a node-name or node-count test (Codex blocker 4,
  agy B2/B3).
- **New since the spec:** the job timeout goes 30 to 45, the copilot
  handoff skips drafts, `review.yml` gains a permission, and PR bodies are
  sanitised.

## Steps

Each step names its files, its check and the traps that apply. Run cheap
checks under `flock /mnt/data/vmtest/codex-build.lock`, one at a time
(AGENTS.md §6 tiers). Every step that adds or changes a `.nix` file runs
`nix fmt` and reads `git diff --stat`, because a hook can rewrite the file
in another style (AGENTS.md §5). Commit after each step with a full-sentence
subject; the PR squashes.

1. **`data/pin-fix.nix`: the auto-fix table.** A plain attrset keyed by root
   input name. Each value is
   `{ probe = "<installable without .#>"; why = "<one line>"; }`, for the
   four rows in "What exists today". The `vm-toplevel` probe is
   `checks.x86_64-linux.vm-toplevel`.
   - Verify: `nix eval --json -f data/pin-fix.nix`.
   - Traps: none.

2. **`.github/scripts/eval-gate.sh`: decision 12.**
   - Interface: `eval-gate.sh [--batch-only]`, run from the repo root.
     Targets = `cache-allowlist.sh` output plus each `.#<probe>` from the
     table, de-duplicated with order kept.
   - Use `nix path-info --derivation` (instantiates without building or
     substituting outputs; Codex verified the manual).
   - `#!/usr/bin/env bash`, `set -uo pipefail`.
   - Verify, at evaluation tier: on `/mnt/data/vmtest/wt-red` (`700ee61c`),
     exit 1 and exactly 18 rows, each a `.#microvm-*` with
     "no longer has any effect" in the message. On `wt-green`
     (`1d56f54d`), exit 0. Break the table path, and an empty allowlist via
     a stub, and get exit 2 each time.
   - Traps:
     - AGENTS.md §4 (mapfile; a format is an interface, so grep every
       consumer);
     - §1 (pipefail; run as a script under bash);
     - §13 (an eval error kills the batch, hence the per-target pass).

3. **`.github/scripts/pin-fix.sh`: decisions 3-8 and 13-14.** Modes:
   - **`--decide OWNER COMPARE_JSON_FILE NEW_SHA`:** prints
     `move <sha> <ahead_by>` or `refuse <reason>`. Pure.
   - **`--replace FLAKE_NIX INPUT OLD_FULL_SHA NEW_SHA`:** edits in place.
     It exits non-zero unless exactly one occurrence of the input's
     `github:<o>/<r>/<ref>` string is found, the ref is a prefix of
     `OLD_FULL_SHA`, and exactly one line changes. Pure on a file.
   - **`--moved BASE_LOCK NEW_LOCK`:** root inputs whose resolved `locked`
     differs, one per line, or exit 2 if the root input set differs. Pure.
   - **`--only-nixpkgs MAIN_LOCK PR_LOCK`:** exit 0 or 1, as in decision 8.
     Pure.
   - **`--sanitize`:** stdin to stdout, as in decision 14. Pure.
   - **The default run.** Reads eval-gate's failure rows from a file
     argument and the baseline from `$RUNNER_TEMP/base`. It runs decision 4
     using the decision 5-7 guards and decision 13's deadline. It writes
     `$PIN_FIX_OUT/body.md`, sanitised, with the moves, commit lists (from
     `compare/<old>...<new>`, at most 100 lines) and refusals. It writes
     `$PIN_FIX_OUT/moved`, the input names, and `$PIN_FIX_OUT/status`,
     `fixed` or `unfixed`. The working tree ends either as baseline plus
     the minimal passing moves, or as the baseline.
   - Candidates: an input is a candidate when its probe target is in the
     failure rows.

   Verify: step 4's check, and step 12's end-to-end run.

   Traps:
   - **§5:** a `sed` that matches nothing exits 0, so assert counts; restore
     from a copy, not with `git checkout`; and never let an EXIT trap read a
     `local`.
   - **§13:** a field that may be empty is split by expansion, not `read`.
   - **§8:** no skip-CI literal in this script's own comments or commit
     messages; spell it "a skip-CI marker". The sanitiser builds its
     pattern from parts so the literal never appears in the source.

4. **`tests/pin-fix.nix` + `flake.nix` `uniformChecks`: the check.** A
   `runCommand` (bash, jq, coreutils, gnugrep, gnused, git) that runs
   `pin-fix.sh`'s pure modes against fixtures:
   - **`--decide`:**
     - ahead 42: move;
     - ahead 101: refuse;
     - ahead 0 or identical: refuse;
     - diverged: refuse;
     - behind: refuse;
     - a malformed sha: refuse;
     - owner `olafkfreund`: refuse.
   - **`--replace`,** on a copy of the real `flake.nix`:
     - microvm's full sha: one line changes, and the 18 other pinned urls
       are byte-identical;
     - zen-browser's short sha: replaced with the full new sha;
     - a sha not in the file: non-zero, file unchanged;
     - a prefix mismatch: non-zero.
   - **`--moved`,** on fixture locks built from the real `flake.lock` with
     jq:
     - only microvm's `locked` changed: `microvm`;
     - microvm plus its `spectrum` node: `microvm`;
     - an added root input: exit 2.
   - **`--only-nixpkgs`:**
     - only the `nixpkgs_2` `locked` changed: 0;
     - plus microvm: 1;
     - a renamed node: 1.
   - **`--sanitize`:** every marker spelling, with mixed case and spacing,
     is removed; `@user` and `#12` come out inside backticks.
   - **Probe existence, at evaluation time:** for each table row,
     `lib.hasAttrByPath` on `inputs.self.packages.x86_64-linux` or
     `inputs.self.checks.x86_64-linux`. Fail at eval with the row's name.
     If referring to `self.checks` from inside a check recurses, use
     `inputs.self.outputs` attr names instead, and record it as a deviation.

   Register `"pin-fix"` in `uniformChecks`, with a one-line comment.

   **§1 proof:** break `--decide` by accepting `diverged`, `--replace` by
   dropping the count assert, and `--only-nixpkgs` by skipping the
   `flake.nix` compare. Each must turn the check red; capture the output
   for the PR. Prove each break landed with `git diff`, then restore with
   `git checkout HEAD --` on a committed baseline.

   Traps: §1 (show the break landed), §5 (`checkout HEAD --`, not the
   index), test-registration.

5. **`pkgs/flake-pins.py`: decision 17.**
   - `tests/review-pins.nix`'s shape loop gains `"zen-browser	rev"` and
     `"nix-skills	rev"`, and keeps `"nix-index-database	ref"`, asserted.
   - The `--list-pins` count stays 8: those are package pins, untouched.
   - Traps: §1 (revert the classifier and watch `zen-browser rev` fail).

6. **`pkgs/review.sh`: decision 16.**
   - Add `rev_verdict` and the `--rev-row` and `--blocked-row` modes, in
     the shape of `--cirow`.
   - Route the two healthy `rev` cases through it.
   - Add `ci flake-update.yml 30` and the blocked-draft row.
   - Every new `gh` call goes through a substitution guarded with
     `|| var=""`.
   - Fixtures in `tests/review-pins.nix`:
     - microvm today (owner microvm-nix, ahead 42, oldest missing more than
       7 days): finding;
     - the same with owner `olafkfreund`: ok;
     - ahead 3, oldest missing 2 days: ok;
     - identical: ok;
     - diverged: finding;
     - an API error (empty fields): ok, "not comparable";
     - blocked created 4 days ago: finding;
     - blocked created 1 day ago: ok;
     - none: ok;
     - an API error: finding.
   - Traps:
     - pkgs/AGENTS.md (errexit from `writeShellApplication`; declare any
       new command in `runtimeInputs`, and `gh` and `jq` are already
       there, verify);
     - §13 (an empty first field);
     - run the **packaged** `nix run .#review -- --rev-row …` once, not

7. **`.github/workflows/review.yml`:** add `pull-requests: read`.
   - Verify: actionlint.
   - Traps: §11 (owner approval, given at this gate).

8. **`.github/scripts/copilot-handoff.sh`: decision 15.** After `pr=` is
   resolved, read `gh pr view "$pr" --json isDraft -q .isDraft`. If true,
   echo "#$pr is a draft -- pin-fix owns it; not handed off" and exit 0.
   - Verify: `bash -n`, then shellcheck through actionlint's run.
   - Traps: none.

9. **`.github/workflows/flake-update.yml`: the workflow, decisions 3 and
   9-14.** In order:
   1. "Move the pin", unchanged, then copy `flake.nix` and `flake.lock` to
      `$RUNNER_TEMP/base/`.
   2. "Every cached output still evaluates" (`id: gate`) runs
      `eval-gate.sh > $RUNNER_TEMP/fail.tsv`:
      - exit 0: `ok=true`;
      - exit 1: `ok=false`;
      - exit 2: the step fails, so the job is red and the review's
        `ci flake-update.yml` row says so.
   3. "Try the allowlisted inputs" (`if: gate ok == 'false'`) runs
      `pin-fix.sh`, with `GH_TOKEN` set to `github.token` for read-only
      API calls.
   4. "Who holds the blocked branch" (`id: owner`, on both paths) applies
      decision 9 and outputs `writable=true|false` and `pr=<n>`.
   5. **Blocked path,** `if: changed && gate ok == 'false' && owner writable`:
      create-pull-request with
      - `branch: update/nixpkgs-blocked`, `draft: always-true`;
      - title `nixpkgs: blocked on <inputs>, fix proposed` when
        `status=fixed`, else `nixpkgs: blocked, <n> target(s) do not evaluate`;
      - the body: pin-fix's `body.md`, the failure rows, the app delta,
        "will not merge itself", all sanitised;
      - the existing commit message, whose trailer is unchanged;
      - no auto-merge step on this path.

      **Blocked and not writable:** the one-time comment, and the summary.
   6. **Clean path** (`gate ok == 'true'`):
      - if `owner writable && pr` names an open bot draft, create-pull-request
        on `update/nixpkgs-blocked` with `draft: false`, the normal title and
        body, then `gh pr ready "$pr"`, failing loudly;
      - otherwise the dated branch, as today.
   7. "Arm auto-merge" on the clean path only:
      - first fetch the PR head sha from create-pull-request's
        `pull-request-head-sha`, then `git fetch origin <sha>`;
      - run `pin-fix.sh --only-nixpkgs <(git show origin/main:flake.lock) <(git show <sha>:flake.lock)`,
        plus `git diff --name-only origin/main <sha>` being exactly
        `flake.lock`;
      - refuse loudly otherwise;
      - then `gh pr merge --auto --squash --delete-branch` and the existing
        check-runs probe on **that sha**.
   8. `timeout-minutes: 45`.
   9. Amend the header's "NIXPKGS ONLY" paragraph: it moves and
      auto-merges nixpkgs only, and may *propose* the four inputs in
      `data/pin-fix.nix` as a draft.

   Verify:

## Rollback

Revert the squash commit. Nothing changes on a user's machine. If the
blocked branch exists at revert time, close its PR and delete
`update/nixpkgs-blocked` by hand. The old workflow would never write to it
again.
