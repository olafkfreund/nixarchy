# Plan: edge's tree builds and passes its checks under main's Omarchy pin

Self-contained: it carries every approved spec decision. Builds, checks,
commits, pushes and dispatches are Claude's. Codex and the coder edit files
only, and agy reviews only, because `agent-run agy` cannot reach `/mnt/data`
worktrees. All file paths below are on edge, read with
`git show origin/edge:<path>`.

## Decisions (from the approved spec)

1. **The pin signal.** An edge pin is `lib.hasPrefix "edge-" omarchy.version`.
   Python checks get it as `--edge`; Nix reads it directly.
2. **The screensaver gate.** `hasScreensaverPackage = elem
   "omarchy-screensaver" basePackages`. The `omarchy-launch-screensaver`
   `--replace-fail` is spliced in with `lib.optionalString` on that flag, so
   the install phase text, and therefore the drvPath, is unchanged on quattro.
3. **The migration test** decides per migration, from `$ORACLE_SOURCE`. A
   helper `applicable <ids…>` lists the ids whose script exists there. Cases
   pass only those ids to `run_ids`, and loop their assertions over the same
   set. A case left with none prints `skip` and returns. `$oracle` is not
   used, because `run:648` reassigns it.
4. **The coexistence check:** the user's `/lib/qt-6/plugins` appears at least
   once under both pins, exactly twice when `hasQtengine`, and exactly once
   otherwise.
5. **The markers:**
   - whole-row: `edge = "only"`, active only under an edge pin, and
     `edge = "absent"`, active only without one;
   - per-allowance, in the bin-ledger: `edge_allow` and `tag_allow`.

   Every reader validates every row under both pins first: the marker value,
   unknown or duplicate fields, non-string syntax, the groups against
   `PATTERNS`, and `edge_allow` disjoint from `allow`. Only then does it drop
   inactive rows, from both directions of every comparison.

   The effective allowance is `allow` plus `edge_allow` or `tag_allow`,
   whichever is active. It feeds both the biconditional and the vendor-row
   guard (`check-bin-ledger.py:311`).

   The migration bundle builder filters the same way.
6. **The `main-pin` job** in `omarchy-edge.yml`:
   - hosted, `needs: prepare`, starting with `Free disk space`;
   - it checks out the candidate, restores `main`'s pin, and commits it
     locally;
   - it then builds, one by one: `.#omarchy`, the cheap tier plus the
     claimed non-VM checks, both toplevels, every `options-*` shard from
     `nix eval`, statix, deadnix and `nix fmt -- --ci`, then runs
     `readme-counts.sh --fix` without committing;
   - wiring: `verify` gains `needs: main-pin`, the promote step requires its
     success, `failed` gains `main-pin`, and `report` gains `needs:
     main-pin`;
   - a `dry_run` input, also implied by any ref other than `main`, skips the
     candidate push, the promote and the issue edits.
7. **It lands in two phases:**
   - phase 1, steps 1 to 8, is a carry on `edge-candidate`;
   - phase 2, step 9, is a workflow PR to `main` that the owner merges.

   #1752 closes when phase 2 merges, and the artifacts PR says `Refs #1752`.

## Tests

- **Under both pins**, on the carry and the tag scratch tree:
  - `.#omarchy`;
  - `bin-ledger`, `menu-actions`, `user-migrations`,
    `user-migrations-ledger`, `omarchy-package-ledger`, `coexistence`,
    `patched-files`, `review-pins`, `grep-q-pipefail`;
  - the four `options-*` shards and `options-shards`;
  - `vm-toplevel`, `reference-toplevel`;
  - statix, deadnix, `nix fmt -- --ci`;
  - `readme-counts.sh --fix` on the tag tree only.
- **What ships is unchanged.**
  - Under quattro, the `omarchy` drvPath equals the base's.
  - Under v4.5.0, the baseline is the base with only the screensaver
    substitution made non-fatal. Against it, the whole `.#omarchy` tree, the
    generated menu JSON, the bundle's `list` and `vm-toplevel`'s package
    names are each diffed, in one tree. Each diff must be empty.
- **The signal's expiry.** The carry with `omarchyVersion = "4.6.0"` in a
  scratch tree must fail the three ledger checks loudly.
- **§1 breaks**, each run red and then restored:

  | break | pin | must fail |
  |---|---|---|
  | a stale `edge_allow` group | edge | `bin-ledger` |
  | an `edge = "only"` row whose subject is gone | edge | the ledger it is in |
  | an unknown field, a duplicate, `edge = true;`, a bad group | both | `bin-ledger`, before filtering |
  | an attrset menu value with an extra key | both | `menu-actions` |
  | a vendor row with only `edge_allow` | tag | `bin-ledger` |
  | a row for something v4.5.0 has, marked `edge = "only"` | tag | each of the four ledgers |
  | the screensaver gate inverted | quattro | `.#omarchy` |
  | a post-`case_1672` migration removed from the runner's list | quattro | `user-migrations` |
  | a mixed case | tag | `user-migrations`: it must still run and assert its applicable ids |
  | the qtengine count forced to 1 | quattro | `coexistence` |
  | the user's Qt path removed | tag | `coexistence` |

- **Not run locally:** the `install` job, and hosted-runner memory under
  `main-pin`. The phase 2 dry-run covers the second.

## Rollback

- **Phase 1:** a revert commit on `edge-candidate`, then a dispatch. Edge stays
  on its last good commit until a run passes.
- **Phase 2:** revert the workflow PR on `main`. The job is additive, and
  removing it restores the old promotion path.
- **The artifacts:** revert the merge. No code goes to `main` from that
  branch.
