# Intent: the Nix skills in olafkfreund/nix-skills reach nixarchy's agents

Closes #888.

## Problem

[nix-skills](https://github.com/olafkfreund/nix-skills) is ours. It holds six
agent skills written against the upstream Nix manual rather than from memory:

| skill | what it answers |
| --- | --- |
| `nix-language` | syntax, scope, laziness, strings, paths, derivations, built-ins |
| `nixpkgs-development` | package expressions, overrides, overlays, build helpers |
| `home-manager` | user environments, and Home Manager inside NixOS |
| `microvm-nix` | declarative microVMs |
| `devenv-project` | per-project devenv environments |
| `nixos-wiki` | where the wiki is the right source, and where it is not |

These are exactly the questions a nixarchy user's coding agent gets asked, and
where it most often guesses. nixarchy's own skills (`pkgs/omarchy/skills`, 15
of them) cover *nixarchy* and NixOS operations. They do not teach the Nix
language or nixpkgs. Today a nixarchy machine's agents do not have these six at
all, unless the user installs nix-skills themselves.

## Proposed outcome

- On a nixarchy machine, the coding agents nixarchy already seeds skills into
  get the nix-skills set too, with no step from the user.
- A user who wants them gone can turn them off, in one place.
- An agent asked a devenv or Nix-language question gets one clear skill to
  follow, not two that disagree.

## Affected users and systems

Every nixarchy desktop's coding agents: Claude Code, Codex, opencode and pi.
On nixarchy's side: `flake.nix` (an input), the Home Manager module where skills
are seeded (`modules/home.nix:966-989`), the docs that list skills
(`docs/manual/ai.md`, `docs/llms.txt`, README), and `readme-counts.sh`, which
counts skills from the built tree. In the nix-skills repository: a licence
file, and anything the overlap below turns out to need.

## Constraints

What scoping found, which any design has to answer:

- **Topic overlap, not name clashes.** No nix-skills name collides with one of
  nixarchy's. But nixarchy's `devenv` and nix-skills' `devenv-project` answer the
  same question, and nixarchy's broad `nixos` skill brushes against
  `nix-language` and `nixpkgs-development`. Two skills that trigger on the same
  question and say different things make an agent worse, not better.
- **The directories differ.** nixarchy seeds `.agents/skills`, `.claude/skills`,
  `.codex/skills` and `.pi/agent/skills`. nix-skills' own module targets Claude,
  Codex (through `.agents/skills`) and opencode (`~/.config/opencode/skills`),
  and knows nothing of pi. Whatever ships reaches the same agents nixarchy's
  skills do, and no fewer.
- **nixarchy's relink step removes store links on every activation**
  (`home.nix:977-982`, any link into `/nix/store/*/agents/skills/*`). Anything
  placed beside nixarchy's skills has to survive that, and must not be removed
  by it or remove it.
- **A user who already enables `programs.nix-skills` is not broken.** Home
  Manager refuses two definitions of one file, and nixarchy must not become the
  second (Mode A, and the same care ai-mirror's module got in #773).
- **Licence.** nix-skills has no licence file. It needs one before nixarchy
  ships it on every machine, as ai-mirror needed one (#773).
- **The counts stay true.** README, `docs/llms.txt` and `docs/manual/ai.md` state
  a skill count, and `readme-counts.sh` derives it from the built tree (§4:
  teach `word_for` any new number in the same change).
- **Pinned to a commit**, like every other input from our own repositories.
- Every new check is proven to fail first (§1).

## Open questions

1. **Vendor or depend?** Copy the six skills into nixarchy's tree, so the
   existing seeding, counting and parity checks cover them unchanged. Or take
   nix-skills as an input and link its skills beside ours, so nix-skills stays
   the single source. The first is simpler to ship. The second is the reason the
   repository exists. For the spec, with a recommendation.
2. **The devenv overlap.** Keep both skills with their scopes made
   non-overlapping, merge them into one, or ship nix-skills without
   `devenv-project` on nixarchy? The spec reads both skills side by side before
   proposing.
3. **Counted with nixarchy's skills, or apart?** Does the README say "twenty-one
   skills", or "fifteen, plus the six Nix skills"? This decides what
   `readme-counts.sh` measures.
4. **On by default, or opt-in?** The outcome above says on. Confirm that, given
   they add six skills to every agent's context.
