# Spec: Gliff-Manager ships as a default plugin, from a NixOS-ready fork

The design was reviewed by Fable (as a Plan agent) and by Codex
(`codex exec -s read-only`) before this file was written. Their findings are
marked **[F]** and **[C]**.

## Design

### 1. The fork, `olafkfreund/nixarchy-gliff-manager`

- **A real GitHub fork** of 28allday/Gliff-Manager
  (`gh repo fork --fork-name nixarchy-gliff-manager`), public, with default
  branch `main`. It copies the shape of nixarchy-podman, the existing
  third-party bar-widget fork.
- **Identity** (`manifest.json`):
  - `id` becomes `nixarchy.gliff-manager`, and `Panel.qml`'s `moduleName` and
    `ipcTarget` follow.
  - `author` becomes "olafkfreund (nixarchy port); Gavin Nugent (Gliff-Manager,
    upstream)", and `homepage` points at the fork.
  - `version` becomes `0.1.0-nixarchy.1`, so a copy of the fork can be told
    from a copy of upstream [F].
  - The description drops "Needs Omarchy 4.5 / not installed by default".
  - `LICENSE` is kept word for word.
- **Fixes, made in the source** because we own the fork:

| breakage | fix |
|---|---|
| local version: `pacman -Q gliff` (`gliff-manager.sh:463`) | `gliff --version`, second field [F] |
| remote version and channel: `pacman -Q`, `pacman-conf` (:557-564) | version from `gliff-server --version`; `channel=` is the `ID` from `/etc/os-release` (`nixos`, `arch`) |
| client processes: `pgrep -x gliff` (:498) | `pgrep -u "$(id -u)" -x 'gliff\|\.gliff-wrapped'` [F] |
| Hyprland owner: `ps -C Hyprland` (:574) | the first pid from `pgrep -x 'Hyprland\|\.Hyprland-wrapp'`, then `ps -o user= -p` on it [F] |
| install fix runs `sudo pacman` on the remote (:1012-1030) | opens a terminal that says how to get gliff on that machine: `omarchy pkg add gliff` on Arch Omarchy; already installed on nixarchy; the README's snippet on other NixOS. No package manager runs |
| session fix installs a script that runs `/usr/bin/gliff-server` (:991-1010) | not offered when `channel` is `nixos` (`Panel.qml:151`). Connecting still works there, through the `--server-bin` environment wrapper the script already uses (`needs_env_server`) [C][F] |
| banner hint `omarchy pkg add gliff` (`Panel.qml:529`) | says gliff is not installed, with no hint that names a package manager |

  Every fix uses a command that works on Arch too, so nothing branches on
  the distribution except the session fix.
- **`flake.nix`** supports `x86_64-linux` and `aarch64-linux`, on nixpkgs
  unstable:
  - **`packages.default`** (also `nixarchy-gliff-manager`) is a `runCommand`
    that copies exactly `manifest.json`, `LICENSE`, `Panel.qml` and
    `gliff-manager.sh`, with the version read from `manifest.json`. Plain
    copies, because `omarchy-plugin-validate` refuses any symlink inside a
    plugin folder.
  - **`homeManagerModules.default`**, for NixOS without nixarchy:
    - `programs.gliff-manager.enable` links the package to
      `~/.config/omarchy/plugins/nixarchy.gliff-manager`.
    - It adds `jq`, `openssh`, `pciutils`, `procps` and `util-linux` at
      `lib.lowPrio`.
    - When `osConfig.programs.nixarchy.enable` is true, it does nothing and
      prints a warning. nixarchy reconciles its own plugin links, and a second
      writer of that path would make Home Manager's `checkLinkTargets` refuse
      a later switch [F].
  - **`checks.default`** is one `runCommand` [F] that runs, in order:
    - the manifest (`jq`: id, kinds, entry point present, no `omarchy.`
      prefix);
    - no symlinks in the package;
    - no `pacman` or `yay` on any non-comment line;
    - `shellcheck -s sh`;
    - `qmllint` (only exit 255 fails, as in nixarchy-pkg);
    - the Home Manager module evaluated in both states;
    - the behaviour test (§3).
  - **`devShells.default`** (shellcheck, jq, qt6.qtdeclarative), and
    **`formatter`** nixfmt.
- **Workflows:**
  - `ci.yml` is podman's: SHA-pinned actions, `permissions: contents: read`,
    on pushes to `main` and on PRs. It runs `nix flake check -L`,
    `nix flake check --all-systems --no-build` and `nix build .#default`.
  - `pages.yml` deploys `docs/` with Jekyll, as podman's does.
  - `upstream.yml` runs weekly and only reads. It compares 28allday's `HEAD`
    with the commit recorded in `UPSTREAM`, and opens one issue when upstream
    has moved and no such issue is open.
- **Documentation:**
  - **README:** credit, what the plugin does, what the fork changes and why,
    and install instructions for nixarchy (a default; nothing to do), other
    NixOS (a flake input plus the module) and Arch (`omarchy plugin add`).
    Also "remove upstream's copy if you added it", development, and licence.
  - `AGENTS.md`, with `CLAUDE.md` as a symlink to it.
  - A one-page `docs/` site that reuses upstream's `preview.png`.
  - `UPSTREAM`, holding `b39ea9b`.
- **Release:** tag `v0.1.0-nixarchy.1` and publish a GitHub release. nixarchy
  pins the commit that tag points at.

### 2. nixarchy

- **`flake.nix`:** a new input
  `nixarchy-gliff-manager = github:olafkfreund/nixarchy-gliff-manager/<sha>`
  with `inputs.nixpkgs.follows` and a `# Why:` pointer. It is re-exported as
  `packages.<system>.nixarchy-gliff-manager` beside podman's (`:1161`) [F].
  `docs/internals/flake.md` gets a section on the licence, what the fork
  changes, and how to bump the pin (read the diff against both the fork and
  upstream). The nightly review finds the pin by itself (`pkgs/flake-pins.py`).
- **`modules/home.nix` `defaultPluginSet.gliff-manager`:**
  - `id = "nixarchy.gliff-manager"`, with `src` the input's package and
    placement `right`.
  - the gate:

    ```nix
    gate = (osConfig.programs.nixarchy.preinstalls or false)
      && !(builtins.elem "gliff" (osConfig.programs.nixarchy.preinstallsExclude or [ ]));
    ```

    This is the same decision that installs gliff (`modules/nixos.nix:1496-1528`).
  - **No `packages`.** Every tool the script calls is already an `omarchy`
    runtime dependency (`pkgs/omarchy/default.nix`) [F].
  - The `defaultPlugins` option's default gains `gliff-manager = true`, and
    its description names the plugin [F].
  - It is enabled once by the existing post-boot hook, like every other
    default. `defaultPlugins.gliff-manager = false` opts out.
- **Menu:** `setup.remote.gliff-manager`, "Manage gliff machines", goes after
  `setup.remote.gliff` in `remoteMenuRows`. Its action is
  `nixarchy-plugin nixarchy.gliff-manager`, and its `when` is
  `nixarchy-plugin --enabled nixarchy.gliff-manager`, the idiom
  `modules/apps.nix:393` uses. A user who turns the widget off loses the row,
  rather than getting a row that cannot open anything.
- **Counts:** sixteen default plugins, twelve always on and four that follow
  their feature [C][F]. `readme-counts.sh` already spells "sixteen", so only
  the prose changes.

### 3. The behaviour test (the fork's `checks.default`) [F][C]

It uses real processes rather than stubbed `ps`/`pgrep`, because the Nix
sandbox mounts `/proc`:

- **A fake Hyprland:** `cp "$(command -v sleep)" .Hyprland-wrapp`, run in the
  background. Its owner is the build user.
- **A fake gliff window with a live tab:**
  `cp "$(command -v bash)" .gliff-wrapped`, run in the background as
  `./.gliff-wrapped -c './ssh me@box 600' --headless me@box`, where `./ssh` is
  a copy of `sleep`. That gives a process named `.gliff-wrapped` with an
  `ssh` child, which is what a gliff window with one tab looks like.
- **Stubs, only for what the sandbox cannot provide:**
  - `gliff` and `gliff-server`, which print `gliff 0.3.1` and
    `gliff-server 0.3.1`;
  - an `ssh` on `PATH` that parses its `-o` pairs, `--` and target, then runs
    the remote command locally.
- **Assertions:**
  - `status fast`: `.local.installed == true` and `.local.version == "0.3.1"`;
  - `probe me@box`: `.gliff == "0.3.1"` and `.hyprOwner == "$(id -un)"`;
  - `live`: `[{target: "me@box", mode: "headless"}]`.
- **Not asserted: `.channel`.** There is no `/etc/os-release` in the sandbox,
  so that assertion could only pass by accident [F].

## Alternatives rejected

- **Patching upstream's source at build time** with `substituteInPlace` (the
  `menu` shape), with no fork. Five fixes across two files, several of them
  multi-line, would be a brittle patch. It would also leave no flake for NixOS
  machines without nixarchy, and no home for the docs.
- **An upstream PR only.** Upstream is a day old and has every reason to keep
  pacman for Arch remotes, and nixarchy's scan forbids pacman outright. A fork
  is needed regardless; a PR with the parts that also help Arch
  (`gliff --version`, the process names) is offered separately (§11).
- **Keeping the id `nosignal.gliff-manager`.** One id would then name two
  programs, and `nixarchy-doctor` and `omarchy plugin remove` could not tell
  them apart. The fork convention is a `nixarchy.` id (podman, menu, pkg).
- **Installed only, not enabled.** Rejected by the intent's answer: the
  request was a default plugin, and defaults are on once.
- **Stubbing `ps` and `pgrep` in the test.** A stub that answers for any
  arguments lets the old `ps -C Hyprland` pass, so the break proof would only
  test the stub [C]. Real processes with the real names fail for the real
  reason.
- **Leaving out the Home Manager module** (podman has none) [F]. The request
  was a flake for nixarchy *and other NixOS*. The module is about 30 lines and
  steps aside on nixarchy.
- **A `packages` list on the nixarchy default.** It would duplicate the
  `omarchy` runtime dependencies, and every default tool goes in at
  `lowPrio` (#809) anyway.

## Coexistence

- **Merged environments:** none. The default adds no package (no `packages`),
  so nothing enters `home.packages` or `environment.systemPackages`. No §14
  fixture applies, because nothing can collide in a `buildEnv`.
- **The plugin directory:** `~/.config/omarchy/plugins/nixarchy.gliff-manager`
  is written by nixarchy's reconciling activation. The fork's own module, used
  on a nixarchy machine, steps aside with a warning instead of writing the
  same path.
- **A user's own copy of upstream** (`nosignal.gliff-manager`) keeps its own
  directory and id. Both widgets read the same `~/.config/gliff-manager/`, and
  both can add the same managed `Include` line to `~/.ssh/config`; the line
  carries a marker, so a second add is a no-op. The manual says to remove
  upstream's copy.
- **A `~/.ssh/config` managed by Home Manager** (`programs.ssh`) is a link into
  the store. "Short tab names" then fails to write it and turns itself back off
  with an error, which is the plugin's own back-out. The manual says so. Nothing
  at build time can see this.

## Risks

- **A third party's code runs ssh from every desktop that has gliff.** It
  probes only machines you have listed or connected to, with `BatchMode=yes`,
  and its checks only read. Its fixes act only through a terminal you type
  into. The pin is a reviewed commit; any bump means reading the diff against
  both the fork and upstream (`docs/internals/flake.md`).
- **The process-name fixes assume nixpkgs' wrapper names** (`.gliff-wrapped`,
  `.Hyprland-wrapp`). If the wrappers change, the behaviour test does not catch
  it, because it names the processes itself; the live check on p620 does. Both
  patterns keep the plain name too, so Arch, and an unwrapped build, still
  match.
- **`gliff --version` output format.** Measured on p620: `gliff-server 0.3.1`
  [F]. A future format change shows the wrong version, not "not installed",
  because installed is `version != ""`.
- **Existing machines gain a bar widget** at their next login after a rebuild.
  It is announced, and turning it off sticks.
- **Fork drift:** `upstream.yml` opens an issue when upstream moves, so this
  fork does not drift silently the way two others have (31 and 77 commits
  behind).

## Verification

- **The fork:**
  - `nix flake check -L` passes. With each fix reverted in turn (`pacman -Q`,
    `pgrep -x gliff`, `ps -C Hyprland`), it fails, and the three failing
    outputs go into the PR (§1).
  - `omarchy plugin validate` passes on a plain copy of `result`. The
    validator refuses the store link itself (#853), so it has to be a copy.
  - CI is green on the PR.
- **Live on p620** (reversible):
  - Copy the build into `~/.config/omarchy/plugins/nixarchy.gliff-manager` and
    run `omarchy plugin enable nixarchy.gliff-manager right`.
  - `gliff-manager.sh status full`, with `olafkfreund@localhost` as a machine,
    reports `installed: true`, `gliff: "0.3.1"` from the real binaries [C],
    `session: true`, `hyprOwner: "olafkfreund"`, and "Ready".
  - After connecting, `live` lists the window, and a second connect adds a tab
    rather than opening a second window.
  - The panel opens with `omarchy-shell nixarchy.gliff-manager toggle`.
  - Afterwards, remove the copy and turn the plugin off. The real install
    comes from nixarchy.
- **nixarchy:**
  - Locally: `checks.remote-tunnel` (the new row, with a break proof),
    `checks.shot-coverage`, `readme-counts.sh`, statix, deadnix and
    `nix fmt -- --ci`.
  - In CI: `checks.options` (`gliffManagerIsADefault` in both states, plus
    Mode A), `checks.plugin` (the opt-out block) and `checks.session`, each
    confirmed from the run log.
