# Intent: quattro's new /usr references stop the edge channel publishing

## Problem

Edge's `verify` (run 39213272085: Omarchy quattro 81fd2d2 merged on main
c12f4cd) fails `checks.session` on one assertion, the guard that no shipped
command reaches into `/usr` without a recorded reason:

```
these shipped commands still reach into /usr in code: omarchy-hw-fingerprint
omarchy-install-t3code-app omarchy-remove-ai-t3-code
```

Every other check in that run passed. Until this assertion passes, the edge
channel publishes nothing (#1350).

The three commands differ:

- **`omarchy-install-t3code-app`** (new in quattro): `squashfs-root/usr/…` is
  a path inside the AppImage it has just extracted, and `/usr/bin/t3` is a
  string it compares a link target against. Neither touches the host's
  `/usr`.
- **`omarchy-remove-ai-t3-code`** (new): `/usr/bin/t3 | /usr/bin/t3-nightly`
  is a `case` pattern, also only a string comparison.
- **`omarchy-hw-fingerprint`** (changed): reads
  `/usr/share/omarchy-platform/fingerprint-readers` behind `-r`. Upstream's
  `docs/file-layout.md` says a *platform package* (omarchy-mac, on Apple
  Silicon) names non-USB readers such as Touch ID there, and that Omarchy
  itself ships none. Without the file the command falls through to its USB
  scan, unchanged.

So the guard has caught three references, and on this reading none of them
misbehaves on NixOS. That reading has to be confirmed before an exception
records it, since an exception is the guard's way of saying "checked, and
harmless".

## Proposed outcome

- `checks.session` passes on edge with quattro 81fd2d2, and the edge channel
  publishes again.
- Each of the three commands has a named exception in `tests/session.nix`'s
  `/usr` list, with a reason someone can check, in the style of the entries
  already there. That holds unless investigation shows one of them actually
  does something wrong on NixOS, in which case that one is fixed rather than
  excused.
- The guard still fails for the next unexplained `/usr` reference.

## Affected users and systems

- `tests/session.nix` on `main`. The guard ignores exception names that do not
  exist, so this lands on `main` (where stable 4.0.5 has none of the three
  commands) and reaches edge through edge's next merge of `main`. Nothing is
  carried on the `edge` branch.
- Edge-channel users, who currently get no edge updates.
- No stable user sees a change.

## Constraints

- §1: the exception list's own control. Removing one of the new entries must
  turn the guard red, naming that command.
- The guard's existing comment requires the filtering to stay in Python, not
  in shell (an earlier shell version matched nothing).
- No patching of upstream scripts when the reference is harmless: a patch
  is carried at every bump (CLAUDE.md §11).
- The proof needs a session VM on quattro. That is the edge `verify` itself,
  re-run from `edge-candidate`, or a local run when CI is idle (§6).

## Open questions

- **`omarchy-hw-fingerprint`: exception, or point it at a NixOS path?**
  nixarchy is x86_64 and ships no platform package, so the file can never
  exist and the USB scan is the whole of detection. That is what Omarchy does
  on any non-Mac machine. My proposal is an exception. Pointing it elsewhere
  would mean inventing a platform file nothing writes.
- **Does `omarchy-install-t3code-app` work on NixOS at all?** It installs an
  AppImage, which needs FUSE or `--appimage-extract` plus a dynamic loader.
  That is a separate question from the guard. If it does not work, the menu
  row should be dimmed with a reason, as #1320 did for others. I propose to
  check it and file it separately if needed, not widen this task.
