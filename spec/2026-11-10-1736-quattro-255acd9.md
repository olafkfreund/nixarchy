# Spec: edge adopts quattro 255acd9 (Qt theming through qtengine, Papers for Evince)

## Design

One carry on `edge-candidate`, as #1684 did. The artifacts go to `main` on
`fix/1736-quattro-255acd9`. Every decision below holds under `main`'s v4.5.0
tag pin as well as under quattro: anything that only quattro has is derived
from the pinned tree, never hard-coded (CLAUDE.md §8, "make the line hold
under both pins").

### 1. The pin

Pin quattro's newest commit at the time of the carry, `255acd9` today. Per
§8 that means both copies in `flake.nix`, the input `url` and
`omarchyVersion`, plus `flake.lock`, then a `from_candidate=true` dispatch.

### 2. `omarchy-agent-local` (open question 3)

`pkgs/omarchy/default.nix:508` replaces upstream's `use` block with the
preflight, using `--replace-fail` against `agent-local-use.upstream.sh`.

- **`agent-local-use.upstream.sh`** becomes upstream's new block, verbatim:
  from `if [[ ${1:-} == "use" ]]; then` to its `fi`, with the `--detach`
  branch inside. Upstream's `run=(omarchy-local-ai "$@")` above the block
  and `exec "${run[@]}"` below it stay upstream's.
- **`agent-local-preflight.sh`** keeps its checks: podman, memlock, and the
  NVIDIA CDI spec. They run on every `use`, whatever position `--detach` has
  in the arguments.
- **When a check fails in a detached run** (`" $* "` contains
  `" --detach "`, upstream's own test), `agent_local_fail` does not exit.
  It sets
  `run=(omarchy-launch-floating-terminal-with-presentation "omarchy-agent-local <args without --detach>")`
  and lets upstream's `exec` run it. The re-run in the terminal repeats the
  preflight and shows the message where the user can read it. That is
  upstream's own pattern, a terminal to resolve what a background setup
  cannot.
- **A passing detached run** leaves `run` untouched: no terminal, exactly
  upstream.
- **A failing interactive run** prints and exits 1, as today.

### 3. Qt theming through qtengine (open question 1)

Upstream's `default/hypr/envs.lua` sets `QT_QPA_PLATFORMTHEME=qtengine`, and
it reaches the session from the pinned tree with nothing done here. What
nixarchy must add is the plugin:

- **`modules/nixos.nix`**, under `programs.nixarchy.enable` (Mode A):
  - `pkgs.qtengine` goes in `environment.systemPackages`;
  - `environment.profileRelativeSessionVariables.QT_PLUGIN_PATH` gains
    `/lib/qt-6/plugins`, so `/run/current-system/sw/lib/qt-6/plugins` holds
    `platformthemes/libqt6engine-plugin.so`.
- **Why that reaches wrapped apps:** `wrapQtAppsHook` *prefixes*
  `QT_PLUGIN_PATH` and keeps the caller's value, so a session-wide entry
  reaches them. The NixOS `qt` module reaches wrapped apps the same way.
  This is the claim the measurement tests.
- **ABI:** qtengine and the apps it themes come from the same nixpkgs, so the
  same qtbase. An app built against another Qt fails to load the plugin and
  is left unthemed. That matches the gtk3 behaviour for such an app today.
- **Packages and seeding:**
  - `data/omarchy-packages.nix`: `qtengine = { nix = "qtengine"; }`.
  - `omarchy-theme-set-qt` ships as upstream wrote it; its `jq` and
    `realpath` join the runtime list in `pkgs/omarchy/default.nix`, which a
    missing command would otherwise read as a wrong answer.
  - `config/qtengine/config.json` is seeded by the existing copy-once seed
    (`modules/home.nix:469`, `--no-preserve=mode`), so it arrives writable.
    No new code.
- **Migration `1792902457`:** `ported`, `run = "edited"`. Remove
  `omarchy-pkg-add qtengine`, because nixpkgs provides it. Keep the seed,
  which skips an existing file and installs mode 644, and keep
  `omarchy-theme-refresh`. This reaches machines installed before the pin.
- **Fallback, if the measurement in Verification cannot pass:**
  - patch `envs.lua` back to `gtk3`;
  - `qtengine = { skip = "<measured reason>"; }`;
  - migration `1792902457` becomes `not-needed` with the same reason;
  - drop the `modules/nixos.nix` lines.

  That is a plan deviation recorded in the same commit.

### 4. Papers for Evince (open question 2)

- **Packages:** `data/omarchy-packages.nix` gains

  that installs Evince today. Its desktop file therefore reaches
  `XDG_DATA_DIRS`. The `evince` row is removed, since upstream's list no
  longer names it.
- **The default association** comes from upstream's
  `default/applications/mimeapps.list` and the existing
  `hyprland-mimeapps.list` seed (`modules/home.nix:2377`), with nothing
  added here.
- **Migration `1794165002`:** `ported`, `run = "edited"`
  (`pkgs/omarchy/user-migrations.nix`).
  - Remove `omarchy-pkg-add papers` and `omarchy-pkg-drop evince`.
  - Replace the guard and the `sed` with: rewrite only when
    `~/.config/mimeapps.list` is a regular file (`[[ -f $f && ! -L $f && -w $f ]]`),

  - A symlink is left alone, and the script prints that it still names Evince
    (the log `omarchy-migrate-user` keeps). The marker is still written, so it
    does not retry for ever on a file the user manages.

### Coexistence (§14)

A user's own NixOS `qt` module also sets `QT_PLUGIN_PATH` and
`QT_QPA_PLATFORMTHEME`.

- **`QT_PLUGIN_PATH`** is a list in `profileRelativeSessionVariables`, so both
  entries merge.
- **`QT_QPA_PLATFORMTHEME`:** inside the Omarchy session, Hyprland's
  `envs.lua` decides it, today `gtk3` and after this `qtengine`. That is
  unchanged precedence. Outside the session, the user's setting stands.

A fixture in `tests/coexistence/fixtures.nix` sets `qt.enable` with
`platformTheme = "kde"` beside nixarchy, and asserts that the merged
`QT_PLUGIN_PATH` holds both nixarchy's entry and the qt module's.

## Alternatives rejected

- **Keep `gtk3` without measuring.** That diverges from upstream on the look
  of every Qt app, and needs a patch carried at every bump. It stays only as
  the measured fallback.
- **`qt.enable = true; qt.platformTheme = …` from nixarchy.** The NixOS `qt`
  module owns `QT_QPA_PLATFORMTHEME` session-wide and has no `qtengine`
  value. Setting it would collide with a user's own `qt` settings, which §14
  forbids, for a value Hyprland already sets in-session.
- **Wrap each Qt app with the plugin.** It is unbounded, and misses the apps
  users install themselves.
- **Run upstream's Papers migration verbatim.** `sed --follow-symlinks`
  fails on a store link and edits a dotfiles checkout through a link
  (intent, Constraints).
- **Drop the agent-local preflight in favour of upstream's terminal
  install.** `omarchy-pkg-add` installs nothing on NixOS, so upstream's
  terminal would end in a refusal and the real cause would go unexplained.

## Risks

- **Qt apps on every edge desktop change look.**
  - A Qt app that loads the plugin and then mis-renders can't be measured
    here; that's a human check on p620.
  - On every edge host, the `omarchy-theme-set-qt` write makes running Qt
    apps reload their icons on a theme switch.
- **`profileRelativeSessionVariables` reaches the session through PAM and
  the profile.** A Hyprland started by uwsm imports the user manager's
  environment. If the variable is not there, the measurement fails, and the
  fix is to export it in the session's environment as the other nixarchy
  variables are. The measurement exists to find this.
- **A user whose `mimeapps.list` is a symlink** keeps Evince associations
  that point at an app that is no longer installed. The migration's log line
  says so. Opening a PDF then falls back to the next handler.
- **Edge only.** `main` and stable are unaffected until edge merges.

## Verification

Every check the carry can reach, by §6 tier, locally on the candidate tree
before pushing. Then the edge run.

- **Cheap tier:**
  - `checks.omarchy-package-ledger`, `bin-ledger`, `user-migrations-ledger`,
    `etc-overlay` and `mise-free`;
  - `checks.user-migrations` gains two fixtures for `1794165002`: a regular
    `mimeapps.list`, rewritten with only the Evince lines changed; and a
    symlinked one, left byte for byte and still a link (#1304: a link to
    identical content, so the `-L` guard can fail). §1 break: drop the `-L`
    guard, and the symlink fixture goes red;

    `podman` and `systemctl`. A failing detached `use` must exec the

    `--detach`. A passing detached run must reach `omarchy-local-ai`, and a
    failing interactive run must exit 1. §1 break: restore the old
    `exit 1`, and the detached case goes red.
- **Package tier:** the `omarchy` edge package builds, with the patch, the
  edited migrations and the runtime list.
- **Session, the qtengine measurement:** `checks.session` runs `qtdiag`
  from `qt6.qttools`, a wrapped nixpkgs Qt 6 binary, in the logged-in
  session.
  - It asserts that the platform theme is `qtengine`, and that the reported
    palette's window colour equals the theme's `qtengine.colors` value.
  - §1 break: drop the `QT_PLUGIN_PATH` line, and the theme reads as the
    generic one.
  - The assertion is guarded on `config/qtengine` existing in the pinned
    tree, so `main`'s v4.5.0 session stays green.
  - `session` does not run locally (`tests/AGENTS.md`), so its first run is
    edge CI on the candidate.
- **Coexistence:** `checks.coexistence` with the new fixture.
- **By hand on p620 after edge deploys:**
  - open a Qt app and switch theme;
  - open a PDF;
  - `omarchy-agent-local use` from the agents panel with podman missing
    shows the terminal.
