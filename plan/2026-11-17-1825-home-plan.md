# Plan: `nixarchy-apply --home-plan` (#1825)

Self-contained. Spec: `spec/2026-11-17-1825-home-plan.md` (approved). Anchors
are by function name in `modules/apps.nix` (the `text` of the
`nixarchy-apply` writeShellApplication; `$`-expansions there are written
`''${...}` only where Nix would interpolate, and `${homeTemplate}` IS a Nix
interpolation). Worktree `/mnt/data/vmtest/wt-1825`, branch
`fix/1825-1824-home-plan-insecure`.

**Handoff rules for every step.** The coder must not commit, stage, deploy,
restart, build, format or print the environment, and edits only the files the
step names. The lead runs `nix fmt`, reads `git diff --stat`, runs statix and
deadnix, `git add`s, runs the step's check, and commits one step per commit
(full-sentence subject, no conventional prefix, step named in the body).

## Approved decisions (from the spec)

1. **Contract.** `nixarchy-apply --home-plan [--json]`, nothing else on the
   line (any other argument: usage, exit 2, decided by a pre-scan of `"$@"`
   before the parse loop). Success exit 0, one stdout line for every decision
   including `refuse`. JSON, key order exactly:
   `{"version":1,"owner":S|null,"caller":S,"state":S,"action":S,"renderUser":S|null,"message":S|null}`.
   `owner` null when empty; `state` is `seed|edited|absent`; `action` is
   `claim|copy|keep|refuse`; `renderUser` = caller for claim/copy, owner for
   keep (null if none), null for refuse; `message` = apply's refusal text
   exactly as printed (with `nixarchy-apply: ` prefix, no newline) for refuse,
   else null. Without `--json`: one line
   `home owner: <o|none>; caller: <c>; home.nix: <state>; apply would: <action>`.
   Error: exit 1, `{"version":1,"error":"<text>"}` on stdout under `--json`,
   same text on stderr (stderr only without `--json`); `<text>` is what apply
   prints on stderr for that failure, trailing newline stripped. Never
   `keep` on error.
2. **Read-only.** No lock, no `mkdir` but a private `mktemp -d` (existing
   `trap 'rm -rf "$pinned"' EXIT`), nothing under `$base`,
   `~/.config/nixarchy`, `$applied`, `$XDG_STATE_HOME`. No `apps.nix`
   needed; the flake dir must exist. The branch guard is skipped
   (`[ -n "$detach" ] || [ -n "$homeplan" ] || nixarchy-branch-guard "$flake"`).
3. **One decision path.** Move the definitions `select_home_src snapshot_home
   classify_home valid_user read_owner home_decide` (and the `srcdir=`
   assignment) from after the lock to just after `dest=...`. Definitions only;
   apply's calls keep their place and order under its lock. Add
   `home_refusal_text <owner> <user>` (apply's refusal text, no newline),
   `home_decision <user>` (needs `owner`, `home_state`; `valid_user "$user"`
   with error `nixarchy-apply: invalid user name: <user>`; `home_decide`; sets
   `home_action`, `render_user`, `home_message`; returns 1 on any failure) and
   a `no_flake_msg` variable (two lines joined by one newline, no indentation
   on the second) used by apply's existing flake-missing branch and by
   `--home-plan`. Apply's non-release arm calls `home_decision`, prints
   `$home_message` with `echo >&2` on refuse. TODAY `render_user=""` and the
   `case "$home_action"` sit AFTER the `fi` of the release/else block: move
   `render_user=""` ABOVE `if [ -n "$release_home" ]` (so the release path,
   which never calls `home_decision`, still has it set under `set -u`), and
   delete the post-`fi` `case` (`home_decision` now sets `render_user`). Keep
   apply's line
   `if [ -n "$render_user" ] && ! valid_user "$render_user"; then` verbatim
   (tests grep it).
4. **Hardenings (apply too).** `classify_home`: cmp exit 0 seed, 1 edited,
   above 1 error (`nixarchy-apply: cannot compare home.nix with the seed`,
   return 1); a non-empty `home_snap` that does not exist is that error, not
   `absent`; apply's call becomes `classify_home ${homeTemplate} || exit 1`.
   `home_decision` checks the caller on every decision; `--release-home` is
   exempt. `read_owner`: a `grep -c` exit above 1 is
   `nixarchy-apply: cannot read <dest>`, return 1 (no `|| true` around it;
   exit 1 with output `0` stays a normal zero count). Form, for BOTH greps:
   `rc=0; candidates=$(grep -cE ... "$dest") || rc=$?` then `[ "$rc" -le 1 ]
   || { echo "nixarchy-apply: cannot read $dest" >&2; return 1; }`, grep's own
   stderr to `/dev/null` so the error text is only ours.
5. **Plan branch** after `dest=` and the definitions, before `[ -f "$file" ]`:
   `homeplan=""` initialised with the other flags (`set -u`), flake check,
   `pinned=$(mktemp -d 2>&1) || plan_fail "$pinned"` (on failure `$pinned`
   holds mktemp's own message), THEN `trap 'rm -rf "$pinned"' EXIT` (only
   after success; reuse the existing trap line text), `user=$(id -un 2>&1) ||
   plan_fail "$user"`, then
   `{ snapshot_home && classify_home ${homeTemplate} && read_owner &&
   home_decision "$user"; } 2>"$pinned/err" || plan_fail "$(cat "$pinned/err")"`
   (empty text gets a generic message), then print with `jq -cn --arg` (strings only; `version` is the literal
   number `1` in the jq program, not an `--arg`). Bare `--json` without
   `--status`/`--home-plan` is not touched.
   `plan_fail` prints the JSON object when `--json`, the text on stderr, exit 1.
6. Add `nixarchy-apply --home-plan [--json]` to the usage, turned into a
   function `usage()` that the `*)` arm calls.
