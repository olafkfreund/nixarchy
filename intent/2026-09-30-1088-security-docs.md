# Intent: Correct Docker and shell PATH guidance

## Problem

The security manual describes the default Docker daemon as rootful and says published container ports bypass the firewall through Docker's iptables rules. That does not describe the module: `modules/nixos.nix` defaults the rootful daemon off and enables rootless Docker instead. The development tools page already calls the daemon rootless; its "enabled by default" wording is correct, so the issue's claim that this page makes the same rootful assertion is overstated.

The root agent rules, `pkgs/AGENTS.md`, `tests/AGENTS.md`, and nearby code comments call `writeShellApplication`'s PATH strict. In the pinned nixpkgs, `inheritPath` defaults to `true`, so `runtimeInputs` take precedence while commands from the caller's PATH remain available. The stated guarantee that an undeclared command always fails is false. This matters here: doctor calls `xdg-settings` without `xdg-utils` in its runtime inputs, and `nixarchy-apply` calls `git` and `sed` without declaring `git` and `gnused`.

## Proposed outcome

The manuals describe the actual rootless Docker default and avoid claims about rootful port publishing for that default. The agent rules and relevant code comments accurately explain PATH precedence and the environment-dependent risk of undeclared commands. The two scripts declare the commands they use so their behavior does not depend on the caller's PATH.

## Affected users and systems

Readers deciding how to expose Docker containers; contributors writing shell wrappers and checks; users of `nixarchy-doctor` and `nixarchy-apply` on any host that enables nixarchy.

## Constraints

- Preserve rootless Docker as the default and the existing `writeShellApplication` PATH behavior; this task corrects guidance and missing runtime inputs.
- Check the actual rootless networking behavior before replacing the security page's firewall advice. Do not carry forward the rootful iptables claim by inference.
- Keep the existing PATH-stub warning where it remains true: declared runtime inputs precede caller-provided stubs.
- Do not edit CI workflows or the concurrent criticals PR's files. Any new check must be shown failing when its target defect is restored.

## Open questions

- **Owner decision:** correct every "strict PATH" claim, including agent rules and code comments. Preserve the accurate point that declared runtime inputs precede caller-provided commands.
