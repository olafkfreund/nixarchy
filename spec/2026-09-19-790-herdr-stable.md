# Spec: Fallback only for a missing Herdr

Owner approval: user explicitly authorized continued issue work and all planning/implementation without further approval on 2026-09-19.

## Design

In modules/home.nix use consumer pkgs.herdr when present; otherwise select herdr from the already pinned nixpkgs legacyPackages for the host system. This is an explicit narrow exception to the same-package-set preference: stable has no native Herdr, and only the standalone CLI is installed, not an alternate dependency set into the profile. jq and iproute2 remain consumer packages. No new nixpkgs import or lock change.

The pinned recipe cannot simply be callPackaged on stable: it requires installAgentSkills, also absent there. Copying recipes/hooks creates maintenance work without benefit here. Disabling the widget would violate the approved default behavior.

## Risks

Stable uses Herdr's pinned runtime closure from unstable; consumer-provided Herdr must remain preferred. This fixes evaluation, not the separately tracked upstream deletion behavior.

## Verification

Existing stable-eval must fail before and pass after. Extend it to assert the real stable user's home.packages contains Herdr so silently disabling the plugin cannot pass. Check the exact package-selection expression with missing and present consumer packages, including a throwing fallback when a consumer package exists. No deployment.
