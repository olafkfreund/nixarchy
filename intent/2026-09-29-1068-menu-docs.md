# Intent: README and site describe the menu and defaults that ship

## Problem

Since #1054, Super+Space opens **nixarchy-menu**, a palette, on every machine.
The pages a newcomer reads first still describe the stock Omarchy menu:

- **`docs/manual/getting-started.md:150-153`** says "`Super + Space` opens
  the menu — the same one upstream has, because it *is* upstream's". That is
  now false. The pictures beneath it (`img/desktop/menu.jpg` and
  `install.jpg`, from 2026-08-31) show the stock menu and its Install submenu.
- **The README's screenshot row** (`docs/screenshots/01-menu-root.jpg` and
  `02-install.jpg`, from 2026-08-25) shows the stock menu too.
- **The README's "What works" table** never names nixarchy-menu. It has
  rows for pkg, GitLab, GitHub, herdr, the rebuild panel, ai-mirror and Voice,
  and none for the menu, Hyprforge, the Plugin Browser or runtime themes.
- **`docs/index.md`'s feature bullets** list what the panels let you do. They
  omit the palette, Hyprforge's Hyprland settings and runtime themes, although
  the count beneath them ("Fifteen ship by default") includes all three.

`docs/manual/plugins.md`, `llms.txt`, the counts and `docs/internals/` were
updated with each PR and are current. The Discussions announcement is posted
(#1067).

## Proposed outcome

- A newcomer reading the README, the front page or Getting started learns that
  Super+Space opens nixarchy-menu, and what it can do. They see pictures of
  the menu their machine will actually show, and learn how to get the stock
  menu back.
- The README table names every default plugin a user can open.

## Affected users and systems

- `README.md`, `docs/index.md`, `docs/manual/getting-started.md`.
- The menu pictures: `docs/screenshots/01-menu-root.jpg`, `02-install.jpg`
  and `docs/img/desktop/menu.jpg`, `install.jpg`. The `03`–`06` Install
  submenus are only in `docs/screenshots/` and linked from nowhere, so check
  that before touching them.
- Probably `docs/capture-screenshots.sh`, which drives the stock menu by name
  (`omarchy.menu` toggle, `namespace: omarchy-menu`). It also pipes
  `hyprctl layers | grep -q` under `set -euo pipefail`, the #1058 trap, in a
  file the #1060 guard does not scan (`docs/`).

## Constraints

- **The house style is in `docs/AGENTS.md`:** a whole desktop at 16:10, shown
  big, and panels showing real data. Its "Driving the menu in a recording"
  section records how nixarchy-menu behaves under automation: close with
  Escape, never with a second `toggle`, and row order changes with use.
- **No claim the pictures do not show.** Each caption says what is in the
  frame.
- **Readme-counts and the plugin-row guards must stay green.** They key on
  exact sentences.

## Open questions

1. **How the new menu pictures are captured.** `docs/capture-screenshots.sh`
   runs inside `nix run .#vm` with `-display gtk,gl=on`, which **opens a VM
   window on your desktop** for the duration of the capture. The options:
   - (a) run it in the VM, with the window on your screen for a few minutes;
   - (b) you capture two frames on a real desktop (root palette, and
     Install scoped);
   - (c) reuse frames from the next screencast recording.

   Default proposal: (a), and the text changes do not wait for the pictures.
   They can land first, with the pictures in a second commit on the same PR.
2. **The getting-started paragraph's point.** It argued "nothing about the
   desktop was reimplemented". The honest replacement: Super+Space opens
   nixarchy-menu, a palette over the same Omarchy menu, which is still inside
   it under "Omarchy Menu", and `defaultPlugins.menu = false` restores the
   stock one. Default proposal: exactly that.
