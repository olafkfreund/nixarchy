# Spec: fix the second round of the 2026-10-15 review

## Design

**apps.nix**
1. `nixarchy-search` Flathub branch (`:3048`): delete the `grep -qE "^flatpak\t…"`
   pre-test. The `awk -F'\t'` exact match right after it is the real test.
2. `nixarchy-app-disable` (`:1600`): validate the ID with the same
   `*[!a-z0-9_-]*` case that `app-enable` uses (`:1547`).
3. Selection rewrites (`:1387`, `:1563`): `mktemp` beside the target, then
   `mv` over it (an atomic rename on the same filesystem), keeping the
   file's mode.
4. "Already enabled" (`:1470`, `:1569`): match `enable = true` only. A line
   set to `= false` is flipped to true.
5. Plausible items: `--add` exits non-zero when it refused a file;
   `pkg-add` exits non-zero when every name was redirected; apply
   refuses to overwrite an edited package draft; one `flock` covers
   copy, stage and switch; flake copies go through temp-and-rename. Each is
   reproduced in the new check first, and anything that does not reproduce
   is recorded instead.

**nixos.nix**
6. Avahi `ExecStartPre` (`:1826`): `lib.mkIf config.services.avahi.enable`.
7. Delete `virtualisation.docker.enable = lib.mkDefault false;` (`:1714`).
   nixpkgs already defaults it to false, and the rootless gate reads the
   merged value. Update the snippet in `modules/AGENTS.md`.
8. `cfg.user or "omarchy"` (`:1073`) becomes
   `if cfg.user != null then cfg.user else "omarchy"`.
9. The four Omarchy user units (`:1882-1966`): `ConditionEnvironment =
   "HYPRLAND_INSTANCE_SIGNATURE"` in place of `WAYLAND_DISPLAY`, plus
   `ConditionUser = "!@system"`. Measured 2026-10-15 on a live Omarchy
   session: the variable is in the user manager's environment, exported by
   the same uwsm step that exports `WAYLAND_DISPLAY`. GNOME has no such
   variable. The fcitx5 double-start is **not** reproduced (no fcitx5
   autostart file is installed), so it is left alone and recorded.
10. Flake safe.directory include (`:1313`): write it with
    `git config --file`, which quotes the value, instead of `echo`.

**home.nix**
11. `mergeJson` and `nixarchyDefaultAgent`: `mktemp` beside the target and
    `chmod --reference` when the target exists, so the `mv` is an atomic
    rename that keeps the mode.
12. Under `DRY_RUN`, nothing is written: the plugin staging file and the
    agent temp file follow `run`.
13. Default-plugins hook: if `omarchy-plugin-list --json` fails or prints
    something other than JSON, stop and retry at the next login. The
    once-markers make that safe. Today it falls back to `[]`.

## Alternatives rejected

- #9: `DESKTOP_SESSION=omarchy` is more specific but greeter-dependent, and
  it would also drop the units from a user's own Hyprland, where they work.
- #13: retrying the plugin list in a loop. The next login already retries.

## Risks

- #9 is the one that can hurt. If the variable were missing from the
  environment, the sleep lock would stop running in Omarchy. It was measured
  present, and `checks.session` (CI) boots the session and is where a
  regression would show.
- #4: a user who wrote `= false` deliberately and then picks the app from
  the menu gets `true`. That is what the pick asks for.

## Verification

- A new `checks.app-selection` (a runCommand over `testLib.vmPackage`
  scripts) holds 1–5.
- `tests/options.nix` cases hold 6–10: avahi off means no avahi-daemon
  unit; Docker evaluates beside a profile's `mkDefault true`; the theme
  engine user; the four units' conditions.
- 11–13: the activation scripts, or the hook text taken from the VM
  configuration, run in a runCommand.
- Each new case is seen red with its fix reverted.
