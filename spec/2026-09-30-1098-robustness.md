# Spec: Make the remaining robustness paths predictable

Refs #1098 (Robustness only).

## Design

1. In `modules/services/syncthing.nix:75-77`, derive both `dataDir` and `configDir` from the selected user's `config.users.users.${svc.user}.home`, not `/home/${svc.user}`. Keep `mkDefault` on these scalar upstream options. A selected user without a resolved home is an evaluation error with an actionable assertion, not a silent fallback to `/home`.
2. In `modules/services/open-webui.nix:40-51`, form the Ollama URL from the existing wildcard-to-loopback selection, then bracket a specific IPv6 literal exactly once. Plain IPv4 and hostnames remain unchanged; already bracketed IPv6 remains bracketed once. Keep the telemetry defaults and existing `mkIf` gate untouched.
3. In `modules/flatpaks.nix:53-57`, make the scalar `services.flatpak.enable` a `lib.mkDefault true`. Its remotes and packages remain plain list assignments, per `modules/services/default.nix:18-25`. An explicit user `false` wins even when a Flatpak is selected; nixarchy does not silently force the daemon on.
4. In `modules/home.nix:213-256,1696-1769`, make the two shared merge helpers and both local-model provider actions respect Home Manager's `DRY_RUN` variable around **every** direct file write, including initial `{}` creation, TOML append, and temporary files. On dry run, print the destination and the action that would have happened, then return without changing user files. Keep merge errors non-fatal on a live activation, with their existing diagnostic. Existing `run` calls stay where they protect directory creation and final moves. Home Manager's pinned `lib/bash/home-manager.sh` defines `run` to echo rather than execute when `DRY_RUN` is set; redirection outside `run` is the current escape hatch that causes the bug.
5. In `pkgs/omarchy/nix-bin/nixarchy-channel:194-205`, insert a Home Manager URL only beside the `inputs.nixpkgs.follows` belonging to the `nixarchy = { ... };` input in the shipped `installer/template/flake.nix:62-66` shape. Other inputs' identical follows must remain byte-for-byte unchanged. If that block or its follows is absent or ambiguous, refuse the rewrite and restore the existing `.pre-channel` backup rather than guess. Preserve the current release pairing and relock behavior.
6. In `pkgs/omarchy/default.nix:659-675`, make the patched `omarchy-version-channel` exit nonzero when `nixos-version` fails or emits no version, before `cut` can hide the failure. On success, print the version once and skip the pacman lookup as now.
7. In `pkgs/skills-relink.nix:61-64`, check the destination before linking an owned skill: replace an existing symlink as before, but report and leave a real file or directory alone. This prevents `ln -sfn` from nesting a link within a user's real skill directory. Retain the guarded-input behavior at lines 66-79 and the four-clean/three-link split.
8. In `modules/apps.nix:3520-26`, forward the caller's effective `XDG_STATE_HOME` into the detached `nixarchy-rebuild` user unit, matching the already forwarded config home. The resumed apply reads `applied` at line 3563 from the same location the caller selected.
9. In `pkgs/rebuild-panel/RebuildState.qml:125-140`, route follow, copy, and terminal log actions through `nixarchy-apply --log` (`--follow` where appropriate). That command already chooses the current `InvocationID` or a bounded 200-line fallback at `modules/apps.nix:3469-3488`; the panel must not independently read the unit's whole journal. Preserve the existing UI actions and `wl-copy` behavior.
10. In `modules/apps.nix:3420-24`, replace `eval` of `systemctl show` text with a key-based read of its four properties. Missing properties continue to mean no run; an unexpected value is data, never shell code. The query still comes from one `systemctl show` call, avoiding inconsistent reads across a unit transition.
11. In `modules/apps.nix:3451-61,3825-35,3904-10`, normalise `ExecMainStatus` to a decimal integer before either JSON status emitter uses it. An empty or malformed property is represented by numeric `0` when idle/running and by a numeric failure sentinel when failed; neither emitter may output a string, boolean, or syntactically invalid JSON `exit`. Preserve the existing state mapping and invocation/timestamp rules.

## Alternatives rejected

- Keep `/home/<user>` as a fallback for Syncthing: it makes a nonstandard home look configured while writing data in the wrong place.
- Use `mkDefault` for Flatpak remotes or packages: those are lists, and module-priority filtering could discard nixarchy's contribution when a user adds another entry.
- Wrap an `echo ... > file` or `cat ... >> file` in `run`: shell redirection happens before the `run` helper decides whether to execute, so a dry run would still write.
- Add a second log-scoping algorithm in QML: `nixarchy-apply --log` already owns the invocation rule and bounded fallback.
- Treat systemd property text as shell source or trust `jq --argjson` to enforce a numeric type: it checks JSON syntax, not that `exit` is a number.
- Include the VM-running lock item, installer validation, CI hygiene, stale scripts, or stale docs: they are separate work, and the lock item is blocked by the criticals PR and #1085.

## Risks

- A Syncthing account without a declared home will now fail evaluation; that is preferable to syncing into a guessed directory. Existing users with ordinary homes retain the same path.
- A user who explicitly disabled `services.flatpak.enable` can still select packages in nixarchy's catalogue; the daemon remains disabled by their choice, so those packages will not apply until they enable it.
- Channel switching edits a user-owned flake. A reshaped but valid flake may be refused; keep the `.pre-channel` recovery copy and never rewrite other input blocks.
- Home Manager activation must stay non-fatal on malformed JSON or an unwritable user file. The dry-run branch must not create even a temporary file in the user's tree.
- Log routing through `nixarchy-apply --log` depends on its invocation discovery; no invocation uses the existing bounded fallback. The panel's full-log action now means this run or that fallback, not unbounded unit history.
- `ExecMainStatus` is typed numeric on real systemd; malformed values are a resilience case and must be tested with a stub, without changing the result for valid systemd output.
