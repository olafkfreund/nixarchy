# Plan: stable moves to Omarchy v4.5.0-rc1, for the owner's machine and the users who want 4.5 now

## Decisions (approved intent and spec)

- **`main` carries Omarchy v4.5.0-rc1, pinned to the tag (03ff1eff).**
  `release` is untouched by the RC, and opt-in users follow `main`, a
  bare `github:olafkfreund/nixarchy` input.
- **No RC tag.** Any `v*` tag fast-forwards `release` (`README.md:750`,
  `release.yml:552-576`), so `release.yml`, its tag guard and
  `release-candidate.sh` stay unchanged.
- **v4.0.6-1 is cut first, on a53f1189.** This releases Omarchy 4.0.6 to
  every installed machine; the owner approved that with the spec.
- **Edge's carries come in through a real merge of `origin/edge`.**
  Edge's sha pin, its edge version and its rev-pin `review-pins`
  expectation stay out. The `edge-*` branch of the ISO label stays.
- **The nightly bump follows RCs and never goes backwards.** A new
  script, `.github/scripts/omarchy-newest.sh`, compares with `sort -V`
  after `-`→`~`. A new `checks.omarchy-newest` covers the six spec cases.
- **ISO label:** `lib.toUpper (lib.replaceStrings [ "." "-" ] [ "_" "_" ] version)`.
- **Docs:** one paragraph in `docs/manual/omarchy-channels.md` and one
  sentence in the README. A Discussions post after the merge.

## Repo traps (every step)

- `git add` new files before evaluating (§5). Installer checks need a
  committed tree, so commit before building them.
- `nix fmt`, then `git diff --stat`, after any `.nix` edit. A hook may
  reformat (§5).
- Cheap builds go one at a time, under
  `flock /mnt/data/vmtest/codex-build.lock`, by drvPath. `.#omarchy`
  builds only when the 1-minute load is below 12. Never `checks.options`
  or a VM check locally.
- In Nix indented strings, write files with `printf '%s\n'`, not a
  heredoc.
- A plain `sort -V` ranks `4.5.0` before `4.5.0-rc1`. Never compare
  without the `~` mapping.
- No skip-CI marker text in any commit or PR body (§8).

  - picks the newest with `sort -V` over `${t/-/\~}`;
  - prints `latest=<tag>`, `current=<current>` and `changed=true|false`;

    failures).

## Rollback

- **Main:** revert the merge PR. Main is back on 4.0.6, and the next
  edge run re-carries edge's delta.
- **Users:** pin `github:olafkfreund/nixarchy/release` or `/v4.0.6-1`.
  If already switched, roll the generation back first.
- **v4.0.6-1:** a release, not reverted. A later release supersedes it.

## Deviations during implementation

- **C1: no red exists for a stale `omarchyVersion`.** The two-copy check
  both reviews cited is in `omarchy.yml`'s bump step (:87-102), which runs
  only on an automated bump; no flake check compares the two copies
  (`version-label.nix` compares revs, `omarchy-version-label` compares the
  package to `omarchyVersion`). A hand pin with a stale version builds as
  `omarchy-4.0.6` on 4.5 code. Recorded as a gap, not fixed here: the
  green proof is `nix eval .#packages.x86_64-linux.omarchy.version` =
  `4.5.0-rc1`, `.#omarchy` building with every `--replace-fail` matching the
  rc1 tree, and `review-pins` green on the tag form.
- **C2: a malformed tag in the release list is skipped, not fatal.** The
  plan said `[v5$(id)]` exits non-zero; the script skips it and answers
  from the valid tags, so one odd upstream tag cannot stop every bump. The
  #1268 property holds: a skipped tag never reaches `GITHUB_OUTPUT`, and an
  invalid `current` still exits 1 (an eighth case). Red: the comparison
  replaced by "take upstream's newest" (today's `!=` behaviour) gives
  `rc1-with-older-release: … latest=v4.0.6 … changed=true`.
- **L3: the full list found one red, ours.** `tests/omarchy-newest.nix:34`
  piped into `grep -q` (`checks.grep-q-pipefail`: "NEW: a pipe into grep -q
  that nobody has reviewed"). Rewritten as a here-string, same comparison;
  `omarchy-newest` and `grep-q-pipefail` green, the other 146 already green.
- **L4: CI found the skill-set assertion** (`build.yml:981`, PR-only, so edge
  never ran it): `unexpected skill set: … omarchy-app`. Acknowledged in the
  expected set with a pointer to #1406. Verified the string against the
  built 4.5 tree, and that the step's later checks (frontmatter names,
  Arch commands in code blocks) pass on it. Those pass for omarchy-app
  only because `makepkg`/`PKGBUILD` are not in the pattern, which is #1406.
