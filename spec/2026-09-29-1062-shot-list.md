# Spec: The shot list names every shipped plugin, and something checks it

Defaults from the intent, as approved:

- **Q1.** Write the entries and the check now. The next screencast's
  `verify-beats` proves the beats; no CI job records.
- **Q2.** Retarget the `menu` beat to nixarchy-menu.

## Design

### 1. Three plugins join the shot list (`tests/demo/screencast/shots.nix`)

- **Hyprforge**, a montage entry with `action = "plugin"`. `nixarchy-plugin
  aziz.hyprforge` opens its panel (layer namespace `hyprforge`, which the
  driver sees).
  - `expect = "Hyprforge|Windows & Gaps|Borders & Colors"`: the header and the
    first two nav titles in `Schema.js`.
  - `name = "Hyprforge — every Hyprland setting, previewed live"`.
- **omatheme (`io.github.nobledoodle.omarchroma`)**, a montage entry. It is a
  bar widget only, but unlike ai-mirror it opens: `shell.summon` sends a
  bar-widget id to `bar.summonBarWidget`, whose `open()` shows a
  `KeyboardPanel` (namespace `omarchy-keyboard-panel`), and its widget is in
  the bar (placement `right`).
  - `expect = "Omarchroma|GTK and GNOME|Dark Reader"`.
  - `name = "Runtime themes — every app, without a rebuild"`.
- **nixarchy-menu**, through the existing `menu` beat, which gains
  `id = "nixarchy.menu"`.
  - The driver ignores `id` for `action = "menu"`. The acts case falls
    through, so the field only names the plugin the beat shows.
  - The route stays `root`. Since #1054 the `omarchy.menu` alias resolves to
    nixarchy-menu, so this *is* what Super+Space opens.

### 2. The menu beat describes the menu that ships

- **`keys = [ "Down" "Return" ]` goes.** It walked the stock launcher's fixed
  row order to reach "Omarchy Menu". nixarchy-menu orders its rows by
  frecency, so the same keys would land on a different row on different
  machines.
- **The beat holds on nixarchy-menu's root palette.** Its `expect` matches
  text only this palette shows:
  `"lists what you can type|Convert Anything|Emoji Picker|Omarchy Menu"`.
  It avoids "Applications" and "Calculator", which other screens share, and
  "What would you like to do?", which the stock launcher had too.
- **The caption says what the beat now is.** For example: "Super+Space: apps,
  commands, answers — and the whole Omarchy menu".
- **The comment block** (shots.nix:135-148, which explains the stock
  launcher's route) is rewritten for nixarchy-menu. The `install` beat is
  unchanged: nixarchy-menu scopes `install` to Install's rows, and its
  `expect` (`Packages|Search|Flatpak`) still matches.

### 3. The counts the header states

- "ALL TWELVE" becomes FIFTEEN.
- The named/montage breakdown gains `nixarchy.menu` (named, via the menu
  beat), Hyprforge and omarchroma (montage): "Four plus eleven".
- The runtime arithmetic becomes `montage 11 x 2.4 = 26.4` and a total of
  **78.9** s. The cut is sped up to target, as the header already argues.
- "shown nine more times" becomes eleven, "the twelve plugins" and "all
  twelve plugins" become fifteen, and so does `shot-coverage.sh:4`'s "all
  twelve".

### 4. `screencast-prep` stops hiding two of nixarchy's own defaults

`tests/demo/screencast/default.nix:232` disables, for the take, every enabled
plugin not matching `^omarchy\.|^nixarchy\.|olafkfreund`. It exists to hide a
viewer's personal plugins. Hyprforge and omarchroma are nixarchy defaults
with third-party ids, so the take would hide them, and their beats would fail
on "is turned off". The regex gains `^aziz\.hyprforge$` and
`^io\.github\.nobledoodle\.omarchroma$`, with a comment saying why: they are
defaults with third-party ids.

### 5. The check means what it says, and runs

- **Missing direction.** `shot-coverage.sh` matches `id = "<id>"` in
  `shots.nix`, not any quoted `"<id>"`. A plugin named only in a comment no
  longer counts as shown. The stale direction already reads `id = "…"`.
- **Its own `printf "$ids" | grep -qxF` becomes `grep -qxF "$cited"
  <<<"$ids"`.** It runs under `set -euo pipefail` with a multi-line producer,
  which is the #1058 trap in the very script being wired into CI. #1060's
  audit then skips this site.
- **`checks.shot-coverage`**, in `flake.nix`: a `runCommand` that copies
  exactly `modules/home.nix` and `tests/demo/screencast/shots.nix` into a
  scratch root (no whole-tree source, so it rebuilds only when those change)
  and runs `bash ${./tests/demo/screencast/shot-coverage.sh} "$root"`.
  Seconds, no VM. `build.yml`'s generated step runs it on pull requests with
  no workflow edit (§4).
- **`tests/AGENTS.md`**: the "screencast harness is scripts, not checks"
  section is updated. Coverage is now a check; recording is still not.

## Alternatives rejected

- **Only wiring the check, leaving the list red.** It would turn every PR red
  over a list nobody can fix without a spec.
- **Give nixarchy-menu its own montage beat.** It would show the palette
  twice, since the menu beat already opens it.
- **Record now.** A real desktop run of tens of minutes, re-recorded again at
  the next scheduled screencast anyway. `verify-beats` gates the beats then.
- **Relax the prep filter to "anything in defaultPluginSet".** It is cleaner
  in principle, but the prep script has no access to the module's evaluated
  set. Two anchored ids, with a comment and the new check naming any new
  default, do the job.
- **A workflow step instead of a `checks.*` entry.** A CI-gate edit (§11) for
  something §4's generated step already runs for free.

## Risks

- **The new beats are unproven until a recording.** `verify-beats` will fail a
  take whose OCR does not find the `expect` text, which is the intended gate.
  The strings are taken verbatim from the plugins' QML.
- **Frecency could put a row off-screen.** The root `expect` alternates four
  rows plus a fixed hint line, so any one visible suffices.
- **The stricter `id = "…"` match could miss an id written as an attribute
  path.** The file's convention is `id = "…"` everywhere today.
