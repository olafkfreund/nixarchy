# Spec: Seven agents get a route that does not go through mise

Line numbers are `main` at Omarchy v4.5.0. "Script" means
`pkgs/omarchy/nix-bin/omarchy-default-agent`.

## Three things the intent did not know

Each was found while writing this, and each changes the design. The first two need
the owner (see Owner decisions).

1. **A menu click has no terminal.** `Menu.qml:171` runs a row through
   `Util.execDetached`, and `setup.default.agent.kimi` is plain
   `omarchy-default-agent kimi`. Upstream's script re-execs itself in a floating
   terminal (`omarchy-launch-floating-terminal-with-presentation omarchy-default-agent
   --install "$agent"`). Our replacement keeps the flag at :82 and dropped the re-exec,
   so its echoes go nowhere. The comment at :211, "the menu's own launcher has a
   terminal", is false. Today a decline is at least recorded. Under the approved
   no-record rule, a click on kimi would do **nothing visible at all**. The pi and omp
   rows would also run `nixarchy-pkg-add` and a prompting `nixarchy-apply` with nobody
   there. This was read in the code, not run on a desktop.
2. **The decline's text is false for two of its rows.** It prints "It is not in
   nixpkgs" for cursor-agent and muse. Evaluated at the pin, `allowUnfree = false`:
   `cursor-cli` has `mainProgram = "cursor-agent"`, and `muse-code` has
   `mainProgram = "muse"`. Both are unfree. `hermes-agent` is absent, so hermes's line
   is true.
3. **`kilocode-cli` is an alias.** It warns and names `kilo`, and `kilo` has
   `mainProgram = "kilo"`. `nixarchy-pkg-add` would write the alias into the user's
   `apps.nix`.

pi-coding-agent 1.4.0 and omp 18.14.0 are both on cache.nixos.org (narinfo 200), which
answers the intent's open point: choosing either downloads rather than compiles.
Re-checked at the newer pin on `main` (#1609, `1d060086`): 1.5.0 and 18.15.0, both 200.
`cursor-cli`, `muse-code` and `kilo` read the same, and the six declined attributes are
still absent from nixpkgs.

## Design

All of this is in the script unless it names another file.

### Routes

| Rows | Route |
|---|---|
| pi, omp | `attr_for`: `pi-coding-agent`, `omp` |
| kilo | `attr_for` now says `kilo`, not the alias |
| cursor-agent, muse | `attr_for`: `cursor-cli`, `muse-code` (owner decision 1) |
| kimi, mcode, freebuff, commandcode, ori, hermes | `elsewhere_attr_for`: `kimi-code`, `minimax-code`, `freebuff`, `command-code`, `ori`, `hermes-agent` |
| an accepted id in neither | "No way to install $name is known." on stderr, exit 1 (:272-275, kept) |

`mise_pkg_for` (:67-80) and :276-299 are deleted. The script's last lines become the
no-route refusal.

### A terminal for everything that prints

After the presence check at :173 and before `attr_for`, with `installing` set by the
`--install` arm at :82:

```bash
# A menu row runs this with no terminal, so every route below would print to nowhere.
if [[ $installing == false && ! -t 1 ]]; then
  exec omarchy-launch-floating-terminal-with-presentation omarchy-default-agent --install "$agent"
fi
```

This is `omarchy-install-font:46`'s shape, for the same reason (#1304). `$agent` is an
id the case statement already validated. An agent already present never gets here and
stays silent. It reaches all 24 rows, because the defect does. The comments at :7-38,
:84 and :211 are corrected (:67-68 goes with `mise_pkg_for`), as the intent asks.

### The decline

For the six `elsewhere_attr_for` rows, replacing :246-267:

```text
Kimi is not installed, and nixarchy does not install it.
Your default agent is unchanged: claude.        (or: No default agent is set.)

It is not in nixpkgs. numtide/llm-agents.nix packages it as kimi-code. Add that
flake as an input and the package to your configuration, rebuild, and choose it
again.

nixarchy does not carry it: llm-agents.nix pins its own nixpkgs, and nixarchy puts

486 MB, for one optional agent.
```

- `record` is not called. Nothing is written, including when no file exists yet. The
  comment at :246-248 that defends the old choice goes.
- **Exit 1** (owner decision 2). The presentation wrapper then shows "Failed!" rather

- The unfree note at :261-265 moves from cursor-agent to commandcode, and is the only
  one printed. ori's sources disagree, so nothing calls it unfree.

### Stale shims and installs

The intent says a leftover shim must not count. The word that matters is leftover: a
shim with a live mise works, and #1625's decision 1 lets a person keep their own mise.
So a mise directory on PATH is dropped only when no mise remains. Before the presence
check at :173, in plain bash with no new dependency:

- split `PATH`, and set aside every entry matching `*/mise/shims`, `*/mise/installs/*`
  or `*/mise/command-wrappers/*`;
- if `mise` resolves on the remaining entries, leave `PATH` alone;
- otherwise export the remaining entries as `PATH`.

The mise lookup uses the remaining entries because a mise inside its own `installs/`
cannot vouch for itself when nothing else starts it.

`PATH` is changed rather than the one test, because `exec omarchy-agent` inherits it,
and upstream's launcher would otherwise run the dead shim that this script stepped
over. The case that needs it is a shell still open from before the #1625 switch: its
`PATH` keeps the directories after mise has gone. Nothing shipped adds them back, so
a new shell cannot reach this.

This runs `command -v mise` and no mise. The script calls mise nowhere.

**The step only fires once #1625 has landed.** Until then nixarchy's own mise is on
every `PATH`, so nothing is dropped, and `default.nix:1149` still prepends the shims
inside `omarchy-agent`. The two never meet: the filter needs mise gone, and #1625
removes that line in the same change that removes mise.

**A live mise proves mise, not the agent behind one shim.** This script cannot ask
which tool a shim belongs to without calling mise, so with a mise present a shim
counts, working or not. That is owner decision 4.

## Owner decisions

1. **cursor-agent and muse: move them into `attr_for`?** Recommended: yes. The approved
   recommendation kept them as declines believing nixpkgs lacked them. Two lines, the
   same route and the same unfree handling as `claude-code`, and `checks.agent-attrs`
   covers them. If no: they stay declined, and "It is not in nixpkgs" must become a
   per-agent line naming `cursor-cli` and `muse-code`.
2. **A decline exits 1, so the terminal ends "Failed!".** Recommended: yes. If no, exit
   0 ends in "Done!" after a message saying nothing happened.
3. **The terminal reaches all 24 rows, not only these seven.** Recommended: yes. It is
   one guard, and without it pi and omp cannot meet the intent's "builds it". It is the
   only change a user of the other rows will notice.
4. **Does "a leftover mise shim does not count" mean a shim whose mise is gone?** The
   intent's sentence could also mean any shim. Recommended: gone, as designed, because
   #1625's decision 1 lets a person keep their own mise, and "not installed" would be
   false for them. The cost: while a mise exists, a shim whose agent cannot start is
   recorded and launched, and fails there. If the owner wants any shim refused, the
   mise lookup goes, and someone with their own mise is told their agent is missing.
5. **`record` runs before `nixarchy-pkg-add` (:185).** With pi, omp, cursor-agent and
   muse on this route, a machine with no `apps.nix`, or a `pkg-add` that fails, loses a
   working default to an agent that was never added. The comment at :181-184 defends
   recording ahead of the rebuild, and it holds for every row. Recommended: move `record`
   to just after `pkg-add` succeeds, which keeps that reason and fixes the failure, with
   a case in `default-agent-routes`. If no: it stays as designed, and this is a named
   risk.

## Alternatives rejected

- **A shim never counts, without looking for mise.** Shorter by one test, and tells
  someone with their own working mise that their agent is not installed.
- **Probing the agent with `--version` to decide it works.** freebuff downloads 49.6 MB
  on first run, and some would start. The presence check is what `omarchy-agent` itself
  uses.
- **Removing the five rows.** `check-menu.py` passes either way, but upstream re-adds
  them at each bump and the row's truthful answer is the decline (intent).
- **Clearing a recorded default that names an absent agent.** It would delete a choice
  someone can still act on, and #1625's decision 4 lists exactly what may be removed.
- **A new flake input.** Excluded by the intent. The script prints why.
- **`--install` kept and the terminal left to each route.** Three copies of one guard.

## Risks

- **The keybinding on a recorded, absent agent is silent.** Upstream's `omarchy-agent`
  exits before opening a terminal. #1625 will produce this state on real machines,
  whose recorded `kimi` stays recorded. The intent calls the message truthful, and it
  is, wherever it can be seen. Patching upstream's launcher here is not recommended:
  this script is the wrong layer. **It is owner decision 2 in #1625's spec, with a
  check**: its outcome 5 says a command that used mise "says plainly why" it has no
  route, stderr from a keypress does not, and that is where the state first appears on
  real machines.
- **Between the two merges**, a working mise-installed agent re-clicked from the menu is
  told "not installed", because `bash -lc` has no shims, while `omarchy-agent` still
  finds it through `default.nix:1149`. The default stays recorded, so launching still
  works. Accepted: the gap is one merge wide.
- **#1622's crash is not gone for everyone on merge.** Someone who already installed
  kimi through mise on a machine with no `node` keeps `exec: node: not found` from an
  activated shell until #1625 removes activation. New choosers cannot reach it.
- **A script calling `omarchy-default-agent <id>` with no terminal and no display** now
  fails to open a terminal rather than rebuilding unattended. No shipped caller does
  (grep over `pkgs`, `modules`, `data` and upstream's `bin` and `shell`); the shipped
  mentions are advice to a person. `stale-scripts` has `agy` present and never reaches
  the guard.
- **llm-agents attribute names can go stale.** Nothing here sees that repository, and
  `tests/AGENTS.md` keeps saying so.
- **Hardware:** none. p620 is unaffected until someone clicks.
