# Intent: a greeter stranded by sleep is recovered on edge, as upstream recovers it

## Problem

Quattro (edge's pin since ebd2974) ships four drop-ins, on `systemd-suspend`, `systemd-hibernate`, `systemd-hybrid-sleep` and `systemd-suspend-then-hibernate`. Each adds `ExecStopPost=-/usr/bin/omarchy-system-sddm-recover`. After sleep, the script restarts SDDM when SDDM is active but no session holds a local seat. That is the state left when autologin or the greeter hit `UnitAllocationFailed` while systemd-sleep had `user.slice` frozen.

nixarchy ships the script but not the drop-ins. `data/etc-overlay.nix` classes all four `divergent`. The preconditions upstream names hold here too. nixarchy runs SDDM, with a greeter and optional autologin. Its systemd (262 on p620) freezes user sessions during sleep, the default since 256, and nothing sets `SYSTEMD_SLEEP_FREEZE_USER_SESSIONS`. `loginctl list-sessions --no-legend` puts SEAT in the fourth column, as the script expects. So the stranding is expected parity with upstream rather than something observed on nixarchy, which has not been seen. If it happens, the user resumes to a screen with no login, and no automatic hook recovers it.

## Proposed outcome

On a pin that ships the script, with nixarchy's SDDM enabled, each of the four NixOS sleep units (`data/etc-overlay.nix`'s rows) runs the script when it stops, including after a failed sleep. The script restarts SDDM only when SDDM is active, logind answers, and no session holds a local seat. A desktop, a TTY login or a healthy greeter is left alone. Under `main`'s tag pin, and under any edge pin without the script, nothing changes. The four rows say what answers them, and a check fails if the hook goes missing.

## Affected users and systems

Edge users with `programs.nixarchy.displayManager` on, which is the default. That covers p620 and razer once deployed. `main` (tag v4.5.0) is unaffected.

## Constraints

- Mode A: a machine whose display manager is not nixarchy's SDDM gets no sleep-unit change.
- The change must hold under both pins (CLAUDE.md §8): a no-op under `main`'s tag and any pin without the script. It lands as a carry on `edge-candidate` because only edge pins a quattro that ships the script, and edge's main-pin job proves the no-op side.
- The script's commands (`systemctl`, `loginctl`, `awk`) resolve when the unit runs it, without changing the sleep units' own environment: set PATH for the hook, not on the unit. This matters for safety. An unresolved `awk` makes the seat test false, and the script then restarts SDDM, which ends a healthy desktop session on every resume.
- The hook is added to the units' `ExecStopPost` and replaces nothing.
- The hook keeps upstream's `-` prefix, so its failure does not fail the sleep unit.
- A check covers both directions: the hook is on all four units when both gates are open, absent when either is closed, and its commands resolve.
