# Intent: The shot list names every shipped plugin, and something checks it

## Problem

`tests/demo/screencast/shots.nix` is the script for nixarchy's screencast.
Its header promises a tour of every shipped plugin. `shot-coverage.sh` (#930)
exists to keep that promise, and it is red today:

```
MISSING aziz.hyprforge is a shipped plugin and the shot list never names it
MISSING io.github.nobledoodle.omarchroma is a shipped plugin and the shot list never names it
MISSING nixarchy.menu is a shipped plugin and the shot list never names it
```

Omatheme and nixarchy-menu have been missing since they shipped, and
Hyprforge joined them today. Nothing noticed, because **no workflow runs
`shot-coverage.sh`**. It is a script under `tests/demo/`, and the harness
there is packages, not checks (§4).

A second staleness follows from #1054. The shot list's `menu` beat describes
the **stock** launcher ("What would you like to do?", Applications, …). Since
#1054, Super+Space opens nixarchy-menu on every machine, so the next recording
would show a different menu from the one the beat's comments and `expect`
describe.

## Proposed outcome

- The shot list names all fifteen shipped plugins, each with a beat the
  recording harness can perform and `verify-beats` can confirm, and the menu
  beat describes the menu that actually ships.
- A plugin added to nixarchy without a shot fails a check on the pull request
  that adds it, not months later when somebody records.

## Affected users and systems

- `tests/demo/screencast/shots.nix` (entries, the header's count, the runtime
  arithmetic).
- `flake.nix` gains a cheap `checks.shot-coverage` wrapping the existing
  script. It needs no workflow edit: `build.yml`'s generated step runs every
  unclaimed check on pull requests (§4).
- Whoever records the next screencast: the new beats are verified then, by
  `verify-beats`, because no CI job records.

## Constraints

- **No beat that cannot be performed.** Each `action` must be one the driver
  supports (`plugin`, `menu`, `settle`, …), and each `expect` must be text the
  panel really shows.
- **The screencast brief.** The cut is sped up to its target, so extra montage
  beats cost pace, not length.
- A `checks.*` entry must be cheap and hermetic: a grep over two source files,
  seconds, no VM.

## Open questions

1. **Record now or later?** The entries can be written now; proving them needs
   a recording (`nix run .#demo-record`, a VM, tens of minutes). Default
   proposal: write the entries and the check now, and leave the recording to
   the next scheduled screencast, where `verify-beats` gates it.
2. **The menu beat.** Retarget it to nixarchy-menu (its root and search), or
   make nixarchy-menu its own montage beat and leave the menu beat as the
   Omarchy menu tree it walks? Default proposal: retarget, since the menu the
   beat shows *is* nixarchy-menu now.
