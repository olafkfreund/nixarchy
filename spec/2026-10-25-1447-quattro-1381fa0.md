# Spec: drop the launcher patches quattro 1381fa0 makes redundant

## Design

Upstream's `omarchy-launch-webapp` and `omarchy-launch-browser` now read
`Exec=` from `${XDG_DATA_HOME:-~/.local/share}:${XDG_DATA_DIRS}`, in the same
order `omarchy-cmd-default-browser` searched. On NixOS, `XDG_DATA_DIRS`
already carries `/run/current-system/sw/share`,
`/etc/profiles/per-user/$USER/share` and `~/.nix-profile/share`, which is
exactly the list our substitution added. Both scripts now also refuse an
empty `browser_exec` with a message and a notification, before the handoff.

So:

1. Delete the `for f in omarchy-launch-webapp omarchy-launch-browser`
   search-path substitution (`pkgs/omarchy/default.nix:598-611`). Its pattern
   is gone, which is the build failure.
2. Delete our no-browser block in `omarchy-launch-webapp`. Upstream's check
   now runs first, so ours would be unreachable. Keep the `"$browser_exec"`
   quoting edit that shared its `substituteInPlace`.
3. Rewrite the two ledger rows so they name the edits that remain.
4. Pin quattro `1381fa0` as `edge-20261025-1381fa0` (`flake.nix`,
   `flake.lock`).

## Alternatives rejected

- **Re-anchor the path substitution on the new loop.** It would add
  directories `XDG_DATA_DIRS` already holds, and `/usr` paths that do not
  exist here.
- **Keep our no-browser message in front of upstream's.** It is
  unreachable now.

## Risks

- A session whose `XDG_DATA_DIRS` lacks the profile directories would not
  find the browser. Every NixOS login session sets them through
  `environment.profileRelativeSessionVariables`, and `checks.session`
  launches a web app on edge's `verify`.
- Upstream's new hint names `omarchy install browser chromium`. Whether that
  command does the right thing on nixarchy is a separate question, recorded
  as a follow-up rather than patched here.

## Verification

- `nix build .#omarchy` builds.
- Every generated check builds with `--keep-going`, and
  `grep -c "Cannot build"` prints 0.
- §1: restore the old substitution and the build fails with the same
  `pattern … doesn't match` line.
- Edge with `from_candidate=true`: prepare, wait-idle, verify and report all
  green, and report closes #1447.
