# Plan: Ask-topic aliases, and a Nixi row that cannot double up

## The approved decisions, carried over

Self-contained: everything needed is here, without opening the intent or spec.

1. **The Nixi row takes the id `help`.** Nixi's installer writes a row under
   exactly that id into `~/.config/omarchy/extensions/omarchy-menu.jsonc`
   (verified on a live host, line 40), and the generated defaults file's own
   header states that the user's file *"overrides anything here by id"*. Taking
   `help` therefore makes two simultaneous Nixi rows **unreachable**: where the
   installer has run, theirs wins as it does today; where it has not, ours
   appears, guarded. Any other id produces two rows on the former.

2. **Aliases are written from the symptom, not the topic name**, because the
   palette ANDs query terms and people type what is wrong. `why` goes on the
   three diagnostic rows for that reason: "why is it slow" fails against
   *Make it faster* without it.

3. **`when` reuses `nixarchy-plugin --enabled <id>`**, the idiom already at
   `modules/apps.nix:362`, `:374` and `:385`.

4. **Not in scope:** anything in nixarchy-menu itself; changing what
   `nixarchy-ask <topic>` does; and the unguarded row Nixi's installer writes,
   which is nixi-nixarchy's to stop and not ours to file (section 11).

   and adds no new shape.
   → verify by `nix build .#omarchy` and reading the nine rows out of

2. **`modules/apps.nix`, in `overrideSpec` (`:334`), beside `install.packages`
   (`:358`)** -- add the row:

   ```nix
   "help" = {
     icon = "󰙴";
     label = "Nixi";
     aliases = [ "help" "how" "ask" "nixi" ];
     action = "nixi";
     when = "nixarchy-plugin --enabled io.github.olafkfreund.nixi";
     description = "Ask Nixi anything about this machine";
   };
   ```

   With a short note at the row recording that its id is `help` deliberately,
   so the user file's own `help` row overrides it rather than doubling it --
   otherwise the next person renames it to `setup.nixi` and reintroduces the
   duplicate.
   → verify by the same build, grepping the generated file for `"help"`.

3. **A note at the row** that its `action` is bare `nixi`, not a floating

   counter-example if that assertion is ever widened.
   → verify by reading it back; no build effect.

4. **`tests/options.nix`** -- one case, on/off, asserting the row's **`when`

   → verify by section 1: delete the `when` line, watch the case go red,

## Rollback

Three files, additive only. `git revert` the commit: the nine rows lose their
`aliases` key and the `help` row disappears from the generated defaults, which
returns machines to exactly today's behaviour -- the user's own `help` row, if
any, is untouched throughout because nixarchy never writes that file.

No migration, no activation step, no state. A machine that has already rebuilt
with this and then reverts simply regenerates the defaults file without the row.
