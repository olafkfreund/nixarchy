source. `nix-bin/` means `pkgs/omarchy/nix-bin/`.

## Design

### Gap 1: the update toast (A)

Add one patch to `pkgs/omarchy/default.nix`, for `install/user/first-run/wifi.sh`:

```
--replace-fail 'checkupdates --nocolor >/dev/null 2>&1 || status=$?' 'status=2'
```

Status 2 is "no packages to update", which is always true here. Upstream's next
branch (`wifi.sh:18`) then asks `omarchy-update-available`, because `OMARCHY_PATH`
is never `/usr/share/omarchy` on this system (`pkgs/omarchy/default.nix:623-626`).
This keeps upstream's text and its second question.

`omarchy-update-available` being narrower than upstream's "any package" is
accepted. A nixpkgs-only change is not offered, and when it can't tell there is
no toast. Those are the answers the bar's icon already gives, and
`tests/update-available.nix` already pins them ('nixpkgs-only update' exits 1).
The toast and the icon can't disagree, since they run the same command.

### Gap 2: reloading outside a session (A)

`nix-bin/omarchy-install-preinstalls:17` and `nix-bin/omarchy-remove-preinstalls:47`
call `omarchy-restart-hyprctl` instead of `hyprctl reload`. Nothing else changes.

### Gap 2a: who owns the Hermes wrapper (A)

**Rule:** `~/.local/bin/hermes` is Omarchy's to delete only when it is a regular
file, not a link, and has a line exactly equal to
`# Written by omarchy-install-hermes-cli.`. That is the vendored script's own
`legacy_stub` test plus its `! -L` (`bin/omarchy-install-hermes-cli:60-64,79`).

Replace `nix-bin/omarchy-remove-preinstalls:60-63` with that test, written in the
script, using `[[ -f $f && ! -L $f ]] && grep -qxF`. Anything else at that path
goes on the `kept` list, as the mise stubs above it do. The script no longer calls
`omarchy-install-hermes-cli`, so the stray usage line goes too.

This rule proves the file *says* Omarchy wrote it, not that nobody edited it since. A
user's wrapper that keeps the marker line goes. The vendored script's `forget_legacy`
makes the same call, and the retired wrapper's exact bytes aren't in the tree to
compare with, so this is accepted rather than tightened (see "For the owner").

The saved copies under `.hermes-before-desktop.*` and the mise environment are left
alone. This script already removes only the wrappers of the other mise stubs, and
leaves their environments.

**#1625:** nothing here runs `mise`. `omarchy-remove-preinstalls` still *recognises*
old mise stubs, which is cleanup of files on disk rather than a use of the tool.
`nix-bin/omarchy-install-preinstalls` names mise only in a comment. So #1625 can
land first or second, with at most a textual rebase.

### Gap 5: Claude's browser extension (A)

One short paragraph in `docs/manual/ai.md`, after "Choosing one installs it
declaratively" (`:254-256`). It gives the declarative route and says what it costs:

```nix
programs.chromium.enable = true;
programs.chromium.extensions = [ "fcoeoabgfenejglbffodgkkbkcdhcgfn" ];
```

The two things the intent left open, read from nixpkgs'
`nixos/modules/programs/chromium.nix`:

- **Reach:** it writes policy for Chromium, Chrome and Brave (`/etc/chromium`,
  `/etc/opt/chrome`, `/etc/brave`). Upstream's script also covers Edge, and this
  doesn't. The paragraph says so.
- **Force-install: yes.** `extensions` becomes `ExtensionInstallForcelist`, so the
  browser won't let the user remove it. Upstream's JSON stub is removable. The
  paragraph says so, and that the Web Store is the removable route.

The id is upstream's (`bin/omarchy-install-chromium-claude`).

### Gap 3: `vi` (B)

In `modules/nixos.nix`, in the `systemPackages` list at `:1392-1402`:

```nix
++ [ (lib.lowPrio (pkgs.writeShellScriptBin "vi" ''exec nvim "$@"'')) ]
```

A wrapper finding `nvim` on `PATH`, not an alias of our Neovim, so a user's own
`nvim` is the one `vi` opens. No `vim` command (owner's decision).

`data/omarchy-packages.nix:750-752` becomes `module = "environment.systemPackages";`,
because a `nix` row needs an attribute in `pkgs` and this is not one. A one-line
comment names where it is. A wrapper in `runtimeDeps` was the other place, but
`runtimeDeps` is what #1625 edits, on the line after `neovim`.

### Gap 4: choosing a missing browser or editor (C)

**A new command, `nixarchy-default-install <browser|editor> <selection> <command>`,**
written in `modules/apps.nix` next to `nixarchy-app-enable`, because it needs the
catalogue and the machine's unfree setting. Its map is a Nix attrset, so a renamed
catalogue row fails evaluation rather than a choice:

| Kind | Upstream's selection → `data/apps.nix` row |
|---|---|
| browser | `chrome`, `brave`, `brave-origin`, `edge`, `firefox`, `zen` keep their names |
| editor | `code` → `vscode`; `sublime_text` → `sublime`; `cursor`, `zed`, `helix`, `vim`, `emacs` keep their names |
| neither | `chromium` and `nvim` have no row: they ship in the session, so reaching this says so and exits 1 |

It does these in order:

1. **Refuse** with exit 1, changing nothing, in two cases. A row with `unavailable`
   prints that sentence. A row with `unfree` on a machine with `allowUnfree` off and
   no predicate names the setting. The second bakes the same values as
   `nixarchy-pkg-add` (`modules/apps.nix:2483-2486`), and with a predicate it does
   not predict a refusal, for the same reason. A rebuild refused there would stay
   refused until the row came out, so this is asked first.
2. **Enable** through `nixarchy-app-enable`. If that fails, stop with nothing recorded.
3. **Record** `<selection>` and `<command>` in
   `${XDG_STATE_HOME:-~/.local/state}/nixarchy/pending-default-<kind>`. Recording
   comes before the build for the reason `omarchy-default-agent` gives: it is still
   the user's answer if they close the terminal. A saved `helix` is probed as `hx`,
   as the setter's existing patch does.
4. **Say what happens, then `exec nixarchy-apply`,** which asks its own two questions
   (preview, then "Build and switch now?"). The line says the choice takes effect when
   a rebuild finishes, now or at the next `nixarchy apply`. This command adds no
   `gum confirm` of its own.

**`nixarchy-default-install --settle`** finishes the choice. For each pending file:
put `/run/current-system/sw/bin` first on `PATH`, because the caller's `PATH` may
predate the switch. If the command exists, run the upstream setter
(`omarchy-default-browser <selection>`). The setter removes the file once it has set
the default. If it exits non-zero, say so and leave the file, so the choice isn't
lost and the next apply tries again. If the command doesn't exist, remove the file
and say the rebuild didn't provide it. The check comes first because the setter
would otherwise open a terminal to install again, with nobody there.

`nixarchy-apply` calls it after its switch succeeds (`modules/apps.nix`, in the
`[yY]*)` branch, about `:4345`), as `... --settle || true`, because a failure to set
a default must not report a good rebuild as failed. A failed rebuild or a "no" keeps
the file. The rebuild panel's detached unit runs the same code path.

**Upstream's two setters** change by patch, each with `--replace-fail`:

- `omarchy-default-browser`: `omarchy-install-browser "$browser" || exit 1` becomes
  `exec nixarchy-default-install browser "$browser" "$command"`.
- `omarchy-default-editor`: the `case "$selection"` of installers becomes
  `exec nixarchy-default-install editor "$selection" "$editor"`.
- Both remove their pending file straight after setting succeeds (after
  `xdg-settings ... || exit 1`, and after the `printf` to the state file), so choosing
  an installed app cancels an older pending choice instead of being overwritten by it
  later, and a set that fails cancels nothing.

`data/bin-ledger.nix` adds #1623 to both rows' reasons.

**The two rows that hide (found while writing this).** `modules/apps.nix:626-627`
sets `when = "omarchy-cmd-present hx"` and `... zen-beta` on Helix and Zen. Upstream
at v4.5 has no `when` on any default row, so these two can't be chosen from the menu
while missing, which is the case this gap is about. Remove both lines.
`tests/menu-conditions.sh:37-43,56-60` assert the gate and get retargeted (§1): the
row shows either way, and the setter patches still probe `hx` and `zen-beta`.

**Upstream's setup after installing is dropped, every step.** Flags, theme, Wayland
environment and policy writes in `omarchy-install-browser`, and the
`omarchy-install-editor-*` scripts. Choosing an app in Install > Browser or Editor
already runs only `nixarchy-app-enable` (`modules/apps.nix:1055`) and none of this,
so both routes now end the same way. Two of them were wrong to run anyway:
`omarchy-install-editor-vscode` overwrites `settings.json`, and the policy writes
target read-only paths. Anything worth having belongs to both routes, in another
issue.

**Sublime Text's sentence** in `data/apps.nix` gains the alternative, "Zed and
VSCode are in the catalogue". Brave Origin's already names Brave.

**Names checked against nixpkgs without building:** `microsoft-edge-stable` and
`microsoft-edge.desktop`, `google-chrome-stable` and `google-chrome.desktop`,
`code`, `cursor`, `zeditor`. Brave's are unread, and rest on #1303's earlier work.

## Coexistence (§14)

| Concern | Answer | Fixture |
|---|---|---|
| A user's own `vi` package | Normal priority beats `lowPrio`, silently, as intended | `systempkg-own-vi`: a marker script, read from `system.path/bin/vi` |
| `programs.neovim.viAlias`, or `pkgs.vim`, which ships `bin/vi` | The same: theirs wins | `neovim-vialias`: asserts `vi` is not our wrapper |
| Mode A | `enable = true` already brings `neovim`, and now `vi`. `enable = false` brings neither | options case below |
| Gap 4 | Acts only on a user's choice, and writes only their `apps.nix` and a state file | none: nothing merges |

## Alternatives rejected

- **A `checkupdates` stub.** It answers one script's question by faking an Arch tool
  every other reader could then find.
- **Replacing all of `update_pending`.** A multi-line `--replace-fail` inside an
  indented Nix string, to save one line of upstream's text.
- **`--retire-mise` for 2a.** It exits 1 without `mise`, and prints "omarchy pkg add
  mise", which is wrong the moment #1625 lands. `--check` asks a different question.
- **Adding `--owns` to the vendored script.** A patch re-applied at every bump, to
  run four lines this script can hold.
- **A printed line for gap 5.** The intent showed `exec omarchy-agent` hides it.
- **`neovim.override { viAlias = true; }`.** A second Neovim build, and it opens ours
  over the user's. **A `vim` command:** the owner said no.
- **Writing `mimeapps.list` before the build.** `xdg-settings` refuses a missing
  desktop file, and until the build the default would name nothing, which
  `omarchy-launch-browser` reports as no browser at all.
- **Different routes for editors and browsers.** Editors could record first with no
  pending file, because the launcher falls back to `nvim`. One mechanism costs less
  than two.
- **Replacing both setters in `nix-bin`.** That carries upstream's selection tables
  and read-back to change one branch.
- **Predicting a predicate's answer, or building and letting an unfree refusal fail.**
  The first is a guess; the second leaves a row that fails every later rebuild.

## Risks

- **`status=2` rests on `OMARCHY_PATH`.** If that ever equalled `/usr/share/omarchy`,
  there would be no toast at all, which fails quietly. The check runs with the real
  tree path and a newer release, and fails if the toast stops.
- **A hand-run rebuild doesn't settle.** The pending file waits for the next
  `nixarchy apply`. Accepted, and said in the printed line.
- **A failed rebuild keeps the row.** The same as any Install pick. `nixarchy-apply`
  already prints the way out.
- **Hermes:** a wrapper from before the marker existed is kept, not removed. That is
  the safe direction. An edited wrapper that keeps the marker is removed, which is not.
- **`xdg-settings` can report success and change nothing** when `mimeapps.list` is a
  Home Manager store link (`docs/manual/configuration.md:563-568`). `--settle` then
  removes the file with no default set. That limit is already documented, and this
  change doesn't widen it.
- **`vi` reaches every default system.** It is one small store path, so the closure
  and cache budgets don't move in any way that matters.
- **Overlap.** #1612 edits `modules/nixos.nix` at `:617-630`, `:716-729`, `:946-982`
  and `:1535-1543`, none of them in B's `:1392-1402`. Its `modules/apps.nix`,
  `data/apps.nix` and `tests/app-selection.nix` hunks are elsewhere from C's, so a
  rebase is expected to be plain. Its "on by default" rows are not browsers or editors.

## For the owner

Decisions beyond the approved intent, with a recommendation:

1. **Remove the `when` on Helix and Zen.** Recommend yes. Otherwise those two can't
   be chosen while missing, and the outcome is false for them.
2. **Drop upstream's post-install steps on this route.** Recommend yes. It matches the
   Install menu, and the alternative is deciding about them per app in this issue.
3. **`vi` in Mode A with `enable = true`.** Recommend yes, at low priority, because
   it comes with `neovim`, which that mode already gets.
4. **A user's edited Hermes wrapper that keeps Omarchy's marker line is deleted.**
   Recommend accepting it. The file says Omarchy wrote it, the vendored script treats
   it the same way, and this only runs when someone chooses Remove preinstalls. The
   alternative is never deleting the wrapper, which leaves a stale `hermes` behind.
