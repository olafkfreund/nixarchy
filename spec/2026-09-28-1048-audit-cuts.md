# Spec: the same code, written once

## The open questions, settled

1. **Shell helpers (cut 2): nothing to cut within the approved scope, so
   dropped.** The approved lean was "`pkgs/*.sh` only, leave `nix-bin`".
   Measured:
   - **every `red`/`dim`/`bold` copy is in `pkgs/omarchy/nix-bin/`**, which
     stays standalone by that decision;
   - the helpers `pkgs/*.sh` do define **differ in behaviour**. `say()` has
     four variants (`echo -e`, which interprets escapes; `printf '%s\n'`,
     which doesn't; and one that prints `try: …` to stderr). Sharing one
     would change what scripts print.

   So the audit's "−150 lines" doesn't survive a closer look, and the issue
   says so.
2. **The 42 registrations (cut 1): a `lib.genAttrs` list, minus `options`.**
   `checks.options` is the 11.5 GB evaluation (§6), and the intent keeps it
   untouched, so it stays an explicit entry and **41 names** go in the list.

## Design

### Cut 1: `flake.nix`

```nix
# Checks whose file takes { inputs, pkgs } and whose name is the file's.
uniformChecks = [ "apply-detach-interface" "apply-imports" … ];  # 41, sorted
…
checks = … // lib.genAttrs uniformChecks (n: import ./tests/${n}.nix {
  inherit inputs;
  pkgs = pkgsFor.${system};
});
```

The explicit entries they replace are deleted, and every other check stays as
it is. Each deleted entry's `# Why: tests/<name>.nix` pointer carried no
information beyond the name, which the list now shows.

### `checks.test-registration` learns the list as data

It currently greps `flake.nix` for `import ./tests/<name>.nix`, and it
refuses when fewer than 50 match. After cut 1 about 46 literal imports would
remain, **so the floor alone would trip even if nothing else changed**.
Rather than teach it to parse more text, `flake.nix` passes it the list:

- `import ./tests/test-registration.nix { …; uniform = uniformChecks; }`;
- `imported = grep-found ∪ uniform`, and the floor applies to that union;
- **the list is data, not text,** so a comment naming a test still can't
  count as its registration (the reason the grep matches `import`, not a bare
  name).

### Cuts 3 and 4: `tests/lib.nix`

```nix
{ inputs }:
{
  # The vm's copy of a package, by pname; the system is evaluated, not built.
  vmPackage = name: builtins.head (builtins.filter
    (p: (p.pname or p.name or "") == name)
    inputs.self.nixosConfigurations.vm.config.environment.systemPackages);
  # Pass/fail printers for check scripts; the caller initialises `fails=0`.
  okBad = ''
    ok() { echo "  ok      $1"; }
    bad() { echo "  FAILED  $1"; fails=$((fails + 1)); }
  '';
}
```

- **`vmPackage`** replaces the pick-by-name blocks in `apply-detach-interface`,
  `apply-imports`, `apply-staging` (2) and `branch-guard`. `options.nix`'s
  two stay (the intent's constraint).
- **`okBad`** replaces the two lines in the 6 test scripts where they are
  byte-identical: `apply-staging`, `branch-guard`, `mise-launchers`,
  `pkg-new`, `skills-relink`, `try-preflight`.
- `tests/lib.nix` is a helper, not a check, so it goes on
  `test-registration`'s exempt list with that reason, like
  `with-vm-cleanup.nix`. Without that, the guard reports it as unregistered.

## The proof: derivations, not diffs

A refactor that changes what a check builds isn't a refactor. So, **in one
tree** (§5: never across commits), every check's `drvPath` is evaluated with
the old and the new `flake.nix`/tests, and compared:

- **all must be identical except `test-registration`**, whose script
  intentionally changed;
- `okBad`'s lines land at the same position after Nix strips the string's
  indentation, so the six scripts' build commands stay byte-identical. If one
  doesn't, the proof shows it, and it gets fixed, not waved through;
- `options` is excluded from the comparison (not touched, and 11.5 GB).

## Alternatives rejected

- **Sharing `say`/`ok`/`fail` across `pkgs/*.sh`:** the behaviours differ
  (question 1).
- **Sharing helpers into `nix-bin`:** excluded at the intent gate.
- **Teaching `test-registration` to parse the list's text:** a second parser
  for a Nix list is worse than being handed the list.
- **Including `options` in the list:** cheap in lines, expensive to prove
  unchanged.

## Risks

- **`test-registration` could go blind to the list.** Break it: take a name
  out of `uniformChecks` without restoring its explicit entry. The guard must
  name that test as unregistered (§1).
- **A new check added to the list with a file that takes other arguments**
  fails at evaluation, loudly. The comment above the list says what belongs
  in it.

## Verification

| what | how | break it by |
|---|---|---|
| nothing that ships changed | every check's `drvPath`, old against new in one tree | any difference outside `test-registration` fails the proof |
| the guard still guards | `checks.test-registration` | a name removed from the list → names it; `tests/lib.nix` not exempt → names it |
| the cut checks still pass | build `apply-*`, `branch-guard`, `mise-launchers`, `pkg-new`, `skills-relink`, `try-preflight`, `test-registration` | — (identical drvs, but built once to be sure) |
| lint | `nix fmt -- --ci`, statix, deadnix | — |
