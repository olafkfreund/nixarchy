# Spec: a theme change reaches kitty, and survives a rebuild in GTK

One PR, two fixes (the intent's second question).

## Fix 1: `omarchy-restart-terminal` matches wrapped terminals

The whole script (stable 4.0.5 and quattro 81fd2d2 both ship it):

```sh
if pgrep -x kitty >/dev/null; then
  killall -SIGUSR1 kitty >/dev/null
fi
if pgrep -x ghostty >/dev/null; then
  killall -SIGUSR2 ghostty
fi
```

nixpkgs wraps kitty, and the running process's `comm` is `.kitty-wrapped`
(measured on p620). `pgrep -x` and `killall` match `comm`, so both miss.

A carried substitution in `pkgs/omarchy/default.nix`, with `--replace-fail`
on each of the four lines:

| upstream | here |
|---|---|
| `if pgrep -x kitty >/dev/null; then` | `if pgrep -x '[.]?kitty(-wrapped)?' >/dev/null; then` |
| `  killall -SIGUSR1 kitty >/dev/null` | `  pkill -USR1 -x '[.]?kitty(-wrapped)?' >/dev/null` |
| `if pgrep -x ghostty >/dev/null; then` | `if pgrep -x '[.]?ghostty(-wrapped)?' >/dev/null; then` |
| `  killall -SIGUSR2 ghostty` | `  pkill -USR2 -x '[.]?ghostty(-wrapped)?'` |

- `pkill` takes the same regex as `pgrep`, while `killall` takes no regex.
- The `-x` anchor stays, so `kitten` and anything named `…kitty…` are never
  signalled.
- The block goes where `main` and `edge` agree in `default.nix`. A trial
  merge into `edge-candidate` must be conflict-free before the PR (#1368's
  lesson).
- `procps` (`pgrep`/`pkill`) must be in Omarchy's runtime inputs. The spec
  author checks that it is already there. If it is not, it is added in the
  same change, because an undeclared command reads as a wrong answer
  (CLAUDE.md §7).

**Check, `checks.restart-terminal-wrapped`** (a cheap `runCommand`, no VM):
copy `sleep` to a file named `.kitty-wrapped` and start it. That gives a real
process whose `comm` is `.kitty-wrapped`, exactly what nixpkgs' wrapper
produces. Then run the patched `${omarchy}/share/omarchy/bin/omarchy-restart-terminal`
with `HOME` set to a temp directory. `SIGUSR1` kills `sleep`, so the check
asserts the process is **gone**. The same is done for `.ghostty-wrapped` with
`SIGUSR2`. A third process named `kitten` must **survive**, which proves the
anchor. The sandbox has its own PID namespace, so nothing outside it can be
signalled.

## Fix 2: the GTK colours survive the `omarchy-theme-gnome` unit

The theme engine (`nixarchy-omatheme`) has **no systemd unit**. It runs
through Omarchy's `theme-set.d`/`font-set.d` hooks, so there is nothing to
order after, and the hook goes on our unit (the intent's first question).
`hyprchroma` accepts `--target=gtk --force --quiet` (checked: `hyprchroma
--help`).

In `modules/home.nix`'s `omarchy-theme-gnome` (line 1350), add:

```nix
ExecStartPost = lib.optional themeEngineGtk "-${osConfig.programs.nixarchyThemeEngine.package}/bin/hyprchroma --target=gtk --force --quiet";
```

with

```nix
themeEngineGtk =
  (osConfig.programs.nixarchyThemeEngine.enable or false)
  && (osConfig.programs.nixarchyThemeEngine.targets.gtk or false);
```

- The condition is the same as the engine's own (`enabled = cfg.targets.gtk`
  under `cfg.enable`), so it fires exactly when the engine manages GTK.
- `or false`: a standalone Home Manager has no `osConfig`, and a Mode A
  machine has the engine off. Both get no `ExecStartPost`, so they are
  untouched.
- The leading `-` means a failing `hyprchroma` cannot mark the login unit
  failed. The worst case is today's behaviour.
- `hyprchroma` is called by store path, so the unit's restricted `PATH` does
  not matter for finding it.

**Check:** an evaluation check over the reference configuration that asserts
three states:

| configuration | `ExecStartPost` |
|---|---|
| engine on, `targets.gtk = true` (the default) | contains `hyprchroma --target=gtk` |
| `targets.gtk = false` | empty |
| engine off | empty |

The spec author places it in the cheapest existing evaluation check that
already builds a reference configuration, rather than `checks.options` (8 min
and 11.5 GB). If none fits, a new evaluation-only check is added.

## Alternatives rejected

- **Order the engine after our unit, inside `nixarchy-omatheme`.** The engine
  has no unit, so there is nothing to order. Adding one is a change to
  another repository, for a two-line effect.
- **Stop `omarchy-theme-gnome` setting `gtk-theme`.** It also sets the
  light/dark half of every theme for machines without the engine, which is
  Mode A behaviour we keep.
- **`killall -r` with a regex:** `killall`'s regex mode does not anchor like
  `pgrep -x`, so `kitten` could match.

## Risks

- **Coexistence (§14):** nothing is installed system-wide. Fix 1 changes a
  vendored script, and Fix 2 adds a step to our own unit. No fixture applies.
- **A user with their own `ExecStartPost`** on this unit: Home Manager merges
  lists, and ours is plain assignment of a list (§7), so both run.
