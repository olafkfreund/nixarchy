# Spec: nixarchy ships Omarchy 4.0.6

## What was measured

All of this was measured in a scratch tree, with nothing committed:

- `flake.nix`: the input set to `v4.0.6` and `omarchyVersion = "4.0.6"`;
- `nix flake update omarchy`, which locks `237f1b4`;
- the rebased hunk below.

| | result |
|---|---|
| `.#omarchy` | **builds**. The single failing hunk was the only drift; every other patch and `--replace-fail` applies |
| `checks.bin-ledger`, `omarchy-version-label`, `restart-terminal-wrapped`, `appimage-extract` | green |
| Trial merge into `origin/edge-candidate` | three conflicts, all resolved to edge's side, with no net change to edge (below) |

That answers the intent's scope question: there is no further drift, so
this is one PR of three files.

## Design

### 1. The bump: `flake.nix`, `flake.lock`

- `flake.nix:82`: `github:basecamp/omarchy/v4.0.5` becomes `…/v4.0.6`.
- `flake.nix:537`: `omarchyVersion = "4.0.5"` becomes `"4.0.6"`.
- `nix flake update omarchy`, and nothing else in the lock moves.

This is exactly what the bump job does (its `sed` lines), so the result
matches what the automation would have produced.

### 2. Rebase hunk 1 of `pkgs/omarchy/1153-owe-video-backgrounds.patch`

4.0.6 (upstream #14978) inserts seven lines between `locked` and
`authenticating`:

```qml

  // Decisions read the lock state afresh. A property binding that missed a change
  // notification once reported locked after an unlock, and a lock request before
  // suspend then took that for done and never locked the session.
  function currentlyLocked() {
    return lockRequested || sessionLock.locked || sessionLock.secure
  }
```

The hunk takes these as context lines. Its header goes from
`@@ -29,14 +29,25 @@` to `@@ -29,21 +29,32 @@`. Every `+` line is
byte-identical to today's, so what the patch adds does not change. Hunks
2-10 already apply, 7 lines lower, and are untouched. `--fuzz=0` stays.

The patch's header comment (deleted at the quattro bump) stays true, and is
not edited.

### 3. What else 4.0.6 changes, and why nothing else needs work here

- **`omarchy-agent`** (ours is `class = "patch"`). Upstream's new guard is
  `omarchy-cmd-missing "$agent" && ! { agent == openclaw && omarchy-pkg-present openclaw; }`.
  nixarchy's `omarchy-pkg-present` answers "is the command runnable"
  (`data/bin-ledger.nix:407`), so when the command is missing it is false,
  and the guard behaves exactly as it did on 4.0.5. Our two substitutions
  still apply, and the ledger reason is still accurate.
- **`omarchy-launch-openclaw`**: its new branch
  `! omarchy-cmd-present openclaw && omarchy-pkg-present openclaw` can never
  be true here, by the same rule. The icon fallback reads `/usr/...` paths
  that just do not exist, so the launcher behaves as on 4.0.5. The ledger
  rows (`vendor`, read-only `systemctl --user`) stay accurate.
- **Migrations, `mkinitcpio`, `test/`**: Arch-only, and not shipped or run
  by nixarchy.
- **`lock/Service.qml`'s `currentlyLocked()`**: this is the user-visible
  fix. It is QML that nixarchy ships, so it reaches users with no work
  from us.

### 4. Edge

`edge` has already deleted the 1153 patch (quattro carries it upstream), and
pins its own Omarchy. Merging `main` into `edge-candidate` gives:

- `flake.nix` at lines 82 and 537: take edge's;
- `flake.lock`: take edge's;
- the 1153 patch (modified here, deleted there): keep it deleted.

With those, the merge introduces no net change on edge. That was measured:
`git diff --cached HEAD` was empty.

### 5. Release notes

v4.0.6-1's notes name what reaches nixarchy: the screen now locks reliably
before suspend (upstream #14978). The OpenClaw, migration, boot-passphrase
and TUXEDO fixes are Arch-side and are left out, with one line saying so.
The release itself is cut after merge, as before (the owner tags it).

## Alternatives rejected

- **Raise `--fuzz`:** that hides exactly this kind of drift, which the
  intent's constraints forbid.
- **Wait for quattro:** that leaves stable users on 4.0.5 without the
  lock-before-suspend fix, for an unknown time.
- **A new check:** the existing bump job is the probe that caught this
  (§2). It needs no addition.

## Risks

- **The lock path:** the patch's lock hunks now sit beside upstream's new
  `currentlyLocked()`. The patch does not call it, and upstream's own
  callers are unchanged by us. `checks.session` (lock and unlock, the owe
  steps) runs in CI and is the gate.
- **Coexistence (§14):** no options or packages change, so no fixture
  applies.

## Verification

- **§1 red:** the bump with the unrebased patch fails `.#omarchy` with
  `Hunk #1 FAILED at 29` (already observed in run 39367966381, and
  re-observed locally on the branch before the rebase).
- **Green:**
  - `.#omarchy` builds, and `nix eval --raw .#omarchy.version` prints `4.0.6`;
  - `bin-ledger`, `omarchy-version-label`, `restart-terminal-wrapped` and
    `appimage-extract` are green locally;
  - CI is fully green, including `install` and `session`.
- **Edge:** the trial merge resolves as in §4, with an empty net diff, and
  `.#omarchy` still reports `edge-…`.
- `nix fmt -- --ci`.

Three files and three short editing steps (the lock is generated), so the
lead implements it rather than handing it to the `coder` agent.
