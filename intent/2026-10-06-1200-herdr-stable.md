# Intent: stable machines evaluate with the default herdr widget

## Problem

An installed machine on stable nixpkgs (26.05) fails to evaluate once it
updates past #792:

```text
error: attribute 'herdr' missing
```

The installer template sets `nixarchy.inputs.nixpkgs.follows = "nixpkgs"`
(`installer/template/flake.nix:65`), so on a stable machine nixarchy's own
`inputs.nixpkgs` is 26.05 as well. The default herdr widget falls back to
`inputs.nixpkgs.legacyPackages.<system>.herdr` when the system's `pkgs` has no
herdr (`modules/home.nix:2031`). On a stable machine that fallback is also
26.05, and 26.05 has no herdr either.

`checks.stable-eval` passes because `stableVm` is built with nixarchy's own
inputs, whose `nixpkgs` is unstable. That is not how an installed machine is
wired. The stable session test in #1199 builds the modules from the 26.05 pair,
as the template does, and that is how this was found.

`v4.0.4-1` does not contain #792, so no released machine is broken yet. The
next release would break every stable machine that updates.

## Proposed outcome

- A stable machine wired the way the installer template wires it evaluates
  and gets the herdr CLI, as #792 intended.
- Unstable machines are unchanged: they keep `pkgs.herdr`.
- A check fails if this breaks again, on every pull request rather than
  weekly.

## Affected users and systems

- Installed machines on `nixarchy channel stable`.
- `modules/home.nix` (the herdr widget), `tests/stable-eval.nix` (the check
  that should have caught it).

## Constraints

- No new flake input that users must override or follow.
- No change to the unstable closure.
- The fix lands on `main` before the next release (#1199's first proposal).

## Open questions

1. **Where the fallback herdr comes from.** Hyprland's own nixpkgs pin
   (`inputs.hyprland.inputs.nixpkgs`) is the leading option. The template
   never overrides it, so it stays nixos-unstable on a stable machine. It has
   herdr (0.9.1 on 2026-10-06), and `modules/nixos.nix:14` already uses that
   pin for a related reason. The alternative is packaging herdr in this flake.
2. **Where the regression check lives.** Make `stable-eval` evaluate with
   the template's wiring (nixpkgs followed to 26.05), or rely on #1199's weekly
   stable session test? The intent asks for a PR-time check, which points to
   `stable-eval`.
