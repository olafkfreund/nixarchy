# Spec: stable moves from Omarchy v4.5.0 to v4.6.0-rc1

## Design

Route (a), as #1477: one branch, `chore/1975-stable-4.6-rc1`, merges `main`,
merges `edge` for real, pins the tag, and adds what the 33 commits past edge's
quattro pin need. A trial on 2026-11-27 (`/mnt/data/vmtest/rc1-trial`) did
exactly that: the edge merge (`edge-candidate` 9d95ffde, now `edge`) is clean,
`packages.omarchy` 4.6.0-rc1 builds after the changes below, and eight cheap
checks then fail, each naming what it needs.

### 1. "Is this pin quattro?" stops meaning "is this an edge pin"

Twenty-eight places ask `hasPrefix "edge-" <omarchy version>` and read *false*
as "this is the v4.5 tag", in `pkgs/omarchy/default.nix`,
`pkgs/omarchy/user-migrations.nix`, `modules/nixos.nix`, `modules/apps.nix`,
`flake.nix` and 20 checks under `tests/`. rc1 is a tag that contains all of
quattro `155c4b4`, so every one of them picks the wrong branch: the first build
failure, the webapp `chromium*` patch, was `!isEdge` patching a line upstream
had already fixed.

One predicate replaces them: `pkgs/omarchy/is-quattro.nix`,

```nix
lib: version: lib.hasPrefix "edge-" version || lib.versionAtLeast version "4.6.0-rc1"
```

and each site calls it. Names stay (`isEdge`, `--edge`, `edge = "only"`): they
are read by scripts, ledgers and docs, and renaming them is churn for no
behaviour. The two rungs keyed on quattro `155c4b4` (`1625-no-mise-edge.patch`,
`1923-reaper-check-155.patch`) also take rc1: `hasSuffix "155c4b4" version ||
versionAtLeast version "4.6.0-rc1"`.

### 2. Build carries for the 33 commits

- **Keybindings menu cache tag** (`v19` -> `v22`): edge's loop over v19..v22
  with a grep that fails when none matches, already on edge.
- **Fingerprint PAM moved to `omarchy-apply-fingerprint-pam`**, run by the
  terminal setup and by the new fingerprint panel's root helper
  (`omarchy-setup-security-fingerprint-enroll`, through pkexec). The setup no
  longer defines `setup_pam_config()`, so its pair leaves the delete loop.
  `omarchy-apply-fingerprint-pam` is replaced, when the pin ships it, by
  `pkgs/omarchy/1975-apply-fingerprint-pam.sh`: exit 0 when `/etc/pam.d/sudo`
  and `polkit-1` already call `pam_fprintd` (the NixOS options are set), else
  print the same `services.fprintd` / `fprintAuth` lines the old replacement
  printed and exit 1. It only reads the stacks, and builds their path from a
  variable, because the drift guard below it refuses any script naming
  `/etc/pam.d/sudo` literally. The guard itself is unchanged.

  "4.6.0-rc1"`, then `nix flake update omarchy`: rev

  `sha256-0tGp3frcYptp7b40nb8UO+mcol3JZTm1UZYUUxC8jio=`.
- Real merge of `edge`; the PR merges with `gh pr merge --merge`.

### Coexistence (§14)

No new NixOS or Home Manager option, and no changed default a user sets. The
fingerprint replacement reads the PAM stacks and edits nothing. The logind file
is classified, and whatever its class, `modules/nixos.nix` installs only what a
`covered`/`shipped` row says. No fixture needed.

### Afterwards

- Close #1972 as superseded.
- Edge's next merge of `main` takes the pin pair and the new rows. Edge's
  pin (`155c4b4`) lacks the 33 commits. The ledgers already tolerate that:
  an `edge = "only"` row the pin lacks is reported as "this pin does not have
  yet" and does not fail the check, which is how the trial's ZBook and
  migration lines read. So every new row is `edge = "only"`, no row edge still
  needs is deleted, and the cheap tier runs under edge's pin too before the
  push (the both-pins rule, §8).

## Alternatives rejected

- **Patch #1972's branch failure by failure.** The first fix copied edge's code
  line for line, and the bump branch belongs to the workflow. #1477 rejected
  the same route for the same reasons.
- **Delete every tag-side branch now that main is past 4.5.** Edge's `main-pin`
  job builds edge under main's pin, and a release can still be cut from the
  4.5 tag; the predicate keeps both working, and dropping the dead branches is
  a separate cleanup.
- **Rename `isEdge` to `isQuattro` everywhere.** Correct, larger, and touches
  names that scripts and docs read. The predicate is the behaviour change.
- **Move edge to rc1's commit first (route b).** Two pipelines' worth of runs
  for the same classification work; #1477 chose (a).

## Risks

- **VM checks see what a package build cannot.** rc1 adds a fingerprint panel,
  camera, bluetooth and network panels and shell QML. `session`, `coexist`,
  `plugin` and `install` boot rc1 first on CI. A red VM check is a new carry
  with its own §1 proof, not a retry.
- **The predicate's version compare.** `versionAtLeast "4.6.0-rc1" "4.6.0-rc1"`
  is true and `"4.5.0"` false; an `edge-…` string is decided by the prefix
  before the compare runs. A future `4.5.x` point release stays on the tag
  side, which is right: it is not quattro.
- **The merge must stay a merge**, as #1477.
- **p620 load.** One push, after the cheap tier passes locally.

## Verification

- §1 for the predicate: on the trial tree with the predicate removed, the
  webapp patch fails (`pattern google-chrome* | ... doesn't match`); with it,
  the package builds.
- §1 for the fingerprint replacement: with the install line removed, the drift
  guard fails naming `omarchy-apply-fingerprint-pam`; restored, the build
  passes. A small test runs the replacement against a stack with and without
  `pam_fprintd` and checks exit 0 and exit 1 with the options named.
- Each of the eight checks: failing output from the trial (above), passing
  after its row or patch.
- Local before push, by tier: `nix fmt -- --ci`, statix, deadnix, every
  generated check under this pin and again under edge's pin
  (`both-pins.sh`), `readme-counts.sh --check`, then the VM tier when no
  runner is busy.
- CI: `build` and `install check` green on the PR head, head checked first.
- After merge: `main`'s runs green; the next `omarchy-edge` run merges `main`
  cleanly.
