# Plan: New installs follow Omarchy 4.5's default app set

Work in `/mnt/data/vmtest/wt-1612`, branch `fix/1612-default-apps`. Issue #1612,
part of #1610. Line numbers are at commit `6adcf77c`; earlier steps move them, so
match on the quoted text.

**Who does what.** Codex and agy write the code (`coders:` above). They cannot

## Decisions carried from the approved spec

- **Existing machines get no keep-line.** A rebuild removes the three apps and adds
  the seven, and the release note says so.
- **The switch covers** Hype, Signed, Monologue, Omacalc, Omacut, Omawrite and Aether.
- **Omarchy Local AI leaves the switch.** It stays in the catalogue, and
  `modules/services/agent-local.nix:56` still installs it for the service's users.
- **Lazydocker stays.** It costs 13 MiB, and `Docker.desktop` runs it.
- **Mode A:** `enable = true` follows `preinstalls`. `enable = false` stays inert.
- **OBS Studio, Kdenlive and Xournal++ leave `preinstalls`.** Their names stay
  accepted by `preinstallsExclude` and do nothing, so nobody who already opted out
  gets a failed rebuild. They come out of the "The set is:" message.
- **Remove must work for a default-on app** (spec Design 5), which the owner approved.
- **`lib.lowPrio` on the seven.** A user's own binary wins, including when they pick
  one of the seven by hand. Not on all of `appPackages`.
- **`nixarchy-app-enable` on a default-on app stays as it is.** It writes a redundant
  `true`, which is how a live `false` is undone.
- **`command-not-found` is out of scope:** #1618 fixes it.

Rejected in the spec, do not revisit: a template line for existing machines; listing
the seven in `preinstalls`; dropping the three names from the accepted list;
`data/apps.nix` rows for the three; telling a pick from the default with
`highestPrio`; a notice at rebuild.

## Three additions beyond the spec's text

Reviewers and the owner should check these, because the spec does not spell them out.

1. **`nixarchy-search` also reads live rows.** `mark_live`
   (`modules/apps.nix:3236-3239`) treats any live `#@ id` row as selected, so a live
   `hype.enable = false` would show `[enabled]` for an app that is off. Spec Design 5
   does not list it, and it is the same defect as the counts. Step 2 fixes it. A
   default-on app on a commented row still shows no status in that picker: accepted,
   since picking it is the harmless redundant `true`.
2. **The baked ids follow the switch.** `defaultOnIds` is empty when
   `omarchyApps.enable` is false. On that machine a commented row really does mean
   off, so the old behaviour is the right one. The default path is what the spec says.
3. **"The shipped mimeapps list" is read as `xdg.mime.defaultApplications`** in the
   conditional step 7. `config/hyprland-mimeapps.list` is seeded once, so it would not
   reach an existing machine, and it is vendored. Nothing sets a default for these
   types today: `modules/` has no `xdg.mime` or `xdg.mimeApps`, and
   `pkgs/omarchy/default.nix:1266-1291` copies only `*.desktop` from upstream's
   `default/applications`. So today's handlers rest on cache order, and whether the
   new apps move them is only answerable in a VM.
