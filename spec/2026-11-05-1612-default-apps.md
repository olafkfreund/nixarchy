# Spec: New installs follow Omarchy 4.5's default app set

The owner's decisions, from the approved intent:

- Existing machines get no keep-line.
- The switch covers Hype, Signed, Monologue, Omacalc, Omacut, Omawrite and Aether.
- Omarchy Local AI is out.
- Lazydocker stays.
- Mode A `enable = true` follows `preinstalls`.

## Design

**1. The switch follows `preinstalls`.** `omarchyApps.enable`
(`modules/apps.nix:1358`) becomes:

```nix
omarchyApps.enable = lib.mkOption {
  type = lib.types.bool;
  default = cfg.preinstalls;
  defaultText = lib.literalExpression "config.programs.nixarchy.preinstalls";
  description = ...;
};
```

The per-app default stays `mkDefault true` (`modules/apps.nix:1526-1530`), so a
line in `apps.nix` still wins. `programs.nixarchy.enable = false` stays inert
through the gate at `modules/apps.nix:1523`.

**2. Local AI leaves the set.** Remove `preinstall = true` from
`data/apps.nix:572`. `modules/services/agent-local.nix:56` installs it for
anyone using the service, and it stays in the catalogue.

**3. Three apps leave `preinstalls`.** Remove `xournalpp`, `obs-studio` and
`kdenlive` from `modules/nixos.nix:1537-1543`.

**4. Old opt-outs keep evaluating.** The three names stay accepted by the
assertion at `modules/nixos.nix:946-982` and do nothing. They come out of the
"The set is:" message. The list is written out twice there; bind it once.

**5. Removing an app has to work for a default-on app.** Commenting a row out
now means "back to the default", which is on. Bake the preinstall ids into the
scripts below. Other apps behave as they do today.

- `nixarchy-app-disable` (`modules/apps.nix:2022-2066`) comments the row out and
  reports "disabled", which leaves a preinstall app installed. A commented row
  reports "is not enabled" while the app is on, and an absent row exits 1. For
  preinstall ids it writes a live `<id>.enable = false;`, in either the short or
  the `programs.nixarchy.apps.<id>` form. If the row is missing, it first takes
  it from the template, the way `nixarchy-app-enable` does at `:1976-1987`.
- `nixarchy-app-remove` (`:2091-2098`) lists only live `.enable` rows. So it omits
  an app that is on by default, and lists one already set to `false`. For
  preinstall ids it lists those with no live `false` row and hides the rest.
- The "queued" and "still enabled" counts (`:2002`, `:2055`) count a live `false`
  as selected. They count `= true` only.
- `templateRow` (`:135-147`) writes preinstall rows as
  `# hype.enable = false;  #@ hype  # on by default`. A commented
  `hype.enable = true` would read as "off". Files already on disk keep their old
  rows, and the scripts above handle both.

`nixarchy-app-enable` on a default-on app writes a redundant `true` and says
"queued". That is harmless, and it stays, because it is how a live `false` is undone.

**6. The new default apps yield to a user's own binaries.** The comment at
`modules/apps.nix:1572-1574` says nixarchy's unasked packages are `lowPrio` and
the user's picks are normal priority. These seven are now unasked. Evaluated on
the target configuration, ours sits at index 26 of `systemPackages` and a user's
own `hype` at index 156, with no priority set on ours. So in `appPackages`
(`modules/apps.nix:117-121`), wrap `preinstall` apps in `lib.lowPrio`. That
changes `meta` only, not the derivation. It also applies when a user picks one of
the seven by hand, so the comment at `:1572-1574` must say so. Their own copy still
wins, which is what they would want.

Nothing in nixpkgs collides today: `nix-locate --at-root --whole-name /bin/<name>`
finds no package for any of the seven. As a control, `obs` finds `obs-studio.out`.

**7. Text that goes stale.** Everything the intent lists, plus:

- `pkgs/apps/omacut.nix:23`, `aether.nix:65`, `omacalc.nix:24`, `omawrite.nix:21-25`
- `data/omarchy-packages.nix:17`
- `data/apps.nix:23-24`, `:527-528`, `:661-664`
- `docs/manual/other-packages.md:22-25` ("every line commented out"), `:58-74`
  ("Two things from 4.5 come without asking"), `:276-280` (what Remove lists)
- `tests/session.nix:1796`, `:1825-1826`, `:1837`, `:1898`, `:1916`, `:1934`
- `installer/cd.nix:634` needs rewording. The reference host now carries these

**8. Named consumers.**

- `pkgs/verify.sh:1205`: `xournalpp` becomes `signed`.
- `tests/demo/default.nix:972`: the row becomes

## `nixarchy pkg add` with a dotted attribute: tried, and it works

The migration step depends on this, so it was run for real. I built the shipped
`nixarchy-pkg-add` and `nixarchy-pkg-remove` from this tree and ran them against a
fixture `$HOME` and the real pinned nixpkgs.

- `obs-studio`, `kdePackages.kdenlive` and `xournalpp` each exited 0.
- The file gained `kdePackages.kdenlive  #@pkg kdePackages.kdenlive` inside
  `with pkgs; [ ... ]`, and `nix-instantiate --parse` accepted it.
- Removing the dotted name deleted only that line, and adding it back worked.

`nixarchy pkg add` is a plain `exec nixarchy-pkg-add` (`modules/apps.nix:3618-3620`),
read but not run. A rebuild from that file was not run either.

`tests/app-selection.nix:82-86` covers only a curated redirect today, so a check
is added. The script's evaluation cannot be stubbed: `nixpkgs=${pkgs.path}` is baked
in, and `writeShellApplication` puts the real `nix` first on `PATH`. So the check
runs the real evaluation with `NIX_STATE_DIR` in the build directory, the setup
`tests/options.nix:5233` uses. Whether that works in the sandbox is unproven. If it
does not, this stays a hand-run measurement and the plan says so in
`tests/AGENTS.md` (§3).

|---|---|---|
| `preinstalls-exclude-retired` | `preinstallsExclude = [ "obs-studio" "kdenlive" "xournalpp" ]` | a name leaves the accepted list, because a false assertion lands in `c.assertions`, which is what stops a rebuild for exactly the people who already opted out |
| `systempkg-own-hype` | `environment.systemPackages = [ (writeShellScriptBin "hype" ...) ]` | ours wins `bin/hype`. Same shape as `systempkg-own-ffmpeg` (`tests/coexistence/default.nix:58-68`): it builds `system.path` and reads the link |

Fixtures do not run themselves. Each needs its own entry in the check body
(`tests/coexistence/default.nix:209-217`). The first reads `c.assertions` through
`agentLocalCheck` (`:103-120`), since extending a config does not fail on an
assertion by itself.

Deliberately no fixture for a user's own `programs.obs-studio`. Once ours is gone
nothing overlaps, so it cannot fail (§14).

## Alternatives rejected

- **A line in the install template for existing machines.** The owner declined it:
  it makes a permanent second population.
- **Listing the seven in `preinstalls` itself.** Opting out would move from a line
  in `apps.nix` to `preinstallsExclude`, and `omarchyApps.enable` would have no
  meaning left.
- **Dropping the three names from the accepted list.** That breaks rebuilds for
  people who already opted out, which the intent forbids.
- **Adding `data/apps.nix` rows for the three.** That adds catalogue, template and
  menu entries for apps upstream dropped, when `nixarchy pkg add` already restores
  them.
- **`lowPrio` on all of `appPackages`.** The comment at `modules/apps.nix:1573`
  keeps a user's explicit picks at normal priority on purpose.
- **Telling an explicit pick from the default, using `options.*.highestPrio`.** That
  is more code to separate a case where the user's copy should win anyway.
- **A notice printed at rebuild.** It cannot tell whether the user wanted these
  apps, and it would nag forever. The owner chose the release note and migration
  step.

## Risks

- **A rebuild removes apps from someone who did not read the notes.** Accepted by
  the owner. `nixarchy update` prints no package diff.
- **`command-not-found` will not help them.** See Open points.
- **Default handlers may move.** All three claims below are read from the built
  `.desktop` files:
  - Signed claims `application/pdf`.
  - Omacut claims `video/mp4`, `video/x-matroska`, `video/quicktime`, `video/webm`,
    `video/x-msvideo` and `video/mpeg`.
  - Omawrite claims `text/plain`, `text/markdown` and `text/x-markdown`.

  Upstream pins pdf, video and plain text to Evince, mpv and nvim in
  `default/applications/mimeapps.list:11,17-30,33`. Nobody has established whether
  that file reaches a nixarchy session: `config/hyprland-mimeapps.list` names none
  of them. Upstream sets no default for markdown. Session gains a probe for this
  that asserts the exact handler (see Verification). If it fails, the fix is entries in the shipped mimeapps list,
  and the plan must say so.
- **aarch64 Mode A machines now build all seven from source.** All seven evaluate
  on `aarch64-linux`, but no job here builds them, and the cache is x86_64 only.
- **Evicted cache paths now cost every network install, not one opt-in user.**
  The nightly `repush` covers allowlist entries (CLAUDE.md §4).
- **Parallel work.** #1611, #1613, #1614 and #1615 change `modules/nixos.nix`.
  This spec touches only `:617-630`, `:946-982` and `:1535-1543` there. #1613 has no
  spec yet, so it needs a rebase check on `tests/session.nix` and the manual.

## Open points for the owner

1. **`command-not-found` is broken today, separately from this issue.**
   `modules/nixos.nix:206` passes `--top-level`, and the shipped `nix-locate`
   (nix-index 0.1.11) rejects it: `error: unexpected argument '--top-level' found`.
   stderr goes to `/dev/null`, so typing `obs` will say nothing in nixpkgs provides
   it, on every machine that loses the app. Recommend a separate issue. The
   migration step above does not rely on it.
2. **Removing a default-on app (Design 5) was not asked for by name, and it is the
   largest part of this change.** Without it, Remove > App / package cannot see the
   seven and a hand-written `hype.enable = false;` is the only way out, which the
   intent's "one line" does allow. Recommend keeping it: otherwise the menu says an
   app was disabled and leaves it installed.
