# Intent: the nightly review stops asking for a downgrade and an RC release while main is on an RC

## Problem

Since #1405, `main` pins Omarchy v4.5.0-rc1 on purpose. The nightly review
(`pkgs/review.sh`) then flags two rows every night, so #1376 can never close
itself:

- `omarchy` (:240-248) compares the pin with `releases/latest`, which skips
  prereleases. It answers v4.0.6 and says "bump": a downgrade, the mistake
  #1405 fixed in the nightly bump but not here.
- `release` (:320-337) says "tag v4.5.0-rc1-1 to publish one". Any `v*` tag
  fast-forwards `release` (#1405), so following that advice would ship the RC
  to every installed machine.

Measured with `nix run .#review` on origin/main 2ee0503d (2026-10-21).

## Proposed outcome

While `main` is on an RC, both rows read ok, as long as the facts they guard
still hold:

- `omarchy`: the pin is the newest by `omarchy-newest.sh`'s ordering.
- `release`: the newest release carries upstream's newest **final**.

A real lag still flags: a newer RC or final than the pin, or a final without
its ISO.

## Constraints

- Reuse `.github/scripts/omarchy-newest.sh`. One ordering, not a second copy.
- §1: show both rows red on the current script and green after, against the
  live review.

## Open questions

None. The approach is fixed by #1405's decisions.
