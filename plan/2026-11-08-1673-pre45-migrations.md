# Plan: machines seeded before Omarchy 4.5 get the 4.5 user-file migrations that still apply

Twenty rows across eleven issues (#1671-#1681), as one PR stacked on #1670
(`fix/1610-user-state-migrations`), one commit per issue, merged with a
merge commit.

## Decisions carried from the approved spec

1. **Run upstream's scripts.** 14 run verbatim from
   `$OMARCHY_PATH/migrations/<id>.sh`. Three run as build-time edited
   copies made with `substituteInPlace --replace-fail`:
   - 1786719479: the `omarchy-mise-install` block is removed;
   - 1788129995: `omarchy-pkg-add omasnap` and `omarchy-pkg-drop satty tensaku`
     are removed;
   - 1791723398: `/usr/share/omarchy-nvim/config` becomes the
     `omarchy-nvim-config` package's `share/omarchy-nvim`, and
     `omarchy-pkg-present omarchy-nvim || exit 0` becomes
     `[[ -d <that dir> ]] || exit 0`.

   One row is a nixarchy port with its own script (1791479273, the
   dictation default). Two are declined: 1791123731 (a comment) and
   1792474908 (Brave Origin is unavailable).
2. **Runner contract** (upstream's `bin/omarchy-migrate:88-96`): for each id
   in ascending order whose marker `$state/<id>.sh` is absent, run
   `OMARCHY_PATH=... bash -euo pipefail <script>`, and touch the marker on
   exit 0. On failure, log the id to the journal, write no marker, and stop
   the run. This runs after `bar_migrations`, today's body made a function
   whose "stop" exits are `return 0`.
3. **The list comes from the ledger.** A `ported` row names
   `run = "upstream"`, `run = "edited"`, or `run = "port"`.
   `checks.user-migrations-ledger` rejects a `ported` row with no `run`,
   and a `run` on a row that is not `ported`.
4. **No pre-4.5 detector.** Every script guards on the old state itself, so
   on a 4.5 home it is a no-op that writes a marker.
5. **Dictation (1791479273)** writes `voxtype` to `defaults/dictation` when
   all hold: it reads `superwhisper`, no marker, `command -v voxtype`, and
   `~/.config/superwhisper/preferences.json` is absent.
6. **#1681:** `"agy"` joins the `defaultAgent` enum (`modules/nixos.nix:660-668`).
   `gemini` keeps evaluating, warns, and maps to `agy`. **This reverses a
   recorded decision.** `pkgs/omarchy/nix-bin/omarchy-default-agent:74-76`
   says "Google deprecated gemini-cli in favour of Antigravity, but nixpkgs
   still has a maintained gemini-cli and people still ask for it by name, so
   both stay." Step 12 rewrites that comment with the new reason (4.5's
   launcher has no `gemini` case, `bin/omarchy-agent:201-203`). The owner
   confirms this at plan approval, or replaces step 12 with the alternative:
   keep `gemini` real by adding a `gemini)` case to the launcher (a carried
   patch).
7. **Deletions** (1787679775, 1792648436) run as upstream ships them. The
   release notes name both.
8. **Verification:** every ported id has a fixture case that asserts the
   4.5 result, a second run that changes nothing, and a 4.5-shaped home
   that stays byte-identical. The 4.5 home carries `live.json`,
   `history.json`, `quiet.json` and a `3.lua` layout. Edited copies and
   the port are also diffed against upstream's original run under the same
   stubs.

## Steps

1. **Runner** — `pkgs/omarchy/nix-bin/omarchy-migrate-user`:
   - wrap lines 21 onward in `bar_migrations()`, turning each bare `exit 0`
     into `return 0`; lines 21-22 become its first two lines;
   - add `run_upstream()` with decision 2's contract, reading the id list
     from `$NIXARCHY_USER_MIGRATIONS/list` (one `<id><TAB><script path>`
     per line), and the main flow `bar_migrations; run_upstream`;
   - `modules/home.nix:2458-2471`: the hook exports
     `NIXARCHY_USER_MIGRATIONS=${cfg.package.passthru.userMigrations}` (step 2).

   Verify: `bash -n`, shellcheck, and #1670's existing `checks.user-migrations`
   still passes (the bar cases are unchanged).
   Traps: `set -e` does not reach inside `$(...)` (§5), so write
   `out=$(cmd) || return`. `read` on a TAB-separated line with an empty first
   field shifts fields (§13), but the id is never empty, so assert it.

2. **The derivation** — `pkgs/omarchy/user-migrations.nix`, a `runCommand`
   taking the built tree's `share/omarchy/migrations`, `omarchy-nvim-config`
   and `data/user-migrations.nix` (via `builtins.toJSON`). It writes `list`,
   plus `scripts/<id>.sh` for the edited rows, each made by
   `substituteInPlace --replace-fail` on a copy. Expose it as
   `passthru.userMigrations` on the omarchy package. Extend
   `tests/user-migrations-ledger.nix:50-57` with decision 3's two rules.

   Verify: `nix build .#omarchy.userMigrations` and read `list`. The ledger
   check passes, and fails on a `ported` row without `run` (§1).
   Traps: keep this out of `installPhase`, because
   `checks.install-phase-budget` measures it (#1663). A `--replace-fail`
   that matches nothing fails the build, which is wanted.

3. **Harness** — `tests/user-migrations/run` and `tests/user-migrations.nix`:

   - `case_fresh45`: a 4.5-shaped home carrying `live.json`, `history.json`,

     `same_tree` against the snapshot apart from new markers, and assert
     every marker was written;
   - `oracle_run <id> <fixture>`: runs upstream's original under the same
     stubs, for the edited and ported rows.

   Verify: the harness builds and `case_fresh45` passes with an empty list
   (no rows ported yet).
   Traps: §1, "a content test is not an ownership test". Fixtures that
   matter carry a symlink to identical content, and the scripts' own
   symlink guards must leave it alone.

## Deviations (Codex plan review, 2026-11-08, verified before coding)

These replace the matching text above; they were found after approval and
before any code.

1. **Fresh homes are marked, not trusted (replaces decision 4).** Two
   scripts are not no-ops on a 4.5 home: 1786719479 links skills into
   `~/.gemini/config/skills` whenever the skills directory exists, and
   1793477875 adds F9 and Super+Ctrl+X when dictation is configured.
   Upstream avoids this the same way: "the finalizer marks all shipped
   migrations complete on a fresh install"
   (`install/user/first-run/audio-tuning.sh:5-7` in the source input). So
   the activation that seeds `shell.json` into a home that has none also
   touches a marker for every id in the list, and for the three bar ids. A
   home seeded before this change has no such markers, and gets the
   migrations. `case_fresh45` asserts the markers and an unchanged tree
   after the runner.
2. **#1672 / 1791723398 is declined, and #1672 stays open.** The edited copy
   needs `lua/plugins/lualine-transparent.lua`, and the script exits 1
   without it. `pkgs/omarchy-nvim` copies a tree that has only
   `plugin/after/transparency.lua`, so the runner would stop at this id on
   every login. Reason: "needs omarchy-nvim-config to ship
   lualine-transparent.lua first (#1672)". The PR says `Refs #1672`.
3. **`bar_migrations` runs in a subshell** (`( ... )`), so the `exit 0`
   lines inside `move()` and the body keep stopping the bar work, with no
   edit to them. The runner then continues with `run_upstream`.
4. **The existing ported bar rows** (1790042972, 1791968925, 1791969355) get
   `run = "bar"`. The list excludes `bar`, and the ledger rule requires a
   `run` on every `ported` row.
5. **The derivation is built first.** Steps 1-3 land together as one commit
   ("the runner"), because step 1's hook references step 2's derivation.
   Verification adds a two-id runner fixture: the first exits 1, the second
   must not run, no marker is written for either, and a second run with the
   first fixed runs both in order.
6. **#1681 also touches `modules/apps.nix:1662`**, the package map indexed
   by `cfg.defaultAgent`. It gains an `agy` entry (the package
   `omarchy-default-agent:29` names, `antigravity-cli`). It exists in nixpkgs
   (1.4.8) and is **missing on nixos-26.05**, so the entry uses the same
   guard the antigravity agent row already uses (`modules/apps.nix:~459`).
   `gemini` selects that same package. The test reads
   the selected package in both states.
7. **References:** `bin/omarchy-migrate:88-96` is the upstream source input
   (the vendored tree carries nixarchy's refusal). The agent option cases in
   `tests/options.nix` are found by grepping `defaultAgent`, not at line
   1914.
