# Spec: an install VM never shares p620 with edge's VM checks

The intent is approved:
- both sides wait (edge before each VM check; the install bounded at 60
  minutes, loudly);
- one script, `vm-host-free.sh`, with a check;
- CLAUDE.md §6 names the local-build rule.

## Design

### 1. `.github/scripts/vm-host-free.sh <install|edge>`

The script asks GitHub which VM job is running, using the jobs API. The
host's qemu count cannot tell an install's VMs from edge's.

| asker | busy when |
|---|---|
| `install` | an `omarchy-edge` run has its `verify` job `in_progress` |
| `edge` | an `install check` run has its `install` job `in_progress` |

- **Reading:**
  - `$GH api "repos/$GITHUB_REPOSITORY/actions/runs?status=in_progress&per_page=50"`
    for the runs;
  - `$GH api …/runs/<id>/jobs` for each run of the other workflow;
  - `$GH` defaults to `gh` and is stubbable;
  - the asker's own run is excluded (`$GITHUB_RUN_ID`).
- **Output:** `free` with exit 0, or `busy: <workflow> run <id> job <name>`
  with exit 1.
- **A failed API call exits 2.** Output is captured before it is split
  (§4: a failed `mapfile < <(cmd)` reads as an empty list, which would
  read as "free"). Exit 2 means "not known to be free".

### 2. The wait, on both sides

One shell loop around the script: poll every 60 s up to a bound, and print
what it waits on.

- **Install** (`install-check.yml`, a new step before "Install onto a
  blank disk…"):
  - asks `install`, bound **60 min**;
  - on the bound: `::error::` naming the edge run, plus a step-summary
    line, then exit 1.
- **Edge** (`omarchy-edge.yml` `verify`, the loop at "boot the VM checks,
  each separately"):
  - asks `edge` before `session`, `coexist` and `plugin`, but not
    `options`, which is evaluation only;
  - bound **120 min** per check;
  - on the bound, that check is marked failed and named, the way a build
    failure is, so the digest and the report see it.
- Exit 2 counts as busy for the loop. A permanently broken API therefore
  ends at the bound with its error printed, never in a silent start.
- **The race that remains** is two checks made in the same minute, before
  either VM starts. It is accepted: the window is under a minute instead
  of 30–50.

### 3. `gh` on the self-hosted runner

A self-hosted step's shell has only what the environment provides (the
install job's own comment: no `ps`, `pgrep` or `gh`). Both waits run the
script as `nix shell nixpkgs#gh -c .github/scripts/vm-host-free.sh …`,
with `GH_TOKEN: ${{ github.token }}`.

`install-check.yml` gains `actions: read`. `omarchy-edge.yml` already has
it.

### 4. `checks.vm-host-free`

A `runCommand` with a stub `gh` that serves fixture JSON. The cases:

| case | expected |
|---|---|
| install asks; edge `verify` in progress | busy, naming the run |
| install asks; edge run in progress but `verify` not started (`prepare`) | free |
| edge asks; an install job in progress | busy |
| edge asks; only its own run in progress | free |
| nothing in progress | free |
| the API call fails | exit 2, not free |

Red: a one-shot variant cannot vary with the job state. Instead, the
script with the `in_progress` filter removed (any run counts) must fail
the "verify not started" case. The "API fails" case must also fail
against a variant that treats a failed call as an empty list.

### 5. CLAUDE.md §6

The tier table's "package build that is not cheap" row adds: "and no
`install check` `install` job or `omarchy-edge` `verify` job in flight
(#1365)". The paragraph under it records that the load gate alone
admitted the 15:09 stall.

## Alternatives rejected

- **A host `flock`:** it needs a shared path in p620's own NixOS config,
  outside this repo (intent constraint).
- **Joining edge's `verify` to the install concurrency groups:** one group
  per job, and extra pending jobs evict (#548).
- **Counting qemu processes in `/proc`:** a second install's VMs and an
  agent's local VM look the same as edge's, so the count would block
  installs on each other, against the measured two-install cap.
- **Dropping to one install slot:** it halves merge throughput to fix an
  overlap that only edge creates.

## Risks

- **Merge latency:** an install waits up to one edge `verify` (once a
  night, or on a dispatch).
- **API rate:** about 2 calls a minute per waiting job, far under
  `GITHUB_TOKEN`'s limits.
- **A job name changes** (`verify`, `install`): the script would see
  nothing and say free. The check's fixtures pin the names, and the
  script names the workflows by their file name
  (`omarchy-edge.yml`, `install-check.yml`), which is stable.
