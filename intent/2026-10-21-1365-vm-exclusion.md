# Intent: an install VM never shares p620 with edge's VM checks

## Problem

Twice on 2026-10-21, a `main` install VM froze mid-boot and failed at its
900 s wait. The same code passed on the next run. Both times the guest
logged the host-starvation signature (CLAUDE.md §6). #1367's probe got
"no answer from the guest within 90 s", so the guest was frozen, not stuck
on a unit:

- **15:09 (16280219):** the target reached `Update is Completed` at 4.5 s,
  then `[311.29] clocksource: Watchdog remote CPU 1 read timed out`.
- **09:59:** `clocksource: Long readout interval … 7286403832`, then the
  timeout.

Both overlapped other VM work on p620:
- 09:59: `omarchy-edge`'s `verify` (10:00–10:49);
- 15:09: a PR install, `verify` (until 15:08), and local agent builds.

The mechanism, read from the workflows:
- **`omarchy-edge` `wait-idle` checks once.** It waits until no run is in
  flight, then `verify` boots VM checks one after another for 30–50
  minutes. An install that starts in that window shares the host.
- **Installs never wait for edge.** `install-check.yml` caps installs at
  two (the `nixarchy-install-vm-{1,2}` groups) but knows nothing of edge's
  VMs.
- CLAUDE.md §6 already measured that two installs alone are fine and that
  a third tenant is not. Edge's `verify` is a third tenant nobody counted.

A red install like this:
- blocks merges until it is re-run;
- reads as a regression until someone digs (today it took a log read to
  rule out #1411);
- teaches people to re-run without reading, which §10 forbids.

## Proposed outcome

- **An install never runs while edge's `verify` boots a VM, and the
  reverse.** The exclusion is two-sided, not a one-shot check.
- **No CI slot is lost or evicted to get it.** GitHub keeps one pending
  job per concurrency group, and extra queuing cancels jobs (#548), so
  the exclusion must not add jobs to the install groups.
- **Everything stays visible.** A job that waits says why in its log, and
  a wait that exceeds its bound fails loudly rather than starting on a
  busy host.

## Affected users and systems

- `.github/workflows/omarchy-edge.yml` (`verify`) and
  `.github/workflows/install-check.yml` (`install`). These are CI gates, so
  the owner merges (§11).
- PR merge latency: an install that lands during edge's `verify` waits up
  to its length (about 30–50 min, once a night or on a dispatch).

## Constraints

- **No host-side lock.** A `flock` on p620 would need a shared path set up
  in p620's own NixOS config, which is outside this repo and not mine to
  touch. The exclusion has to live in the workflows, through `gh` queries,
  the way `wait-idle` already works.
- **Re-check, don't check once.** The race is the window after the check.
- **§1:** the decision ("may I boot a VM now?") goes into a script with a
  stubbed `gh` and a check, like `omarchy-newest.sh`. A red case shows
  today's one-shot logic letting an install overlap.
- **Measure afterwards:** state the expected effect, and watch the next
  nights' installs and edge runs. Do not claim the fix from one green run.

## Open questions

1. **Where does each side wait?** I propose:
   - (a) edge's `verify` re-checks before **each** VM check that no
     `install` job is in progress, and waits if one is;
   - (b) the install job, before its VM build, waits while an
     `omarchy-edge` `verify` job is in progress, bounded (60 min) and
     loud.

   Together that leaves at most a sub-minute race, not a 50-minute one.
2. **One script for both sides?** I propose yes:
   `.github/scripts/vm-host-free.sh <who-is-asking>` prints "free" or what
   is busy. Both workflows call it in a wait loop.
3. **Local builds:** agents' package-tier builds also loaded p620 at
   15:09. I propose that CLAUDE.md §6's tier table names this explicitly:
   no package-tier local build while an install or edge `verify` is in
   flight, not only "load below 12". (Already adopted as an agent memory
   today.)

## Decisions (owner, 2026-10-21)

Approved with the three proposals: both sides wait (edge per VM check;
the install bounded at 60 min); one script `vm-host-free.sh` with a check;
CLAUDE.md §6 names the local-build rule.
