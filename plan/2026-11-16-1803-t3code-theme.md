# Plan: T3 Code follows the Omarchy theme when nixarchy installs it

## Approved decisions (from the spec)

- **Where:** a `home.activation.nixarchyT3CodeTheme` entry in
  `modules/home.nix`, beside `nixarchyChromiumHosts` (:1651). It is
  `lib.mkIf (appEnabled "t3-code")`, with `lib.hm.dag.entryAfter [
  "nixarchySeed" ]`.
- **Non-fatal under `set -eu -o pipefail`.** Every step that can fail is an
  `if` condition or ends in `|| warn`, and nothing exits the activation
  shell. `warn` prints `nixarchy: T3 Code: <what>` on stderr.
- **Steps:**
  1. `t3home` is `lib.escapeShellArg` of
     `config.home.sessionVariables.T3CODE_HOME` when set, else
     `"$HOME/.t3"`;
  2. `run mkdir -p "$t3home/userdata" "${config.xdg.stateHome}/nixarchy"`,
     or warn and skip everything else;
  3. run `omarchy-theme-set-t3code` (`run env PATH=<coreutils gnused
     gnugrep>:$PATH OMARCHY_PATH=${omarchyPath} T3CODE_HOME="$t3home"
     ${omarchyPath}/bin/omarchy-theme-set-t3code`). "Published this time"
     requires all of:
     - exit 0;
     - the source `$HOME/.local/state/omarchy/current/theme/t3code.json`
       exists;
     - `cmp -s` of that source with `$t3home/userdata/themes/omarchy.json`;
  4. the marker is `${config.xdg.stateHome}/nixarchy/t3code-theme-selected`.
     If it is absent and the palette was published this time, read
     `jq -e 'has("defaultTheme")' "$t3home/userdata/settings.json"`:
     - **file missing, or exit 1:** `run timeout -k 5 20 "$t3" theme set
       omarchy --base-dir "$t3home"`, then, only on success, `run touch`
       the marker;
     - **exit 0:** `run touch` the marker;
     - **anything else:** warn, and do nothing more;
  5. `$t3` is `${osConfig.programs.nixarchy.apps.t3-code.package}/bin/t3`.
- **`jq`** is referenced as `${pkgs.jq}/bin/jq`, not from `PATH`.

## Steps

1. **`modules/home.nix`:** the entry, as above, after
   `nixarchyChromiumHosts`.
   - A one-line comment says why (#1803).
   - A one-line comment on `t3home` says a shell-rc-only `T3CODE_HOME`
     does not reach activation.
   - Verify: the evaluation in step 2's check; `home-writers-dry-run` and
     `home-activation-writes` still pass.
   - Traps:
     - Nix `''` strings: `''${` for a shell `${`;
     - `set -e` does not reach inside `$(...)` (CLAUDE.md §5), so capture
       `jq`'s status with `if … then` or `rc=$?` right after the call, and
       never through a command substitution;
     - nixfmt after the edit.
2. **`tests/t3code-theme.nix`** (runCommand, cheap tier), registered in
   `flake.nix`'s `uniformChecks` (:1820) with a one-line comment.
   - **Shape:** a standalone Home Manager configuration in the shape of
     `tests/home-manager-writers.nix`, with
     `extraSpecialArgs.osConfig.programs.nixarchy.apps.t3-code = { enable =
     true; package = fixtureT3; }`.
   - **`fixtureT3`:** a `writeShellScriptBin "t3"` that appends `$*` to
     `$T3_CALLS`, then `exec ${pkgs.t3code}/bin/t3 "$@"`, wrapped as a
     package with `bin/t3`.
   - **A second fixture,** `sleepyT3`, runs `trap '' TERM; sleep 600`, for
     case 12.
   - **The harness:**
     - `set -eu -o pipefail`;
     - source the pinned home-manager input's
       `modules/lib-bash/activation-init.sh`, for `run` and `DRY_RUN`. Read
       the file for what it expects defined first, and define only that;
     - then source the entry's `.data`;
     - every case runs in a subshell under `timeout 120`, with a fresh
       temporary `HOME`.
   - **Fixture theme:** `$HOME/.local/state/omarchy/current/theme/t3code.json`,
     a valid palette, meaning `appearance` is `"dark"` and every colour is
     `#rrggbb`. The spec's measurement found that a placeholder-only file is
     rejected.
   - **The publisher** runs from `omarchyPath`'s real
     `omarchy-theme-set-t3code`. For case 5, a `PATH`-first wrapper named
     `omarchy-theme-set-t3code` is not possible, because the entry calls it
     by absolute path. So case 5 asserts "publish attempted" through the
     side effect the real script has when the source exists in a sibling
     run, and through the entry's own stderr message. Pick the cheapest
     falsifiable signal, and say which in a comment.
   - **Cases:** the twelve from the spec, each printing PASS or FAIL.
   - An evaluation `assert` that the entry's `after` contains
     `nixarchySeed`.
   - Verify: the check passes. Then the §1 mutations from the spec, one at a
     time from a clean `HEAD`, each failing its case.
3. **`tests/options.nix`:** a Mode A case like `aiCase` (:507-511):
   - `on = (homeOn { apps.t3-code.enable = true; } { }).home.activation ?
     "nixarchyT3CodeTheme"`;
   - `off` is the same with the app off;
   - registered where `aiCase` is used, in the shard the cases' family
     belongs to (`options-shards` says which).
   - Verify: `options-shards` (cheap), and the shard that holds it (VM
     tier).

## Tests

- **Cheap tier:** every target `generated-checks.sh generated` prints,
  `t3code-theme` among them, plus `home-writers-dry-run` and
  `home-activation-writes`.
- **VM tier:** the options shard holding step 3's case, and
  `options-files`.
- No VM boots T3 Code. The CLI is exercised headless in step 2, which is
  where its behaviour was measured.

## Rollback

Revert the commit. The entry is the only thing that writes, and what it
wrote stays, as any T3 Code use would leave it: `~/.t3/userdata`, the
palette, `defaultTheme` and the marker.
