# Intent: Small Omarchy 4.5 gaps, in three groups that can close separately

## Problem

Five small gaps came out of #1610's second pass. Each was checked on this
branch, on `main` at Omarchy v4.5.0, by reading the code and running it in a
throwaway `HOME` with no compositor to reach. Running them changed two of the
descriptions and turned up one more bug.

**1. Every first run that gets online offers an update that isn't there.**
`install/user/first-run/wifi.sh:12-23` calls `checkupdates`, which nothing here
ships (`pacman-contrib` is a `skip` row). Its status is 127, the script only
treats 2 as "nothing to do", and so `update_pending` answers yes. Run verbatim on
a `PATH` without `checkupdates`, it printed yes. Once the machine is online, a
critical toast sends the user to `omarchy-update` on a fresh install. Upstream's
own comment says a toast that leads nowhere "teaches people to dismiss the next
one". nix-bin's `omarchy-update-available` answers the nearest question NixOS
has: is this machine's locked release behind the `release` branch? It is narrower
than upstream's "any package". The installer writes the `release` ref it needs
(`installer/mkFlake.nix:38`), but it exits 1, so no toast, for an untagged lock or
tip, a flake that doesn't track `release`, or no network. `wifi.sh:19` already
calls it, on a branch the 127 never reaches.

**2. Preinstall scripts call `hyprctl reload` directly.**
`omarchy-install-preinstalls:17` and `omarchy-remove-preinstalls:47` print
`HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)` outside a session
(ssh, for example). This is milder than the issue says:

- `install` has finished its work by then, and exits 1 on a run that worked.
- `remove` carries on and exits 0, with the error in its output.

Upstream's `omarchy-restart-hyprctl`, already in the tree, exited 0 in the same
conditions.

**2a. Found while running gap 2: `remove` asks a question v4.5 can't answer.**
`omarchy-remove-preinstalls:61` calls `omarchy-install-hermes-cli --owns`. That
vendored script has no `--owns`, only `--check`, `--now` and `--retire-mise`, so
it prints a usage line and returns non-zero. The Hermes wrapper is therefore
never removed, and each run prints that stray line. The failure is safe: it
keeps a file rather than deleting one. The probe ran against the tree on this
machine's `PATH`. The missing flag was read from the v4.5 source. The fix needs an
ownership rule: `--check` asks whether Hermes is fully installed, and
`--retire-mise` exits 0 whether or not it owns the wrapper, so swapping either in
could delete a user's own `hermes`.

**3. `vi` doesn't exist, and the ledger says it does.**
`data/omarchy-packages.nix:751` says "Neovim provides vi/vim aliases where
wanted". The reference system's `environment.systemPackages` has `neovim` and no
package named `vi` or `vim`. `modules/`, `pkgs/` and `installer/` set no
`viAlias` or `vimAlias`. Upstream lists `vi` in `install/omarchy-base.packages`,
and no upstream script calls it, so what's missing is the command for someone who
types it. The ledger's reason is false either way.

**4. Choosing a missing default browser or editor stops at advice.**
In a throwaway `HOME`, with only stubs and basic tools on `PATH`:

- `omarchy-default-browser --install firefox` printed `nixarchy-app-enable
  firefox` and `nixarchy-apply`, then exited 1 without setting a default.
- `brave` is worse: `omarchy-pkg-aur-add` printed "no AUR on NixOS" and exited 1,
  though `data/apps.nix` maps Brave. By reading, Chrome, Edge and Zen take the same
  route, and so does Brave Origin, which `data/apps.nix:335` marks unavailable.
- `omarchy-default-editor --install vim` printed the same advice, exited 1 and
  recorded nothing. Cursor, and Neovim if removed, also go through
  `omarchy-pkg-add`; VSCode, Zed, Helix and Emacs go through their own installer
  scripts, which were read but not run.

The probe used a two-row fixture table in place of the generated one, with rows
matching `data/apps.nix`.

The user has to enable the app, rebuild, then choose again. `omarchy-default-agent`
in nix-bin already does this properly: it records the choice, adds the package
and offers to build.

**5. Choosing Claude doesn't offer the browser extension.**
Upstream's `bin/omarchy-default-agent:150-152` runs
`omarchy-install-chromium-claude`, which writes to `/usr/share/*/extensions`.
nix-bin's replacement doesn't call it, and `tests/session.nix:2080` already lists
that script as an Arch installer that isn't reachable here. Nothing tells the user
the extension exists. A printed line is a weak fit: when the agent is already
installed, the script goes straight to `exec omarchy-agent`, whose screen takes
over the terminal. A line would only be seen when the agent still has to be
built.

## Proposed outcome

- A fresh install shows the update toast only when `omarchy-update-available`
  says a newer release exists. When it can't tell, there is no toast, the same
  answer the bar's update icon gives.
- Preinstall scripts run cleanly outside a session, and `remove` no longer calls
  a flag that doesn't exist, and removes only a Hermes wrapper Omarchy wrote.
- `vi` opens an editor on a default install, and a user's own `vi` still wins.
  The ledger row says what is true.
- Choosing a missing browser or editor ends with it installed and set as the
  default, without choosing twice. A choice that can't be installed here (Sublime
  Text, Brave Origin) says so and names the alternative.
- Someone looking for Claude's browser extension can find the declarative route.

## Affected users and systems

- Installed systems running the Omarchy session, on the first run and in the
  Setup > Defaults menu.
- Anyone who runs the preinstall scripts over ssh or from another remote session.
- `vi`, because it adds a command to every default system.
- Mode A users, who must see no change from anything opt-in.

## Constraints

- **Each gap needs a check that can fail (§1, §2), with the failing output in the
  PR.** No check currently covers `wifi.sh`, or the preinstall scripts outside a
  session.
- **Probes need an isolated `PATH`.** The first gap 4 run reported "already
  installed" because the host's own Firefox was on `PATH`. A check using the
  host's `PATH` would pass without testing anything.
- **`vi` needs a coexistence fixture (§14).** `system.path` resolves name clashes
  silently, so a user's `vim`, or their `programs.neovim.viAlias`, must not be
  shadowed or broken.
- **Gap 4 is not one route, and browsers differ from editors.** There are 7
  browsers and 8 editors, split across `omarchy-pkg-add`, `omarchy-pkg-aur-add` and
  the `omarchy-install-editor-*` scripts. Editors write a state file, so the agent's
  record-first order carries over. Browsers use `xdg-settings`, which needs an
  installed desktop file, so a declined build must not lose the choice.
  `omarchy-install-browser` also does setup after installing (flags, theme, Wayland
  environment, and policy writes to read-only paths), and that has to be kept or
  dropped per step. Some apps are unfree, so a machine with unfree off needs an
  honest answer too.
- **#1612 is changing default apps.** `neovim` reaches the system through
  `runtimeDeps` (`pkgs/omarchy/default.nix:271`, `modules/nixos.nix:1397`), which
  are low priority. If `vi` and #1612 touch the same lines, whichever lands second
  rebases.
- **§12 applies to closing #1623.** It closes only when every group below has a
  merged PR, so each PR uses `Refs #1623` and only the last uses a closing keyword.

## Proposed groups

| Group | Gaps | Why together | Size |
|---|---|---|---|
| A: scripts that answer wrongly | 1, 2, 2a, 5 | Small and independent. 2a needs an ownership rule in the spec, the only design in the group | smallest |
| B: `vi` | 3 | Adds to every default system, and needs a fixture and #1612 ordering | small |
| C: defaults that install | 4 | Real design across several routes, the only group that could take long | largest |

No gap blocks another. Grouping only keeps gap 4's design work from holding up the
small fixes.

## Open questions

The owner approved every recommendation below on 2026-11-05.

For the owner, with a recommendation for each:

1. **Should 2a be in scope?** It isn't in the issue, but it is a small fix in a
   file group A already edits. Recommend yes.
2. **What should `vi` be?** Recommend a `vi` that runs `nvim`, and no `vim`, because
   upstream ships only `vi` and a `vim` command would imply Vim.
   The alternative is to leave `vi` out and only correct the ledger, which costs
   nothing but leaves `vi: command not found`.
3. **How far should gap 4 go?** Recommend installing every browser and editor
   `data/apps.nix` can provide, keeping the choice through the build, and refusing
   plainly for the ones it marks unavailable. A smaller version only replaces the
   wrong AUR message, and still means choosing twice.
4. **Where should gap 5 live?** Recommend a line in the `nixos` skill or the
   manual, rather than in the script, where the agent's screen would hide it in the
   common case. `programs.chromium.extensions` is what `omarchy-install-service-1password`
   already points to. Which browsers it reaches, and whether it force-installs where
   upstream's is removable, are unverified and for the spec to settle.
