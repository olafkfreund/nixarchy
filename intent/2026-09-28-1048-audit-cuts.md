# Intent: the same code, written once

## Problem

A repo-wide complexity audit found four places where identical code is
written out many times (measured on `main`, `c9e1a86`):

1. **42 of `flake.nix`'s 88 check registrations are identical** apart from
   the name (168 lines).
2. **Shell print helpers are redefined per script.** `red`/`dim` in 10,
   `say` in 9, `bold` in 8, `ok`/`fail` in 7, `warn`/`step` in 5.
3. **"Pick a package out of the vm's systemPackages by name" appears 7
   times** across the tests.
4. **`ok()`/`bad()` pass/fail printers are repeated in 6 test scripts.**

Nothing is broken. The cost is reading and editing: a new check means a
fifth copy of the same block, and a helper fixed in one script stays wrong in
nine others.

## Proposed outcome

Items 1, 3 and 4 are written once. Every check still builds exactly what it
built, with the same derivations, the coverage guards still pass, and each
guard can still fail. Item 2 goes as far as you decide (question 1).

## Affected users and systems

Contributors only. No machine changes, and nothing a user sees.

## Constraints

- **Proof by derivation, not by eye** (§5, "you cannot compare closures across
  commits"). Every check's `drvPath` is compared before and after, evaluated
  in the same tree. A refactor that changes a check's derivation is not a
  refactor.
- **`checks.test-registration` must keep failing for an unregistered test.**
  It matches the literal `import ./tests/<name>.nix` (`tests/test-registration.nix:41`).
  If item 1 moves 42 names into a list, the guard must learn to read that
  list, and must be shown still refusing a test that is in neither place
  (§1).
- **`checks.options` isn't touched.** It's the 11.5 GB one (§6), and none of
  these cuts need it.
- **`nix-bin` scripts stay standalone** unless you decide otherwise: each one
  replaces an upstream standalone script, and upstream's style is one
  self-contained file.

## Open questions

1. **Item 2, the shell helpers: do it or not?** A shared `ui.sh` saves about
   150 lines. For the `writeShellApplication` scripts in `pkgs/*.sh` it is
   cheap and safe. For the `nix-bin` replacements it couples files that are
   separate by design and would need a splice at build time. My lean: do
   `pkgs/*.sh` only, and leave `nix-bin` alone.
2. **Item 1's shape.** One option: `lib.genAttrs [ … ] (n: import ./tests/${n}.nix { … })`
   for the 42, with `test-registration` taught to read the list. The other:
   leave `flake.nix` as it is, since explicit is also a virtue, and 168
   lines is a small price. My lean: do it, because the guard update is small
   and the list then shows every uniform check in one screen.
