## Deviations recorded during implementation

- **Step 1, catalogue-diff refusal:** the branch was dead, not merely
  exiting 0. `close=$(grep … | tail | cut)` under errexit and pipefail ended
  the script, silently, whenever no `}` line existed, so the "no closing
  brace" explanation never printed. Fixed with `|| true` on that capture,
  plus the planned non-zero exit. The check asserts both, and each half was
  seen red on its own.
- **Step 1, edited drafts:** Codex's refusal also fired when no record
  existed yet, which is every machine's first apply after this change. It
  would have refused a draft edited in `~/.config`, the normal place. It now
  follows the selection files' rule (a record must exist and differ), and
  the check has that case.
- **Step 1, apply lock:** waits with a message instead of blocking silently.
  `--detach`'s parent exits before the lock, so the unit cannot deadlock on
  it.
- **Step 1, check:** failures are counted rather than `exit 1`, so one red
  run names every case. Enable's missing-row path cannot show a rename,
  because its own `sed -i` replaces the inode straight after; the
  catalogue-diff case proves the rename.
- **Step 3, check:** the default-plugins hook prepends its own PATH, which
  shadowed the stubs, so the case first passed vacuously, before and after
  the fix. The stubs are now spliced into the hook's PATH line, and the list
  stub leaves a mark the check requires.
- **Step 2, avahi:** `mkIf` on `serviceConfig.ExecStartPre` still created
  the `avahi-daemon` unit, so the guard moved up to
  `services.avahi-daemon = lib.mkIf …` (found by agy).
- **Step 2, unit gating:** `omarchy-recover-internal-monitor` runs before
  `graphical-session-pre`, ahead of the compositor, so it keeps no
  environment gate, which it never had. A session-variable gate would have
  skipped it at every login. `checks.session` now asserts that
  `omarchy-sleep-lock` and `omarchy-crash-watch` are active in a booted
  session, because nothing checked that the units actually run (§2).
