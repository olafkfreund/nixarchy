## Decisions carried from the approved spec

**Promise.** A single failing command leaves `/home` and `/var/lib` both reset or both
untouched. A second failure, in the rollback, is outside the promise and is reported
with the exact state and repair. Power loss is not promised (owner, 2026-11-05).
Nothing that existed before this run is ever deleted. `/etc/nixos` stays untouched.
A failed reset does not fail the boot or retry on each boot. The unit stays absent from
Mode A. Every confirmation stays. No *Coexistence* fixture (§14): no option a user
also sets.

**Unit order.** All fallible staging first, then two `exch` calls
(`renameat2(RENAME_EXCHANGE)`, util-linux, already on the unit's `path`):
`mv` request to `.failed`, mount top, guards, copy `/var/lib`, write the success receipt
into the copy, snapshot `@factory-home`, sync, `exch @home`, `exch /var/lib`. The
`/var/lib` exchange is the commit point and carries the receipt, so `.done` is present
only if both happened. `oldvar=/var/lib.before-reset-$stamp`,
`oldhome=$top/@home-before-reset-$stamp`, the names the receipt already promises. Each
starts as the fresh factory copy, and the exchange leaves the old data under that name,
so no rename follows the commit. `rm -rf /var/lib.factory-new` goes.

**The trap deletes only what it staged.** `phase` is set after each exchange succeeds,
and logged:

| phase | trap does | `.failed` first line |
|---|---|---|
| `guard` | removes **nothing**: either name may be somebody's data (the stamp has one-second resolution, from a clock that can be wrong early in boot) | `nothing changed` |
| `stage`, including a failed first exchange | removes `$oldvar`, `$oldhome` | `nothing changed` |
| `home-swapped` | exchanges `@home` back; only if that succeeds, removes both. **If it fails, removes nothing** | `rolled back` or `rollback failed` |
| `done` | nothing | no report |

**Failure record.** `/var/lib/nixarchy/factory-reset.failed` is the renamed request
(0600, root), filled in by the trap, present in the live `/var/lib` exactly when the most
recent reset did not commit. Empty means unknown: crash, power cut, or an unwritable
report. The command prints it after elevation and before the baseline answer, then stops,
`--force` included, until `sudo rm <path>`. A new request would otherwise overwrite the
only record of a failed rollback. `--check` never prints it.

**Command.** Three answers (`yes`, `no`, `unknown`) from the exit status of
`btrfs subvolume list -r /`. `--check` never elevates and prints nothing:

| exit | meaning |
|---|---|
| 0 | managed, baseline there |
| 1 | not managed, or the filesystem answered and there is no baseline |
| 3 | managed, and the question could not be asked |

`unknown` and non-root: resolve self with `readlink -f`, refuse unless it is under
`/nix/store/`, `exec sudo "$self" "$@"`. Elevation keys on `unknown`, not `EUID`, so the
unprivileged fake-`btrfs` cases keep working. At the top, if root:
`export PATH=/run/wrappers/bin:/run/current-system/sw/bin`, so a caller's `gum` cannot
answer. `unknown` and root: "Could not ask whether this machine has a factory
snapshot:" plus btrfs's words, exit 1. `GUM_*` and `PATH` are not forwarded, `--force` is
never added, and the ownership refusal still runs first with no sudo. The menu row does
not change. Upstream's three elevation fixes: #13047 is the `/nix/store` case; #13316
(`GUM_*`) is deliberately not copied; #16032 does not apply.

**Rejected, do not revive:** only moving the snapshot; exchange then rename; plain
renames with rollback (**the fallback only if step 1 fails, and only by amending the
spec**); a `/var/lib` subvolume; an install-time `baseline` file; `sudo` in the row;
`pkexec`; keeping the request until success; a doctor row, a login notification, a manual
page.

**Plan-level choices, none changing a spec decision:**

- `checks.factory-reset` goes in `uniformChecks`, like `hibernate-resume`.
- Layout: systemd initrd plus `systemd.repart` with `Subvolumes`, the precedent in
  nixpkgs' `nixos/tests/non-default-filesystems.nix` (`btrfs` test) on our pin.
- **Case 12 is added:** the first exchange failing. No spec case reaches the
  `btrfs subvolume delete` cleanup, because case 3 fails before `$oldhome` exists.
- **Case 5 also runs the marker's repair**, so the printed repair is proven.
- **Case order is chosen so a break fails fast**, since the driver stops at the first
  failure: 1, 11, 6, 2, 10, 3, 4, 7, 5, 12, 8, 9.
- **Spec's "a row in `tests/install-matrix.py`" becomes a paragraph in its docstring.**
  That file's only table is `CELLS`, installs a published ISO, and has no reset; a cell

### 3. `installer/factory-reset.nix`, the `script` (was `host.nix:459-563`): the new order

Replace the script with this shape, keeping the receipt's text and adding the listing.
`''${` escapes aside (§5), this is the design, not a sketch to improve on:

```bash
set -euo pipefail

request=/var/lib/nixarchy/factory-reset.request
failed=/var/lib/nixarchy/factory-reset.failed
stamp=$(date +%Y%m%d-%H%M%S)
oldvar=/var/lib.before-reset-$stamp
top=""
oldhome=""
device=""
phase=guard
step="moving the request aside"

# A failed report must not change the unit's result.
report() {
  printf '%s\n' "$@" >"$failed" || echo "could not write $failed" >&2
}
remove_staged() {
  rm -rf "$oldvar" || echo "could not remove $oldvar" >&2
  if [ -e "$oldhome" ]; then
    btrfs subvolume delete "$oldhome" || echo "could not remove $oldhome" >&2
  fi
}
on_exit() {
  rc=$?
  set +e
  case $phase in
    guard)
      report "nothing changed" "Failed while $step. See: journalctl -u nixarchy-factory-reset"
      ;;
    stage)
      remove_staged
      report "nothing changed" "Failed while $step. See: journalctl -u nixarchy-factory-reset"
      ;;
    home-swapped)
      if exch "$top/@home" "$oldhome"; then
        remove_staged
        report "rolled back" "Failed while $step, and /home was put back. Nothing changed."
      else
        # $oldhome holds the person's home. Nothing is removed.
        report "rollback failed" "Failed while $step, and /home could not be put back." \
          "/home is reset and /var/lib is not. Your home is @home-before-reset-$stamp. To repair:" \
          "  sudo mount -o subvol=/ $device /mnt" \
          "  sudo exch /mnt/@home /mnt/@home-before-reset-$stamp" \
          "  sudo rm -rf $oldvar    # the unused factory copy" \
          "  systemctl reboot"
      fi
      ;;
    done) ;;
  esac
  if [ -n "$top" ]; then
    umount "$top" 2>/dev/null
    rmdir "$top" 2>/dev/null
  fi
  exit "$rc"
}
trap on_exit EXIT

# One rename removes the trigger and creates the record, so a crash still leaves one.
mv "$request" "$failed"

step="mounting the top level"
device=$(findmnt -no SOURCE / | sed 's/\[.*\]//')
top=$(mktemp -d)
mount -o subvol=/ "$device" "$top"
oldhome=$top/@home-before-reset-$stamp

for sub in @factory @factory-home @home; do
  step="checking $sub"
  if ! btrfs subvolume show "$top/$sub" >/dev/null 2>&1; then
    echo "$sub is not a subvolume here: nothing has been changed." >&2
    exit 1
  fi
done
step="checking the names are free"
if [ -e "$oldvar" ] || [ -e "$oldhome" ]; then
  echo "$oldvar or $oldhome already exists: nothing has been changed." >&2
  exit 1
fi

phase=stage
step="copying the factory /var/lib"
cp -a --reflink=auto "$top/@factory/var/lib" "$oldvar"
step="writing the receipt"
mkdir -p "$oldvar/nixarchy"
cat >"$oldvar/nixarchy/factory-reset.done" <<EOF
<the existing receipt text, :539-559, plus how to list earlier leftovers:
   ls -d /var/lib.before-reset-* /mnt/@home-before-reset-*>
EOF
step="snapshotting @factory-home"
btrfs subvolume snapshot "$top/@factory-home" "$oldhome"
step="syncing the filesystem"
btrfs filesystem sync "$top"

step="exchanging @home"
exch "$top/@home" "$oldhome"
phase=home-swapped
echo "phase=$phase"
step="exchanging /var/lib"
exch /var/lib "$oldvar"
phase=done
echo "phase=$phase"
btrfs filesystem sync "$top" || true

echo "factory reset complete: /home and /var/lib are as the installer left them."
```
