# Spec: No check or script fails because grep found what it was looking for

## One change to the approved defaults

The intent's Q2 default was to rewrite every site where the rewrite is
mechanical, and allowlist only the rest. **This spec narrows that:** rewrite
the **30 exposed** sites and allowlist the **66 measured-safe** ones, each with
its reason.

- Many safe sites are Python strings inside VM tests, several of which only run
  nightly (`wifi-hwsim`, `install-iso-net`, `reinstall-vm`, `demo`). A quoting
  slip there would not show on the PR.
- Rewriting them buys uniformity and nothing else.
- The guard still fails any **new** occurrence, so the tree cannot grow a
  sixty-seventh unreviewed one.

Overrule this at approval if you want the uniform rewrite anyway.

## What was measured

The per-site audit lives in #1060. It read the pinned nixpkgs to establish
where `pipefail` holds, and used strace to count producer writes.

- **stdenv builders** (`runCommand`, phases): pipefail **on**. `setup.sh` sets
  it and never restores it.
- **`writeShellApplication`:** on.
- **NixOS test driver** (`succeed`, `fail`, `execute`,
  `wait_until_succeeds`): `bash -c 'set -euo pipefail; …'`, so on.
- **A pipe inside `su user -c '…'` or `sh -c`:** a fresh shell, off.
- **GitHub Actions `run:`:** `bash -eo pipefail`, on.
- **Writes:**
  - bash's builtin `printf`/`echo` write once per line;
  - external tools write in 4 KiB chunks, so output under 4 KiB is one write
    at exit;
  - `gh` writes line by line;
  - `journalctl` output is unbounded.

**A worse form: masking.** Under `! … | grep -q` or `machine.fail("… | grep
-q …")`, a match followed by SIGPIPE turns into a **pass**. The check then
passes with the bug present. Seven of the 30 have this shape.

## Design

### 1. Rewrite the 30 exposed sites

These are the forms to use. None pipes into a `grep -q`.

| Producer | Rewrite |
| --- | --- |
| a string already in a variable, fixed text | `[[ $v == *'text'* ]]` |
| a variable, where the pattern is a regex (`^`, `\b`, `-E`, `-x`) | `grep -q[E/x/F] 'pat' <<<"$v"` |
| command output | `out=$(cmd)`, then one of the above on `"$out"` |
| inside a VM driver string | `"out=$(CMD); grep -q 'PAT' <<<\"$out\""` |

Per file:

- `tests/microvm-template.nix`: 737, 739, 741.
- `tests/apply-imports.nix`: 79, 91, 109 (masking).
- `tests/qml.nix`: 96 (masking).
- `tests/test-registration.nix`: 74.
- `tests/options.nix`: 3416, 4573, 4588, 4589.
- `tests/install.nix`: 765.
- `tests/demo/default.nix`: 227.
- `tests/session.nix`: 467, 501, 562, 611, 1569 (masking).
- `tests/install-iso-net.nix`: 398.
- `tests/wifi-hwsim.nix`: 128 (masking), 168, 169.
- `pkgs/verify.sh`: 601.
- `pkgs/omarchy/default.nix`: 541 (masking), plus 953 (safe today, same shape,
  and upstream can grow the file past 4 KiB).
- `.github/workflows/release.yml`: 473, 489.
- `.github/workflows/build.yml`: 390.
- `.github/workflows/nightly.yml`: 300.

`tests/demo/screencast/shot-coverage.sh:52` is fixed by #1062, and excluded
here. Line numbers are at `3cceade` and will be re-read at implementation.

**Two sites where the rewrite changes meaning, handled explicitly:**

- **`pkgs/verify.sh:601`** (`timeout 15 nix-store --gc --print-roots`). Today
  a timeout forces the "not a root" branch. After the rewrite, the capture
  keeps `rc=$?`, and a non-zero `rc` reports "could not list GC roots" rather
  than matching partial output. That is more honest than either old path.
- **`release.yml:473/489`** (`gh … --jq`). Today a `gh` failure reads as
  "asset missing" and triggers a re-upload. After the rewrite, the capture
  fails the step under `set -e`, which is the correct answer to "the API did
  not answer". 489 re-fetches after the uploads, never reusing 473's capture.

The three workflow files are edits to the shell inside existing steps. There
is no trigger, required-check or timeout change. Still, §11 says a human
merges CI-gate territory, so the PR says so plainly, and **you** merge it.

### 2. The guard: `checks.grep-q-pipefail`

A `runCommand` over a filtered copy of the tree (`tests/`, `modules/`,
`pkgs/`, `installer/`, `.github/`, `flake.nix`):

- It finds every `| grep -…q` line.
- It compares them against `tests/grep-q-allowlist.txt`, where each line is
  `path<TAB>exact line text, trimmed<TAB>reason`. The key is the line's text,
  not its line number, so edits elsewhere in a file do not invalidate it.
- It fails in **both directions**, naming each offender (§4, "a
  hand-maintained list fails open"):
  - an occurrence not on the list: "new `| grep -q` — rewrite it, or allowlist
    it with a reason";
  - a list entry no longer in the tree: "stale entry".
- It is seconds and no VM, run on PRs by the generated step, with no workflow
  edit.

The 66 safe sites seed the list, each with its measured reason (for example
"inside `su -c`: no pipefail", "one write: `blkid` prints one line", or
"`|| true` absorbs 141").

### 3. The lesson grows

`tests/AGENTS.md#a-pipe-into-grep-q-can-fail-because-grep-matched` gains:

- the masking form (`!` / `machine.fail` turns the race into a false pass);
- where pipefail holds (the driver, stdenv, workflows) and where it does not
  (`su -c`, `sh -c`);
- the 4 KiB rule for external producers;
- a pointer to the guard and its allowlist.

## Alternatives rejected

- **`grep pat >/dev/null` instead of `-q`.** GNU grep 3.12 happens to read to
  EOF without `-q`, but that is an implementation detail, and the dev host's
  `grep` is ugrep. It is not a fix to rely on.
- **Line-number allowlist keys.** They break on every unrelated edit, and the
  guard would teach people to regenerate the list blindly.
- **Rewriting all 96.** Covered above: uniformity at the price of changes to
  nightly-only VM tests the PR cannot run.
- **`set +o pipefail` around sites.** It hides the producer failures pipefail
  exists to catch.

## Risks

- **Quoting in VM driver strings.** Each rewrite goes through the driver's
  lint (pyflakes) only when the driver builds. `session` and `install` run on
  the PR. `wifi-hwsim`, `install-iso-net` and `demo` run nightly, so a slip
  there shows the morning after. Mitigation: those five driver-string
  rewrites use one identical, reviewed template, and the PR lists them.
- **A capture holds the whole output in memory.** The largest is `journalctl`
  of one unit, which is fine.
- **The allowlist is 66 lines.** It is honest rather than small. It shrinks
  when someone rewrites a site, and the stale direction makes them remove the
  entry.

## Verification

- `checks.grep-q-pipefail` is green.
  - **Break a:** add a new `printf … | grep -q x` line to a test. The check
    fails, naming it.
  - **Break b:** delete one allowlist entry. The check fails, naming the site.
  - **Break c:** add a stale allowlist entry. The check fails, naming it.
- **The masking class, demonstrated.** `! { printf 'x\n'; sleep 0.2; printf
  'y\n'; } | grep -q x` passes under pipefail although `x` is present. That
  is the PR's proof that the seven masking rewrites matter.
- **Local checks:** `checks.options`, `checks.qml`, `checks.microvm-template`,
  `checks.apply-imports`, `checks.test-registration` and the omarchy package
  build, with CI idle. CI runs `session`, `install` and `verify` on the PR.
  The nightly-only VM tests are named in the PR as first proven by the
  nightly.
- `nix fmt -- --ci`, statix, deadnix, actionlint on the three workflow files.
