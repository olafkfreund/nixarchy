# Plan: Superwhisper arrives when the person chooses it

## Approved decisions

- Superwhisper stays the recommended and preselected engine. Its package reaches a machine only after the person chooses it, so "works" means after one choice and one rebuild, not at first boot (owner, 2026-11-07).
- No closure nixarchy builds holds it: not references, VMs, runners or the cache. Nothing is downloaded or started before the choice.
- The package is the vendor's v1.2.0 x86_64 archive, with a pinned hash, marked unfree, `unfree = true` and `prebuilt = true`. It has no `updateScript`; a bump is a reviewed change.
- The choice is `omarchy-install-dictation-superwhisper`, replaced in `pkgs/omarchy/nix-bin`. It shows where audio goes and the vendor's terms, asks Cloud or Offline, and runs `nixarchy-app-enable` and `nixarchy-apply`. It writes the selection only after the rebuild succeeds. Crash reports go off before the first start.
- First login shows one notification pointing at the row, installs nothing and records that it ran.
- `dictation.enable` machines keep Voxtype. With unfree off, Voxtype is the engine with the same keys, and the selection file moves from `superwhisper` to `voxtype`.
- Mode A doesn't change. The user unit uses store paths and doesn't link into agent directories.
- Kyber is out of this task and of #1610's list (owner, 2026-11-07).

**Added since the spec, as what the code requires:**

- The `apps` row has **no `menuId`.** `modules/apps.nix:1102-1120` rewrites a row with a `menuId` to `nixarchy-app-enable`, which would skip the consent screen. `setup.default.dictation.superwhisper` already runs `omarchy-default-dictation superwhisper`, which opens `omarchy-install-dictation-superwhisper` in a floating terminal, so the replacement doesn't open a second one. `tests/options.nix:2573-2597` filters on `a ? menuId`, so a row without one is fine.
- **`omarchy-remove-dictation-superwhisper` is replaced too.** A person who chose it must be able to take it back. Upstream's calls `omarchy-pkg-drop` and unlinks `/usr/bin` paths. The replacement stops the unit, runs `nixarchy-app-disable superwhisper` and `nixarchy-apply`, clears a `superwhisper` selection only after that succeeds, and leaves preferences, history and models alone. `modules/apps.nix:1218-1240` rewrites a guarded `remove.*` row to `nixarchy-app-disable` when `arch` maps its package, which would skip this script. So the row has **no `arch`** either, and `remove.dictation.superwhisper` keeps upstream's action. Its guard asks `omarchy-pkg-present superwhisper-bin`, which strips `-bin` and looks for the command, so the row shows only when the app is there. If a check requires `arch` on an `ours` row, use an explicit override with the same action instead. Step 8 tests the route.

## Rollback

Before a release carries it, revert the squash commit. After one has, don't: a person who chose it has `superwhisper.enable` in their own `apps.nix`, and with the row gone that is an undeclared option and their rebuild fails. Instead, set the row to `unavailable = "<reason>"`, the existing path that warns and drops the package (`modules/apps.nix`, `available`). The selection file falls through the key guard, which binds nothing.
