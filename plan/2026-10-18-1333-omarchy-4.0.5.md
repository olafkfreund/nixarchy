   `1153-owe-video-backgrounds.patch` is rebased with a three-way merge and
   regenerated, with its header updated.

## ⚠ One change from the approved spec: #953's patch retires

The spec retargeted #953's kill loop and kept its readiness knob. Built on
v4.0.5, `checks.shell-restart-race` went red on its negative control:

```
FAIL: upstream's script no longer ends with zero shells here: the harness cannot see #953, or upstream fixed it and the patch can go
```

`pkgs/AGENTS.md#omarchy-restart-shell-waits-for-the-old-shell-to-be-gone-953`
says: "**When to drop it:** once upstream waits for the old instance itself
... That red is the signal, not a regression." v4.0.5 kills with `timeout 30`,
then waits up to 30 s on `quickshell list -a -j`, then launches with a 60 s
readiness deadline. So:

- **delete** both #953 substitutions (`killOld`/`killNew` and
  `readyOld`/`readyNew`, ~1998–2025). #982's relaunch edit just above them
  stays. `OMARCHY_SHELL_EXIT_TIMEOUT` and `OMARCHY_SHELL_READY_TIMEOUT` go with
  them. Nothing else in the tree reads either (grepped).
- `checks.shell-restart-race` is **retargeted**: the slow and fast cases run
  the shipped script, which is now upstream's logic, and must still end with
  exactly one shell. Case 2 (the negative control) and case 3 (the wedged
  shell, which tested our own "refuse to launch" message) are deleted.
- What we lose: a wedged old shell is no longer reported. Upstream launches
  after 60 s, and its new shell refuses to start beside the old one. That
  still leaves one shell, the wedged one, rather than zero.

If you would rather keep the patch, step 2 retargets it as the spec said
(`timeout 5` → `timeout 30` in `killOld`, and `deadline=$((SECONDS + 60))` as
`readyOld`), and step 3 rewrites only case 2's expectation.

**Deviation found by CI on #1335 (2026-10-18):**
- `checks.patched-files`: the mimeapps loop read `${src}/config/*mimeapps.list`.
  `omarchy-patched-files.sh` takes every `${src}/<path>` in `default.nix` as a
  file read straight from the source, so `config/` read that way hid
  `config/hypr/xdph.conf`'s "seeded" reason. The loop now reads
  `$out/share/omarchy/config`, copied at `default.nix:433`, before the loop.
  B1 was re-proven against it.
- `checks.session`'s `/usr` scan: four 4.0.5 commands name `/usr`, and they
  join its named exceptions, each with its reason:
  - `omarchy-cmd-default-browser`: an unset `XDG_DATA_DIRS` default;
  - `omarchy-cmd-browser-handoff`: it matches `/usr/bin/<browser>` and falls
    back;
  - `omarchy-install-hermes-cli` and `omarchy-install-openclaw-cli`: Arch
    seeds that NixOS does not have. Both refuse with a message and exit 1, as
    `omarchy-install-ai-hermes` already does.

  Setup › Default › Agent › OpenClaw or Hermes therefore refuses, as it did
  on 4.0.4.
- I had not run `patched-files` or `panel-loaders` locally. Both are cheap, and
  CI's catch-all job builds them.
