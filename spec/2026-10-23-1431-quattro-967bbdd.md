# Spec: edge on Omarchy quattro 967bbdd

## Design

Two changes on `carry/1431-quattro-967bbdd`, cut from `edge-candidate`
76ef7d33.

1. **Pin.** In `flake.nix`, set the Omarchy input to
   `github:basecamp/omarchy/967bbdd…` and `omarchyVersion` to
   `"edge-20261023-967bbdd"`. Then run `nix flake update omarchy`. This is
   the same mechanism as #1428.

2. **A ledger row** in `data/bin-ledger.nix`. It goes in sorted position,
   between `omarchy-apply-lock` and `omarchy-apply-system`, and follows the
   shape of `omarchy-refresh-pacman`:

   ```nix
   "omarchy-apply-pacman" = {
     class = "vendor";
     reason = "Vendored unchanged. This row exists only to record why an Arch-only package path is carried and unreachable -- see `pacman` below.";
     pacman = "Renders /etc/pacman.conf and the mirrorlist from channel templates and a regional profile. Not reached by nixarchy's flows: its callers are omarchy-refresh-pacman (unreachable, see its row), the Arch installer's post-install, and omarchy-channel-set, which is patched to delegate to nixarchy-channel (#1431).";
   };
   ```

   The row has no `allow` field. The script matches no behaviour group,
   because its `/etc` writes go through `"$etc/…"`, and an allowance the
   script does not match fails the check
   (`.github/scripts/check-bin-ledger.py`).

Nothing else in 446361a..967bbdd needs a carry change.

- **The new files:** the China-region pacman fragments,
  `default/regions/cn/timezones`, `docs/regions.md`, the migration, and
  upstream tests.
- **The changed files:** Arch-only scripts, shell QML and JS, docs and tests.
- **Arch-only scripts** (`omarchy-refresh-pacman`, `omarchy-channel-set`,
  `install/post-install/pacman.sh`): our patch on `omarchy-channel-set`
  replaces its body, so upstream's edit there does not reach us.
- **Shell QML and JS:** these are vendored, and `checks.session` and `qml`
  cover them.
- **The Taildrop receive unit** (`default/systemd/user/omarchy-tailscale-receive.service`):
  nixarchy does not ship it (`modules/AGENTS.md`, Tailscale).

## Alternatives rejected

- **A `nix-bin` refusal shim**, like `omarchy-refresh-plymouth`. That
  pattern is for a command a user reaches from the menu and expects to work.
  This one is hidden, and no supported flow calls it. Run by hand with sudo,
  it writes pacman files that NixOS never reads. A shim would be divergence
  carried at every bump, for no caller.
- **Patching out the `/etc` writes.** This has the same cost, and patching
  a dead path is pointless.
- **Porting upstream's notification migration** (`1792648436.sh`).
  nixarchy runs no upstream migrations, by design
  (`pkgs/omarchy/nix-bin/omarchy-migrate`). The migration also deletes
  users' notification history. If the trimmed engine cannot read 4.0-era
  state, that is a separate issue, found by `session`.

## Risks

- **The trimmed notification engine meets old state.** Upstream's migration
  clears that state, and ours does not run. On edge machines, old history
  files stay. `checks.session` asserts that a closed notification enters
  history (`tests/session.nix:1065`). That covers a fresh state only, not a
  4.0-era one. If old files confuse the engine, the first sign would be on
  a user's edge machine. It is accepted for edge, and reported if seen.
- **The VM checks have not run on 967bbdd.** The failed run stopped at
  `prepare`. Edge's `verify` (`options`, `session`, `coexist`, `plugin`) is
  the first run. If it goes red, the fallback keeps edge on 446361a again,
  as it did today, so edge users are not exposed.
- **The row's claim goes stale** if nixarchy ever calls the script. The
  ledger cannot see that. A grep for `omarchy-apply-pacman` belongs in any
  future change that brings pacman-adjacent flows back.
