# Intent: edge on Omarchy quattro 967bbdd

## Problem

Upstream quattro moved from 446361a to 967bbdd: five commits.

- China pacman mirrors (#16256);
- notification-engine trims, and instant show and dismiss (#16296, #16306);
- Taildrop notification fixes (#16301);
- an indicator peek fix (#16293).

Edge's run 39909651743 could not take it, so its fallback published `main` on
446361a (edge `76ef7d33`) and filed #1431. Edge users are fine, but one
upstream step behind.

One generated check failed, `bin-ledger`:

    omarchy-apply-pacman: calls pacman or yay and has no `pacman` reason.

`bin/omarchy-apply-pacman` is new upstream: a hidden, requires-sudo helper. It
renders `/etc/pacman.conf` and the mirrorlist from channel templates and the
optional China region profile. The ledger's `\b(pacman|yay)\b` scan
(`.github/scripts/check-bin-ledger.py:62`) matches its path names, and
`data/bin-ledger.nix` has no row saying why an Arch-only path is carried.
The `etc-write` group did not fire, because the writes go through `"$etc/…"`.
Nothing else in that run's generated checks failed. The VM checks never ran
on 967bbdd.

## Proposed outcome

Edge publishes quattro 967bbdd, and #1431 closes on the next edge report.

## Affected users and systems

- **Edge users:** they get the five upstream commits.
- **`data/bin-ledger.nix`**, plus the pin in `flake.nix` and `flake.lock`.
- **The carry** reaches `edge-candidate` by fast-forward only, as #1428's did.
  `main` is untouched until the next release.

## Constraints

- The ledger row's claim has to be true. Upstream calls the script from:
  - `omarchy-refresh-pacman`, which is vendored here with a `pacman` reason
    and is unreachable;
  - `install/post-install/pacman.sh`, the Arch installer, which nixarchy never
    runs;
  - `omarchy-channel-set`, which is patched here into a delegation to
    `nixarchy-channel`.

  Nothing in `pkgs/`, `modules/` or `data/` calls it.
- Upstream's migration `1792648436.sh` clears 4.0-era notification state.
  nixarchy does not run upstream migrations
  (`pkgs/omarchy/nix-bin/omarchy-migrate`), so the trimmed engine meets the
  old state. `checks.session` already asserts that a closed notification
  enters history. Edge's `verify` boots it on the new quattro.

## Open questions

1. **Ledger row only, or shim the command?**
   - (a) A `vendor` row with a `pacman` reason, the same shape as
     `omarchy-refresh-pacman`.
   - (b) A `nix-bin` refusal shim, like `omarchy-refresh-plymouth`.

   **Recommendation: (a).** The command is hidden and no supported nixarchy
   flow reaches it. Run by hand with sudo, it writes pacman files NixOS never
   reads. A shim adds divergence that has to be carried at every bump. Codex
   (gpt-6-sol) and agy (model not reported) both reviewed this read-only, and
   both said (a), with no `allow = "etc-write"`.
