# Intent: nixarchy follows Omarchy v4.0.5

## Problem

Omarchy v4.0.5 was released on 2026-10-16. `omarchy.yml`'s nightly bump
cannot build against it (run 39096047628), so the port stays on v4.0.4, and
every night's bump fails the same way. Nothing else opens a pull request for
it.

Found on a local bump (`/mnt/data/vmtest/wt-405`):

- `1153-owe-video-backgrounds.patch` does not apply to `LockView.qml`.
  Upstream qualified its palette references for Qt 6.12 (bfac6650e). A
  three-way rebase onto v4.0.5 is clean.
- The `--replace-fail` anchors in `omarchy-launch-webapp` (default.nix:606) are gone.
  4.0.5 moved browser choice into new helpers: `omarchy-cmd-default-browser`,
  `omarchy-cmd-browser-handoff`, `omarchy-browser.desktop` and a
  `hyprland-mimeapps.list`. Our edit used to make that choice work on NixOS.

The release changes 201 files. It adds scripts (`omarchy-hyprland-session-lock-stranded`,
`omarchy-hw-nvidia-display`, …) and rewrites the Hermes and OpenClaw
installers, so the build failures are the first of several.

## Proposed outcome

- `nix build .#omarchy` and every check `build.yml` runs are green on v4.0.5.
- Every edit nixarchy made on v4.0.4 still has its effect on v4.0.5, or is
  deleted because upstream now does the same thing. The PR lists each one.
- New scripts reachable from the menu run on NixOS, or are hidden, the same
  way their v4.0.4 neighbours were treated.
- The default browser, web apps and the lock screen still work. `checks.session`
  boots a desktop and is the probe.

## Affected users and systems

Every stable-channel user, on the next release. That touches
`pkgs/omarchy/default.nix`, the carried patch, `data/apps.nix` and
`data/menu-actions.nix` if menu rows changed, and `flake.nix`/`flake.lock`.
Edge is unaffected: it tracks quattro.

## Constraints

- A fix to Omarchy's own behaviour goes upstream rather than being patched
  here. No upstream posting without approval.
- `--replace-fail` stays. No anchor may be loosened to `--replace`.
- p620's runners: the session and install checks run in CI, not locally,
  while CI is busy (§6).

## Open questions

None. Each anchor's decision goes in the spec.
