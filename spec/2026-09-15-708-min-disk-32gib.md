# Spec: 32 GiB is the minimum disk, and everything agrees on it

## Facts this design rests on

- **Layout** (`installer/disk-config.nix`): a 2 GiB ESP, then the rest of the disk
  as btrfs mounted `compress=zstd`. No swap partition.
- **Installed closure:** about 14 GiB on disk. That is `installer/try.sh:49`'s
  measured figure: "a 2G ESP plus ~14 GiB of closure". A fresh install on a
  32 GiB disk therefore has roughly 32 − 2 − 14 ≈ **16 GiB free**. Step 5's check
  measures the real number in CI rather than trusting this estimate.
- **Collection today** (`installer/host.nix:170-171`): below `min-free` 5 GiB,
  collect until `max-free` 20 GiB is free. On 32 GiB, 20 GiB free is out of reach
  once the closure is on disk, so every collection runs to exhaustion.
- **The crash:** NixOS/nix#15614 ("Don't detach the auto-GC thread") is in Nix
  2.35.0 and later, not 2.34.8. Both our `nixpkgs` and `nixpkgs-stable` ship
  `nixVersions.nix_2_35` at 2.35.2; both default to 2.34.8. nixarchy's scripts
  already read `config.nix.package` (`modules/apps.nix`), so they follow the
  change.
- **Installer floors:**
  - `ask_device` uses `min_bytes=$((8 * 1024 * 1024 * 1024))` (`install.sh:770`)
    and says "at least 8 GiB" (`:791`);
  - free-space mode uses `FREE_MIN_GIB=32` (`:822`);
  - `tests/installer-wizard.nix` pins the floor with a 1 GiB disk (under) and a
    12 GiB disk (over), and asserts exactly one device is offered.
- **p620's disk guard** (`install-check.yml`, `need_gb=40`): target images are
  sparse qcow2 and grow only by what is written. Growing the target from 20 to
  32 GiB writes the same install, so the guard's 40 GB stands.

## Design

### 1. One floor in the installer: 32 GiB

- **A single constant.** `install.sh` gets `MIN_DISK_GIB=32`, used by `ask_device`
  (replacing the literal 8 GiB in `min_bytes` and in the message) and by
  free-space mode. `FREE_MIN_GIB` becomes `MIN_DISK_GIB`.
- **Refusal wording.** The refusal names the size:
  `nixarchy needs at least 32 GiB; nothing attached qualifies.`
- **When it refuses.** Still at device selection, before partitioning, so
  nothing is touched (#300).
- **Answers files.** An unattended install whose `device=` is under 32 GiB is
  refused the same way, in validation, before formatting. The implementation
  confirms `validate_answers` checks device size; if it does not, this adds the
  check.

### 2. Collection thresholds for a 32 GiB machine

`installer/host.nix`: `min-free = 3 GiB`, `max-free = 8 GiB`.

- **3 GiB floor.** Room for a `nixos-rebuild switch` to write a new generation
  without starting a collection mid-build. Low enough that a fresh 32 GiB
  install, at about 16 GiB free, is nowhere near it.
- **8 GiB target.** Reachable on 32 GiB, so a collection ends instead of deleting
  everything it can. Still frees enough that the next dip is not minutes away.
- **Fixed, not scaled.** 32 GiB is the minimum; a larger disk does not need
  larger numbers to be safe, only more room above them. A scaled value is
  complexity no machine has asked for.
- **The comment** above them states the 32 GiB basis and the arithmetic, so the
  next change to the closure can redo it.

### 3. Nix 2.35 on installed machines

`installer/host.nix`: `nix.package = pkgs.nixVersions.nix_2_35;`

- **Why here.** It removes the crash outright; the thresholds only make it rarer.
- **Only installed machines.** `host.nix` is imported by installed machines alone,
  so Mode A keeps nixpkgs' default (§7).
- **A pin that must not rot.** A comment names #15614 and says to drop the line
  once nixpkgs' default `nix` is 2.35 or later.
- **Tested both channels.** `checks.stable-eval` already evaluates the installed
  host on stable, so a stable nixpkgs without `nix_2_35` would fail there.

### 4. Every install-class target is 32 GiB

| file | today | becomes |
|---|---|---|
| `tests/install.nix` `emptyDiskImages` | 20480 | 32768 |
| `tests/install-encrypted.nix` `emptyDiskImages` | 20480 | 32768 |
| `tests/install-iso.nix` `qemu-img create … 24G` | 24G | 32G |
| `installer/vm.nix` `emptyDiskImages` | 24576 | 32768 |
| `installer/try.sh` `DISK_MB` | 24576 | 32768 |
| `tests/installer-wizard.nix` "over" disk | 12288 | 32768 |

- **The wizard test** keeps its shape: a 1 GiB disk under the floor, a 32 GiB disk
  over it, exactly one offered. It gains a 16 GiB disk, which **was** over the old
  floor and must now be hidden. That is what proves the floor moved rather than
  merely that the numbers changed.
- **Unchanged:** `tests/free-space.nix` (a 36 GiB disk with a 32 GiB free region
  already meets it) and `tests/reinstall-vm.nix` (to be checked in the plan and
  moved if it is under).

### 5. A free-space check where it happens

In `tests/install.nix`, right after the installed target boots, before any
rebuild:

```python
avail = int(target.succeed("df --output=avail -B1 / | tail -1").strip())
print(f"free after install on a 32 GiB target: {avail / 2**30:.1f} GiB")
assert avail >= 8 * 2**30, (
    f"a fresh install leaves {avail / 2**30:.1f} GiB free on a 32 GiB disk, "
    "under max-free (8 GiB): the machine would collect garbage from its first "
    "rebuild. The closure grew; see #708.")
```

- **The bar is `max-free`.** A fresh minimum-size install must not already be
  somewhere a collection would run toward.
- **It prints the number every time,** so a PR that grows the closure sees its
  cost in the install log, the measurement #702's spec lacked.

### 6. The manual says 32 GiB

`docs/manual/getting-started.md`, `the-iso.md` and `dual-boot-install.md` state
32 GiB as the minimum for both modes. The sentence "Anything under 8 GiB is left
out" becomes 32 GiB.

## Answers to the intent's open questions

1. **Thresholds:** fixed, `min-free` 3 GiB and `max-free` 8 GiB (§2).
2. **Headroom:** at least 8 GiB free after install, asserted and printed (§5).
3. **`installer-vm` / `try.sh`:** yes, 32 GiB. They are what a user tries first, and
   they should model the minimum.
4. **Nix 2.35:** yes, pinned in `host.nix` with a removal note (§3).

## Alternatives rejected

- **Only raising the test disks.** Users on 20 GiB disks keep the crash, and the
  installer still accepts 8 GiB (§3 of AGENTS.md).
- **Scaling thresholds to disk size.** Nothing needs it at a fixed minimum.
- **Keeping `min-free` 5 / `max-free` 20.** The target is unreachable on the
  minimum disk, and that is the loop that crashed.
- **Only pinning Nix 2.35.** It fixes the crash, but machines still collect to
  exhaustion and CI still tests under-promise disks.
- **A new dedicated free-space VM check.** `checks.install` already boots a fresh
  install; one `df` there costs nothing.

## Risks

- **Nix 2.35 behaviour changes** for every installed machine. Covered by
  `checks.install`, `install-encrypted`, `free-space` and `reinstall-vm`, which
  rebuild and switch on it, plus `checks.stable-eval`. The nightly carries the
  ISO and reinstall paths.
- **Real machines on 8–31 GiB disks** are refused by a new installer. Already
  installed ones keep booting; the release notes say it.
- **The 16 GiB estimate could be wrong.** §5 is the measurement. If a fresh
  install leaves under 8 GiB, the check fails, and the spec's thresholds are
  revisited with the real number, not the assertion.
- **Wizard test ordering.** A third empty disk changes device names (`vdb`/`vdc`/
  `vdd`); the assertion is updated to name the one allowed device by size.

## Verification

1. **`checks.installer-wizard` (local):** passes; with the floor put back to 8 GiB
   it fails because the 16 GiB disk is offered.
2. **`checks.options` (local):** a case that the `vm` configuration's
   `nix.package.version` is 2.35 or later and `min-free`/`max-free` are 3/8 GiB,
   and a Mode A system has neither.
3. **`checks.stable-eval` (local):** passes with the pin.
4. **`checks.install` (CI):** passes, prints free space, and asserts ≥ 8 GiB. Seen
   red once with the assertion bar raised above the measured free space, which
   proves the check reads a real number rather than a constant.
5. **`install-encrypted`, `install-iso` (nightly) and `free-space`, `reinstall-vm`:**
   pass on 32 GiB targets.
6. **p620's guard** still passes with two installs running (CI log).
7. **Lint:** statix, deadnix, `nix fmt -- --ci`, actionlint, and shellcheck on
   `install.sh` and `try.sh`.
