# Intent: Verify only running Distrobox containers

## Problem

`pkgs/verify.sh:1057-1060` says it cannot distinguish boxes from other containers and lists every name from `podman ps -a`. It then calls `distrobox enter` for each name at line 1094. Both issue claims hold in the code: an ordinary Podman container is misclassified as a box, and a stopped container is passed to `distrobox enter`. The pinned Distrobox 1.8.2.5 `distrobox-enter` starts a container whose status is not `running`, so verification can change the user's container state. The issue's example output for an ordinary PostgreSQL container was not reproduced here; the incorrect selection and possible false failure are established by the call path.

## Proposed outcome

`nixarchy-verify` checks the first-start, export, and entrypoint properties only for running Distrobox containers. It neither starts stopped boxes nor reports unrelated Podman containers as broken boxes. When none are running, it explains that no running boxes were checked.

## Affected users and systems

Users with `services.boxes` enabled who also keep ordinary Podman containers or stopped Distrobox containers. The affected path is the Boxes section of `pkgs/verify.sh`; it runs in the user's rootless Podman context.

## Constraints

- Identify Distrobox containers by its `manager=distrobox` label. The pinned `distrobox-create` adds this label; verify the filter against the package and a check before relying on it.
- Select running containers before calling `distrobox enter`; verification must not start a stopped container. Preserve the existing checks for selected boxes.
- Add a cheap check that demonstrably fails if ordinary or stopped containers reach `distrobox enter`, using the repository's break-and-restore rule. No Nix build or VM run occurs at this intent gate.
- #1085 also edits `pkgs/verify.sh`. Rebase or sequence implementation after that change so both sections survive; keep edits confined to the Boxes section.
- Do not edit the criticals PR's in-flight files (`installer/install.sh`, `modules/microvm/*`, `modules/services/microvm.nix`, `pkgs/microvm.nix`, `tests/installer-*.nix`, `tests/microvm-*.nix`, `tests/options.nix`). No workflow edit is needed; changing a CI gate would require human review under root `AGENTS.md` section 11.

## Open questions

None. The owner chose to check only running Distrobox containers, print a concise skipped count for stopped ones, and report a failed Podman listing as a failure rather than an empty list. Because #1085 also edits `pkgs/verify.sh`, implementation must rebase onto main after #1085 merges.
