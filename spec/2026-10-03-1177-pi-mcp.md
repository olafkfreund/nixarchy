# Spec: pi gets the MCP servers the other three agents already get

## Design

Four changes, in the order the work falls: one predicate, two writers per
server, one argument on the remover, and the claims that stop being true.

### 1. `piOn`, beside the predicates already in `modules/home.nix`

```nix
piOn = localAi.enable && builtins.elem "pi" localAi.agents;
```

This is not a new idea: it is the exact condition `nixarchyPiProvider`
(`home.nix:1795`) and `nixarchyPiSettings` (`:1832`) already compute inline, and
`localAi` already falls back to `{ enable = false; agents = []; }` when there is
no `osConfig` (`:32-34`), so a standalone Home Manager user gets `false` rather
than an evaluation error. Naming it once and using it four times is the whole
of it; the two existing pi writers should use it too rather than keep their
copies.

pi is gated where the other three are not, and the intent settles why: `mcp`
defaults **true** and both helpers create the file they merge into, so an
ungated pi writer would put `~/.pi/agent/mcp.json` on every nixarchy machine,
almost none of which have pi. The three ungated agents are left exactly as they
are — see "Not in scope".

### 2. Two more activations, reusing the claude-code flavor

```nix
home.activation.nixarchyMcpPi = lib.mkIf (mcpEnabled && piOn) (mergeJson {
  what = "the NixOS MCP server";
  file = "${config.home.homeDirectory}/.pi/agent/mcp.json";
  json = mcpConfig { flavor = "claude-code"; fileName = "nixarchy-mcp-pi.json"; };
});
```

and the same shape for `nixarchyAiMirrorMcpPi`, gated on `aiMirrorMcp && piOn`,
using `aiMirrorConfig`.

`flavor = "claude-code"` is not a guess. `pi mcp add ai-mirror -- ai-mirror mcp`
in a throwaway `HOME` writes:

```json
{ "mcpServers": { "ai-mirror": { "command": "ai-mirror", "args": ["mcp"] } } }
```

and `mcp-servers-nix.lib.mkConfig` with `flavor = "claude-code"` was built and
read back with the same server entry: same nesting, same `command` and `args`.
It is NOT byte-identical — the generated file also carries `"env": {}` and
`"headers": {}`, the second of which is an HTTP-transport field on a stdio
server. pi accepts both: `pi mcp list` against the generated file reports the
server connected with its tools. So no new flavor, no
new helper, and `mergeJson` carries pi unchanged — including its symlink
refusal, its `{}` seeding and its "not plain JSON" message.

The file is `~/.pi/agent/mcp.json`, from pi's own `--help`: *"Reads
`~/.pi/agent/mcp.json` and, in trusted projects, `.pi/mcp.json`."* Only the
global file is written. The project-level one is the same shape as the
`<cwd>/.codex/config.toml` layer #74 is about, and nothing here should create
one.

### 3. A fourth path on the remover

`pkgs/ai-mirror-mcp-remove.nix` takes `<claude.json> <opencode.json>
<codex.toml>` positionally (`:28`) and runs a per-agent `json_drop`: Claude is
`.mcpServers["ai-mirror"]` with `.command`, opencode is `.mcp["ai-mirror"]` with
`.command[0]`, codex is an awk pass. pi's file has Claude's shape exactly, so it
is one more call with Claude's paths.

The argument is **optional**, `pi=${4:-}`, and `json_drop` already returns early
on a file that is empty or missing. Two reasons, both load-bearing: the script
runs under `writeShellApplication`, where `set -u` makes a bare `$4` fail the
whole activation for any caller still passing three; and `tests/ai-mirror-mcp-
remove.nix` calls it three times with three arguments (`:31`, `:50`, `:57`),
including once with deliberately missing files. An optional fourth keeps every
existing caller working whether or not it is updated in the same commit.

The caller at `home.nix:1514-1517` gains pi's path **ungated** — the opposite of
the writers. Removal must not depend on `piOn`: a machine that had pi and then
dropped it from `localAi.agents` would otherwise keep ai-mirror in a config file
nixarchy wrote, with no switch left that takes it out. The remover is already
safe on a file that does not exist.

### 4. The claims that stop being true

Not documentation housekeeping — these are promises about what the switch does:

- `modules/nixos.nix:745-752`, `programs.nixarchy.mcp`: "The other two skill
  directories … `~/.pi/agent/skills`, have no documented MCP configuration file
  to write, and inventing a path for them would be a feature that silently does
  nothing." Becomes: `~/.agents/skills` alone, and pi's file is written where pi
  is installed.
- `modules/nixos.nix:762-763`, `aiMirror.mcp`: "Connect Claude Code, Codex and
  opencode" → and pi, where it is installed.
- `modules/nixos.nix:777`: "all three agents' configuration files" → the agents'.
- `docs/manual/ai.md:118` "Three agents get it"; `:126-129` "**Pi documents no
  MCP configuration file.** Writing one anyway would put a file on your disk
  that nothing reads"; `:141` and `docs/manual/plugins.md:329` "the same three
  agents".
- `modules/home.nix:1438-1444`, the comment that records the exclusion: it keeps
  `~/.agents`, loses pi, and says what changed — pi 0.99.2 documents the file,
  which is the condition that comment itself set.

## Alternatives rejected

- **A `pi` flavor in mcp-servers-nix.** The generated object is already
  identical to `claude-code`'s; a flavor whose only content is "same as that
  one" is a second place to change when either moves.
- **Writing pi's file ungated, like the other three.** `mcp` defaults on, so
  this lands a config file on every machine for an agent almost none of them
  have — the exact complaint `home.nix:94-98` makes about orphan editor config.
- **Gating the other three in this change.** It would change when three files
  are written on every existing machine. Right, probably; not here.
- **A required fourth argument on the remover.** `set -u` turns that into a
  broken activation for any caller not updated in lockstep, including three test
  call sites.
- **Gating removal on `piOn`.** Dropping pi from `localAi.agents` would strand
  an ai-mirror entry nixarchy wrote with no way left to remove it.
- **Writing `.pi/mcp.json` in projects.** That is the per-project layer #74 is
  about; nixarchy has no business creating one.

## Risks

- **A file appears in `~/.pi/agent/` on machines that have pi.** Intended, and
  the point of the change, but it is new state in a directory the user may
  consider theirs. `mergeJson` refuses a symlink and preserves every other key,
  so the blast radius is one object inside one file.
- **pi may reject extra keys.** `mcp-servers-nix` could add fields beyond
  `command`/`args` for some server definitions. Verified for the two
  configurations this writes, not in general — the verification below pins it.
- **`localAi.agents` is the only pi predicate.** If pi ever gains an
  apps-catalogue entry, there will be two ways to install it and `piOn` will be
  wrong for one of them. Named in the comment so it is found.
- **Docs drift the other way.** `~/.agents` is still excluded for the original
  reason; an edit that removes the whole paragraph would lose that.

## Verification

- `nix flake check` — covers `tests/options.nix`, whose `aiMirrorActivationNames`
  (`:295-299`) gains `nixarchyAiMirrorMcpPi`, asserted present when the switch is
  on and absent by default (`:702`).
- `tests/ai-mirror-mcp-remove.nix` gains a pi fixture alongside the existing
  three: a `~/.pi/agent/mcp.json` holding a nixarchy store-path entry plus an
  unrelated key, proving ours goes and theirs stays; and a second pass proving a
  user-written `ai-mirror` entry survives. Its existing three-argument calls
  must keep passing untouched, which is the regression test for the optional
  fourth.
- `tests/home-writers-dry-run.nix` and `tests/home-manager-writers.nix` already
  create `$HOME/.pi/agent` and run the writers under `DRY_RUN`; the new
  activations join that sweep.
- **A pi-less machine writes nothing**: with `localAi.enable = false`, neither
  pi activation is present at all. Asserted in `tests/options.nix` the same way
  `aiMirrorMcp.off` is.
- **Against the real pi**: after activation on a machine with pi, `pi mcp list`
  reports the servers rather than an error — the one check that proves the file
  is not merely well-formed but acceptable to the tool that reads it. This is
  the compositor-shaped half CI cannot reach, and it is what "documents a file"
  has to mean in practice.

## Not in scope

- **The three ungated agents.** nixarchy writes `~/.claude.json`,
  `~/.config/opencode/opencode.json` and `~/.codex/config.toml` on machines with
  none of those agents installed, against the principle `home.nix:94-98` states
  for editors. Its own issue.
- **`~/.agents`.** Still no documented MCP file; still excluded; the comment
  keeps saying so.
- **pi as a nixi harness.** pi is not an ACP agent — its modes are `text`,
  `json` and `rpc`, and there is no `agent-client-protocol` in the package — so
  none of this makes pi usable in the nixi card.
- **Watching `<cwd>/.pi`.** nixi's `noticeUnaccountedEnvironment` watches
  `<cwd>/.codex` for the project-config layer #74 describes. pi has the same
  shape, and would deserve the same watch the day pi becomes a harness. Not now,
  and not in this repository.
