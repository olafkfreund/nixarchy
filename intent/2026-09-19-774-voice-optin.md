# Intent: nixarchy-voice is one opt-in setup away, and never drives the desktop unless asked

Closes #774.

## Problem

[nixarchy-voice](https://github.com/olafkfreund/nixarchy-voice) turns speech
into desktop actions. The owner wants it to be part of nixarchy. As it stands
it can't simply be on by default:

- **It connects itself to ai-mirror.** Whenever `ai-mirror` is on PATH, voice
  registers it as an MCP server (`claude_backend.py:427-429`) and tells its
  agent to "Call control with mode=agent first" (`:135-139`). With both
  installed, a spoken sentence can drive the mouse and keyboard although the
  user never asked for that.
- **It needs a cloud model and sends it the desktop.** The default engine
  starts a Claude session at login. Screen, clipboard and notification text go
  to it, and notification bodies are logged to
  `~/.local/state/omarchy-voice/notifications.jsonl` by default. Setting
  `allow_shell = false` does not switch off Claude Code's own Bash tool.
- **It is large.** About 1 GiB with whisper and the Piper voice models. The
  models are part of the package, so turning the service off does not shrink
  the machine.
- **Its default voice needs a credit.** The default Piper voice ("Jenny") comes
  with dataset terms that ask for visible credit wherever it speaks, and today
  there is none.

## Proposed outcome

The owner's decision, 2026-09-19:

- **Voice is not in the default install**, so the default machine and the ISO
  stay the size they are.
- **One "Set up voice" menu row** installs it and asks which backend to use.
- Until the user turns each on, notification logging, the wake word and
  desktop control stay off.
- **Voice connects to ai-mirror only when the user explicitly says so**, never
  just because both are installed.
- The default voice is credited as "Jenny (Dioco)" where speech is generated.

## Affected users and systems

Anyone who sets up voice, and nobody who doesn't. On the nixarchy side:

- `flake.nix` (the input);
- a new opt-in option and its menu row;
- tests and docs.

In the voice repo:

- an explicit desktop-control flag;
- notification logging off by default;
- its plugins moved onto `programs.nixarchy.plugins` with prefixed ids;
- the attribution;
- runtime readiness checks instead of an evaluation-time warning.

## Constraints

- **Package presence is not consent.** Voice never links ai-mirror without an
  explicit opt-in, and that is tested at runtime with both installed.
- **Voice is not in the default install**, and not on the ISO: the default
  closure does not grow.
- Secrets are never read during Nix evaluation.
- `allowUnfree = false` still evaluates.
- Mode A stays inert.
- Every new check is proven to fail first (§1).

## Open questions

None. The owner decided the default and the desktop-control opt-in on
2026-09-19.
