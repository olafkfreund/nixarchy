# Spec: voice is an app you install, not a default you switch off

## Design

nixarchy does not reference nixarchy-voice at all today — not a flake input, not
a package, not a menu row. That is the starting point, and it is the right one:
the intent's first decision is that voice **is not in the default install**, so
the work is to make it *installable*, not to add it and gate it.

### 1. Voice is a row in the app catalogue

`data/apps.nix` already describes everything **Install ▸ Search** offers, and
five entries carry an `option` path for the things that are a NixOS option
rather than a package (`firefox`, `_1password`, `steam`). Voice is that shape:

```nix
omarchy-voice = {
  menuId = "install.ai.voice";
  label = "Voice";
  category = "AI";
  option = [ "services" "omarchy-voice" "enable" ];
  note = "about 1 GiB with whisper and the Piper models";
};
```

This is the whole of the "one **Set up voice** menu row" the intent asks for,
and it costs nothing on a machine that does not pick it: the catalogue is data,
and `nixarchy-apply` writes the option into the user's own flake only when they
choose it. It also means voice is found by the same search as everything else,
rather than living in a corner of the menu somebody has to be told about.

### 2. The module comes from upstream, pinned as a flake input

`inputs.nixarchy-voice`, with `homeModules.default` imported the way
`inputs.nixi.homeModules.default` already is in `modules/home.nix:479`. The
module is upstream's; nixarchy does not reimplement it.

**The defaults this depends on are already upstream**, merged today:

- `[hands] desktop_control` and `programs.omarchy-voice.desktopControl` default
  **false**, gating the ai-mirror link at the one place it is made
  (nixarchy-voice#19);
- notification logging defaults **off**, with `allow_notifications_explicit` so
  somebody who chose it keeps it silently;
- plugins register under prefixed ids with the "Jenny (Dioco)" attribution
  visible in the built wrapper (nixarchy-voice#21).

So nixarchy sets **no overrides**. If it had to force those off, the upstream
defaults would be wrong and that is where the fix belongs (§11: a fix to how the
thing behaves belongs upstream, not patched here).

### 3. Nothing is added to `defaultPluginSet`

Voice's own plugins install through `programs.nixarchy.plugins` when the module
is enabled, which nixarchy-voice#21 implements. A `defaultPluginSet` entry would
be the opposite of the decision.

## Alternatives rejected

- **A bespoke "Set up voice" menu row with its own script.** More code than a
  catalogue entry, a second way to install something, and invisible to
  **Install ▸ Search** — which is the surface the front page advertises.
- **Shipping voice and gating it behind an option.** The intent's reason is
  size: about 1 GiB with whisper and the Piper models, and the models are part
  of the package, so an off switch does not shrink the machine or the ISO.
- **Overriding the upstream defaults from nixarchy.** They are already correct
  as of today's merges. Restating them here would create two places to change
  and hide it if upstream regressed.
- **`lib.mkDefault` on voice's options from nixarchy.** Same objection, and
  §7's rule: a `mkDefault` on a merging type silently drops the contribution.

## Risks

- **The input adds evaluation weight to every machine**, including ones that
  never install voice. Measured in verification below; if it is material the
  fallback is `flake = false` with the module imported by path.
- **Upstream could regress its defaults**, and nixarchy would inherit that
  silently. This is the honest cost of not restating them — `checks.options`
  gains a case asserting the off state, so a regression is caught here rather
  than on somebody's desktop.
- **`checks.options` is already at 11.7 GiB of a 16 GiB runner** (#747). Adding
  an input and two cases is small, but it is not nothing, and #747 is open
  precisely because there is little headroom left.
- **The "about 1 GiB" figure is the intent's**, carried forward untested. The
  note in the catalogue should say what is measured, so verification measures it.

## Verification

1. **Red first** (§1): `checks.options` gains `voiceIsNotADefault` — on a default
   home, nothing named `omarchy-voice` is in `home.packages` and no
   `services.omarchy-voice` unit exists; `off` is the same predicate against a
   home with it enabled, so deleting the catalogue entry cannot make it pass.
   Break it by adding voice to `defaultPluginSet` and watch it fail.
2. **Mode A** is untouched: the same case asserts a machine with nixarchy off
   gains nothing.
3. `checks.menu-verbs` (or the existing menu case) sees the new row, so the
   catalogue entry is proved to reach the menu rather than assumed to.
4. **Measure the cost**: `nix eval` on `nixosConfigurations.vm` before and after
   the input, wall clock and peak RSS, reported in the PR. If it moves
   `checks.options` materially, say so against #747 rather than quietly adding to
   it.
5. **Measure the size**: the closure of the voice package, so the catalogue's
   note states a measured number rather than repeating "about 1 GiB".
6. `nix fmt -- --ci`, statix, deadnix, and `checks.options` green.
